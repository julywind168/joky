# 版本兼容与升级政策

Joky 当前处于 `0.x` 开发阶段。这里说明升级预期；当前已实现的语言与标准库行为以
[语言参考](language.md)为准，各版本的具体变化见[更新记录](../CHANGELOG.md)与
[GitHub Releases](https://github.com/julywind168/joky/releases)。

## 版本与变更记录

- `0.x` 的次版本升级可能修改语法、标准库 API、CLI 参数或 Rust 嵌入 API，可能需要迁移源码。
  维护者应在更新记录中标出破坏性变化、受影响对象与替代写法；可行时先提供弃用提示。
- 补丁版本以兼容修复为目标。纠正类型、所有权或 ABI 检查的缺陷时，过去误接受的程序可能开始报错，
  这类可见变化也必须记录，不能仅以“修复”代替升级说明。
- `main` 上尚未发布的提交可能继续变化。需要可复现环境时固定 Release／tag 或完整提交号，
  并记录工具链与依赖；多个开发提交可能显示相同的 `joky --version`。
- 不承诺每次变化都有自动迁移工具，也不承诺旧版本长期支持或固定发布周期。
  修复通常进入当前开发分支；是否回补旧版本以具体发行说明为准。

发布时把 `CHANGELOG.md` 的 `Unreleased` 条目整理到带版本与日期的章节，列出升级操作、
已知限制、对应源码提交和验证证据。未发布的条目不能当作某个现有安装包已经具备的能力。

## 哪些部分可能受影响

| 部分 | 升级预期 |
| --- | --- |
| Joky 源码与标准库 | 次版本可能调整语法、类型准入、方法名称与所有权要求；先运行项目检查，再处理诊断 |
| CLI | 参数和默认行为的变化需记录；终端排版、颜色、耗时、自然语言诊断不是稳定的机器解析协议 |
| Rust 嵌入 API | `0.x` 期间可能调整签名或类型；更新依赖后重新编译宿主并验证注册函数 |
| C ABI、AOT 与 runtime | CLI、头文件、AOT 对象和 `libjoky.a` 使用同一发行版本；源码开发时使用同一提交并一起重编，不能只按相同的 `0.x.y` 判断兼容 |
| 字节码、缓存、预编译镜像与私有布局 | 不承诺跨版本可读；保留源码并用新工具链重新生成 |
| VS Code 扩展 | 与编译器独立编号；扩展说明列出依赖的 CLI 能力，最低 VS Code 版本由扩展清单声明；尚无跨版本兼容矩阵 |

完整升级工具链后，重新构建原生产物和相关宿主。已链接完成的独立原生程序不会被升级 CLI 自动改写；
如它还依赖外部动态库或资源，仍需自行保留相应运行环境。具体 ABI 约束见[架构文档](architecture.md)。

## 升级步骤

1. 阅读从当前版本到目标版本的更新记录与 Release 说明，确认平台、工具链要求和迁移事项。
2. 将新版本完整安装到新目录，保留旧目录；不要混用其他版本的 runtime 或头文件。
3. 用新版本检查自己的项目，并用 `fmt --check` 审查格式变化；有项目测试时运行它们。
   `fmt` 写回是独立选择，不作为升级的自动步骤。
4. 重编原生程序和嵌入宿主，完成自己的运行验证后再切换 PATH／编辑器编译器路径。
   有问题时切回保留的旧目录，并附双方版本与复现向[问题入口](../SUPPORT.md)反馈。

完整安装、自检和卸载操作见[发行包说明](distribution.md)。

## 平台与工具链证据

[CLI smoke CI](https://github.com/julywind168/joky/actions/workflows/ci.yml) 配置了 macOS arm64 和
Linux x86_64 的 Debug 安装与基本 CLI 流程验证。每次运行的 job summary 和日志记录提交号、
Rust 版本、目标架构、系统 C 编译器和检查结果。
这是基本可用性证据，不代表全量测试、压力测试、性能测量或 Release 发行验收。

工作流未运行、失败或跳过时，不能把该提交对应的平台写成“已通过”。
README badge 显示 `main` 的最近运行状态，PR、tag 与其他提交应查看各自运行记录。
最低 Rust 版本为 **1.99.0**，与当前实际开发工具链一致；工作区各包均声明 `rust-version = "1.99"`。
CLI smoke 与发行包工作流固定使用 1.99.0，避免 CI 跟随 stable 漂移；平台验证状态仍以具体运行结果为准。
发行包验证另见 **Build distributions** 工作流和具体 Release 附件说明。
