# 状态域语法糖草案

状态：2026-10-15，设计草案，尚未实现。确定方向是 `when` 统一访问 1–64 个域，
作为受检域操作的语法糖，默认支持兼容热更新；`#state` 不作为使用 `when` 的前置条件。
显式操作名、返回类型和分阶段限制是本草案的首版建议，具体拼写尚未冻结。
本文所有 `text` 代码块均为不可执行的设计示意，不表示当前编译器已支持。

本草案负责业务写法、语义选择与实施阶段。已有 API 见[语言参考](language.md#内置域访问-jokydomain)，
状态及任务边界见[并发设计](server-concurrency.md)，发布与迁移协议见[热更新计划](aot-script-hot-reload.md)。
实现后将正式语法归入 `language.md`，运行时及 ABI 不变量归入 `architecture.md`。

## 1 现有基础与目标

已有单域读写、双域联合短操作、最多 64 域的集合快照与候选原子提交，以及具名操作的兼容晚绑定。
Rust 宿主已有 2–64 域短操作入口；Joky 源码的直接联合短操作目前开放到双域，更多域主要通过
集合快照和候选表达。执行仍由同一宿主驱动的单线程 FIFO 推进，没有并行读执行或 CPU 抢占。

单域已支持经过资格检查的嵌套记录、String、Array/Map 等拥有图；多域主要仍限标量记录。
域操作输入及投影结果仍限标量。HR7 的嵌套纯值 `Context` 扩展的是 Script 调用契约，
并未同时开放域操作的组合输入或拥有型结果。

语法糖的目标是减少独立操作函数、权限接线和参数打包代码，保持状态归属、取消、错误隔离及
热更新规则可见。不增加 Service 生命周期，不创建模块可变全局状态，也不把短操作解释为事务。

| 写法 | 目标 | 优先级 |
| --- | --- | --- |
| `when` | 内联编写 1–64 域受检短操作，兼容发布后执行新版实现 | 首先实现 |
| `#state` | 在类型声明处检查域根资格 | 后续补充，不阻塞 when |
| `handle.method(...)` | 单域方法调用、纯值参数打包、具名晚绑定 | 在统一操作契约之上实现 |
| 候选编辑流程 | 从冻结状态派生、修改候选，再验证并原子发布 | 另立切片，先确定存储与依赖规则 |
| 周期与迁移声明 | 简化已有 Timer 和迁移入口的接线 | 后续，不混入 when 首版 |

## 2 when 写法与状态访问

首版建议使用显式操作名；`transfer` 是操作标签，不是另一份函数定义：

```text
let amount = 10
let outcome = when transfer (mut source, mut target, rules) {
    if amount <= 0 || amount > rules.maximum || source.balance < amount {
        false
    } else {
        source.balance = source.balance - amount
        target.balance = target.balance + amount
        true
    }
}
```

外部三个名字是域句柄；块内同名名字分别表示对状态的可写或只读访问。`amount` 是独立捕获值。
先完成业务检查再修改；示例不表示溢出等运行时失败会回滚。

`when` 只在 `@suspends` 流程中使用。建议作为上下文关键字识别，首版访问项只接受已有句柄
绑定名，复杂查找先在外部完成，不提供可能重复求值的访问项表达式。具体解析规则在 W0 冻结。

- 一个访问列表包含 1–64 个绑定位置，因此不同域数也不超过 64；第 65 项在编译时拒绝。
- `mut` 要求写句柄；无 `mut` 只授予读权限，即使外部持有写句柄也不能在块中写入。
- 同一域重复只读可归一化调度，保留各参数绑定；任何包含可写参数的同域别名在执行前拒绝。
- 全部域须属于当前执行器。权限不能由记录字段、整数或语法糖伪造。
- 一次申请覆盖完整访问集合，不逐域持权等待。块体同步执行，其他域操作不会插入其中。

单域 `when read_score (player) { player.score }` 与多域采用同一语义，不分别设计关键字。
初期实现可从单域开始，但不能把双域数量限制固化进语法和隐藏操作契约。

## 3 块体 捕获与返回

编译器把块体提取为带域引用参数和独立捕获包的隐藏操作，沿用 `domain_entry` 的同步、
无外部效果和不逃逸证明；检查整个可达调用链，而非只检查块内有没有 `@suspends`。

块体不能挂起、调用网络或宿主函数，不能再次申请域访问或嵌套 `when`。
域引用、容器借用和视图不能作为结果或保存到外部。普通受检辅助函数及域状态内部的合法
容器操作可以使用，临时存储仍受状态峰值预算约束。

首版捕获与业务结果 R 建议支持标量和有界嵌套纯值记录，复用 HR7 的资格规则：
总字段数最多 64、记录深度最多 8，Unit 和空记录字段也计数。多个捕获合成一个外层记录，
共同计入上限；不按每个捕获分别获得完整额度。捕获按值复制，不能借用、移入拥有资源或保存函数值。
实现需扩展域操作打包与校验，不能仅因 Script 桥已支持就跳过三后端验证。

捕获在入队前固定，排队期间不观察外部变量后续变化。普通局部赋值只修改操作内部副本，
需要影响外层流程的数据通过结果返回。捕获的句柄不能绕过访问集合在块内追加域操作。

块末尾表达式产生 R。首版禁止 `return` 跳出 `when` 到外层流程；`break`、`continue` 只能作用于
块内定义的循环，不能跨边界。业务枚举、拥有型捕获和拥有型结果留待后续资格及清理协议设计。

## 4 稳定操作身份与兼容热更新

`when` 是可晚绑定的域操作，不能默认提取成固定指针闭包。排队项保存稳定操作身份、
访问契约、域句柄及独立捕获值，在实际执行前解析当前实现。旧流程提供旧时刻的输入，
兼容的新块体处理这些输入；不会重新执行旧流程的网络查询、条件判断或捕获表达式。

### 4.1 显式身份与匿名形式

首版建议用逻辑模块路径、外层具名函数限定名和显式标签组成操作键，例如
`game/room.join.accept`。重复标签在同一所属函数中报错；同一标签位于循环中，每次迭代
是同一个操作的新调用。泛型和局部匿名函数中的操作身份先不开放，另行确定实例身份规则。

标签不能取自行号、块序号或源码哈希。移动源码行、插入其他操作、修改算法不应改变身份；
重命名模块、所属函数或标签则视为删除旧入口并新增入口，除非未来显式提供身份别名。
删除后不得把旧身份复用于语义无关但 ABI 相同的操作；编译器的兼容检查不能证明业务语义相同。

匿名 `when (...) { ... }` 保留为候选写法。没有可靠的跨编译身份方案前，首版只实现具名形式；
不能让匿名形式静默固定代码，也不能凭位置猜测新版对应块。匿名形式若开放，必须遵守同样的晚绑定契约。

### 4.2 实现归属与契约

沿用现有多域具名操作方向：第一个参与域的当前模块决定操作实现，其余域逐一检查兼容性。
访问顺序因此是契约的一部分，不允许运行时为了排序而改变实现归属。
隐藏操作须导出到该业务模块的内部操作表；普通公开函数名称不能冒充隐藏操作身份。

块体必须编译在能为该域提供实现的模块中。AOT 中的块不会自动被搬到 Script 模块；
AOT 宿主应调用 Script 业务入口，让业务模块拥有可热更新的操作。AOT 自有域仍可使用原生操作，
但此语法不赋予 AOT 二进制自我热替换能力。

准入及实际执行前都校验：操作键、域参数数量与顺序、逐项读写权限、状态结构契约、
捕获字段名／顺序／类型、结果契约，以及同步、无宿主效果、不逃逸的证明。
捕获字段名暂取词法绑定名，重命名也视为不兼容；编译器采用确定的字段顺序，不靠机器地址
或本次编译的名义 ID 判定跨版本兼容。精确编码和导出元数据在 W0 定案。

| 发布变化 | 排队或旧流程后续发出的 when |
| --- | --- |
| 同一身份和契约，只修改块内算法 | 执行当前域绑定的新版实现 |
| 等待期间多次兼容发布 | 实际执行前解析当时的当前实现 |
| 捕获、返回值、访问权限或状态契约不兼容 | 执行前拒绝，不执行旧实现作为兜底 |
| 操作身份被删除或改名 | 执行前拒绝，不按相似源码匹配 |
| 已经开始执行块体 | 同步运行结束，发布在执行器后续处理 |

不要求数据修订或代码版本仍等于入队时的值：`when` 操作的是执行时的活状态，兼容代码发布
本身不构成冲突。它与快照候选不同，后者仍须验证原读取凭据，不能因为支持晚绑定就放宽。
各域不必绑定同一个模块版本，但每个参与域都必须满足当前选定操作的对应契约。

操作表和排队记录需保留必要的旧契约及结果解码元数据，但不能以此固定执行旧块体。
解析后须保活实际执行模块直到操作结束，调用方用原契约接收结果；这些生命周期需要新增验收。
布局兼容不保证业务兼容，发布者仍负责判断新版逻辑能否处理旧流程传来的值。

## 5 错误 取消与资源

首版建议 `when` 返回 `Result<R, DomainAccessError>`。上例的 R 是 Bool，
`Ok(false)` 表示业务拒绝，不能与运行时拒绝访问混淆。错误名称暂拟如下：

| 错误 | 发生条件 |
| --- | --- |
| Closed | 任一参与域已关闭或正在关闭 |
| DomainFailed | 任一参与域已被隔离 |
| InvalidAccess | 执行器、权限或可写别名不合法 |
| Incompatible | 操作缺失，或当前操作与调用契约不兼容 |
| ResourceLimit | 受理额度或预留存储不足，且尚未开始执行块体 |

此 Result 外层是调度协议，不要求先开放任意业务枚举结果。句柄及捕获表达式在入队前求值时
发生的错误仍属于调用流程错误。捕获包、结果空间和队列资源在执行前准备好；块体中的分配
或其他运行时失败走既有任务失败通道，不能伪装成上述表示“没有执行块体”的 Err。

直接修改不提供失败回滚。正常返回 false 也不撤销写入，所有声明可写的域正常完成后推进修订。
块体运行时失败按现有协议隔离全部声明可写域，只读域和无关域保持可用。
需要任何失败都保留全部旧根时，使用独立候选与原子提交。

调用者取消时撤销尚未执行的申请并释放捕获。取消调用者本身不保证还能收到一个 Cancelled 结果。
已经完成的写入不因等待者取消、结果丢弃或后续关闭撤销；执行中的同步块没有中途抢占取消。
旧结果及捕获在取消、关闭、失败、热更新交错下只能清理一次，并持续按现有配额计费。

## 6 状态声明与句柄方法调用

```text
#state
struct Room { count: Int32 }

impl Room {
    fn count(&self) -> Int32 { self.count }
    fn add(&mut self, amount: Int32) -> Int32 {
        self.count = self.count + amount
        self.count
    }
}
```

`#state` 在声明处检查域根资格，复用已有字段图、清理和预算限制；不自动创建域，不改变
Owner 归属，也不将状态放进模块全局变量。没有属性但满足资格的现有普通记录仍能创建域。
属性不代表全部方法自动合格：域入口仍需逐个通过效果和不逃逸检查。

拟议 `room.add(amount)` 根据接收者为域句柄解析为单域具名调用，在 `@suspends` 流程中等待，
建议与 `when` 使用一致的访问错误协议。普通 Room 值或块内状态引用上的方法仍是同步方法调用。
多个参数按独立纯值包传递，方法身份来自类型及方法限定名，执行前按同一契约规则晚绑定。

Owner 已有 `close`，写句柄已有 `read_only` 等能力 API；业务方法与句柄方法的消歧、资格失败诊断和
泛型方法范围必须在实现前确定。该语法不允许从只读句柄调用可写方法，也不能从同步代码中
隐式驱动执行器。`#state` 和句柄方法调用均不阻塞 `when` 的先行实现。

## 7 候选流程与其他语法糖

`when` 不会自动创建快照，也不会复制整个状态来实现回滚。候选路径继续采用
“联合快照 → 独立候选 → 完整依赖验证 → 原子发布”。除多域标量限制外，还需解决：

- 从冻结状态派生候选并局部修改，避免业务手动重建所有无关字段。
- 活根、快照、候选与临时存储的峰值；明确完整复制、分块复制或写时复制的成本和清理责任。
- 组合输入、拥有型投影及可分步候选构建；普通业务构造不能直接视为已具备 HR5 分步迁移能力。
- 域粒度冲突及重算策略，配置等额外依赖必须显式纳入版本验证，不自动无限重试。

这些涉及存储和所有权，不先用一个类似事务的关键字掩盖。候选编辑的语法与错误类型留待专项切片，
不在本草案承诺通用事务、自动依赖追踪或字段粒度冲突检测。

出站信箱的便捷写法仍须保留提交绑定及满队列整次拒绝的边界。普通 `when` 内不能直接发送
网络消息，也不因正常返回就自动获得候选信箱的提交协议。该协议保证内存提交与入队，
不保证 TCP 已送达或崩溃后仍可恢复。

`#every` 未来只简化显式 Timer 注册，必须保留宿主所有者和取消控制，不能在模块加载时
偷偷启动永久任务。迁移声明只简化已有显式 prepare/step/publish 流程，不能由 `#state`
自动猜测结构迁移。Service 关键字、配置快照与隐式 Context 注入均不纳入本轮。

## 8 实施阶段与验收

性能测量按当前决定暂缓，本计划先验证语义、三后端一致性与资源清理。

| 阶段 | 范围 | 必须验收 |
| --- | --- | --- |
| W0 契约定案 | 显式标签语法、上下文关键字解析、操作身份与 ABI、访问错误和捕获规则 | 设计用例覆盖旧流程调用新块、删除入口、不兼容捕获；明确匿名形式及模块归属 |
| W1 单域贯通 | 命名块提取、独立纯值包、结果与取消；沿用已有单域根资格 | JIT／解释器／AOT 执行生成代码；读写权限、逃逸拒绝、兼容晚绑定及执行前拒绝 |
| W2 完整多域 | 统一扩展到 1–64 个标量记录域，不新增 pair 专用语法 | 1／2／3／64／65 边界、读写混合、别名、只读依赖独立发布及不兼容整次拒绝 |
| W3 多域拥有状态 | 将受检拥有图用于多域直接短操作，闭合跨根所有权规则 | 容器替换、跨根移动的允许或拒绝规则、预算失败、全部可写域隔离和唯一清理 |
| W4 声明与调用便利 | #state、句柄方法调用、多参数纯值包 | 声明诊断、旧 API 兼容、方法消歧、权限和热更新行为一致 |

W1 是实现切片，不代表完整 `when` 目标已经完成。W3 不能仅删除标量资格检查：必须证明
多个根之间不会产生共享拥有存储、悬空引用或重复释放；无法安全支持的跨根移动先拒绝。

共同验收矩阵还包括：等待期间连续发布两次、算法变化但捕获不变、同类型捕获字段换序或
改名、不兼容返回类型、操作改名／删除、模块身份变化、状态 schema 迁移、读句柄传入写项、
取消发生在入队前／等待中／执行后未收取结果、域关闭、配额耗尽和旧模块最终退役。
发布元数据需覆盖独立 AOT 链接和两种 Script 后端；不得把编译进程地址写入 AOT 操作表。

实现验证遵循 [AGENTS.md](../AGENTS.md#按改动范围验证)：相关生成代码行为测试、默认 Debug 检查，
涉及捕获存储与取消的切片补相关 Debug 穷举。正确性测试不加入耗时性能断言。

W0 尚需冻结：显式标签的最终拼写、捕获字段稳定排序、精确错误枚举、元数据编码与诊断格式，
以及源码加载与 AOT 如何提供稳定逻辑模块身份；不能把临时文件路径作为发布身份。
匿名身份、泛型操作、拥有型输入／结果及方法消歧各自在开放前单独定案；不能用尚未确定的
细节推翻 1–64 域、默认兼容晚绑定和显式权限这三个总体方向。
