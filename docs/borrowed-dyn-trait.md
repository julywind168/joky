**V0–V5 已完成首版验收：类型与擦除、三后端分派、借用组合、切片/代码保活及集成发布均已交付。**

## 1. 目标与首版边界

提供同步局部、同步参数位置的 `&dyn Trait` 与 `&mut dyn Trait`，让不同具体类型
通过相同的借用接口调用。对象所有权始终属于原变量，擦除只隐藏具体类型，不延长寿命。
首版必须同时支持关联类型等式和默认方法，不能形成与第 4 项不同的 trait 身份体系。

不开放裸 `dyn Trait` 值、`Box<dyn Trait>`、拥有型动态对象、dyn 返回值、聚合/容器/
arena/持久实例存储、闭包捕获 dyn、宿主保存、FFI、向下转型、trait 向上转型、
`dyn A + B`、dyn Fn 家族、反射或跨语言挂起。可以借用持久实例调用中现有的合法短期引用，
但不能把生成的 dyn 视图写回实例。内建 Drop 不可动态化或显式调用。

本项需要真正的间接分派和新增内部表示；不能声称当前静态 trait 已有 vtable，
也不能把现有无捕获 fn 指针或闭包环境直接当作 trait 对象。

## 2. 目标语法与转换

```joky
trait Read {
    fn value(&self) @noescape -> Int32
    fn doubled(&self) @noescape -> Int32 { self.value() * 2 }
}

struct Counter { value: Int32 }
impl Read for Counter {
    fn value(&self) -> Int32 { self.value }
}

fn inspect(value: &dyn Read) @noescape -> Int32 {
    value.doubled()
}

fn main() -> Int32 {
    let counter = Counter { value: 21 }
    let view: &dyn Read = &counter
    inspect(view)
}
```

由明确的期望类型触发 `&T -> &dyn Trait`、`&mut T -> &mut dyn Trait`，
用于带类型局部初始化、赋值和实参。T 必须具有唯一适用的 impl，且关联类型等式一致。
可以从受约束泛型参数擦除，在每个具体实例生成匹配的分发表。
不增加通用 `as` 值转换、不自动分配、不自动借用临时拥有值；无期望类型时 `&value` 仍是 `&T`。
多分支可在同一期望 dyn 类型下分别转换，所有来源按现有分支合并规则保留，不能只记最后一个。

`dyn` 在本项成为保留字，V0 盘点标识符，V1 迁移受影响源码、测试及文档。
`&dyn Source<Item = Int32>` 沿用第 4 项的具名等式文法；每个关联类型都必须显式绑定，
即使某个方法没有使用它也不能省略。绑定顺序不影响类型身份，未知/重复名称拒绝。
绑定必须满足 trait 声明的能力要求；导入别名不产生新 dyn 类型。
别名可以命名完整的借用类型，不开放通过别名藏入裸 dyn 的值存储。

沿用第 4 项的 Source/Counter 定义，独占视图与关联绑定的目标用法为：

```joky
fn take(source: &mut dyn Source<Item = Int32>) @noescape -> Option<Int32> {
    source.next()
}

fn main() -> Int32 {
    var counter = Counter { value: 40 }
    let source: &mut dyn Source<Item = Int32> = &mut counter
    take(source).unwrap_or(0) + take(source).unwrap_or(0)
}
```

两次调用分别得到 41 和 42；参数传递采用短期独占重借用，不能在第一次调用时消费底层 Counter。

动态调用写 `view.method(args)`；`Read.value(view)` 沿用显式 trait 调用形式，
但选择 view 所属 trait 的动态槽。不能取得绑定方法函数值，也不能让其他可见 trait
或具体类型的固有方法改变槽选择。`&dyn Trait` 不自动满足泛型 `T: Trait`，
不新增 `?Sized` 或对引用类型的隐式 blanket impl。

## 3. 可动态化条件

首版对整个 trait 检查，不隐藏不兼容方法，也不引入 `Self: Sized` 排除方法的机制。
不兼容 trait 仍可用于静态分派，只有请求构造 dyn 类型/转换时报告具体不兼容项。

| 项目 | 首版条件 |
| --- | --- |
| 接收者 | 每个方法有 `&self` 或 `&mut self`；拒绝按值 self 和无接收者方法 |
| 泛型与 Self | 无方法泛型；除接收者外签名不能出现裸 Self、`&Self` 或包含 Self 的聚合 |
| 关联类型 | 全部显式绑定，替换后参数和结果具有确定的布局与存储分类 |
| 效果 | 所有方法同步，声明保证接收者及其余全部借用参数不逃逸；可用全体 `@noescape` 或覆盖全部相关参数的选择式契约 |
| 返回 | 可返回无借用的 Copy/拥有值，包括绑定后合规的关联类型；首版拒绝返回引用及含引用结果 |
| 默认方法 | 与抽象方法同样检查；槽指向该具体 impl 的最终默认实例或覆盖方法 |

例如 `Self.Item` 在绑定后可成为 Int32 或 String；它不等于签名中的裸 Self。
若具体 Item 含引用或依赖仍不确定的投影，应按本表和已有存储规则检查；不能因表面上
没有 `&` 而漏掉聚合里的引用。持有 `&dyn Trait` 只能调用共享方法；持有 `&mut dyn Trait`
可调用共享或独占方法，trait 含独占方法本身不妨碍创建共享视图。

`@noescape` 不承诺无分配、无失败或无副作用。定义与每个 impl 必须验证契约，
动态调用使用声明契约，不能根据当前恰好选中的实现推导更强保证。
只写在具体 impl 上的属性，或默认体推导出的保证，不能代替 trait 接口契约。
未提供契约的现有静态 trait 不会因此失效，只是不满足本次同步局部动态化范围。
例如 Eq 的第二个 Self 参数不满足动态化条件，不能把两个任意对象交给原静态比较方法。

## 4. 借用与生命周期

dyn 视图必须携带底层对象的完整来源集合、字段路径和权限，不能只有数据地址。
借用从擦除创建时开始，按现有最后使用/作用域分析结束；原对象在借用有效期间的
移动、销毁、替换和冲突写入须拒绝，透过别名、helper、分支或再次赋值也一样。

- 共享视图可按共享引用规则复制，所有副本仍依赖原来源，不复制底层对象或创建新所有者。
- 独占视图不可 Copy。直接赋给另一个绑定会移动视图；传给同步借用形参、点调用以及
  显式 `&mut *view` 按现有规则建立短期重借用，子借用期间原视图不可冲突使用。
  `&*view` 可建立共享 dyn 重借用，不能从共享权限恢复独占权限。
- `&mut T` 在期望 `&dyn Trait` 时可建立共享重借用；不能消除原独占来源与冻结关系。
  同一来源的多个方法实参必须一起检查别名冲突，不能逐个转换后漏掉重叠。
- 擦除与转换不得运行用户方法或 Drop。视图结束只结束借用，原值仍由原清理路径销毁。
  调用失败也不能通过 vtable 析构原对象；拥有型返回值与其他拥有参数按普通调用清理。
- 同步 helper 必须证明 dyn 参数不返回、不保存；这一分析覆盖隐藏表示与传递调用，
  不只扫描表面引用。拒绝返回 dyn、放入聚合/容器或闭包、转交未知宿主保存点。

首版拒绝 `@suspends` 形参中的 dyn，也拒绝活跃 dyn 借用跨语言挂起或进入并发分支；
挂起函数内完全在两个挂起点之间结束的同步局部使用可按现有活跃性证明接受。
解释器时间片暂停不是语言挂起：寄存器/帧中的视图、原对象与代码所有者必须一起保留。
取消或指令/内存预算失败时，借用元数据撤销，原拥有者与调用中临时资源恰好清理一次。
零大小对象也保留来源身份，不能靠相同占位地址判断无冲突。

## 5. 表示、分派与代码所有权

### 5.1 共享契约

V0 冻结逻辑二元组 `(data, table)`：data 引用稳定物化的底层存储，table 标识
具体 Self 与 trait 绑定的不可变方法表。借用元数据是编译器/运行时责任，不是用户字段。
此逻辑表示不意味着解释器也保存两个原生裸指针；native 使用目标指针宽度，解释器可用受检 ID。
不能假定现有单槽引用的所有布局/复制/传参路径天然支持 dyn。

表的身份包含当前编译产物、具体 Self、trait 身份和规范化关联绑定；槽按 trait 声明顺序。
同一编译内复用表，别名不重复建表，禁止依赖 HashMap 顺序或跨版本固定槽号。
每个槽的参数、结果、接收者权限、隐藏 task context 和失败约定由共享类型描述确定。
所有后端使用同一描述，禁止为碰巧简单的标量示例手写另一套 ABI。

默认方法槽指向具体实例，默认体内部继续按已确定的 Self 静态调用最终方法。
分派不需要为每次内部调用再次擦除；优化器可去虚化，但必须保留求值次序、借用与错误行为。
借用表不提供所有权 Drop 入口、尺寸查询、downcast 或宿主可见的类型标签。

### 5.2 后端与失败边界

复用 [function_values.rs](../src/core/ir/function_values.rs) 的受检间接调用原则，
显式增加数据接收者与表/槽信息；前端资格检查放在共享 IR，不能只由某个后端拒绝。
三后端覆盖零/多参数、整数窄值、浮点、Unit、拥有及聚合结果，包含内部时间片恢复路径。
新增 native 入口遵守浮点环境保护，动态方法失败保留首错并继续必要清理。
构造视图所需的临时物化要计入现有预算；对象存储不得在视图活跃时迁移失效。

JIT 表和适配入口由不可变编译产物持有；AOT 表使用可重定位符号/数据，不能嵌入编译器
进程地址。解释器验证表、槽、函数身份与签名，不能把可伪造整数当成任意入口地址。
解释器暂停期间及旧实例同步调用期间，保留整条可达方法代码与表所有者；模块重载只发布新表，
失败重载不影响旧快照。即使用户不能保存 dyn，正在执行的调用仍可能持有旧表。

内部表示不构成稳定 C ABI；禁止 extern、宿主反射导出、InstanceValue 或序列化接受 dyn。
不得仅靠当前签名白名单偶然拒绝，需对别名与嵌套类型进行同样的边界验证。

### 9.1 V0 前置证据与冻结模型

核对时工作区无未提交改动，HEAD 为 `feea9b8`。第 4 项的 T1–T5 已在该提交交付，
其第 9 节记录 macOS arm64 下 full、stress、Godot 和独立 AOT 执行结果。
这些是静态 trait 的前置证据，不是本项动态分派的证据。
默认方法与关联类型均直接复用第 4 项的声明身份、定义作用域、唯一 impl 与投影求解器。

| 核对到的实现 | 本项责任 |
| --- | --- |
| `TraitDef.self_parameter.id` 是声明身份；`methods` 为声明顺序的 Vec；导入 scope 保存 trait binding | 动态接口键使用声明身份，槽按这个 Vec 的序号；不能重新按方法名称排序或遍历 HashMap |
| `traits::collect` 生成最终覆盖/默认实例，泛型规划复用具体实例 | 表只能引用最终具体实例；不得另写默认方法展开器，默认体内部仍静态分派 |
| `ReferenceType` 只有 target 与 mutable，普通引用仅占一个标量槽 | dyn 需要专用的二元承载路径，不能让现有引用复制、参数展开或帧布局直接按单槽处理 |
| `borrowing::Reference` 保存 origins、loans、ancestors、invalid、storage；Origin 保存 root 与路径 | 擦除复制完整来源并建立相应贷款；表身份不参与对象来源相等判断，零大小对象也按 root 区分 |
| 函数值通过 `Op::Call.indirect` 调用；解释器函数值保存受检函数 ID | 可复用调用约定与失败路径，但不能把 trait 视图伪装成单个函数值 |
| native 对挂起函数值已生成可重定位只读描述符；可达性扫描收集函数引用 | 借用方法表增加独立数据与入口引用；每个表槽都必须加入可达性闭包，不能只保留当前调用槽 |

[函数值](../src/core/ir/function_values.rs)、[来源分析](../src/core/ir/borrowing.rs)、

冻结以下逻辑描述；尚未交付的结构不得出现在当前能力表中：

- `DynInterface`：trait 声明 ID、按关联项声明序号规范化的完整绑定、按方法声明序号排列的
  槽签名。源码拼写、导入别名、绑定顺序和 Span 不参与语义身份；诊断仍保留各自 Span。
- `DynMethodSlot`：方法身份、共享/独占接收者、已替换关联类型的参数和结果、每个借用参数
  的声明 noescape、同步效果及既有隐藏 task context/失败约定。结果分类和布局用普通
  FunctionSignature 与布局入口计算，不另建标量特例 ABI。
- `DynTable`：所属编译产物、具体 Self、DynInterface 和最终具体入口的有序列表；每个
  编译产物内部按该键复用。表不包含 Drop、尺寸、downcast 或宿主反射入口。
- 视图的逻辑顺序固定为 `(data, table)`。native 按目标指针宽度承载两个分量，表使用只读
  数据和可重定位入口；解释器使用类型化的受检表/函数身份，禁止从用户整数构造入口。
  两分量复制、分支合流、参数传递、物化和帧保存必须由同一类型描述驱动。
- 擦除操作显式关联原引用；动态调用显式关联表、槽和数据接收者。借用检查完成之前
  不得擦掉来源操作。普通 `&T` 仍为普通引用，不因内部表示增加用户可访问字段。

两类借用与清理责任冻结如下：

| 操作/退出 | 静态与运行时责任 |
| --- | --- |
| `&T -> &dyn Trait` | 按共享借用保留全部 root/path；复制视图只复制借用，不复制 T |
| `&mut T -> &mut dyn Trait` | 保留独占权限；绑定赋值移动视图，调用建立短期重借用 |
| `&mut T/view -> &dyn Trait` | 共享重借用保留独占祖先与冻结关系；不能恢复独占权限 |
| 条件、赋值、helper、多个实参 | 合并全部来源，实参作为一次调用共同检查冲突；不能只保留最后转换来源 |
| 正常返回/方法失败 | 视图不销毁 T；T 由原所有者清理，拥有参数与结果沿既有清理路径处理，失败保留首错 |
| 解释器切片/取消/预算失败 | 保存数据、表和可达代码所有者；恢复不重放，取消撤销借用并恰好清理一次 |
| 语言挂起、并发、宿主入口 | 活跃 dyn 不得进入；extern、实例存储及反射边界递归检查别名和嵌套类型 |

资格正例为第 2 节 Read、Source 以及选择式 noescape 覆盖全部借用参数的接口；
关联 Item 可为 Int32、String 或无引用聚合。负例包括按值/无接收者、裸 Self/含 Self
参数、借用结果、挂起、未声明 noescape、漏绑定、重复/未知绑定与能力不满足。
静态使用这些不兼容接口仍须正常工作。方法级泛型继续由既有 trait 文法拒绝。

关键字盘点：仓库 `.jk` 源码、标准库、fixture、examples 中没有以 `dyn` 为标识符的
现有用法；Rust 源码中的 Rust `dyn` 不迁移。文档中的目标语法保留，syntax.md 的
关键字说明随解析器更新。新负例专门确认函数名、局部名、类型名不能使用 `dyn`。

第 9.2–9.7 节保留当时阶段的验证与限制；当前能力与发布验证以第 9.8–9.10 节为准。

### 9.4 V1 类型与擦除

本次从 `d19a387` 继续，重新核对第 4 项 `feea9b8` 的 T1–T5 验收及本文件 V0
冻结模型。以下实现取代第 9.2 节的原型限制，不改变第 4 项静态 trait 的语义。

- `DynTraitType` 保存源码位置和声明身份，绑定后的 `DynInterface` 使用 trait ID 与
  按关联项声明顺序排列的等式作为语义身份。别名、导入名称、等式书写顺序和源码位置
  不改变身份；方法槽保持声明顺序，保存接收者权限、替换后的普通 FunctionSignature、
  借用形参的声明 noescape 和原声明位置。默认与抽象方法使用相同资格检查。
- 关联等式、别名、定义作用域和泛型替换复用既有投影求解器、唯一 impl 证明与预算。
  期望类型驱动局部绑定、赋值和实参位置的共享/独占擦除，逐项比对具体 impl 的等式；
  需要显式引用，拒绝临时对象及共享到独占转换。dyn 视图不自动满足普通泛型 trait 约束。
- 共享语义计划显式保存 `DynErasure(source, target, span)`；借用分析使用已有 Reference
  重借用操作，完整保留 origins、字段路径、loans、ancestors、invalid 与 storage。
  定向测试验证字段不重叠、两个分支的来源、同源实参冲突、独占移动和短期共享重借用。
  同步 helper 的 dyn 参数必须通过不返回、不保存的固定点证明。
- 未使用签名同样检查，返回、聚合/容器/函数值存储、闭包捕获、extern、宿主注册、
  持久实例与原始 *p / *p = next / mem.replace 边界拒绝 dyn。泛型实例及合成分支入口
  再次检查签名，防止模板实参替换后引入 dyn 返回或挂起参数。语言挂起检查直接识别活跃
  dyn 槽，不能因来源在 arena 而绕过；挂起形参也拒绝。没有新增拥有包装或清理入口。
- 类型与借用检查通过后，JIT、解释器、AOT 的正常编译入口仍统一报
  `Borrowed dyn trait execution is not implemented; dynamic dispatch requires V2`。
  点调用和显式 trait 调用只按视图声明身份检查槽与权限，然后进入该门禁，不回退静态调用。
  语义分析中的单槽引用不构成物理布局；dyn 的字节布局查询明确失败，方法表及二元承载留待 V2。

### 9.6 V2 三后端分派

非法程序通过全部三后端编译入口核对权限、来源冲突、作用域、存储/捕获、语言挂起与并发拒绝。

[lifecycle fixture](../tests/fixtures/borrowed_dyn_lifecycle.jk)及
[AOT harness](../src/backends/aot/tests/borrowed_dyn.rs)覆盖拥有关联结果、拥有实参、
嵌套共享调用、方法失败与失败 Drop：核对副作用/清理顺序、原所有者和临时资源各自销毁，
AOT 核对原始除零位置，失败析构不能覆盖首错。零 arena 预算下擦除/重借用仍可执行零大小
接收者的同步方法，不新增拥有包装或堆分配；这不是方法无分配的保证。

挂起函数内可在两个挂起点之间短期借用合法 Copy 局部对象，并同步调用返回拥有值的方法。
关联绑定描述方法签名，不是视图实际持有的缓冲区；活跃 dyn 跨语言挂起或并发仍拒绝。
没有扩大拥有局部对象的一般异步借用限制，这类用法继续放在同步 helper。
JIT/解释器/AOT 核对两个 Pending 之间的同步局部执行与完整清理事件。

短期持久实例调用在 JIT/解释器核对重复共享/独占访问、拥有返回临时值、实例字节计数稳定、
失败后进入 Failed、原根恰好清理一次、close/VM 释放不重复析构；失败加载保持旧实例，
成功重载后新旧实例分别调用新旧方法表。实例接口未接受 dyn 值。

### 9.9 V4 切片、代码保活与限额

解释器时间片逐指令暂停同步 dyn 方法，保存原对象、两分量、参数求值进度和代码所有者。
暂停在参数第一个副作用后，依次进行失败重载、成功重载及 VM 释放，恢复仍使用旧表，
核对参数与方法副作用顺序 `[20, 22, 30, 7]`，不重放也不跳转到新表。
[受检字节码测试](../src/backends/interp/dyn_tests.rs)篡改表标签、槽、签名和函数 ID，
均报告 InvalidCall 且 arena 归零；正常字节码仍执行得到 42。

默认测试抽样资源变化边界，Release 穷举包含：

- `exhaustive_borrowed_dyn_v2_instruction_cancellation` 与
  `exhaustive_borrowed_dyn_v4_instruction_cancellation`：逐条解释器指令取消，覆盖默认体、
  局部重借用、拥有参数/结果、参数求值副作用和方法失败，直到实际完成；每个边界核对
  不重放、清理不重复和 arena 归零，完成边界核对完整事件序列与原错误。
- `exhaustive_borrowed_dyn_v4_memory_boundaries`：JIT/解释器从零开始逐字节增加同步调用
  arena 限额，覆盖原对象与关联结果/实参，直到成功；失败为 ResourceLimit，每轮无残留，
  恢复正常预算后再次调用成功。
- `exhaustive_borrowed_dyn_v4_instance_call_budgets`：JIT/解释器逐字节检查短期实例调用
  临时预算，覆盖共享/独占访问及拥有结果；失败实例不可继续调用，关闭后根、峰值记账
  和 arena 均归零，原根 Drop 恰好一次。

另检查解释器帧数限额由失败到成功的边界，以及动态方法申请超出容量限额时释放原所有者，
后续正常调用恢复。容量失败也在独立 AOT 进程执行，核对错误通道、预算错误文本与原对象 Drop。
前端补齐 dyn 专项资格预算：根接口 Item 内再嵌套 32 个接口可接受，33 个报 ResourceLimit；
同一求解请求 256 个不同义务可执行，257 个拒绝，三后端一致。
