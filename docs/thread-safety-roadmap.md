# 线程安全与并行资格收敛路线

状态：2026-10-30，S0 必要收敛与 S1 最小接口集合已实现，记录见第 7 节；S1 其余接口及 S2–S6 待实施。
起始实现基线为 W6q（`22525a4`）。

本文承接[启动时 worker 配置与并行能力演进计划](startup-worker-configuration.md)，
规划从逐项扩展并行能力，转向统一、安全且可解释的并发规则。
当前已实现行为仍以[语言参考](language.md#任务执行模式)为准，
生命周期与 ABI 不变量见[架构说明](architecture.md)；本文不提前改变语言准入。
W 系列文档保留已有设计和验收记录，后续跨主题工作使用本文的 S 编号。

## 1. 最终目标与保证边界

目标是：**安全 Joky 代码不会产生数据竞争；同一份合格程序可以在启动时选择合法的 worker 数量，
编译器与运行时共同保证迁移、共享、取消和清理的安全。**

这一目标目前是需要持续验证的设计约束，不是对现有全部实现已经完成安全证明的声明。

具体要求：

- 已通过 Parallel 资格检查的同一份 AOT 产物，在当前合法范围 1–256 内选择 worker 数量，
  不改变类型准入、唯一所有权、借用权限或清理责任；JIT、解释器和 AOT 使用同一套语义。
- 跨 worker 迁移拥有值后，来源不能继续访问已移动的值；接收方取得完整且唯一的清理责任。
- 共享访问必须满足只读数据规则，或使用具有同步契约的资源接口；共享句柄不意味着内部状态不可变。
- 独占访问必须排除所有冲突访问；成功、失败、取消和池关闭都先停止读写，再恢复来源使用权。
- 不能证明安全时，明确限制该用法；不依靠恰好只有一个 worker、偶然串行调度或测试未复现来放行。

保证范围是语言规则、编译器生成代码和受检运行时协议。Rust/C 绑定仍属于信任边界：
注册方必须兑现声明的线程、借用和停止契约，普通 Joky 源码不能自行伪造这些证据。
本计划不新增用户可用的 unchecked 逃生通道。

无数据竞争不等于业务操作自动串行化，也不等于没有死锁、饥饿或逻辑竞态。
竞争赢家、I/O 完成顺序和服务响应顺序可以随调度改变；不会承诺不同线程数产生完全相同的执行轨迹。
多个同步操作组成的业务事务仍需使用状态域或其他明确的原子性机制。

本轮不包含运行中动态增减 worker、抢占式调度、性能自动调优、任意线程绑定资源迁移，
也不要求所有 join/race/branch 都跨核执行。task worker 数量不等于进程总线程数。
Local 与 Parallel 继续是不同执行模式，Parallel 的 1 worker 不等同于 Local。

## 2. 起始基础与缺口（W6q）

以下以 W6q 为起点，本轮交付后的变化见第 7 节。已有能力的详细范围与测试记录引用 W 系列文档，
不在这里复制完整类型支持表。

| 方面 | 已有基础 | 接下来的缺口 |
| --- | --- | --- |
| 启动配置 | 同一 Parallel 产物按启动配置选择 worker 数量 | 收敛更多业务代码的执行资格，不重新设计线程数接口 |
| 拥有值 | 普通聚合、容器、受检闭包、Drop 与拥有型 dyn 已有不同范围的传递支持 | 将类型性质、物理传输和调用资格的证据联系起来，避免不同入口各自判断 |
| 结构化只读借用 | 静态 join/race、动态 branch、嵌套再借用及多种聚合已实现 | 减少重复的类型展开与判定，明确新的组合何时可以自然复用已有协议 |
| VM 资源借用 | W6q 支持 VM 句柄及包含它的合法存储；借用视图保留同一控制代理身份 | 其他资源不能照搬 VM 白名单，需要分别证明访问契约 |
| 宿主引用接口 | 内置 VM 适配器已有 scoped 调用资格，一般宿主引用 ABI 仍受限 | 区分可安全读取本地视图的接口、只允许本地独占参数的接口，以及完全不合格的接口 |
| 独占借用 | 语言已有局部独占借用；资源已有部分操作级租约 | 尚无通用跨 worker 独占借用归还协议，不能把操作忙标记直接当成整个借用的权限 |
| 诊断 | explain-parallel 已报告资格及阻断调用链 | 逐步说明限制属于存储、来源、调用、资源协议还是执行上下文，并提供有效处理路径 |

W6q 后 chat 的已知阻挡点是：

- 顶层 race 中的 `&Script` 已通过输入形状检查，但调用链仍被 `admission.Pool.handle` 的宿主引用 ABI 阻挡。
- session 的收发 race 仍包含 `&mut Mailbox`。
- 带超时的读取 race 仍包含 `&mut BufferedTcpReader`。

这是当前报告暴露的首个阻挡点集合，不代表清除它们后一定没有其他依赖限制。
每次扩展后都重新检查完整调用链，包括日志、析构、回调和内部资源操作。

## 3. 统一资格模型

### 3.1 分开回答四个问题

| 问题 | 必要证据 | 不能代替它的证据 |
| --- | --- | --- |
| 拥有值能否迁移？ | 存储可传递，真实代码与析构可执行，成功与失败时清理责任唯一 | 只有固定大小、只有 Copy 或只验证外层记录 |
| 值能否共享访问？ | 普通存储不会被冲突修改；内部可变资源具有受检同步契约 | 能移动到其他 worker，或参数表面上写成 `&T` |
| 某次借用能否派发？ | 来源合法、作用域保活、共享或独占权限成立，接收端可安全表示该借用 | 类型符合共享规则，或指针落在某个仍活着的内存根内 |
| 调用能否执行？ | 入口、传递调用、动态候选、宿主适配器与清理依赖全部符合要求 | 参数布局合格，或只是给 extern 声明一个名字 |

这些概念先作为编译器内部证据和文档术语，不承诺新增用户可实现的 Transfer、Share 或独占借用 trait。
资源协议也不能退化成一个“线程安全”布尔值：共享调用、独占调用、关闭、析构和线程归属须分别描述。

### 3.2 聚合规则与资源规则

普通记录、元组、枚举和容器优先按成员组合得到资格，统一处理名义实参、phantom 参数、
零长度／空值、隐藏变体、自定义 Drop 与间接调用。语言存储准入与跨 worker 资格仍分别检查：
拥有共享协议不会自动使资源成为合法 FixedArray 元素。

资源按实际协议分类：拥有值迁移、共享代理、独占借用、线程绑定本地使用。
一个资源可以同时具备其中部分能力，但必须逐项证明。资源类型证据与具体实例的
控制树、任务身份、存活状态及活动租约也必须分别验证。

已证明安全的组合可以复用描述与传输逻辑；含内部可变状态、游标或特殊析构的对象不能仅按字段递归放行。
不为统一表面接口而合并不同权限的运行时协议。

### 3.3 不支持时怎么办

| 情况 | 处理原则 |
| --- | --- |
| 用法违反所有权、借用或逃逸规则 | 编译拒绝，与 worker 数量无关 |
| 完整 Parallel 入口调用了不合格的宿主／线程绑定能力 | 拒绝该 Parallel 入口，不能静默切换整个程序到 Local |
| Parallel 入口合法，但某个结构化子组不能安全跨 worker | 保留当前有定义的本地协作执行，并由诊断明确说明 |
| 某种语法局部安全，但没有跨 worker 协议 | 优先限制远程捕获或传递，不因此删除其局部使用能力 |
| 无法定义可靠的局部生命周期，或组合收益不足以承担实现复杂度 | 明确暂不支持该用法，并保留稳定拒绝测试 |

本地协作执行仍须通过借用和宿主线程归属检查。“留在当前 worker”不等于“自动满足宿主主线程要求”。
已有合法的本地回退不在本计划中无故改成错误；若以后提供“必须具备远程派发资格”的检查选项，
另行定义兼容性和诊断，不把它解释成实际跨核执行保证。

## 4. 实施顺序

以下顺序体现依赖和业务收益，不是一次性大重构要求。S0 必要收敛和 S1 的 admission 最小集合已完成；
S1 中其他宿主适配器仍需逐项审查，不能把最小集合交付解释为整个宿主引用 ABI 已开放。

| 阶段 | 工作 | 完成标准 |
| --- | --- | --- |
| S0：规则与证据收敛（必要收敛已完成） | 梳理现有判定入口，统一共享的名义展开、资格依据及拒绝原因 | 各后端与诊断对既有用例作出一致决定；没有无意扩张准入 |
| S1：受检宿主引用接口（最小集合已完成） | 审计 chat 调用链，开放最小、可证明安全的内置适配器集合 | 每个新接口有绑定身份、参数权限和停止契约；实际调用与诊断一致 |
| S2：独占借用基础 | 定义跨 worker 借出、执行、停止、归还及失败恢复协议 | 正常、取消和部分安装失败均不存在冲突访问或重复清理 |
| S3：Mailbox 独占借用 | 使用 S2 接通唯一接收方，同时保留发送／关闭句柄行为 | 收发与关闭并发、等待取消、借用后继续使用来源均符合原语义 |
| S4：TCP 与缓冲状态归还 | 接通合适的 TCP 端点和 BufferedTcpReader，明确完整状态归属 | 部分读写、缓冲剩余数据、超时与取消后恢复都无丢失、重复或悬空访问 |
| S5：诊断与标准库收尾 | 统一报告原因和可行替代路径，按稳定规则整理业务例子 | 用户能区分安全限制、暂未实现与运行时条件，不需要猜测后端细节 |
| S6：安全边界审计与验收 | 审查共享状态、适配器信任边界、清理和后端一致性 | 高价值服务路径可按线程数部署；剩余限制、证据及未验证项明确记录 |

实施顺序是先完成 **S0 的必要收敛与 S1 的受检接口**，获得规则和实际服务路径上的收益，再进入独占借用。
S0 不先重写整个类型系统；S2 与第一个 Mailbox 行为用例一起设计，避免只交付没有执行证据的抽象。
S3 验证清楚之后再做 S4，不把 TCP 的复杂缓冲状态混入第一次独占协议实现。

### S0：规则与证据收敛

建立判定入口清单，至少覆盖 IR 的类型资格、拥有包分类、scoped 签名与形状、
调用图、原生入口描述符、解释器入口和 explain-parallel。为每项列明职责、输入证据与失败原因。

先提取真正重复的展开与规则，保留物理布局、代码资格和实例来源各自的检查。
已有独立拒绝理由不能因重构而被一个宽泛的“可共享”标记覆盖。
使用现有正反例核对准入差异；需要改变行为的部分单列为 S1 或后续阶段，不混成无说明的重构。

交付物是内部证据说明、必要的共用实现和小规模边界回归，而不是新的用户语法。

### S1：受检宿主引用接口

从 chat 的 admission 接口开始，继续按实际阻断链审查 outbox、TCP、文件及输出适配器。
这一步审查的是借用任务内部调用接口的能力，**不等于开放这些资源本身作为共享借用输入**。
例如任务内部自己拥有的资源可以有局部独占操作，而传入的共享引用仍不得用于该独占操作。

每个候选接口须明确：参数是否读／写、访问的是本地视图还是原始控制块、是否保留地址、
Pending 期间由谁访问、stop 返回前如何停止、关闭和错误时如何归还，以及绑定身份如何校验。
只读文本输出与资源接收操作不能共用未经审查的引用 ABI 豁免。

实现上优先复用已有编译器专用适配器或受检绑定注册机制；不能只按函数名放行，
也不能让一般 extern 声明自动获得权限。保留伪造绑定、错误签名和未获资格宿主的拒绝行为。

验收同时检查 chat 报告和实际执行。报告变成 eligible／runtime-check 不代表实际跨 worker，
关键用例需要派发证据。目标是消除已审计接口造成的阻挡，不预先承诺 chat 顶层 race 在 S1 结束时必然完全放开。

### S2：跨 worker 独占借用基础

首先定义一条可检查的状态路径：来源可用、借出准备、已交接、使用中、停止中、已归还。
每次状态转换都要说明谁有访问权、谁拥有清理责任，以及失败时接下来由谁推进。

必须解决：

- 整个借用期的独占权限与一次 I/O 操作的 ResourceLease 分离，避免先占满 busy 标记，
  导致接收方连合法的内部操作也无法发起。
- 来源任务在借用完成前不能读、写、移动或销毁冲突对象；结构化取消仍先排空子树。
- 部分交接失败恢复为原状态，或进入明确且不可继续使用的终态，不能留下一半归还的对象。
- 不把其他 worker 的 Buffer、Rc、帧或可变控制元数据直接当作接收端本地对象。
- 借用不可作为结果逃逸；再借用、重入和嵌套独占先限制为能够完整证明的子集。
- 归还路径不能依赖可能已经耗尽的普通预算才能完成必要清理；需要的元数据提前准备，
  并明确失败或关闭后的来源状态。

先针对有业务收益的资源实现，不以一次交付通用 `&mut T`、可变切片分区或可变容器迭代为目标。

### S3：Mailbox 独占借用

第一种实际资源选 Mailbox：独占借用的是接收端访问权，其他 Handle 仍可按原契约发送或关闭。
队列内容、等待登记与控制代理的生命周期必须保持一致，不能把整个消息系统误锁成只有借用任务可操作。

验证空队列等待、消息到达、关闭唤醒、race 取消、读取失败、同一来源再次接收以及池关闭。
明确每条消息是在队列中、被交付还是被释放；取消不能让已移出的消息既未交付也未清理。
接入 session 后重新检查完整收发 race，不因一个参数已获资格就宣称整组可远程执行。

若唯一接收端拥有权交接可以显著简化实现，先比较其对 session 关闭及 on_close 顺序的影响，
再决定是否调整库内部结构；不能靠提前销毁队列改变可观察的关闭语义。

### S4：TCP 与缓冲读写

从已有端点归属、操作租约和共享 reactor 出发，分别审查 reader、writer、listener，
不以“底层 socket 可跨线程”代替完整对象的证明。
BufferedTcpReader 还包含缓冲区、已消费位置和剩余数据，借出／归还必须覆盖整个状态。

验证部分读取、预读后的剩余字节、EOF、部分写入、背压、超时、取消后再次使用及嵌套清理。
字节已经从 socket 取出后，不能在取消时丢弃缓冲状态并把表面上的空 reader 归还；
已发送字节也不能因恢复路径而被重复发送。新协议应保持既有 API 的取消语义，不能假装 I/O 可以回滚。
等待登记撤销和正在使用句柄的操作停止，必须先于归还或最终关闭。

如果可靠归还要求长期共享可变内部状态或过多特殊路径，可保留跨 worker 借用限制，
另评估移动端点所有权、单接收任务或库内封装；本阶段允许以明确限制结束，不以强行开放为完成标准。

### S5：诊断与标准库收尾

统一呈现类型／存储、具体来源、调用链、资源协议和运行上下文等不同阻挡原因，
并区分“允许本地执行”和“Parallel 入口拒绝”。保留编译器及运行时的最终准入依据，避免报告自建一套近似规则。

提示只给有语义依据的处理方式：移动拥有值、对具备共享语义的句柄显式 share、缩短借用作用域，
或保留本地执行。不能一律建议 clone／加锁；复制状态或改变资源身份可能改变程序语义。

依据稳定后的规则整理标准库内部接口与 chat 示例，不为了清空报告中的 local 项增加样板代码。
允许 isolate 主体、线程绑定操作及其他合理的本地子组继续存在。

### S6：安全边界审计与验收

审查编译器与运行时中负责跨线程传输、共享状态、unsafe 实现和宿主证据的入口。
重点追踪权限与责任如何建立、移动、停止和释放，而不只是搜索 Send／Sync 标记。
每种资源都要能回答：取消与宿主退出时，还有谁可能访问对象，何时可以安全归还或销毁。

把嵌入式 JIT／解释器、独立 AOT 和宿主信任边界分开验收。独立 AOT 必须真正链接并启动，
不能只用嵌入式 Native 入口代替；W6q 的代码保活修正已说明这两条路径存在不同根对象。

完成标准是常用能力具备一致规则、真实执行证据和可解释的限制，不是把所有限制或 local 标签消除。
未解决的漏洞阻止相关能力开放；未实现、低收益的功能可以作为明确限制保留。

## 5. 暂缓与明确限制

以下限制不应为了“语言支持多线程”而一并解除。

| 能力 | 本轮策略 | 重新评估的条件 |
| --- | --- | --- |
| 任意裸指针、未受检 extern 引用跨 worker | 保持拒绝 | 有明确且可验证的宿主契约与绑定身份，不能只提供源码声明 |
| 线程绑定宿主对象直接迁移 | 保持拒绝；Godot 主线程桥仍独立规划 | 有实际接入需求及宿主拥有的调度／退出协议 |
| 一般借用结果、脱离结构化作用域的借用任务 | 暂不开放 | 有独立生命周期模型，且收益足以承担复杂度 |
| 借用型 dyn、携带引用的通用闭包跨 worker | 暂不扩展现有子集 | 真实对象、动态候选及析构证据不会因类型擦除而丢失 |
| 已有游标、Entry 和可变迭代状态直接共享 | 保持原有限制 | 能证明游标状态独立或有明确分区协议；优先借用容器后在任务内创建游标 |
| 通用可变切片分区、通用跨 worker `&mut T` | 不与资源独占借用一起交付 | 高频业务场景需要，且现有资源协议不足以解决 |
| FixedArray 的资源／自定义 Drop 等未开放元素存储 | 继续由存储计划决定 | 有独立存储设计与验证，不能借共享资格绕过 |
| 非结构化资源借用、复杂嵌套独占归还 | 暂不开放 | 有清晰的终止、归还和失败责任，不依赖无限保活 |
| 运行时动态扩缩容、自动性能调度 | 不在本轮范围 | 启动时配置与安全边界稳定后另行规划 |

“暂缓”不是废弃已经安全可用的局部语法。若实现代价主要来自极少用的组合，
优先保留稳定诊断和文档限制，而不是不断增加类型或后端专属例外。

## 6. 验证与交付纪律

执行时按[仓库验证规则](../AGENTS.md)和当次用户指定范围选择检查，不因新建本计划触发代码测试。
后续实现至少保留以下证据：

- 静态拒绝：冲突访问、借用逃逸、未知动态目标、错误宿主绑定及未获资格资源不能穿过边界。
- 实际派发：针对新增能力证明子任务确实可以离开来源 worker，不能只检查最终值。
- 生命周期：正常、失败、取消、池关闭和部分安装失败后，访问先停止，来源后归还，析构责任恰好履行一次。
- 预算与保活：需要的归还元数据已预留；失败可清理，最终预算归零；重载与旧代码存活不破坏借用。
- 后端一致性：JIT、解释器和独立 AOT 覆盖同一核心行为；1 与多个 worker 不改变安全准入。
- 服务行为：相关阶段运行 chat 自身的网络、重载及关闭回归，并核对诊断与实际执行。

类型边界、资源契约与 API 行为分别验证，复用已有 fixture，避免为所有组合重复建立完整矩阵。
只对发生变化的所有权或取消路径补充相关 Debug 穷举，不自动运行全部压力用例。
同一代码版本的检查通过后，不因更新文档或准备提交再跑一遍全量；若出现新失败或修改，则重跑受影响范围。
每阶段记录实际检查、未验证项及保留限制。仅更新本计划时检查内容、链接与 diff，不运行 Cargo。

### 7.2 admission 最小接口集合审计

| 操作 | 输入权限与实际跨线程内容 | 结果与生命周期 |
| --- | --- | --- |
| create | 容量、等待上限等标量 | 控制线程创建 Pool，调用任务得到拥有型代理 |
| handle | 本任务 Pool 的共享引用；队列只保存代理身份 | 返回标量 Handle，不保活 Pool 的开放状态 |
| close | 本任务 Pool 的共享引用；队列只保存代理身份 | 逻辑关闭按现有协议执行；共享引用不表示操作没有内部副作用 |
| try／acquire | 标量 Handle；不传源任务地址 | 产生拥有型 Permit／状态；acquire 可在控制线程等待 |
| status | 本任务 Permit 的共享引用；队列只保存代理身份 | 读取控制线程许可结果，映射 Full／Closed／WaitLimit 等状态 |

引用形状检查仍拒绝跨 worker 的 `&Pool`、`&Permit` 和可变资源借用。
借用任务可以使用自己的资源，不能借这批宿主调用权限共享来源任务的 admission owner。

编译器专用名称须匹配完整签名和挂起约定，并由固定适配器执行；VM 的注册入口禁止覆盖内置绑定。
绑定证据还核对实际 Domain 操作及 ABI，错误操作、错误签名、不同 ABI 或普通函数指针不获得该资格。
普通 extern 引用 ABI、stdout、TCP、outbox、目录及文件适配器没有因此获得新的 scoped 调用权限。

请求只持有标量或 `Arc<Proxy>`。源任务的 Buffer、引用地址和帧不进入控制队列。
worker stop 标记撤销并唤醒控制线程；控制侧先停止活动调用，再释放它持有的代理和请求。
ControlReceipt 让调用任务的 cleaned 屏障等到控制侧完成清理，不能在提交取消后就提前释放来源。
复用原有预算、代理身份和取消路径，没有新增资源布局或公开 ABI。
