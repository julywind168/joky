# 服务端状态域与任务并发设计草案

状态：2026-10-12，SC0 契约与独立探针、SC1 标量单域与访问已验收；SC2 进行中，标量投影快照、候选根独立存储与单域原子提交已落地；SC3–SC5 未开始。
SC0 不开放 Domain、提案或提交的源语言 API。目标是在现有宿主驱动执行器、结构化任务和
持久实例之上，建立可用于房间、会话和请求处理的并发模型，同时保留客户端按帧推进的能力。

主线是：**长期状态由状态域拥有，临时工作由任务域拥有；操作按状态访问权限调度，
异步计算通过经过验证的提案提交结果。** Actor、Service、World 和数据流可以在上层组合。

本草案承接 [语法设计](syntax.md#8-挂起与结构化并发)的并发阶段目标。
当前可用能力以 [language.md](language.md) 为准；既有 ABI 与存储不变量以
[architecture.md](architecture.md) 为准。本文定义新增能力的目标契约及验收阶段，
不改变已有 `scope`、`branch`、`parallel`、`race` 或实例 API 的行为。

## 1 目标与范围

服务端应能并发处理请求、等待网络和持续推进房间 tick，而不要求每个长期对象绑定一个
永不结束的根任务。一次业务操作可以访问多个状态，例如玩家换房需要同时更新玩家、
原房间和新房间。等待期间应释放状态借用，恢复后检查对象和业务条件是否仍然有效。

首版目标限定在同一进程、同一执行器内，继续采用单线程协作执行。权限调度先保证隔离、
顺序与生命周期；“互不冲突”表示允许独立推进，不承诺同时使用多个 CPU。

首版不提供跨进程事务、崩溃恢复、透明重试、游离任务、通用共享可变引用或完整效果系统。
持久状态仅指跨调用存活的内存，不代表落盘。多线程迁移、确定性回放和可恢复工作流需要独立设计。

保留 `@suspends` 和普通调用写法，不引入 `async` / `await`。本文所有 `text` 代码块均为
不可执行的语义示意；`Domain`、`Handle`、`Proposal`、`when`、`commit` 等名称不代表已冻结
的类型、API 或新增关键字。SC0 确定采用模块调用和受检函数入口，完整签名在 SC1 冻结。

## 2 已有基础与新增边界

| 范围 | 已有基础 | 本阶段新增目标 |
| --- | --- | --- |
| 执行 | HostExecutor、就绪队列、定时器、外部唤醒与宿主 poll | 将状态操作和准入等待接入同一驱动 |
| 任务 | `scope`、`branch`、`parallel`、`race`、失败传播与取消清理 | 为请求建立独立失败边界，登记状态有效期依赖 |
| 长期状态 | Rust 持久实例、拥有图转移、实例身份与关闭 | 语言可用的状态域句柄、访问排队和版本快照 |
| 网络 | TCP、双向拆分、有界缓冲、消息编解码与 DNS | 将请求生命周期、业务状态和负载准入连接起来 |
| 内存 | 任务 arena、拥有值清理、实例和任务预算 | 提案候选状态的独立清理与原子归属转移 |

既有约束见 [动态任务设计](structured-concurrency-scopes.md)、
[持久实例设计](persistent-instances-numerics.md)及 [网络计划](network-runtime.md)。
现有 `branch` 和 `race` 没有通用结果句柄；这里不能直接假定它们能返回提案或获胜值。
现有同步闭包也不能直接作为可保存的排队回调，新增捕获环境必须另行验证。

## 3 概念与所属关系

| 概念 | 负责什么 | 不承担什么 |
| --- | --- | --- |
| 状态域 Domain | 长期拥有根、类型版本、修订号、访问权限和关闭状态 | 不自行运行消息循环 |
| 任务域 Task domain | 一次工作及其后代的汇合、取消、临时资源和失败边界 | 不隐式延长业务对象寿命 |
| 句柄 Handle | 定位状态并携带经过授权的访问能力 | 不是可直接解引用的地址，不负责销毁状态 |
| 短操作 Turn | 对声明的状态集合执行一次同步访问 | 不保证失败回滚 |
| 提案 Proposal | 保存计算结果、读取版本和待发布的候选状态 | 不因计算完成就改变长期状态 |
| 提交 Commit | 验证依赖后，一次性发布全部候选状态 | 不撤销外部副作用，不提供网络 exactly-once |
| 准入许可 Permit | 预留任务数、队列项或资源额度 | 不等同于业务名额已经提交 |

任务所属关系形成树；状态访问关系可以形成图。一个请求只有一个负责汇合和失败传播的父级，
但可以依赖多个状态域。额外依赖只触发失效或取消，不把任务同时挂到多个父节点。

逻辑生命周期父级与执行/存储根分开：独立请求可以有自己的 CPS 根、arena 和 fail-fast 组，
但必须在首次执行前登记到唯一请求所有者。所有者负责取消、收取终态并等待清理，
不能在还有请求存活时报告关闭完成。独立请求的终态隔离属于新增受检接口，
不把现有 `branch` 的运行时失败改成可忽略事件，也不提供 `detach`。

房间可登记一组所属任务用于关闭时统一取消；跨房间请求仍由请求任务域拥有，并登记所依赖
的房间身份。房间关闭时停止其关联工作，不能仅因请求的父级仍存活就允许旧结果写回。

状态创建方持有唯一的关闭责任。普通句柄可以复制，但不把已关闭状态保活；仅正在执行的
受控访问和清理登记可以暂时保留内部存储。状态之间存放句柄不形成拥有环，也不自动获得
传递访问权限。

## 4 状态域与内存边界

### 4.1 身份和修订

句柄至少验证所属 VM、执行器、状态身份、对象世代和类型版本。业务修订号独立于对象身份：
同一个对象的内容变化使修订递增；关闭再创建的对象不能接受旧对象的句柄或提案。
计数耗尽必须受控失败，不能绕回造成旧请求重新有效。

首版按整个状态域记录修订。正常返回的独占短操作保守推进修订，包括返回业务 `Result.Err`
及业务值最终相同的情况；运行时失败则按第 7 节隔离写域，不能恢复原修订继续接收提案。
只读访问不推进修订。提交对每个写入域推进一次修订。字段级修订和减少伪冲突留待测量。
独占短操作开始前检查下一修订是否可用，不能修改完成后才发现计数已耗尽。

权限首版显式区分读和写；复制只读句柄不能产生写权限。运行时验证真实身份与权限，
编译器检查操作体只能访问本次授予的状态。获取一个域后再沿句柄访问另一个域，必须先退出
本次访问，重新申请完整集合。

### 4.2 借用与快照

状态引用仅在短操作或受控提交准备期间有效，不能跨挂起、返回到调用者、捕获进排队工作、
保存进任务 arena 或存入其他状态。复用现有来源与 noescape 检查，并为域访问引入明确来源。

跨等待携带的数据应为独立拥有的投影快照、值或受检句柄。快照不默认复制整个房间；
业务可只提取参与判断的字段，但必须记录所有实际读取域的修订。多个域的联合快照在一次
完整读权限授予期间取得；不把分时读取的数据冒充同一时刻的一致快照。

任意拥有值不自动具备复制能力。资源叶和用户 Drop 对象不能因“只读”就被复制；
业务应提取值描述，或使用另行验证的显式复制接口。首版不开放共享对象图或借用快照。

### 4.3 临时存储进入长期状态

沿用持久实例的完整拥有图描述，转移根、容器载荷、清理登记、预算和代码保活责任。
禁止只搬外层地址，或通过保留整个请求 arena 维持一个业务结果。

任务域本身不自动创建独立 arena。现有结构化子任务仍遵守共享根任务 arena 的规则；
首版请求应使用可独立回收的根任务，提案则使用明确拥有且可独立销毁的存储包。
否则，挂在长期房间根任务下的临时 `alloc` 仍可能积累到房间结束。

原有分配迁移不重复计费；复制快照、候选状态与旧状态同时存在时必须计入实际峰值。
状态长期额度、请求临时额度、执行器总额度以及待清理存储均纳入预检。
转移失败时保留唯一清理责任，不能以源任务结束作为“已完成移交”的依据。

## 5 按访问集合调度短操作

调用者提交完整的状态集合、读写模式和已准备好的输入。排队时只保存受检句柄与拥有输入，
不保存状态引用；状态地址在授予权限后才解析。所有队列项登记在发起任务的清理记录中。

首版规则如下：

1. 申请集合内的状态必须属于同一执行器。重复读合并，读写重叠归为写；同一状态的两个写
   参数不能产生两个独占引用，首版拒绝这种重复绑定。
2. 全部权限一次取得，或一项也不持有；等待时不占有部分状态。操作体不能嵌套等待域权限。
3. 读与读相容；写与同一域的其他读写冲突。冲突申请按执行器受理的单调序号排序，
   多域申请使用同一个序号，不能在各域形成不同顺序。
4. 不冲突的工作可以绕过等待项；与较早等待项冲突的后来申请不能插队。
   取消或关闭移除申请在全部域上的登记，及时唤醒后继。
5. 主体同步执行，禁止挂起、网络 I/O、任务创建及可重入的宿主调用。
   执行完或失败后归还全部权限，再推进下一项工作。

业务顺序以已受理申请为边界；多个外部事件同时到达时，不承诺跨运行相同的受理顺序。
单调序号不代表全程序确定性，也不提供跨执行器排序。

短操作可以计算和修改状态，但不是事务。若修改后返回业务 `Err`，已发生的修改仍然存在；
需要“拒绝就不改变状态”的操作必须先验证，或走第 6 节的候选提交。
运行时失败后无法证明一致性的写域进入 Failed，取消依赖它的工作；只读域和无关域不因此失败。
不得把失败前发生的外部资源清理解释为可回滚行为。

“同步”不保证“短”。解释器预算耗尽可以使操作失败，但不能在持有权限时把半次修改暴露给
其他业务操作。原生后端的死循环仍会阻塞执行器；首版不承诺强制时限、公平 CPU 份额或实时性。
若将来引入抢占，必须另行保证被抢占操作的权限与状态不可见性。

## 6 提案与原子提交

### 6.1 提案内容与首版类型范围

提案保存读集合及其身份和修订、写集合、候选拥有根、业务有效期以及请求结果所需的数据。
读集合必须覆盖决策的全部状态依赖；只验证写集合会遗漏由第三个域变化引起的冲突。
首版通过显式快照包声明这些依赖：运行时生成版本凭据，提案消费整个快照包，不能从该包中
删除某个依赖再提交。读取“集合里没有某个键”同样记录集合所在域的修订。
每个写域必须携带构造候选时的基准修订，首版不支持无版本的盲覆盖。

这不等于追踪任意值的历史来源。业务若使用包外旧标量、先前请求的结果或外部服务判断，
必须显式补充相应依赖、有效期或在提交时重查条件；首版只保证已声明依赖得到验证，
不承诺自动发现遗漏的业务不变量。快照包的封装不能被任意用户构造的记录替代。

首版提交采用完整候选根替换。SC0 将首批类型收窄为标量字段记录，以及包含 String、
标量元素 Array 的平面记录，完整名单见第 11.1 节；其他无引用拥有组合逐类扩展。
递归排除资源叶、用户 Drop、借用、视图及未经验证的宿主值；释放旧状态只运行受信任的
存储清理。普通状态域可分阶段承载更多类型，但不能因此自动进入可事务提交的类型集合。

该选择会增加复制与峰值内存成本。不能复制或过大的状态可以先使用短操作，
后续再设计字段级候选变更；首版不同时引入任意代码回滚和通用软件事务内存。
只读依赖可使用投影快照；写域的候选必须是完整合法的拥有根，未修改部分也要显式保留或复制，
不能从仅包含几个字段的投影凭空恢复其他状态。

### 6.2 提交流程

1. **准备：** 在状态权限之外完成网络等待、计算及候选根构造。候选属于发起任务，
   准备失败或取消只销毁候选，不修改长期状态。
2. **排队：** 以读写集合申请全部权限，预留队列和提交记录额度；等待期间可以取消。
3. **验证：** 重新核对身份、Open 状态、完整读取修订、有效期、请求取消状态及业务前置条件。
   条件检查只读且不能调用外部代码；版本或业务不匹配返回明确拒绝，不执行隐式重试。
4. **预留：** 完成所有可能失败的预算检查、拥有登记、结果槽和旧根清理记录准备。
   修订及提交身份的计数耗尽也在此检查。预留只立即成功或失败，不持有域权限等待额度；
   此阶段失败时撤销预留并销毁候选，旧状态保持可继续访问。
5. **发布：** 在执行器内不可插入其他业务操作的区间，一次转移全部候选根、更新修订，
   并写入已预留的提交结果。进入前再次核对取消、关闭及当前时钟/阶段下的有效期；
   此区间不得挂起、分配、执行用户代码或触发可恢复失败。
6. **收尾：** 归还权限并释放旧存储，退还实际额度。不能因为调用者已离开就丢失旧根清理责任。

发布是提交的线性化点，即所有参与者统一认定“已经发生”的边界。验证后直到发布之间
仍持有完整权限，不能让状态在检查与写入之间再次变化。读集合中没有写入的域不推进修订。
发布期间若发生进程崩溃或内部不变量损坏，不提供崩溃原子性或恢复保证。

解释器执行预算必须在进入发布前预检；发布是受信任的有界运行时原语，不得在替换一半根时
按普通字节码预算退出。域数量、拥有图扫描和清理工作仍需限制，不能把用户循环放入该区间。

### 6.3 结果与外部副作用

| 结果 | 状态是否改变 | 调用者后续选择 |
| --- | --- | --- |
| Committed | 全部目标已发布，返回提交身份及新修订 | 继续后续工作或结束 |
| Conflict | 未发布，读取版本过时 | 显式重新读取并决定是否重算 |
| Rejected | 未发布，业务条件不成立 | 向业务返回拒绝原因 |
| Closed 或 Stale | 未发布，域关闭或身份失效 | 放弃旧工作 |
| Cancelled 或 Expired | 未发布，取消或有效期先被确认 | 清理提案 |
| ResourceLimit | 未发布，预检或预留失败 | 按负载策略拒绝或退避 |

结果名称仅为语义分类。首版提交消费提案；拒绝路径也统一清理候选，避免未定义的半转移状态。

提交后发送网络回复，可能遇到断线或调用者取消；“回复未收到”不能推导“提交未发生”。
提交结果槽独立于请求后续执行，在所属任务域收取或关闭前保留并计入额度；不建立无界历史。
业务若需要断线重试去重，应将请求身份和业务结果记录纳入同一次状态提交，并定义保留窗口。

需要可靠驱动后续通知时，可在同一次提交中写入待发送记录，由后续任务消费。
内存中的待发送记录不提供崩溃恢复；外部系统仍需幂等键、去重或补偿协议。
数据库写入、付款、发包等不能放入本地提交后声称可自动撤销。

## 7 取消 关闭与失败隔离

### 7.1 取消与提交排序

外部取消、关闭和有效期变化先登记为执行器控制事件；事件到达线程安全队列并不等于业务
已经停止。执行器在授予权限及进入发布前处理相应控制状态，并确定它们与发布的先后关系。
首版使用这一本地顺序，不承诺外部线程发出请求的墙钟时刻就是取消生效点。

| 竞争情况 | 保证 |
| --- | --- |
| 取消先于发布被执行器确认 | 不发布，清理候选、队列登记和许可 |
| 发布先于取消确认 | 保留 Committed 事实；仅停止后续工作 |
| 关闭先于授予或发布确认 | 返回 Closed，不允许旧任务写回 |
| 发布后、结果消费前关闭 | 先记录提交事实，再按关闭流程销毁状态；不改写成未提交 |

超时是本地有效期检查，不承诺操作在截止时间前完成。真实时间、宿主模拟时间和业务阶段
分别使用不同来源；它们可共享唤醒机制，不能混用一个毫秒值表达全部语义。
进入发布前必须重新读取对应的受信任时钟或阶段；即使到期事件尚未入队，已经到期也要拒绝。
截止时间约束最后一次有效期检查，不保证整个发布和后续清理在该时间之前完成。

### 7.2 状态域关闭

状态域经历 Open、Closing、Closed；运行时执行失败还可进入 Failed。
关闭可重复请求，但清理责任只能执行一次，不能因一次析构报错而再次调用同一析构。

关闭顺序固定为：停止新准入并使业务世代失效，撤销等待访问和未发布提案，取消所属任务与
依赖任务，等待活动访问及外部 stop 完成，最后释放状态和内部记录。域在 Closing 时不能再
授予普通访问；正在执行的同步操作不能在其调用栈中被释放。

关闭协调由域的生命周期记录负责，不等待自己所属任务域中的关闭调用者，避免自等待。
任务里的关闭请求先登记；需要等待关闭完成的调用必须发生在不被该关闭取消的外层作用域。
清理路径不能再次申请业务域权限或等待新网络事件。执行器持续被宿主驱动且同步工作能返回，
才有关闭最终完成的保证。

### 7.3 失败边界

一次请求内部继续采用现有结构化失败传播：子任务运行时失败会取消该请求的兄弟任务。
房间关联任务不应全部放入同一个 fail-fast 组；独立请求使用独立的可回收根和组，
普通业务 `Result.Err` 由请求处理，不令房间失败。不能静默修改现有执行器组的失败规则。

提案准备失败只影响本请求；业务拒绝、版本冲突或预留失败不会使原本 Open 的域进入 Failed，
也不会重新开放已关闭的域。直接写操作发生运行时失败时，
无法证明有效的写域进入 Failed，其他请求会观察到域不可用。Failed 域只允许诊断与关闭，
恢复或重建应产生新身份，不在原身份上偷偷重试一半业务操作。

## 8 有界准入与通信

在创建昂贵任务、复制大消息或构造候选状态之前，先申请准入许可。许可至少覆盖活动请求数、
待访问项数、候选字节数和结果记录数；等待许可的轻量登记也必须有界。
超过等待上限时明确拒绝，不能通过“先创建一个等待任务”绕过限制。

首版按统一次序获取资源许可，或一次预约完整集合；禁止持有状态访问权限等待许可。
待运行请求不能占着数据库等稀缺执行许可等待另一项无期限资源。首版先提供少量明确配额，
不实现任意条件匹配的全局调度器。

通信由库组织，但基本原语必须与任务清理集成：

| 原语 | 首版契约 |
| --- | --- |
| 有界 Channel | 明确容量、关闭、发送/接收取消与拥有值交接；满时等待或拒绝 |
| 单次应答 | 请求方离开时使应答端可感知；未交付的拥有结果有唯一清理责任 |
| 状态订阅 | 可明确选择只保留最新修订，过期计算在发布时重新检查 |
| 取消通知 | 只表达生命周期变化，不携带“业务已经回滚”的含义 |

事件流默认不丢消息；状态流只有显式选择合并策略后才可丢弃中间版本。
Channel 的发送取消必须区分尚未接管载荷与已经入队，接收取消也不能丢失已转移的拥有值。
这套规则需独立验收，不能用非受检宿主队列代替语言侧生命周期保证。

## 9 业务示例与可观察行为

### 9.1 换房请求与持续 tick

下面用概念操作表示一项请求；挂起发生在调用中，没有新增 `await` 语法。
`build_move_proposal` 显式构造三个候选根，`commit` 运行第 6 节协议，
不是执行一个能够任意修改状态的回调。

```text
fn move_player(player, old_room, new_room, request) @suspends {
    let permit = admit(request)
    let view = snapshot(player, old_room, new_room)
    let verdict = check_admission(view.public_inputs, request)
    let proposal = build_move_proposal(view, verdict, request.id)
    let outcome = commit(proposal)
    reply(request, outcome)
}
```

请求等待外部检查时，两个房间可继续 tick。提交同时验证玩家仍在原房间、新房间仍开放且
有空位，并更新三个状态。期间任一读取修订变化都返回 Conflict，调用者决定重算或拒绝。
不能隐式再次执行外部检查或发送第二次回复。

首版整域修订会使高频 tick 与成员变更产生伪冲突。示例宜将房间成员状态和模拟状态分域，
仅在业务确有共同不变量时联合访问；不以无限重试掩盖不合适的状态粒度。

玩家断线后重新连接应推进连接业务世代。旧请求取消即使尚未执行，提交的世代验证也应阻止
它覆盖新连接状态。若业务允许断线后完成换房，则显式将请求归属到玩家会话，
不登记连接有效期依赖；生命周期策略不能由线程调度偶然决定。

例如新房间只剩一个名额，请求 A 的提案已准备好，同时到达另一个申请、取消和关闭事件：

| 执行器先确认的变化 | A 的结果 |
| --- | --- |
| 另一个请求提交并占用名额 | A 的基准修订过时，返回 Conflict；重读后才判断房间已满 |
| A 的取消 | Cancelled，不占用名额 |
| 新房间进入 Closing | Closed，撤销 A 的排队申请 |
| A 先发布 | 保留 Committed，后到的取消或关闭执行其后续生命周期行为 |

终态一旦确定就不被后续事件覆盖；测试应枚举这些受理顺序，而不是依赖真实网络碰巧产生竞态。

### 9.2 客户端场景切换

场景状态域拥有长期资源描述，加载任务拥有临时结果，并记录场景世代。切换场景后关闭旧域，
撤销旧任务；迟到的加载结果在发布前检查身份与世代，不得写入新场景。

首版事务提交不含资源叶，因此引擎资源安装使用经审核的短操作或宿主接口，
不能声称与任意多个资源安装具有失败原子性。纯值描述的提交可以走相同提案协议。
宿主仍决定在哪个帧阶段驱动任务和应用结果。

### 9.3 Actor 与 Service 适配

一个状态域、一个有界邮箱及其消费任务可以构成 Actor；独立请求组和应答原语可以构成
Service。需要消息协议、封装或独立故障边界时，库可选择这种组织方式。
跨多个域的一次短操作或提交无需伪装成多个 Actor 间的协调消息。

## 10 编译器与运行时边界

源语言首版显式声明访问集合，不依赖自动推导业务读写集。编译器仍须传递检查操作体的
挂起、借用逃逸和宿主调用限制；单靠没有 `@suspends` 不能证明没有 I/O 或重入。
可先对允许的内部操作与同步 helper 建立保守检查，泛型实例和间接调用都不能绕过限制。

排队工作需要专用捕获描述与清理入口，复用动态分支的值快照、移动和代码保活原则。
普通同步闭包不因能捕获变量就允许存进调度队列。域句柄、提案和结果的类型资格均须由
共享语义层验证，不依赖后端或宿主声明跳过检查。

运行时维护域登记、访问申请、准入许可和提交记录，通过现有就绪机制恢复任务。
宿主事件只登记就绪，不在网络线程或信号回调栈中执行用户状态操作。
轮询、关闭和 stop 不得持有会与重入清理冲突的内部可变借用。

JIT 与 AOT 共用原生实现，解释器实现相同的申请、取消、提交和清理契约。
首版探针可先从 Rust 宿主验证，但交付必须覆盖纯 Joky 入口及独立 AOT；
不能把 Rust 专有的持久实例能力当作三后端的源语言能力。
新 ABI 需要独立版本与布局约定，不修改已有 CPS 帧或公开句柄的隐含含义。

### 11.1 SC0 契约定案

**首批状态类型。** SC1 先开放普通记录根及标量字段，SC2 扩展同一记录根中的 String 和
`Array<S>`，其中 S 是已有标量类型：Unit、Bool、Rune、八种定宽整数、Float32、Float64。
首批记录仅包含这些字段；泛型记录实例、嵌套记录、元组、枚举、拥有元素 Array、Map、List、
Set 和 StringBuilder 先不进入该名单。资源叶、用户 Drop、借用、视图、裸指针、函数值和
动态分派对象继续排除。普通持久实例支持某类型，不代表它已获得提交资格。

类型检查需要同时检查名义类型身份、完整字段图和清理描述，不能仅凭“无引用”或
`core::instance::persistent` 判定。后者允许资源类型，持久实例也允许用户 Drop；
这些是原地实例调用的能力，不满足本草案的发布约束。SC0 不修改已有类型资格检查，
拒绝不合格 Domain 类型的源语言诊断由 SC1/SC2 实现。

**调用形式。** 采用模块函数和已有 `@suspends` 约定，不增加 `when` / `commit` 关键字。
短操作首版接收受检同步函数入口和独立拥有的输入；入口的状态借用不得逃逸，输出也不得
携带域借用。排队环境采用编译器生成的捕获与清理描述，不接收任意可存储闭包。
最终模块名、泛型签名和错误枚举留给 SC1，不在 SC0 注册一个只能供宿主绕过检查的公开接口。

**候选存储。** 先把候选完整拥有图从计算任务移入独立存储包，再申请发布。候选包拥有 arena、
根和清理责任；任务临时分配留在原 arena，不能一起带入状态。实际运行时的
`Buffer::owning_allocations`、`Arena::transfer` 和 `Buffer::migrate_metadata` 可以用于这一步。
迁移可能分配或失败，所以必须在发布前完成；多个域各调用一次 `Arena::transfer` 不能
直接构成多域原子发布。发布阶段只切换已经准备好的根包、修订和结果槽，旧根在发布后清理。

**结果与关闭责任。** 结果记录在提交前预留，独立于请求帧保活；请求取消不覆盖已有 Committed。
首版采用所有者收取终态的方式，不返回可游离保活业务状态的结果句柄。请求所有者关闭时先
收取或明确丢弃终态，再释放结果记录额度。单域探针用独立计费的收据模拟这项责任，
执行器结果队列和关闭联动仍需 SC1/SC4 接线。

**现有实例的复用边界。** 持久实例已经证明长期拥有图可脱离一次调用存活，独立 continuation
取消后也能保留实例状态。其调用仍采用 Ready/Busy/Failed 协议，不是候选提交：
调用期间原地写入、用户析构以及出口失败都不能被包装成事务。现有实例任务组的 fail-fast
规则也不能直接用来隔离同一房间的所有请求。状态域应复用存储描述与底层执行器，
另建版本、访问申请和逻辑请求所有者，不直接把 InstanceId 宣称为 Domain 句柄。

### 11.2 SC0 探针与验证记录

运行时探针位于 [state_domain_probe.rs](../src/runtime/state_domain_probe.rs)，仅通过
`#[cfg(test)]` 接线。使用真实 Arena、Buffer、Budget 和 ExternalCharge；版本、访问权限与
取消/关闭事件使用单域实验模型，不是现有 HostExecutor 的生产实现。

| 探针 | 已验证的边界 |
| --- | --- |

| 现有拥有图转移 | 真实 transfer 的三个失败点不改变登记；成功迁移后只保留候选图，释放任务临时存储不影响候选 |
| 现有实例与任务 | JIT/解释器的独立任务在挂起后取消或完成，不释放长期实例；相关 arena 计数回到基线 |

发布函数只有拥有根移动和标量写入，不包含分配、可失败调用或回调。探针的分配禁止只覆盖
语言 arena，并非全进程 malloc 拦截；发布区间无其他分配依靠该函数的代码结构约束。
故障注入和事件回调都发生在发布前。模型使用固定布局的标量/String 载荷，不声称验证了
任意类型资格、编译器生成的事务入口、多域原子性或可抢占的原生执行。

生成代码前置能力由 [state_domain_probe.jk](../tests/fixtures/state_domain_probe.jk) 验证：
显式复制 String/Array 快照、原值改变后快照保持独立、两次挂起后移动候选、整根替换后旧值
仍归独立拥有者清理，以及 race 取消时只清理一次临时 RequestGuard。
CLI 用例执行 JIT、解释器和独立 AOT，正常输出为 `42`、`77`、`99`。
这个用例使用现有 `mem.replace`，验证的是生成代码所有权前置能力，不是新的原子提交 API。

2026-10-12 验证结果：8 个运行时探针及 1 个三后端 CLI 用例通过，格式、Clippy 与差异空白
检查通过。预算探针计入语言存储和收据逻辑大小；生产队列、控制记录及额外宿主元数据的完整
计费仍随 SC1/SC4 实现，不能把当前模型的字节数视为整个执行器的内存上限。

### 11.3 SC1 当前进度：受检入口与宿主核心

`InstanceId` 访问状态，也不借用实例的 fail-fast 组。Rust 宿主能力与限额见
[语言参考](language.md#rust-宿主标量状态域)，实现不变量见
[架构说明](architecture.md#标量状态域核心)。

当前交付包括：标量普通记录资格、传递的同步无宿主调用证明、唯一关闭责任、可降级的
不保活句柄、模块版本保活、FIFO 短操作、独立标量输入、读写权限与修订、有界请求和
结果登记、取消移除、关闭失效、写失败隔离。JIT、解释器与独立链接 AOT 使用同一行为验收。

新增统一执行器接线：移除独立 `poll_domains`，`poll_tasks` 同时驱动就绪请求与短操作，
完成结果通过 waker 唤醒请求。每个请求具有独立失败组、根 arena 和唯一域所有者；关闭先
使域进入 Closing，再取消排队与关联任务，等待活动 poll/stop 退出后释放根。没有游离请求。

源码 `joky/domain.read/write` 提供首个受限切片：操作为命名同步函数，编译器验证不逃逸与
无宿主调用；排队捕获为操作身份及独立标量输入，不持有状态借用。房间双请求中的
排队取消、独立请求失败、只读权限、race/parallel 清理和多次唤醒由同一三后端用例验收。

源码现已提供 `Owner<S>`、可复制的 `ReadHandle<S>` / `WriteHandle<S>`、创建与消费式关闭、
显式短操作，以及启动并等待的 `request/request_read`。自然退出和取消均释放 Owner；
请求失败以 `Result<R, RequestError>` 返回，回执只在请求清理后发布。请求与短操作
共用有界额度，JIT、解释器与独立 AOT 均可直接执行纯 Joky 生命周期程序。

源码签名现已覆盖全部整数宽度、Float32/64、Bool、Rune 和 Unit；单个输入与结果分别泛型化。
请求返回完整标量载荷，并区分 Failed、Cancelled、Closed、ResourceLimit、InvalidAccess 和
DomainFailed。接口与边界以[语言参考](language.md#内置域访问-jokydomain)为准。

**SC1 的验收范围冻结为标量单域访问。** 源码签名固定为单个标量输入，拥有/组合输入及用户自定义错误载荷
未开放。每个请求绑定一个所属域，不提供跨域依赖或多域访问。后续新增这些入口时须继续保持同一注册表、执行器和关闭协议，不能另起调度器。

首版入口证明刻意保守：只允许可静态证明的直接同步调用和标量计算/局部借用，拒绝
外部宿主、间接调用、任务操作、arena 分配及用户清理。它不证明操作会终止，也不提供
帧时限。后续扩展拥有输入或结果时必须同时扩展清理、计费和捕获证明。

验证已通过：`cargo test state_domains_`（覆盖 JIT、解释器、独立链接 AOT）、`cargo test exhaustive_state_domains_ -- --ignored`（包含源语言所有者、请求和完整标量回执的逐指令取消）、`./scripts/check.sh`（默认 Debug：
格式、Clippy、默认测试及三后端短输入基准正确性）和 `git diff --check`。未运行 Release 或性能测量。

### 11.6 SC2 候选根与单域原子提交

已实现 `candidate_from`、`commit_to` 及唯一拥有的 `CommitReceipt`。候选消费整个单域快照，
保存原域身份、修订、类型和代码版本；受检构造器以一个标量输入在独立 arena 内生成完整根。
旧根与候选共同计入状态预算峰值，不把调用任务 arena 保留为长期状态。

提交复用短操作 FIFO。回执资源在准入前分配，请求与结果记录在排队前预留；进入发布前
重新验证身份、Open 状态及修订，检查下一修订可用。发布只整体移动根并写入修订和终态，
不运行用户代码、不分配也不挂起；旧存储在回执已记录提交事实后清理。提交身份使用同一
执行器的受理序号。回执可重复收取，完成记录保留到回执释放，并持续计入额度。
接口、错误与等待取消语义以[语言参考](language.md#候选根与单域原子提交)为准。

验收覆盖三后端完整根替换及标量位模式、Unit 投影、过期修订拒绝、错误域和失败域拒绝、
关闭后读取已提交回执；Rust 行为测试覆盖提交与短操作交错的 FIFO、发布前取消或丢弃、
发布后取消、构造失败、状态峰值不足、队列额度与身份/修订耗尽、资源两阶段分配失败回收、跨执行器拒绝及重载后的代码版本保活。
逐指令取消穷举覆盖候选构造、所有权交接、排队、发布及回执交付；三前端拒绝凭据/存储伪造、
已消费快照或候选重用、只读写入、动态构造器及带宿主调用/挂起的构造器。

验证使用 `cargo test state_domains_`、`cargo test exhaustive_state_domains_ -- --ignored`、
`./scripts/check.sh` 和 `git diff --check`，均采用 Debug，不运行 Release 或性能测量。

## 12 验收矩阵与验证范围

| 场景 | 必须观察到的行为 |
| --- | --- |
| 两次写同一房间 | 按受理顺序执行，无重叠独占引用 |
| 无关域与被阻塞申请 | 无关操作可以推进，冲突后来项不能无限插队 |
| 申请集合出现别名 | 重复读规范化，重复独占绑定受控拒绝 |
| 完整读取依赖变化 | 即使变化的域不在写集合中，提案也返回 Conflict |
| 读快照与多域提交交错 | 快照只能看到一次提交之前或之后的联合状态 |
| 多域发布任一预检失败 | 全部旧状态、修订和拥有责任保持不变 |
| 取消覆盖每个可取消边界 | 队列、候选、许可、结果和外部 stop 各清理一次 |
| 发布前后取消或超时 | 前者未提交，后者保留 Committed，不产生半次发布 |
| 域关闭与迟到完成事件 | 不再授予访问，不命中新世代，stop 完成后才释放存储 |
| 请求失败与写域失败 | 独立请求互不取消；损坏写域进入 Failed，拒绝继续业务访问 |
| 拥有根替换与反复拒绝 | 原有分配不重复计费，临时副本计峰值，周期结束回到资源基线 |
| 不可提交类型 | 资源、用户 Drop、引用和未经审核组合在编译期被拒绝 |
| 多次挂起与重载 | 不重放副作用，旧工作保活原代码和布局，不写入新身份 |
| Channel 背压和取消 | 已交接与未交接载荷都有唯一清理责任，等待项不绕过上限 |
| 网络回复丢失后重试 | 已提交事实不消失；启用业务去重时不重复施加同一操作 |

实现阶段先运行受影响的生成代码行为测试，覆盖 JIT、解释器与 AOT，再按
[AGENTS.md](../AGENTS.md#按改动范围验证)运行默认 Debug 检查。
所有权、任务生命周期和发布边界补充相关 Debug 穷举，不自动扩大到无关 stress 或 Release。
默认回归保留短模型周期，长序列和逐边界枚举标记为 `exhaustive_`。

## 13 后续探索与待定问题

首版完成后可以沿同一边界扩展，不要求同时加入全部能力：

- **业务有效条件作用域：** 将世代订阅封装为自动请求取消；发布时仍须验证有效性，
  不能把取消投递当作正确性的唯一防线。
- **事实与增量数据流：** 对单调数据使用可合并结果，减少顺序依赖；否定条件、最终结果和
  事件窗口需要显式完成边界。事件流与只保留最新值的状态流保持区分。
- **效果与权限推导：** 在显式访问集合稳定后推导部分读写和副作用契约，降低注解负担；
  不自动推导“网络操作可重试”这样的业务保证。
- **多核与多执行器：** 增加可发送值、隔离存储和调度协议；不能直接把当前 Rc、帧和状态指针
  放到其他线程。同进程多域语义不自动延伸到分布式事务。
- **持久工作流：** 若需要跨进程重启继续执行，另行设计日志、幂等和效果重放边界，
  不直接持久化当前 continuation 或把内存提交称为持久事务。

SC0 已确定首批类型、调用与捕获方向、候选包移交以及实例复用边界。SC1 已冻结标量范围的公开
签名、访问入口资格元数据和逻辑请求所有者接口；SC2 需要把候选包与版本凭据接入生成代码。
这些工作不改变本草案对发布原子性、不跨挂起持有状态借用、关闭顺序和有界排队的要求。

首版主要风险是候选复制与整域冲突成本，以及把访问控制、事务与任务管理同时引入后产生的
实现复杂度。先用标量和少量拥有类型验证闭环，分别测量快照、排队、转移和清理成本，
再决定是否需要字段级变更或更细状态粒度；性能测量遵循 [基准方法](../benches/README.md)。
