本文记录启动时选择 worker 数量的目标、决策与实施顺序。当前行为以[语言参考](language.md#任务执行模式)为准，

## 1. 目标与范围

同一份通过并行资格检查的 AOT 产物，可以在每次启动时选择 task worker 数量，
无需修改源码或重新编译。数量从 1 改为 8 不改变类型准入、资源归属、取消与清理契约。
JIT、解释器和 AOT 保持同一套 Parallel 语义；项目构建和单文件构建均支持此能力。

长期目标是让普通业务代码较少受执行方式影响：编译器证明任务与数据的执行资格，
运行时按资源归属调度。线程绑定的操作可以由指定线程处理，不要求每个对象都能跨线程。

本计划明确不包含：

- 运行过程中动态增加、减少或迁移 worker；进程启动后线程池规模固定。
- 根据 CPU 数量自动选择规模、性能调优、抢占式调度或公平性承诺。
- 自动把未通过检查的 Local 代码升级为 Parallel，或在检查失败后静默回退 Local。
- 取消 Godot 等宿主的线程归属约束，或者允许任意裸指针跨线程。

这里的数量只指 task worker，不是进程总线程数；共享 reactor、控制线程、文件和 DNS
服务可能另外使用线程。设置为 1 也不代表整个进程只有一个线程。

## 2. 实施前的实现基础

| 位置 | 当前行为 | 对本计划的意义 |
| --- | --- | --- |
| `src/cli/build.rs` | `--task-workers N` 选择 Parallel 并生成独立入口 | 需要拆开构建资格与启动默认值 |
| `src/backends/aot/mod.rs` 的 `parallel_entry` | 检查完整调用图与入口任务包资格 | 继续作为构建阶段的必要检查 |
| 同文件的 `standalone_main_v1` | 将 worker 数量写入生成的 C 配置 | 数量没有参与业务代码特化，可改为启动时取值 |
| `include/joky_executor.h` | `JokyExecutionConfigV1` 已包含 mode、workers、max_tasks | 首阶段无需变更 ABI 布局或版本 |
| `src/runtime/parallel/standalone.rs` | 读取配置并创建线程池 | 已支持按调用者提供的数量启动 |
| `src/runtime/parallel/pool.rs` | 验证 1–256，创建固定数量的 worker | 保持现有生命周期与关闭协议 |
| `src/cli/build/driver.rs` 与 `project_main.c` | 项目启动包装先定位资源根，再调用生成入口 | 新启动参数须完整转发，保留搬迁与符号链接启动行为 |

当前 Local 与 Parallel 使用不同启动路径。Parallel 的 1 worker 仍要求完整并行资格，
不能借数量为 1 接纳只允许 Local 的代码。

## 3. 已交付用户接口

以下命令已随 W0–W2 实现：

```sh
# 构建时声明并行执行，默认 1 个 task worker
joky build examples/chat -o /tmp/chat-app --parallel

# 同一份产物在不同启动中选择数量
/tmp/chat-app/chat --task-workers 1
/tmp/chat-app/chat --task-workers 8

# 服务部署可通过环境变量配置
JOKY_TASK_WORKERS=3 /tmp/chat-app/chat

# 保留旧命令：构建 Parallel 产物，默认 3，启动时仍可覆盖
joky build examples/chat -o /tmp/chat-app --task-workers 3
```

### 3.1 规则

| 情况 | 行为 |
| --- | --- |
| 配置优先级 | 启动参数 > `JOKY_TASK_WORKERS` > 构建默认值 |
| `build --parallel` | 资格检查成功后构建 Parallel，默认数量为 1 |
| `build --task-workers N` | 保留兼容行为：启用 Parallel，N 成为可覆盖的默认值 |
| 两个构建选项同时出现 | `--parallel --task-workers N` 合法；重复同一选项报错 |
| 构建时两个选项都不传 | 保持现有 Local 默认，不改变既有程序准入 |
| `run --parallel` | 以 1 worker 启动，与 `run --task-workers N` 共用资格检查 |
| `run` 的数量覆盖 | 显式 Parallel 时，参数 > 环境变量 > 1；环境变量不能单独启用 Parallel |
| 数量格式 | 仅接受十进制数字且值为 1–256；空值、符号、空白、溢出与越界均报错 |
| 未生效的低优先级值 | 不解析；有效显式参数可以覆盖环境中的错误值 |
| Local 程序收到 worker 参数或变量 | 明确报错，不忽略配置，也不切换执行模式 |
| 重复或缺值的启动参数 | 明确报错，在业务入口和线程池创建之前退出 |
| 初始化失败 | 报告失败并退出，不减少 worker 数量重试，也不回退 Local |

配置解析只在 `joky run` 执行路径及 CLI 生成的独立程序启动层生效。
`joky build` 不读取 `JOKY_TASK_WORKERS` 作为构建默认值，避免部署环境改变构建产物；
该变量也不影响 fmt、帮助等非执行操作。

首阶段只增加运行时配置参数，不扩展 Joky 的用户程序参数 API。生成入口须预留 argc/argv
传递边界，明确拒绝尚不支持的参数；未来应用参数与运行时参数的分隔规则另行设计。
项目清单暂不增加线程数配置字段，避免同时引入新的配置来源。

### 3.2 嵌入边界

保留 C ABI 的“无环境变量覆盖”契约。Rust/C 宿主仍显式传入配置，运行库不自行调用 getenv，
不受进程环境隐式影响。CLI 生成的启动层先解析并校验，再构造 `JokyExecutionConfigV1`。
现有公开入口生成 API 的兼容性须保留，CLI 的可配置启动行为通过明确的生成选项或独立入口开放，
不把 CLI 策略隐式施加到所有使用 `ParallelEntry` 的嵌入方。

worker 数量在任何业务调用前确定。同步 main 仍可使用 Local；Parallel 仍要求符合现有
无参数、返回 Unit 或 Int32 的挂起入口，不为配置数量额外放宽入口 ABI。

## 4. 并行能力的后续演进

启动时配置不依赖下面所有限制先被解除。能力扩展按独立阶段推进，不能为了统一接口而跳过证明。
现有能力细节统一引用[语言参考](language.md#任务执行模式)，不在本文复制完整支持表。

| 能力 | 后续方向 | 必须保持的边界 |
| --- | --- | --- |
| 捕获闭包与间接调用 | 对拥有捕获、具体目标和调用链建立证据；从无引用捕获开始 | 冻结代码与环境共同保活，未知目标不能只凭签名通过 |
| 自定义 Drop 的拥有值转移 | 检查析构调用图与线程能力，明确成功转移前后的唯一清理责任 | 取消、部分构造与转移失败均恰好清理一次 |
| 拥有型与借用型 dyn | W3 接入拥有型动态对象、受检转移及所属 worker 内的动态借用调用 | 擦除类型不能擦除方法、析构及存储资格；借用视图不跨 worker |
| 引用、切片与游标跨 worker | W6b–W6e 已实现结构化子任务内的有限只读借用；游标与其他借用另行审查 | 来源保活、别名排斥、子树清理屏障及取消路径全部成立；现有同 worker 路径仍保留 |
| 显式 Arena | W4 已开放所属 worker 内同步使用 | Arena 及其依赖引用不跨语言挂起或跨 worker |
| Local VM／状态资源 | W5b 已通过控制代理开放拥有型迁移会话；其他 Local 操作按需求推进 | 不移动原始 Local owner，不把控制线程变成阻塞等待自身请求的调用者 |
| Godot／线程绑定宿主 | 通过宿主拥有的主线程消息桥执行，其他计算可进 worker 池 | 主线程归属、宿主退出、回调保活和取消由显式协议保障 |
| 自定义 extern | 保留明确的线程安全绑定契约并改善诊断 | 编译器不能自动证明任意外部代码安全；不允许用户普通声明伪造证据 |

`isolate` 内部子任务、含借用的静态 join/race 继续允许同 worker 协作执行。
“可使用任意合法 worker 数量”不承诺所有并发结构都产生跨核并行，也不改变结果顺序与竞争仲裁规则。

### W3a：拥有闭包输入（已实现并验收）

先开放无引用 move 环境在挂起帧中保留，以及同树拥有参数和 branch 移动捕获。
Fn／FnMut／FnOnce、包装记录和嵌套环境使用已有稳定存储；闭包精确目标及捕获树均须证明资格。
Rust TaskValue、宿主 ABI、闭包并发结果和跨 worker 借用不在范围内；W3a 当时仍拒绝自定义 Drop 捕获转移，W3b 已接续开放。
具体语法和当前边界见[语言参考](language.md#任务执行模式)，本阶段不新增闭包语法。

### W3b：共用清理协议与自定义 Drop 转移（已实现）

保留语言层自定义 `Drop`，与 W3c 共用清理责任交接机制。拥有型 dyn 本身不依赖用户 Drop：
没有自定义钩子的对象也必须按实际类型释放字段；带钩子的对象额外执行受检用户代码。
实现前 `Packet::capture` 在发送方执行剩余 cleanup，`OwnedBuffer` 不接纳用户清理回调；
解释器的本地回调还可能持有 Rc 和执行帧。因此实现了独立的析构转移协议，
没有为这些本地状态直接实现 Send，也没有仅移除 `has_custom_drop` 拒绝条件：

- 使用冻结模块内的受检析构入口和布局描述重建接收方清理，检查完整析构调用图及线程能力；
  不在包中放发送方帧指针、借用或本地回调对象。
- 明确准备中、已发布未安装、已安装、结果待领取各状态的唯一清理责任和交接时点。
  部分构造、安装失败、队列拒绝、取消以及 race 败者结果都必须恰好析构一次。
- 包在任意宿主线程释放时不能直接运行用户析构；设计由具备执行上下文的 worker 完成清理的路径，
  并把这项责任纳入子树终态和池关闭屏障，处理析构失败且保留冻结代码直到清理结束。
- 同时覆盖记录、枚举非激活变体的类型资格、容器元素清理和嵌套闭包捕获；
  JIT／解释器／AOT 共用协议，验证正常析构、失败与取消及预算最终归零。

### W3c：拥有型 dyn Trait 与 worker 内动态调用（已实现）

2026-10-28 纳入 W3，与 W3b 共用清理协议并合并最终验收。以下规则已实现，
当前语法及使用边界见[语言参考](language.md)。

**表面语法与所有权**

- `dyn Trait` 表示唯一拥有的动态对象；`&dyn Trait`／`&mut dyn Trait` 保留借用视图含义，
  不增加 Box 语法。所有关联类型必须绑定，沿用现有接口身份和关联类型相等约束。
- 带类型绑定、赋值、实参和返回位置的期望类型触发具体值到 `dyn Trait` 的拥有转换。
  非 Copy 具体值移动进入对象，Copy 具体值复制快照；动态对象本身不可隐式复制，移动后不可再用。
  没有期望接口时保留具体类型，不因多个实现可用而自动选择或推导某个 trait。
- 同一接口下的不同具体类型可作为工厂返回值，进入记录、枚举及拥有容器。
  支持普通与挂起函数的拥有参数／返回，以及同树 join/race 输入／结果和 branch 捕获。
  Array/List/Map/Set 仍遵守各自元素及键约束；动态对象不自动获得 Eq/Hash 或其他 trait。
- 方法点调用按接收者建立短期共享／独占借用；可显式取得上述两类 dyn 视图。
  对象移动、替换和销毁必须服从现有借用检查。借用视图保留来源，不能变成拥有值。
- 第一版只接纳完整存储树无引用的具体对象；保留现有动态接口的方法限制：
  同步 `&self`／`&mut self`、借用参数不逃逸、不返回引用、除接收者外不使用 Self。
  不同时开放挂起动态方法、消费式 self 方法、向下转型、trait 上转型或动态 callable。

**存储、代码与转移**

- 使用稳定、计入任务预算的拥有载荷以及不可变的具体类型／方法／清理描述。
  类型擦除和转换失败遵守单一拥有责任；不把原调用者栈地址或本地 Rc 封入对象。
  描述的 native 地址须经 AOT 重定位，解释器使用冻结代码身份，不使用编译进程地址。
- 无自定义 Drop 的对象沿实际字段布局释放；带 Drop 的对象复用 W3b 协议。
  不建立第二套 dyn 专用取消或析构调度器。返回未领取、容器清理、转换中断和池关闭
  都必须保留代码直到清理结束，并最终归还预算。
- Parallel 资格检查覆盖实际对象完整存储、接口方法表中的全部可调用目标以及析构依赖。
  擦除为接口后不能仅凭接口签名通过，也不能因为当前路径不调用某方法而跳过 Local 目标。
  准备时使用冻结模块内可验证的目标集合；无法证明时明确拒绝，不运行后再静默回退 Local。
- 同树 worker 移动的是拥有对象；动态借用调用留在所属 worker。
  此项包含现有借用型 dyn 的 worker 内目标证据检查，统一复用动态方法资格分析；
  不因此授予借用视图跨 worker 的 Transfer／Share，也不扩大其存储和逃逸范围。
- Rust TaskValue、C／宿主 ABI 和持久状态仍不接纳拥有型动态对象，跨树导入导出另行设计。
  未获得资格的外部资源仍保持 Local；不把 W3 扩展成通用跨线程借用或主线程代理机制。

### W3d：联合验收与文档收尾（已完成）

W3b 先建立清理责任协议，W3c 在其上接入拥有型 dyn；在同一批稳定实现上完成联合验收。
具体实现可拆提交，但不按子阶段重复全量测试：

- 三后端验证两种具体实现经同一 dyn 接口返回、保存、调用和替换，以及共享／独占借用。
  覆盖无 Drop、带 Drop、嵌套容器及闭包捕获动态对象；分别验证接口类型边界与运行时行为。
- 验证拥有值跨 worker 的输入与结果、未开始即取消、部分安装失败、race 败者和结果丢弃，
  断言析构次数、代码保活、清理完成顺序及预算最终归零。
- 验证 VM 重载／释放后旧对象仍使用旧目标；Local 方法／析构、伪造描述和跨树交接受控拒绝。
  AOT 验证同一二进制以 1／3 worker 启动，保持与两种 VM 后端一致的所有权语义。
- 按清理生命周期补相关 Debug 预算／取消穷举，首次完整成功并验证清理后停止预算扫描；

### W4：显式 Arena 的 worker 内同步使用（已完成）

范围固定为 worker 自建、自用、自行释放的显式区域，沿用 `Arena.new()`、`arena.alloc(value)`
和同步 `&Arena` helper，不引入新语法或自动迁移。Arena 及其引用只获得 worker 内使用资格，
不获得 Transfer／Share；语言挂起边界、闭包捕获、聚合／容器存储和宿主 ABI 仍按原规则拒绝。
拥有型 dyn 擦除显式 Arena 也须拒绝，不能把能力隐藏进可转移对象。区域内 Copy 对象的短期
动态借用仍遵守既有来源、逃逸及同步调用规则。

普通 Parallel 分片由任务根保留，以支持拥有包交接；显式区域中的对象不能逃逸，所以区域析构
必须主动释放自己的载荷和分配表计费，不能等到任务树结束。空分片头可由任务根复用。
各区域共享根预算，释放一个区域不影响其他区域或任务分配；失败、取消与解释器时间片恢复
继续走既有拥有者清理。原生同步代码也必须响应任务取消。

## 13. W6a：结构化跨 worker 只读借用设计

本节前半保留 2026-10-29 的 W6a 首阶段设计，完成情况见 13.7–13.11。
W6b 已实现静态 join 借用；W6c 扩展局部子树排空、嵌套借用组与只读 race。
W6d 允许收到的只读借用在受检区间内继续派发；W6e 接通动态 scope/branch 的受检只读捕获。
W5c 按用户决定暂缓。当前能力与限制以语言参考为准。

### 13.1 结论与实现依据

有限只读子集值得实施；不能直接把引用加入现有拥有值 packet 白名单。
目标是让静态 join 的子任务读取父任务的同一份大数组／文本数据，省去负载复制，
同时保留 Local 执行及不符合跨 worker 准入条件时已有的同 worker 路径。
不新增用户关键字，不把普通引用升级为可任意移动的线程安全值。

现有代码提供了以下基础和明确缺口：

| 位置 | 当前事实 | W6 的工作 |
| --- | --- | --- |
| `src/core/ir/parallel.rs` | Qualification 已区分 transfer、share、worker_local，并明确类型性质不构成具体指针传输证明 | 增加静态 join 调用点的借用来源与范围证据，不能只读取 share 布尔值 |
| `src/core/ir/parallel/packet.rs` | Reference 落到 Local；拥有值 packet 准入按整个名义类型图检查 | 单独描述受限借用输入；原有普通参数／返回值 packet 规则保持封闭 |
| `src/runtime/parallel/packet.rs` | Packet 接管拥有者，或复制 Copy place；install 注册目标任务清理 | 新借用输入只持租约和描述，不接管来源的析构责任 |
| `src/runtime/buffer.rs` | slice/view 已创建无负载所有权的本地描述头；原始 Buffer 含预算、资源和清理元数据，游标还有 Cell 位置 | 目标 worker 重建自己的只读描述头，只共享获证的负载区间 |
| `src/runtime/parallel/pool.rs` | 父任务终态等待 children_cleaned，Group.poll 在全部句柄 cleaned 后交付；worker 禁止阻塞 wait | 复用异步排空与唤醒，并补父任务内部提前清理路径的证明 |
| `src/runtime/cps/parallel.rs`、`src/backends/interp/execute/parallel.rs` | 各 worker 创建自己的执行帧，输入目前走拥有值 packet | 两条路径共同安装借用描述；JIT／AOT 共用原生 lowering 与协议 |

主要风险是“底层存储还在”和“其中对象仍然存活”不同。保留 Storage 的 Arc 不会自动阻止
显式 Buffer.release、字段清理或析构。池最终才 drop 父 Job，也不自动证明 Job.poll 内部
错误展开没有提前清理来源。因此，父任务恢复、错误和取消三个入口都必须经过借用排空屏障。

### 13.2 W6b 首阶段准入

首阶段只开放 Parallel 下静态 `join` 的直接、已知目标调用；所有分支一起决定执行路径。
先在前端借用检查已经通过的程序上增加执行能力，不放宽来源、别名和逃逸检查。

| 项目 | 首阶段决定 |
| --- | --- |
| 共享输入 | `&String`、`&Array<T>`、`&Slice<T>`；T 限普通数值、Bool、Rune 等无引用、无拥有字段、无 Drop 的标量 |
| 来源 | 当前 join 所属任务能证明保活的拥有存储，或能追溯到它的共享 slice；不接受仅有地址却无法追溯来源的引用 |
| 其他实参 | 可以混合现有可转移的拥有参数；在所有参数求值、快照和资格检查完成后才发布子任务 |
| 结果 | 仅使用现有受检拥有／值 packet；不返回借用、含借用聚合或捕获来源的闭包 |
| 分支行为 | 可以挂起，可以在自身 worker 创建只读视图和独立游标；完整调用图仍须满足 Parallel 资格 |
| 移动边界 | 父任务创建的游标不传给子任务；子任务新建的游标仅在该 worker 使用 |
| 后续工作 | `&mut`、普通标量／记录地址、FixedArray place、嵌套拥有图、dyn／闭包中的借用、外部引用来源、race 和动态 scope/branch 均暂缓 |

这里的标量集合不包括虽然由整数表示的 domain.Handle、admission.Token 或其他宿主能力。
不以“没有指针”代替名义类型与权限检查。初版也不允许借用来源经嵌套远程任务再次转发；
内部普通调用与同 worker 结构化并发沿用现有规则。后续开放重借用跨线程时须证明租约可传递。

不满足新准入条件、但原来合法的静态借用 join，继续在所属 worker 执行；原来不合法的借用
仍由前端拒绝。明确为整个组保守选择路径，避免混合派发使父帧部分恢复、清理顺序变得不清晰。
Local、Parallel 1 worker、Parallel 多 worker 不改变数据结果与清理契约，不承诺具体线程分配顺序。

### 13.3 只读传输协议

采用私有的“作用域借用输入”描述，与拥有值 Packet 分离。下列是内部职责，名称待实现时确定：

1. **调用点证据**：携带共享权限、名义元素类型／布局、来源身份与 join 身份。只由编译器和
   受检 lowering 产生；普通 UInt64、裸指针和公共 host TaskValue 不能构造这类输入。
2. **来源租约**：覆盖真实负载、必要的源对象存储和冻结代码。发布前建立；组未排空前不解除。
   来源的拥有者、析构责任及预算仍属于父任务，不能偷偷转给某个读者。
3. **不可变区间描述**：传递经过验证的地址、初始化范围、长度、对齐、元素布局与租约身份。
   只复制这部分元数据，不复制整个数组或文本负载；空数据和零长度区间也必须有合法表示。
4. **目标本地视图**：在目标 worker 的 arena 中新建非拥有描述头；任何游标、临时 slice 或
   克隆所得拥有值也归该 worker。禁止把来源 Buffer、CpsFrame、解释器 Value 容器或 Rc
   整体声明为 Send/Sync 后直接共享。原有 Buffer.view 的线程契约须经审核，不能直接扩大注释。
5. **只读访问审核**：覆盖 len、索引、切片、UTF-8 访问和只读迭代，包括间接 helper。
   证明不会写父任务的描述头、懒初始化状态或预算计数，不构造覆盖共享负载的独占 Rust 引用。
   源码中的共享借用、函数无 @suspends、或类型的 Copy 性质都不能单独替代这一证明。

准备借用描述、目标视图和控制元数据计入任务预算；负载的预算不重复计费。
租约仅在同一父子任务树及受检组内有效，不能通过公开并行入口、宿主回调或返回值带出组。
首阶段排除向未具备该协议的宿主引用 ABI 转交这些视图。

### 13.4 生命周期与失败顺序

协议逻辑顺序为：准备 → 发布 → 运行 → 停止／排空 → 解除借用 → 父任务继续或清理。
这不是另建调度器；实现应复用现有 Group 和池的完成、取消及清理回执。

- **准备失败**：尚未发布的描述销毁时只归还租约元数据，不销毁来源负载。拥有实参的部分接管
  仍按原 Packet 契约清理。必须覆盖后续参数求值失败和其中一次参数求值挂起的情况。
- **部分发布失败**：先取消并排空已经可运行的子任务，再让父任务失败路径释放来源。
  若沿用现有批量发布的原子承诺，应补测试证明，而非假设 publish 出错就没有子任务。
- **普通完成**：所有读者及其派生视图、必要清理回执结束，才允许父任务继续写、移动或释放来源。
  源数据写入与发布、子任务完成与父任务恢复之间须有明确的同步关系。
- **子任务失败**：停止兄弟任务并排空；错误返回之前来源保持只读且存活。已产生但未领取的结果
  沿用原有清理协议，不携带借用来源。
- **父任务取消／池关闭**：只发送取消和安排推进，不在 worker 内阻塞等待。父帧的错误展开、
  EndLocal、cleanup hook 和 arena 释放必须等同一屏障完成；不能仅延迟最外层 Job 的 Drop。
- **源对象析构**：仍在父任务的所属 worker 执行，且只执行一次。一个读者结束不能解除其他读者的租约。
- **迟到唤醒**：绑定原任务／组身份，终态之后不再访问已释放来源；不得让新组复用旧租约。

### 13.7 W6b-1：根任务错误排空基础与前置探针（历史记录）

本次先修复实施门槛中确认的提前清理路径；**不开放跨 worker 借用，不把 W6b 标为完成**。
类型／调用点来源证据、作用域租约和借用输入协议仍未接通。现有合法借用 join 继续在同一 worker 执行。

实际错误展开有三层，必须一起保留：

1. 原生生成代码在失败返回时调用 `__joky_cps_finish`。存在未清理的远程子任务时，先保留
   失败 CPS 调用链中的帧、清理登记和 arena，错误继续返回到 worker 根；成功 helper 的普通清理保持原路径。
2. 解释器 `Execution.fail` 在同样条件下返回失败但保留激活树，不提前调用 `release_for`。
   没有远程子任务的 Local 执行仍立即清理。
3. `ParallelExecution.resume` 原来会在收到内部 Job 失败后立即 `take` 并 drop 它，
   即使外层池仍保留 RootJob。这是 W6a 表格未单独列出的第二层提前清理；现在一并保留内部 Job。
   池负责取消子树、异步等待 cleaned 回执，再在所属 worker drop 根 Job，执行最终清理。

`children_pending` 只检查当前任务的直接子任务清理状态；子任务的 cleaned 已包含其子树和清理回执。
它不阻塞 worker，不共享原生／解释器帧，也不以 Storage 保活代替对象保活。

新增验证责任：

- 发布容量不足时，整批工厂均不启动；两个捕获各释放一次，任务登记没有部分提交，预算最终归零。
- 父 Job 报错而子 Job 正在执行时，父 Job 清理严格晚于子 Job 清理，且仍在父 worker。
- 执行生成代码的 JIT／解释器回归：父任务退出失败轮次后，持有文本的用户 Drop 尚未执行；
  子任务停止后恰好执行一次，清理线程与父任务一致。测试通过池的 Stopping 状态同步，不以睡眠猜测错误展开是否结束。
- Buffer 探针用 Rust scoped threads 提供已知生命周期屏障，检查重叠标量区间共享原负载地址、
  每个 worker 的 Buffer 头与游标独立、派生 slice 的地址、空区间和 Unicode；读者结束后父端可以修改和释放来源。
  这些是底层存储探针，不能当作语言借用已跨 worker 的证明。
- 单独证明保留 Storage 仍不能阻止 `Buffer.release` 立即回收头和负载。
- 共用 `tests/fixtures/scoped_borrow_join.jk`，检查 JIT／解释器／链接 AOT 在 Parallel 1／3 worker
  下的 String、Array、重叠 Slice、空 Slice、分支挂起和 join 后修改；当前该用例中的借用组仍走同 worker。

下一步仍有明确的安全门槛：

- `Arena.contains` 在并行模式下查询整个 Storage 根，不是“当前任务拥有来源”的证据。
  必须建立当前任务拥有者与区间的对应关系，拒绝从另一个读者视图再次远程转发。
- 根任务终止屏障不能代替局部 race、动态 scope 或 isolate 中的子树排空。
  局部取消后父任务还可能继续执行，必须先完成相关读者排空，才可恢复写权限或运行局部析构。
- 准入证据要覆盖完整调用图与只读宿主边界；共享类型性质和相同 ABI 布局不足以产生租约。
- 尚未实现的作用域输入不得加入普通 Packet／TaskValue 白名单；所有三后端接线完成并通过生命周期测试后再开放。

验收记录：

- `cargo test scoped_borrow_ --lib`：7 项通过。
- `cargo test task_pool_generated_branches_overlap_and_cancel_on_all_backends --lib`：三后端生成代码的并发／取消回归通过。
- `cargo test exhaustive_parallel_drop_value_budgets --lib -- --ignored`：相关 Debug 预算穷举通过。
- `./scripts/check.sh`：仅完整运行一次并通过。fmt、Clippy、Debug 库测试（1756 通过，151 忽略）、
  CLI（338 通过，8 忽略）、其余默认测试与 while／Map 短输入三后端正确性检查通过。
- `git diff --check` 通过。代码验证后仅补充文档验收记录，不重跑代码检查。

### 13.8 W6b-2／W6b-3：静态 join 借用与联合验收（历史记录）

三后端现已接通第 13.2 节的只读 String／标量 Array／Slice 借用。普通 helper 调用链、
拥有实参交接后的再次借用、混合拥有实参及拥有结果均沿用同一私有输入协议；公共 Packet／TaskValue 不增加引用。
具体实现契约归 [架构](architecture.md)，使用边界归 [语言参考](language.md#任务执行模式)。

来源证明使用真实 Buffer owner 的任务身份与本地 origin，slice 保留来源；远程视图不带 origin，
不能再次远程转发。接收方创建独立头和游标，负载保持同一地址。编译器对直接分支的传递调用图
生成额外凭据，排除宿主引用 ABI、间接调用及函数值；正常 Parallel 资格仍独立检查。

W6b 当时的局部子树采用保守准入边界：本地结构化分支和 isolate 内不再派发借用组，继续整组本地执行。
已准入的组通过 Group cleaned 屏障或 W6b-1 的完整根激活树排空保活来源，不存在局部取消后
父任务先恢复的路径。因此本次完成首阶段静态 join；任意局部子树的通用排空、race、动态借用 branch、
可变借用及跨 worker 再借用没有开放，不应从本阶段完成推导出这些能力。

验证责任：

- 共用 fixture 在 JIT／解释器／链接 AOT 及 1／3 worker 下验证数值、Unicode、重叠和空 slice、
  挂起恢复及父端重新修改；线程与地址探针验证真实跨 worker、共享负载及目标独立视图。
- 拥有值传递后在普通 helper 中借用，混合拥有参数并返回拥有结果；公共根引用仍拒绝。
- 本地 race／isolate、再次远程转发和传递调用图中的宿主引用 ABI 保守回退；形状测试覆盖
  可变引用、普通标量地址、拥有元素及名义能力不获新资格。
- JIT／解释器暂停真实读者，分别触发兄弟失败、父任务取消和池关闭，验证来源 Drop 晚于读者停止、

### 13.10 W6d：只读借用的跨 worker 再借用（已实现并验收）

本地派生 slice 只能缩小收到的区间，不能恢复被上游裁掉的范围。

接收方使用本地、地址稳定的借用凭据；Buffer 头及本地 slice 仅引用所属 worker 的凭据，

### 13.11 W6e：动态 scope/branch 只读借用捕获（已实现并验收）

保持既有语法与按整绑定捕获规则，允许 branch 捕获受检的只读 String／标量 Array／Slice 引用，
复用 W6d 的来源身份、区间及再借用凭据。拥有绑定仍在登记时移入分支，不自动改成共享捕获。
借用分析已经按引用可变性保留 scope 区域借用；本阶段补回归并修正过时文档，不另建共享捕获规则。

每个动态分支独立检查并行调用图、捕获布局和运行时来源。已获 Parallel 调用图资格、
但不能证明跨 worker 借用条件的分支继续本地执行，
不会清除同 scope 之前已登记的远程组。join 同时等待本地与远程子任务及其后代，远程 Pending
期间仍推进本地分支。提前 return／break／continue 也经过所属 scope 的汇合。
