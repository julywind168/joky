# 启动时 worker 配置与并行能力演进计划

状态：2026-10-28，W0–W2 已实现并验收，验证记录见第 8 节；W3a 已实现并验收（第 9 节），W3b–W6 待实施。
本文记录启动时选择 worker 数量的目标、决策与实施顺序。当前行为以[语言参考](language.md#任务执行模式)为准，
执行器与 ABI 不变量见[架构说明](architecture.md)。

## 1. 目标与范围

同一份通过并行资格检查的 AOT 产物，可以在每次启动时选择 task worker 数量，
无需修改源码或重新编译。数量从 1 改为 8 不改变类型准入、资源归属、取消与清理契约。
JIT、解释器和 AOT 保持同一套 Parallel 语义；项目构建和单文件构建均支持此能力。

长期目标是让普通业务代码较少受执行方式影响：编译器证明任务与数据的执行资格，
运行时按资源归属调度。线程绑定的操作可以由指定线程处理，不要求每个对象都能跨线程。

本计划明确不包含：

- 运行过程中动态增加、减少或迁移 worker；进程启动后线程池规模固定。
- 根据 CPU 数量自动选择规模、性能调优、抢占式调度或公平性承诺。
- 自动把未通过检查的 Local 代码升级为 Parallel，或在检查失败后静默回退 Local。
- 取消 Godot 等宿主的线程归属约束，或者允许任意裸指针跨线程。

这里的数量只指 task worker，不是进程总线程数；共享 reactor、控制线程、文件和 DNS
服务可能另外使用线程。设置为 1 也不代表整个进程只有一个线程。

## 2. 实施前的实现基础

| 位置 | 当前行为 | 对本计划的意义 |
| --- | --- | --- |
| `src/cli/build.rs` | `--task-workers N` 选择 Parallel 并生成独立入口 | 需要拆开构建资格与启动默认值 |
| `src/backends/aot/mod.rs` 的 `parallel_entry` | 检查完整调用图与入口任务包资格 | 继续作为构建阶段的必要检查 |
| 同文件的 `standalone_main_v1` | 将 worker 数量写入生成的 C 配置 | 数量没有参与业务代码特化，可改为启动时取值 |
| `include/joky_executor.h` | `JokyExecutionConfigV1` 已包含 mode、workers、max_tasks | 首阶段无需变更 ABI 布局或版本 |
| `src/runtime/parallel/standalone.rs` | 读取配置并创建线程池 | 已支持按调用者提供的数量启动 |
| `src/runtime/parallel/pool.rs` | 验证 1–256，创建固定数量的 worker | 保持现有生命周期与关闭协议 |
| `src/cli/build/driver.rs` 与 `project_main.c` | 项目启动包装先定位资源根，再调用生成入口 | 新启动参数须完整转发，保留搬迁与符号链接启动行为 |

当前 Local 与 Parallel 使用不同启动路径。Parallel 的 1 worker 仍要求完整并行资格，
不能借数量为 1 接纳只允许 Local 的代码。

## 3. 已交付用户接口

以下命令已随 W0–W2 实现：

```sh
# 构建时声明并行执行，默认 1 个 task worker
joky build examples/chat -o /tmp/chat-app --parallel

# 同一份产物在不同启动中选择数量
/tmp/chat-app/chat --task-workers 1
/tmp/chat-app/chat --task-workers 8

# 服务部署可通过环境变量配置
JOKY_TASK_WORKERS=3 /tmp/chat-app/chat

# 保留旧命令：构建 Parallel 产物，默认 3，启动时仍可覆盖
joky build examples/chat -o /tmp/chat-app --task-workers 3
```

### 3.1 规则

| 情况 | 行为 |
| --- | --- |
| 配置优先级 | 启动参数 > `JOKY_TASK_WORKERS` > 构建默认值 |
| `build --parallel` | 资格检查成功后构建 Parallel，默认数量为 1 |
| `build --task-workers N` | 保留兼容行为：启用 Parallel，N 成为可覆盖的默认值 |
| 两个构建选项同时出现 | `--parallel --task-workers N` 合法；重复同一选项报错 |
| 构建时两个选项都不传 | 保持现有 Local 默认，不改变既有程序准入 |
| `run --parallel` | 以 1 worker 启动，与 `run --task-workers N` 共用资格检查 |
| `run` 的数量覆盖 | 显式 Parallel 时，参数 > 环境变量 > 1；环境变量不能单独启用 Parallel |
| 数量格式 | 仅接受十进制数字且值为 1–256；空值、符号、空白、溢出与越界均报错 |
| 未生效的低优先级值 | 不解析；有效显式参数可以覆盖环境中的错误值 |
| Local 程序收到 worker 参数或变量 | 明确报错，不忽略配置，也不切换执行模式 |
| 重复或缺值的启动参数 | 明确报错，在业务入口和线程池创建之前退出 |
| 初始化失败 | 报告失败并退出，不减少 worker 数量重试，也不回退 Local |

配置解析只在 `joky run` 执行路径及 CLI 生成的独立程序启动层生效。
`joky build` 不读取 `JOKY_TASK_WORKERS` 作为构建默认值，避免部署环境改变构建产物；
该变量也不影响 fmt、帮助等非执行操作。

首阶段只增加运行时配置参数，不扩展 Joky 的用户程序参数 API。生成入口须预留 argc/argv
传递边界，明确拒绝尚不支持的参数；未来应用参数与运行时参数的分隔规则另行设计。
项目清单暂不增加线程数配置字段，避免同时引入新的配置来源。

### 3.2 嵌入边界

保留 C ABI 的“无环境变量覆盖”契约。Rust/C 宿主仍显式传入配置，运行库不自行调用 getenv，
不受进程环境隐式影响。CLI 生成的启动层先解析并校验，再构造 `JokyExecutionConfigV1`。
现有公开入口生成 API 的兼容性须保留，CLI 的可配置启动行为通过明确的生成选项或独立入口开放，
不把 CLI 策略隐式施加到所有使用 `ParallelEntry` 的嵌入方。

worker 数量在任何业务调用前确定。同步 main 仍可使用 Local；Parallel 仍要求符合现有
无参数、返回 Unit 或 Int32 的挂起入口，不为配置数量额外放宽入口 ABI。

## 4. 并行能力的后续演进

启动时配置不依赖下面所有限制先被解除。能力扩展按独立阶段推进，不能为了统一接口而跳过证明。
现有能力细节统一引用[语言参考](language.md#任务执行模式)，不在本文复制完整支持表。

| 能力 | 后续方向 | 必须保持的边界 |
| --- | --- | --- |
| 捕获闭包与间接调用 | 对拥有捕获、具体目标和调用链建立证据；从无引用捕获开始 | 冻结代码与环境共同保活，未知目标不能只凭签名通过 |
| 自定义 Drop 的拥有值转移 | 检查析构调用图与线程能力，明确成功转移前后的唯一清理责任 | 取消、部分构造与转移失败均恰好清理一次 |
| 借用型 dyn | 先支持所属 worker 内具备目标证据的调用 | 不因此允许借用对象跨线程，不混入拥有型动态对象设计 |
| 引用、切片与游标跨 worker | 先研究结构化子任务内的有限借用，再决定是否开放 | 来源保活、别名排斥、子树清理屏障及取消路径全部成立；现有同 worker 路径仍保留 |
| 显式 Arena | 先评估在所属 worker 内使用的可行性 | 不默认开放 arena 或其中引用的跨 worker 共享 |
| Local VM／状态资源 | 复用控制代理和已存在的状态域授权机制，逐项补齐操作 | 不移动原始 Local owner，不把控制线程变成阻塞等待自身请求的调用者 |
| Godot／线程绑定宿主 | 通过宿主拥有的主线程消息桥执行，其他计算可进 worker 池 | 主线程归属、宿主退出、回调保活和取消由显式协议保障 |
| 自定义 extern | 保留明确的线程安全绑定契约并改善诊断 | 编译器不能自动证明任意外部代码安全；不允许用户普通声明伪造证据 |

`isolate` 内部子任务、含借用的静态 join/race 继续允许同 worker 协作执行。
“可使用任意合法 worker 数量”不承诺所有并发结构都产生跨核并行，也不改变结果顺序与竞争仲裁规则。

## 5. 实施阶段

W0–W2 已实现；W3 按 W3a／W3b 分步交付，W4–W6 继续作为后续路线。
开始前需针对相应类型或资源补充设计，不要求随启动配置一次交付。

| 阶段 | 内容 | 完成标准 |
| --- | --- | --- |
| W0（已实现）：配置接口与边界 | 固定第 3 节规则；区分构建资格、默认数量与启动覆盖；梳理公开入口生成 API 的兼容路径 | 选项、默认值、错误优先级和嵌入边界有一致测试；修正旧 TP 支持表的过期描述 |
| W1（已实现）：启动配置实现 | 新增 `--parallel`；在独立程序启动层解析参数／环境；接通单文件、项目包装与 `run` | 同一份 AOT 二进制以 1／3 worker 正确运行，数量实际生效，原生 ABI 不读取环境变量 |
| W2（已实现）：chat 与参考收尾 | chat 切换为构建一次、按启动配置运行；更新 README、语言参考、架构和帮助 | 搬迁、热更新、关闭与资源回收正常；记录针对性验证与一次默认 Debug 检查结果 |
| W3（分步实施）：拥有值和可调用资格 | 分步开放拥有捕获闭包与自定义 Drop 转移；改善间接调用拒绝原因 | 每项分别证明转移与清理责任，JIT／解释器／AOT 行为一致；不依赖开放跨线程借用 |
| W4：worker 内受限能力 | 研究借用 dyn、显式 Arena 的 worker 内使用，补充目标与生命周期证明 | 准入范围明确，同 worker 能力不隐式获得 Transfer／Share |
| W5：Local 资源桥接 | 按实际应用需求补齐 VM／状态操作；Godot 主线程桥单独设计与验收 | 资源仍由所属线程拥有，等待、取消与宿主退出无环路；不要求所有 Local API 自动开放 |
| W6：结构化跨 worker 借用 | 先完成可行性设计，再选择有限子集实施 | 普通与取消路径均证明子任务停止先于来源销毁；无法证明的用法继续拒绝 |

W3–W5 的优先级可按业务收益调整，W6 不阻塞前面阶段。
运行时动态扩缩容不列为本计划的后续阶段。

### W3a：拥有闭包输入（已实现并验收）

先开放无引用 move 环境在挂起帧中保留，以及同树拥有参数和 branch 移动捕获。
Fn／FnMut／FnOnce、包装记录和嵌套环境使用已有稳定存储；闭包精确目标及捕获树均须证明资格。
Rust TaskValue、宿主 ABI、闭包并发结果和跨 worker 借用不在范围内；自定义 Drop 捕获继续拒绝转移。
具体语法和当前边界见[语言参考](language.md#任务执行模式)，本阶段不新增闭包语法。

### W3b：自定义 Drop 转移（待实施）

不能通过移除 `has_custom_drop` 拒绝条件完成。当前 `Packet::capture` 在发送方执行剩余 cleanup，
`OwnedBuffer` 不接纳用户清理回调；解释器的回调还可能持有本地 Rc 和执行帧。
因此需要独立的析构转移协议，不能为这些本地状态直接实现 Send：

- 使用冻结模块内的受检析构入口和布局描述重建接收方清理，检查完整析构调用图及线程能力；
  不在包中放发送方帧指针、借用或本地回调对象。
- 明确准备中、已发布未安装、已安装、结果待领取各状态的唯一清理责任和交接时点。
  部分构造、安装失败、队列拒绝、取消以及 race 败者结果都必须恰好析构一次。
- 包在任意宿主线程释放时不能直接运行用户析构；设计由具备执行上下文的 worker 完成清理的路径，
  并把这项责任纳入子树终态和池关闭屏障，处理析构失败且保留冻结代码直到清理结束。
- 同时覆盖记录、枚举非激活变体的类型资格、容器元素清理和嵌套闭包捕获；
  JIT／解释器／AOT 共用协议，验证正常析构、失败与取消及预算最终归零。

W3a 验收不代表 W3 整体完成；W3b 在上述协议具备实现与行为证据之后才能更新支持表。

## 6. 验证策略

W1 首先运行针对性行为测试，W2 在最终代码状态运行一次默认 `./scripts/check.sh`。
若作为同一批交付，合并验证，不因阶段编号重复全量检查。默认使用 Debug，
不运行 Release、性能测量或无关穷举；本计划文档本身只检查内容、链接与 diff。

- AOT 用同一个编译产物分别启动 1／3 worker；用测试专用的运行时观测确认实际 worker 数量，
  不能只断言相同输出，也不通过耗时推断并行度。256 的上界解析测试不要求真的创建 256 个线程。
- 验证参数／环境／默认值优先级、非法值、重复值、Local 拒绝、默认兼容和错误发生前未进入业务。
- 对单文件与项目启动分别覆盖路由；项目覆盖从其他目录、搬迁后及符号链接启动，参数与资源根均正确。
- `run` 覆盖 JIT 与解释器；AOT 覆盖独立程序，不在多个测试层复制完整的配置组合矩阵。
- chat 的 Parallel 原生包构建一次，以 1／3 worker 分别运行协议、热更新与关闭场景，
  复用现有 Local／Parallel、host／script 后端矩阵，避免重复相同网络流程。
- 设置进程环境后，显式配置的嵌入入口仍使用宿主给定值；旧入口生成 API 保持原契约。
- W3–W6 按实际变更补充所有权、取消、目标保活与资源归属测试，涉及生命周期时再选择相关 Debug 穷举。

## 8. W0–W2 实施与验证记录

实现保持 `JokyExecutionConfigV1` 布局和运行库行为不变。新增
`ParallelEntry::standalone_driver_v1` 为 CLI 启动包装提供接收数量的受检 C 入口，
原 `standalone_main_v1` 继续采用显式固定数量且不读取环境变量。
项目入口先校验配置，再定位资源根并执行程序；不依赖 shell 转发。

2026-10-28，macOS 本机 Debug 验证通过：

- `cargo test startup_workers`：4 项通过，覆盖 Rust/C 数量解析一致性、配置优先级、
  JIT／解释器路由、项目搬迁与符号链接启动、Local 拒绝，以及非执行命令不读取配置。
  测试专用 CPS 回调记录线程身份，同一 AOT 产物在 1／3 worker 下实际使用相应数量的执行线程；
  旧生成器在设置环境变量后仍使用显式固定数量。上界 256 仅验证解析，不创建 256 个线程。
- `cargo test --test cli task_pool_cli_explicit_mode_and_standalone_driver`：1 项既有任务入口回归通过。
- `cargo test --test cli project_`：6 项项目相关测试通过，包含新的启动配置路由。
- `cargo test --test chat -- --ignored`：Local／Parallel 两个矩阵通过。
  每种脚本后端的 Parallel 原生包只构建一次，搬迁后分别以 1／3 worker 验证协议、热更新和关闭。
- `./scripts/check.sh`：仅运行一次，quick／Debug 完整通过；包括格式、全目标 Clippy、
  1731 项库测试、2 项生成启动入口测试、333 项 CLI 测试、其他默认集成测试和三后端短输入基准正确性。
  默认忽略项保持原规则，chat 已按上一项单独执行。
- 文档链接与 `git diff --check` 通过；最终只补验证记录，未重复运行代码检查。

未运行 Linux 实机、Release、性能测量或无关压力穷举。运行中动态扩缩容不属于交付范围。


## 9. W3a 实施与验证记录

开放无引用 move 闭包在挂起帧中存活，以及同树任务的拥有输入和 branch 捕获。
环境的精确目标纳入资格依赖，未调用的闭包也不能携带 Local 目标进入 worker。
捕获数据沿已有拥有包转移；恒空的 cleanup 身份使用私有布局版本 8，AOT 对象须与运行库一起重编。
公开执行器 ABI 不变，W3b 自定义 Drop 转移尚未实施。

2026-10-28，macOS 本机 Debug 验证：

- `cargo test parallel_owned_closures`：5 项 VM／前端测试、1 项独立 AOT 测试通过。
  覆盖 Fn／FnMut／FnOnce、零捕获、拥有数组、嵌套环境、包装记录、未调用丢弃、
  实参挂起和迭代器组合器跨挂起。Local／Parallel 的 JIT 与解释器均执行，
  同一 AOT 二进制分别以 1／3 worker 启动；测试回调直接记录跨 worker 线程身份。
- 任务准备后重载并释放 VM，原任务仍使用冻结目标；外部取消、race 败者和失败清理之后，
  等待池关闭并断言预算归零。Local 环境的自定义 Drop 在正常、失败和取消路径各执行一次，
  跨 worker 自定义 Drop 捕获与 Local 目标仍在准备时拒绝。
- `cargo test exhaustive_parallel_owned_closure_budget_failures -- --ignored` 通过；
  扫描准备、发布、安装及执行期间的预算失败，每次等待清理并检查最终归零，到首次完整成功停止。
- `./scripts/check.sh` 只启动一次：格式与 Clippy 通过；库测试 1735 项通过、1 项旧拒绝断言失败、
