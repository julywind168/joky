# Joky AOT 与 Script 热更新开发计划

状态：2026-10-12，设计草案，基线 `71f437a`。HR0–HR5 尚未开始。

目标是用 **Joky AOT 主程序承载服务，用动态加载的 Joky Script 定义可更新的业务状态与逻辑**。
服务端开发者不需要编写 Rust 宿主。AOT 与 Script 共用任务、状态域、取消和资源预算；
新模块先用于新实例，已有实例在明确的业务边界排空旧工作、迁移状态并切换版本。

Script 表示可动态加载的代码，可以由 JIT 或解释器执行，不限定为解释执行。
Rust 是编译器和运行时的实现语言，不是业务应用必须使用的宿主语言。

本计划负责模块契约、版本切换、实施顺序和验收。已有并发语义以
[服务端并发计划](server-concurrency.md)为准，已实现接口以
[语言文档](language.md#内置标准库-jokyvm)为准，已有代码与存储约束以
[架构文档](architecture.md#加载与代码所有权)为准。阶段落地后再更新相应能力说明。
本文类型名是概念名称，`text` 块不可执行；不提前冻结公开 API，不增加 `async` / `await` 关键字。

## 1 目标与首版范围

首版限定同一进程、同一单线程协作执行器。AOT 主程序管理服务启动、连接接入、资源额度、
模块部署和升级策略；Script 可以拥有独立长期状态并执行同步操作及挂起流程。
标准库可以驱动服务器，无需业务代码手写每一次 poll；显式驱动仍保留给客户端和特殊宿主。

热更新分成两个独立动作：发布模块版本改变新实例的默认绑定；升级实例改变某个现存实例的
代码与状态世代。发布新版本不会自动重绑旧实例、旧函数句柄或正在运行的任务。

首版不提供挂起栈迁移、运行时二进制自身热替换、跨线程或跨进程原子升级、崩溃恢复、
任意外部副作用回滚、透明请求重放或不可信脚本隔离。长期状态表示跨请求存活的内存，
不代表已经落盘。AOT 基础设施和接口的不兼容变更仍通过程序部署处理。

## 2 当前基础与缺口

| 范围 | 当前已具备 | 本计划需要增加 |
| --- | --- | --- |
| 语言侧动态加载 | `joky/vm` 创建、加载、重载和受限同步数值调用 | 有类型的模块绑定及共享调度的异步调用 |
| 代码寿命 | 不可变模块快照；continuation、实例根和域根保留所属代码 | 可检查的模块契约、版本驻留额度和完整世代保活诊断 |
| 调度与网络 | HostExecutor、定时器、外部唤醒、TCP 与 DNS | AOT 发起的脚本调用接入同一执行器、预算与取消树 |
| 状态与提交 | SC2 单域独立候选；SC3 最多 64 域的标量联合访问与原子发布 | 跨代码和状态类型版本的迁移、隐藏候选世代和服务入口发布 |
| 请求准入 | SC4-A 有界活动许可、FIFO 等待、关闭与取消归还 | 可暂停的服务入口、世代绑定、排空与升级互斥 |
| 生命周期 | 独立请求失败边界、域关闭、任务清理 | 稳定服务身份、世代任务登记及消息和订阅的升级规则 |

现有 SC2/SC3 候选仍受原域身份、类型和代码版本约束；`commit_set` 不是跨版本迁移接口。
普通持久实例能存放的类型也不自动获得候选提交或迁移资格。
现有 `joky/vm` 的同步调用和重载不等于已经完成 AOT 到 Script 的结构化异步桥。
SC4-A 的关闭是终态，不能把关闭一个 Pool 当作可恢复的准入暂停。

## 3 运行时对象与归属

| 概念对象 | 归属与用途 |
| --- | --- |
| Runtime | AOT 程序持有的运行环境，管理执行器、域登记、事件源与额度 |
| ModuleImage | 不可变模块及依赖快照，包含入口、类型、清理描述和执行后端 |
| Contract | AOT 与 Script 共同编译依据，声明接口身份、值类型、所有权和挂起约定 |
| ServiceOwner | 唯一服务关闭责任，管理稳定入口、准入策略与升级操作 |
| ServiceHandle | 可复制的非拥有稳定身份，通过受检入口申请工作，不暴露根地址 |
| ServiceGeneration | 一次服务世代，绑定模块、状态域集合、请求登记与订阅 |
| Upgrade | 唯一升级操作，拥有准备中的新世代和独立结果回执 |

```text
AOT application
  Runtime
    Executor / I/O / Timers / Budgets
    ServiceSlot
      Current generation
        Module image and dependencies
        Domain bundle
        Request registry and lifecycle scope
        Generation subscriptions
```

服务世代管理请求的生命周期，但不把全部独立请求放进同一个 fail-fast 组。
单个业务请求仍有自己的失败边界，关闭或升级协调者可以等待整组登记归零。
Service 是库层组织方式，不要求 Actor 邮箱，也不改变 World 或主循环的使用方式。

稳定服务 ID、世代序号、模块身份、接口版本、状态 schema 和业务修订各有职责。
世代及域身份不可复用；业务修订检查同一世代内的计算冲突。
现有 `ModuleId` 只在所属 VM 内有效，不能直接作为跨运行环境的全局类型或代码身份。

创建新世代必须创建新的受检域身份。旧域的方法和清理绑定保持不变，不能原地修改旧域类型。
稳定入口的切换不延长已关闭对象的访问权，复制 ServiceHandle 也不复制关闭责任。
世代私有域只能由已登记的服务工作访问，域句柄不通过公共契约向外导出。
已有外部访问者的共享域不能直接纳入封闭迁移集合；必须先证明所有访问都受升级入口管理。

## 4 模块契约与调用边界

接口契约作为独立编译输入，记录稳定接口身份、明确版本、入口名称、完整参数和返回类型、
移动或借用规则、同步或 `@suspends` 约定，以及需要的能力。
AOT 编译调用端，Script 编译实现端；加载时验证两者的描述，成功后得到类型化绑定。
首版要求接口版本和描述精确匹配，不按同名、字段数量或结构相似推断兼容。

运行时 ABI 版本、目标数据布局和接口语义分别校验。摘要可以加速查找，但不能替代完整描述
与名义身份核对。接口值的身份来自共同契约；模块私有状态仍带各自的版本身份。
新模块必须固定依赖快照，不能在每次函数调用或任务恢复时重新寻找最新依赖。

公开调用使用编译器生成的桥，不要求业务逐次传字符串函数名或把所有数据序列化为 JSON。
内部桥需要完整帧大小、入口与清理描述以及代码所有者；AOT 通过符号重定位连接运行时，
不能把编译进程地址写入对象文件。新描述和入口采用显式 ABI 版本，不改写已有 CPS 帧的含义。

HR1 首批参数和结果限定现有标量及无引用的平面标量记录，错误协议使用受检的运行时结果。
拥有型 String、Array 和稳定能力句柄逐类加入，必须先证明交接、失败清理与后端一致性。
首版边界不接受裸指针、私有根引用、视图、任意闭包或依赖旧局部帧的借用。
接口同步借用的开放另行验收，不能因本地调用合法就默认可跨模块挂起。

脚本访问 AOT 功能同样通过显式绑定的契约或已受检的标准能力；不得从任意整数恢复代码地址。
接口声明允许挂起时，反向调用也进入原有取消树与执行器。
业务 `Result` 拒绝、运行时失败和取消必须保持区别，不继续扩大以数值零表达调用失败的方式。

## 5 共享调度与调用所有权

AOT 到 Script 的异步调用是当前结构化任务中的受管调用。被调用方挂起后，外层任务也等待；
由同一执行器的事件和定时器恢复，不在调用内部启动第二个 block_on 或私有事件循环。
模块可拥有不同的编译环境，但执行时使用明确传入的同一 Runtime 上下文。
跨运行环境的句柄拒绝，不能通过放宽现有执行器身份检查实现共享。

一次调用在首次执行前固定模块、输入所有权、失败传播方式、预算和清理责任。
Pending 不重放参数求值、入口副作用或拥有值转移。取消先终止子调用和外部等待登记，
再清理帧与未交付结果；结果必须先进入独立的接收方存储，才可销毁调用临时 arena。
调用失败不发布半初始化结果；已交付结果只由接收方清理。

普通跨模块调用保持父任务的结构化失败规则；显式服务请求才建立独立请求失败边界。
共享调度不表示任意任务可以取得别的服务状态：域操作仍需类型、身份、能力与生命周期检查。
恢复脚本时必须安装正确的模块与任务环境，返回或取消时恢复外层环境。

模块保活覆盖 continuation、状态根、候选、快照、函数绑定、回调及结果清理描述。
最后一个业务任务结束不等于模块可以卸载。释放代码前必须完成仍可能调用该代码的清理。
长期状态使用独立存储，不依靠一个永不退出的脚本根任务维持寿命。

## 6 模块发布与请求版本绑定

准备模块只做解析、校验、编译和资源预留，不执行有外部副作用的业务初始化。
加载失败保留现有默认版本；准备成功后可显式发布为新实例的默认版本。
每个新服务实例捕获一次默认版本，构造中途不追随后续发布。

服务请求在准入成功时原子取得完整世代绑定与活动登记，然后才能执行。
入口前有界队列中的消息尚未绑定世代，恢复准入后可以由新版接收；已经受理的请求，包括
已排队但未执行的内部工作，均属于旧世代，必须参与排空。
准入失败不创建昂贵工作，暂停时采用明确的有界等待或拒绝策略，不无界积压。

任务恢复、域写入、提案提交和事件消费均校验世代有效性。旧任务不能通过再次查询稳定入口
取得新世代的写能力；跨服务调用可以申请目标服务的独立请求，但仍受目标准入控制。
服务内多个域从同一次世代绑定取得，不能分别解析入口而混合新旧域。

已完成请求的回执属于既成事实。升级不会把成功改成取消，也不能仅因回复带旧世代号就丢弃
一个已经提交请求的应答。世代检查阻止迟到工作产生新写入，不抹除历史结果。

## 7 单实例升级协议

默认策略是等待已受理请求自然完成；需要取消旧业务时由调用者显式选择策略。
持续 tick 在业务定义的边界停止产生新 tick，当前 tick 和已受理子工作仍需完成。
首版同一服务最多一个升级操作，关闭优先于尚未发布的升级。

### 7.1 准备与暂停

先校验新模块、接口、迁移路径和预算，再暂停实例的新请求受理与周期性工作产生。
暂停不关闭稳定连接，也不阻断旧请求需要的网络回复或定时唤醒。
新世代的业务初始化不得在候选准备期间自行启动后台任务。

暂停须可恢复：保留旧 tick、长期订阅的登记、必要资源和恢复额度，只关闭其产生新业务工作的
入口，不通过不可逆关闭资源实现暂停。暂停期间的事件采用明确的有界保存、合并或拒绝策略；
恢复时按登记策略处理，不自动重放全部错过的 tick。不能保证恢复的订阅类型先拒绝升级。

已受理请求可以完成其正常的结构化后代；后代必须在父请求结束前加入登记并汇合，
不得逃逸或转为新独立请求。协调者停止独立新工作的产生，在全部登记归零后冻结旧世代的
业务执行入口；冻结可恢复，与终态关闭分开。
如果旧请求等待本服务新的独立准入而不能完成，排空超时应失败，而不是破例绕过暂停。

### 7.2 排空与基线

排空条件包括请求、子任务、域访问和提交登记结束，取消清理完成，所属请求的外部等待注销，
以及长期订阅已静默且无业务回调在途；长期订阅的恢复登记可以继续存活。
已完成但尚未领取的结果可独立保留，其代码所有者继续保活。
不能只观察正在运行的任务数为零：等待网络的任务、排队提交和可重入回调同样属于旧工作。

排空超时默认放弃升级，在同一次恢复转换中恢复健康旧世代的准入、tick 与长期订阅，
不得重复登记；仍在执行的旧请求继续原生命周期。
显式选择取消策略时，取消并不撤销已发出的网络或数据库操作；只有清理结束后才取得迁移基线。
旧域已 Failed、服务已 Closing 或资源已不可恢复时，不得以升级失败为由重新开放。

协作式执行的超时只能在运行时重新取得控制时观察，不能保证抢占不让出的原生循环。
需要硬耗时界限的操作须有受检工作上限或执行安全点；不能用轮询次数冒充时间保证。

### 7.3 迁移与候选世代

迁移读取冻结的旧状态，构造独立的新根。旧 schema 的受检只读视图由编译器生成，
迁移实现同时依据归档的旧 schema 和新类型编译；不重新解释旧内存为新类型。
首版要求显式迁移函数，即使 schema 相同也不直接重绑旧根的代码和析构描述。

迁移只允许受检状态读取、纯计算及候选分配，不允许挂起、网络、数据库写入、任意外部调用、
旧状态修改、用户 Drop 或新业务任务启动。HR3 先限制为平面标量记录与编译器可证明有界的
字段转换，拒绝用户循环和递归；HR4 再开放受限拥有字段迁移并验证复制预算与安全点。

旧根始终保持唯一原所有者。候选根使用独立 arena，准备失败只清理已初始化的新值。
新域、世代登记、必要的任务元数据和资源绑定在发布前全部准备好，但不对业务暴露。
候选句柄不可逃逸，也不能用于提前访问尚未发布的状态。

### 7.4 发布与退休

发布前重新检查服务仍暂停且健康、旧世代一致、升级未取消、期限和预算有效，并验证完整
迁移读取集合。首版只允许声明的封闭状态集合，拒绝集合外的可变状态访问。
后续若开放额外只读依赖，也必须在发布前验证其完整凭据，变化则使整次升级失败。

发布在同一执行器的一个不可挂起区间内完成：替换服务槽位中的完整世代绑定，记录终态回执，
撤销旧世代业务访问权。区间内只做预先准备的移动和标量更新，不运行用户代码、析构或可能失败的分配。
旧订阅的终态注销及旧根和旧代码的清理在发布后执行，清理错误单独报告，
不把已成功发布的事实改为未发布。
撤销业务权限不禁止退休清理和独立回执读取；这些路径不能再提交业务工作。

恢复准入后，新工作只绑定新世代。需要执行的新版启动逻辑属于发布后的普通受管工作；
其失败按服务失败协议处理，不能假称新世代从未发布。
发布前失败恢复仍健康旧世代的准入和周期工作；排空期间已经完成的正常业务写入仍然保留，
不回滚到暂停前。发布后回退须走另一轮兼容迁移，不能直接恢复旧指针。

升级调用者取消若先于发布，则销毁候选并按旧服务状态恢复；若发生在发布之后，则只影响
等待与领取，不撤销发布。升级回执独立于等待任务，允许查询发布是否已经发生。

## 8 连接与跨世代消息

| 对象 | 首版升级规则 |
| --- | --- |
| 监听器、TCP 连接及接入缓冲 | AOT 基础设施持有唯一资源所有权，服务通过受检能力使用；升级不默认断线 |
| 稳定入口的待受理消息 | 使用共同接口契约并有界保存；尚未绑定世代的消息按恢复后的入口受理 |
| 世代内部 Channel 与单次应答 | 按所属请求排空或取消，不把私有消息布局直接交给新模块 |
| 旧代码回调、tick 和订阅 | 暂停并保留恢复登记；失败则恢复，发布后终态注销；新版按明确策略登记 |
| 已在途外部请求 | 保留请求 ID 和结果归属；迟到结果不能写新状态，已完成应答不因升级丢失 |
| 独占外部资源 | 不进入普通数据迁移；将来若允许转移，必须单独提供预留、发布和失败归还协议 |

首版稳定连接由独立请求层调用，通过共同契约交付数据；不要求迁移函数持有 socket。
受检能力必须包含所属运行环境、服务权限和有效期，不能仅凭可复制整数授予新世代访问。
保留跨世代 Channel 的积压消息需要独立消息契约及兼容性检查，SC4 的通用 Channel 本身不提供升级协议。

外部效果不在内存原子发布范围内。可能重复执行的业务使用幂等键、结果去重或补偿；
运行时不在升级失败后自动重发业务请求，也不承诺网络 exactly-once。

## 9 预算与诊断

升级同时保留旧状态、新候选和必要中间值，按实际峰值计费，不能只检查新根大小。
候选字节、请求记录、入口等待、模块版本驻留和待清理资源分别设限。
编译代码与元数据的额度独立于已有 arena 逻辑额度，不将逻辑字节数宣称为进程 RSS 上限。
排空和迁移使用独立期限；所有期限仍受第 7 节的协作执行边界约束。

诊断至少区分接口不兼容、状态 schema 不匹配、正在升级、排空超时、迁移失败、
资源超限、服务关闭、取消与发布后清理失败。提供当前模块、服务世代、升级阶段、
未排空登记和旧版本保留原因。返回新世代身份的成功回执不可被迟到控制事件改写。

## 10 分阶段实施与验收

| 阶段 | 交付范围 | 关键验收 |
| --- | --- | --- |
| HR0 契约决策与异步桥探针 | 冻结首批值类型、错误和所有权协议；验证 AOT 加载 Script 并共享执行器上下文 | 脚本多次挂起期间 AOT 其他任务推进；取消清理一次；加载失败保留旧入口；旧调用继续原代码 |
| HR1 有类型的异步模块调用 | 语言侧受检绑定、参数和结果桥、预算与结构化取消；首批标量和平面标量记录 | 拒绝错误接口、签名、运行环境和借用；覆盖成功、失败、Pending、取消及结果交接 |
| HR2 服务世代共存 | 稳定入口、唯一关闭责任、世代登记、模块默认版本和有界准入暂停 | 新实例用 v2，旧实例继续 v1；请求在受理时固定版本；旧结果不能获得新域权限；关闭与发布排序明确 |
| HR3 单域实例升级 | 单个平面标量域，显式有界迁移，排空、隐藏候选、世代发布与独立回执 | schema 变化保留业务数据；排空超时或任一发布前故障保留健康旧服务；迟到取消不撤销已发布升级 |
| HR4 封闭多域与拥有状态迁移 | 同一服务世代内显式声明的完整域集合；逐类开放 String 和标量 Array | 任一候选失败不发布；不能观察混合世代；完整读取凭据、峰值额度和逐阶段清理正确 |
| HR5 服务器联合验收 | 纯 Joky AOT 接入连接，Script 处理房间与 tick，发布与迁移覆盖真实请求生命周期 | 连接保持、新旧房间共存、积压有界、故障恢复、版本退役及资源基线恢复 |

HR0 先跑独立链接的 AOT 主程序，分别加载 JIT 和解释器 Script；必要的 Rust 探针只能补充
内部计数与故障注入，不能代替纯 Joky 入口验收。探针无法共享调度与身份检查时先调整设计，
不以第二个事件循环绕过问题，也不先扩大公开语法。

HR1 还要覆盖 JIT、解释器作为调用端时的同一语言语义；涉及反向 AOT 能力调用的入口覆盖
成功、挂起和取消。不同后端不能依赖对方拥有原生函数指针。
纯值桥打通之后，HR2 补齐服务句柄和受检能力绑定，HR4 补齐相应拥有值交接；
均按独立切片验收，不默认开放全部持久类型，HR5 开始前完成实际示例所用的消息类型桥。

HR2 的暂停是新的服务入口协议，复用 SC4-A 配额但不改变 Pool.close 的终态含义。
HR3 不依赖任意拥有图或挂起栈迁移。HR4 的域数量上限需按新迁移描述与预算重新验收，
不自动继承 SC3 的 64 域结论；跨服务联合升级留待独立方案。

SC4-B Channel／单次应答及后续生命周期联动继续按服务端并发计划推进。HR0 的窄异步探针
不必等待完整 Channel；需要拥有消息和稳定请求入口的集成依赖相应 SC4 切片。
SC5 的普通业务验收与 HR5 的升级验收分别记录，不能互相代替。

## 11 行为测试与故障矩阵

| 场景 | 必须观察到的行为 |
| --- | --- |
| 旧脚本在网络等待期间发布新模块 | 旧请求按原版本恢复，不重放入口；新实例绑定新版 |
| AOT 和 Script 交替挂起 | 共用调度与预算；外层取消停止完整子调用链，没有内部忙轮询 |
| 受理与暂停发生在相邻调度边界 | 请求完整归入旧世代或保持未受理，不能半登记 |
| 排空时旧请求等待外部回复 | 回复仍可到达；超时不伪造已完成清理 |
| 暂停后超时或迁移失败 | 健康旧服务恢复准入、tick 和订阅，无重复登记；暂停期间的事件按原策略处理 |
| 迁移中任一分配或校验点失败 | 候选按初始化进度清理，旧根、代码和稳定连接保持有效 |
| 关闭、取消与发布竞争 | 终态只有一个；发布前关闭阻止切换，发布后关闭作用于新当前世代 |
| 旧 token、回调或候选在切换后到达 | 拒绝新写入；已完成回执仍可读取；不因 ID 重用落到新对象 |
| 多域迁移任一成员失败 | 所有服务内访问仍观察旧世代；没有部分新根可见 |
| 新状态含 String 或 Array | 移动、复制、失败和取消的唯一清理责任明确，峰值计费可回收 |
| 旧根、结果或回调仍依赖旧模块 | 模块暂不卸载，诊断指出保留原因；最后依赖释放后退休 |
| 更新期间真实连接持续收发 | 接入背压有界；已受理请求不被静默重试，未受理消息按策略等待或拒绝 |

取消穷举覆盖参数接管、首次挂起、结果交接、迁移准备、发布前最后校验和发布后的等待取消。
成功、失败、关闭和取消分别记录状态、回执、任务数、域登记、等待注册与相关逻辑字节，
完成后恢复允许的资源基线。清理探针还需覆盖重入，不能在回调或 stop 期间保留冲突借用。

代码实现按 [AGENTS.md](../AGENTS.md#按改动范围验证)运行针对性生成代码测试、默认 Debug
检查及受影响的 Debug 穷举；不因阶段结束自动运行 Release 或无关压力测试。
独立 AOT 验收需要实际链接并运行可执行文件，编译成功或 Rust API 测试不算完成该项。

## 12 开始 HR0 前的决策清单

HR0 需要产出首批契约描述、异步桥所有权表、取消与结果交接状态机，以及运行环境身份的
注入路径。公开模块名、绑定语法、接口版本编码和错误类型在探针证明可行后冻结。
迁移 API、schema 描述以及资源能力扩展保持分阶段设计，不能借由一个通用 opaque 参数提前开放。

首个可运行验收程序只有一条主线：AOT 加载 v1 Script，发起会挂起的请求；等待期间加载 v2，
另一个 AOT 任务继续推进；旧请求按 v1 完成，新调用显式绑定 v2；再覆盖取消、失败加载和清理。
该程序通过后才开始 HR1 的公开接口实现，不把既有旧模块保活回归当作本计划已经完成。
