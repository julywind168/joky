# Joky AOT 与 Script 热更新开发计划

状态：2026-10-13，设计草案。HR0 已补齐 Rust 宿主代码发布的多域执行前检查、完整读取凭据
与版本耗尽保护（JIT 与解释器）。HR2 标量异步探针已实现：独立 Joky AOT 可加载 JIT/解释器
Script，共享执行器并发布兼容域代码。HR1 已扩展嵌套记录与 Array/Map 拥有图；
HR2 已完成标量与平面记录的类型化入口契约；HR3-A 出站信箱与 HR3-B 域目录已实现；HR4 显式具名定时调用已实现；HR5-A 单域标量迁移已实现，HR5-B1 同步拥有图迁移已实现，HR5-B2 分步调度、HR5-C 与 HR6–HR7 待做。

目标是用 **Joky AOT 主程序承载服务，用动态加载的 Joky Script 定义可热更新的业务逻辑**。
服务端开发者不需要编写 Rust 宿主。Script 表示可动态加载的代码单元，可以由 JIT 或解释器
执行，将来也可以是预先编译的原生补丁；热更新语义不依赖具体后端。

本计划负责热更新的语义、能力缺口、实施顺序和验收。并发与状态域的基础语义以
[服务端并发计划](server-concurrency.md)为准，已实现接口以 [语言文档](language.md)为准，
代码与存储不变量以 [架构文档](architecture.md#状态域核心)为准。
本文 `text` 块不可执行，未实现部分的类型名和入口名是概念名称，不提前冻结公开 API。

## 1 核心原则

**状态是数据，具名域操作在每次执行时绑定当前代码，流程按启动时的版本跑完。**

1. 长期可变状态只放在状态域中。域操作是同步、不挂起、不调用宿主的 `fn(&S) -> R` 或
   `fn(&mut S, A) -> R`，操作之间没有业务代码持有状态引用，因此每两次操作之间都是
   天然的静止点。结构与业务契约均兼容的代码更新不要求排空请求。
2. 域操作按名字和签名晚绑定：发布新代码后，下一次调用就执行新实现。
   房间 tick、结算、道具使用等大部分游戏逻辑属于这一层。多域操作的完整晚绑定仍待实现，
   在此之前遇到代码版本变化必须拒绝执行；已计算的候选必须重新验证读取凭据。
3. 挂起流程（等待网络、数据库、定时器的 `@suspends` 代码）可以保存句柄、拥有值和快照，
   不持有域状态的借用；流程在启动时固定自己的代码，跑完后旧代码自然退役。不迁移挂起栈。
   内联 `when` 块也属于流程代码，其版本约束见第 8 节，不能自动获得具名操作的晚绑定语义。
4. 流程的生命周期必须有界。长时间等待改用"状态中的到期时间 + 按名字触发的域操作"，
   不能用一个常驻循环或长时间 sleep 把旧代码钉住。
5. AOT 主程序只放稳定内核：运行时、网络、调度、准入、域目录和性能敏感的库。
   AOT 与 Script 之间只有少量通用入口，业务协议在 Script 侧分发，新增协议不需要重新部署 AOT。

## 2 分层与更新方式

| 层 | 内容 | 更新方式 | 停顿 |
| --- | --- | --- | --- |
| 配置 | 数值表、活动配置 | 不可变快照，请求开始时绑定 | 无 |
| 域操作 | tick、结算、道具、技能逻辑 | 发布代码，下一次调用起生效 | 一次调用的间隔 |
| 状态 schema | 玩家、房间、公会等记录的字段结构 | 独立构造全部候选，完整验证后原子发布 | 同步迁移占用执行器；冻结准备窗口需单独计费 |
| 流程 | 等待外部结果的多步请求 | 按启动时的版本跑完，不迁移 | 无 |
| AOT 内核 | 网络、调度、目录、稳定库 | 重新部署进程 | 进程重启 |

只改逻辑且保持业务契约兼容的热修复只需第二层，不复制状态。重新发布旧代码只恢复代码绑定，
不会撤销新逻辑已经写入的数据；旧代码是否还能处理这些数据需要独立验证。
布局相同不等于业务不变量兼容，破坏业务契约的更新可能仍需暂停准入、排空相关流程或迁移。
状态结构变化进入第 4 节的显式迁移。

## 3 代码发布（HR0，已实现）

当前由 Rust 宿主 API 提供，已有 JIT 与解释器的发布和版本冲突测试；范围不包含后续迁移与信箱。
HR2 标量探针与类型化平面记录入口已接入语言侧与 AOT。

```text
vm.load_source(v2)          // 只影响之后新建的域
vm.publish_domain_code()    // 把结构兼容的现有域切到当前模块，返回切换数量
```

### 3.1 结构兼容

记录类型每次加载都会分配新的名义 id，因此跨版本的状态类型身份按结构判断：同名，
字段名、可见性、标量槽偏移逐一相同，字段类型递归兼容；非记录类型要求相等。
兼容只证明同一份根存储可以被新代码按相同布局读写，不推断业务语义是否一致。

### 3.2 发布协议

1. 收集新模块中合格的状态类型（受检构造函数的返回类型和受检操作的接收者类型）。
2. 遍历存活且健康的域；同名记录结构变化时整次发布失败，返回 `TypeMismatch`，所有域保持原样。
   新模块未声明的类型对应的域留在原代码上。
3. 发布前检查所有待切换域的代码版本余量，任一耗尽则整体返回 `ResourceLimit`，版本不回绕。
   校验完成后只做移动和标量更新：替换域的模块与类型，并递增该域的代码版本号；
   根存储、修订号、身份和句柄不变，修订号也不因发布推进。
4. 释放注册表借用之后再丢弃旧模块引用；旧代码在最后一个持有者释放后退役。

### 3.3 调用侧规则

- 调用方用自己模块中的签名编码输入、解码结果。源码 `domain.read/write/request` 在准入时
  检查调用方签名与域当前代码的签名兼容，然后执行域当前的代码；不兼容时直接调用返回
  `TypeMismatch`，`request` 返回 `InvalidAccess`。
- 请求任务记录自己运行的模块。旧流程在发布后调用 `domain.write(op, x)`，会用旧签名
  对新实现做兼容检查，兼容则执行新实现。
- 发布前已经排队的单域调用，执行时若发现代码版本变化，会重新解析操作并核对签名；
  签名不兼容只让这一次调用失败，域保持健康。旧编码的输入不会进入新代码。
- 已加载但未发布时，新代码调用结构兼容的旧域会执行旧域当前的代码。
- 当前限制：pair 操作的登记、候选的写域等路径仍有同模块约束，尚不支持完整的跨版本多域调用。
  已排队的 pair/access 在执行前检查全部参与域的模块与代码版本，发生变化以 `InvalidCall`
  拒绝，所有根和修订保持不变，域仍可用。读取凭据的代码变化按 `Conflict` 处理；候选写域
  自身已换模块时仍由原有同模块检查返回 `InvalidAccess`。

### 3.4 HR0 版本校验

- 已排队的多域操作在执行前验证全部参与域的代码绑定。完整晚绑定完成前，任一绑定变化就
  拒绝该操作且不修改状态，不允许继续执行捕获的旧模块。不能只在登记时检查。
- 单域及联合快照的每项读取凭据除身份、生命周期和修订号外，还捕获并验证代码版本；凭据
  在操作执行时保存，领取结果时不重新采样。HR5-A 已纳入 schema 身份。仅发布只读依赖的新代码，也必须使旧候选失效。
- 候选计算已经发生，提交时不能靠重新解析操作名使旧计算变成新计算。任一读取依赖失效就
  拒绝整个提交集合，由业务显式重新读取和计算；不透明重放可能包含外部效果的流程。
- 验收至少覆盖：排队 pair 后发布、仅更新只读第四域、联合快照后发布再提交、无发布时正常
  提交。所有失败均须在任何根写入或替换之前确定。

### 3.5 HR1 域根拥有类型（已实现）

域根支持嵌套记录、`Array<Record>`、`Map<K, Record>`，元素可继续拥有 String、数组、
Map 与元组。类型资格、深度边界及未开放类型见[语言参考](language.md#rust-宿主状态域)。
域操作仍需编译器证明同步、无宿主/间接调用、无用户清理回调；空容器也检查完整元素类型。

构造和候选各自拥有独立 arena，短操作后只保留可达拥有图；提交移动整个候选，旧根、
冲突候选、未提交候选和关闭时的根各有唯一释放路径。快照仍是标量投影与完整版本凭据，
不深拷贝整个拥有图；多域访问、联合快照和集合提交仍保持原有标量根边界。
兼容发布递归校验容器元素的 schema，旧存储可由新代码继续访问；不兼容布局仍需 HR5。

房间 Map、元组与非拥有枚举；验证快照后独立构造、提交、冲突、容器元素替换和关闭。
运行时回归另外检查重复操作/提交后预算回归、只读与写入分配失败、兼容发布及深层 schema
变化拒绝；同样覆盖 String 键 Map 和部分状态替换后失败的隔离清理。

## 4 状态迁移（HR5）

以下是完整 HR5 的目标协议，HR5-A/B1 已实现范围见第 4.1–4.2 节。

状态结构变化时，新版本声明显式迁移函数，例如 `migrate(old: &v1.Room) -> Room`。
旧类型由编译器根据归档的旧 schema 生成只读视图，迁移按旧 schema 和新类型共同编译，
不把旧内存重新解释为新类型。迁移只允许受检读取、纯计算和候选分配，不允许挂起、宿主调用、
修改旧状态或启动任务。

迁移借鉴现有快照、独立候选和集合提交协议；现有 `commit_set` 尚不支持跨 schema 根替换。
以需要原子更新的完整访问集合为一批，目标协议如下：

1. 准备阶段捕获旧根快照及全部读取依赖的修订、代码版本和 schema 身份，在独立 arena 中
   构造所有新根。分配、迁移用户代码及所有可能失败的预检均在这一阶段完成。
2. 准备期间允许旧代码继续服务。最终校验发现任一依赖变化时，丢弃或重建受影响候选并重新
   校验完整集合；重试有明确预算。必要时可冻结相关访问集合后完成准备，但冻结窗口与最终
   发布区间分开计费，不能先发布部分根再迁移剩余根。
3. 最终完整验证与发布之间不得交错任何域操作、关闭或代码更新。验证通过后，发布区间内仅做
   不会失败的所有权移动和标量更新，一起替换根、类型与代码；不分配、不调用用户迁移代码。
   旧根和旧模块的释放在发布区间之外进行。
4. 发布前任一失败或可观察到的超时使整批作废，按初始化进度清理候选，保留发布前的根和绑定。
   这不撤销准备期间正常业务已经完成的写入。

迁移可以分步调度，但单线程执行器上的每次同步迁移都会占用整个执行器，不能称为后台无停顿
或只暂停一个域。预算只能在重新取得控制时检查，不能强制中断不让出的迁移代码。
峰值计费包括旧根、候选、快照及迁移临时存储；大规模状态可分批，但分批不提供跨批原子性，
新旧版本并存必须在发布报告中可见。发布后的回退是另一轮经过验证的迁移，不直接恢复旧指针；
仅切回旧代码也必须满足第 2 节的业务兼容条件。

### 4.1 HR5-A 单域平面标量迁移（已实现）

当前入口是 `vm.domain_schema`、`vm.prepare_migration`、`vm.publish_migration` 和
`vm.cancel_migration`，精确签名及生命周期见[语言文档](language.md#内置标准库-jokyvm)。
运行时根据存活域的 Type 生成 `PreviousState`，业务编写 `fn upgrade(old: &PreviousState) -> Room`；
无需手工复制旧布局。HR5-A 首版限定平面标量，HR5-B1 已扩展拥有图（第 4.2 节）；根必须同名且 schema 变化。旧 schema 令牌只在
当前进程内有效，尚无持久化 schema 归档、命名空间导入或 `migrate ... from ...` 语法糖。

准备阶段暂存编译模块并在独立 arena 中运行受证明的迁移，当前 Script 入口和域保持不变。
发布验证完整凭据、Script 当前绑定及唯一域选择后，一起替换根、类型、代码与当前入口，
随后在发布区间外清理旧资源。域目录保持原身份，旧目标定时器被取消并标记 InvalidAccess。
中间写入、关闭、代码/schema 变化、新增第二域、计数耗尽均拒绝发布；不自动重试。
仅选择该 Script 恰好一个存活域，避免新入口面对同一脚本部分迁移的状态。

候选由 VM 句柄持有，最多一个；显式取消或关闭 VM 释放候选。取消发起任务不自动关闭共享
句柄。旧根、新根和候选元数据同时受状态预算约束；编译/迁移仍是同步操作，不提供强制超时。
默认迁移测试覆盖 JIT/解释器核心与 JIT/解释器/AOT 宿主 × 两种 Script 后端；取消穷举覆盖
准备后持有候选及发布后的清理。拥有图复制由 HR5-B1 实现，分步迁移由 HR5-B2 实现（第 4.3 节），多域全批校验与原子切换归 HR5-C。

211 个 CLI 测试、模块测试及三后端 while/Map 短输入正确性）。另运行

### 4.2 HR5-B1 同步拥有图迁移（已实现）

沿用 HR5-A 的 prepare/publish/cancel API，扩展为 String、嵌套记录、Array/Map、元组与
Copy 枚举组成的有限状态图。编译时固化容器元素定义，准备时据此生成完整旧视图；业务只读
借用旧图并显式重建新图，不能转移旧容器或保留旧借用。标准库容器复用受检读取接口，嵌套
用户类型提供 `PreviousPlayer` 等数据视图，命名与限制见[语言文档](language.md#内置标准库-jokyvm)。

准备错误、分配/指令预算耗尽、候选取消、发布冲突都清理新图并保留旧图；关闭旧域后即使候选
仍存活，也不能再发布。候选不依赖旧根存储，发布后旧图完全退役。旧根、新根和临时分配共享
状态预算。尚不支持外部资源、用户 Drop、递归拥有图或拥有载荷枚举，也不自动复制业务对象。

这一阶段仍同步准备整个候选。HR5-B2 的显式分步推进见第 4.3 节；不能把同步回调称作可抢占迁移。
HR5-C 多域联合迁移的发布协议不在本次范围内。

### 4.3 HR5-B2 宿主驱动分步迁移（已实现）

新增 `vm.begin_migration` 与 `vm.step_migration`，复用已有 publish/cancel。start 建立候选骨架，
advance 按业务解释的 UInt64 工作量提示构造下一批，进度保存在候选里。宿主可以在批次之间
让出、处理网络或查询旧域；最后完成标志与完整凭据同时满足才允许原子发布。返回码、精确
签名和错误消费规则见[语言文档](language.md#内置标准库-jokyvm)。

本阶段选择乐观验证：不额外复制并保活旧版本快照，每批在验证最初捕获的读取凭据后，短暂
借用当前旧根。旧根在批次间写入、关闭、换代码或换 schema，下一批就拒绝并清理整个候选，
不会混用不同修订。最终发布再次验证；没有自动重试或冻结协议，忙碌域可由业务暂缓写入后重建。
这避免了初始化时先同步复制整个旧图，也使每次返回宿主时不保留旧根借用。

候选由 VM 句柄持有；cancel/close 释放已构造的各批，发起任务取消不隐式关闭共享句柄。
未完成就 publish 会拒绝并消费候选。单批失败，包括临时分配失败与解释器指令限额耗尽，
回收整个新图并保留旧状态。独立 arena、峰值状态预算和单域选择限制沿用 B1。

这是协作式分批构建：编译、start、advance、图扫描及回收仍同步执行，budget 无法强制限制
回调耗时，图扫描成本也随候选增长。后台编译、旧版本快照隔离、任务所有的迁移作用域与硬
时间片均未实现；多域全批迁移归 HR5-C。下一阶段不能将这些边界视为已有能力。

## 5 流程、定时与 tick（HR4，显式原语已实现）

提供 `domain.timer()` 所有者、可跨 HR2 传递的 TimerHandle，以及 `domain.after` / `domain.every`。
AOT 可以持有所有者，由 Script 用句柄登记具名同步写操作 `fn(&mut S, A) -> Unit`；A 限定标量。
定时器保存操作名、类型契约与输入，不持有域根、业务闭包或 Script 模块。每次到期都是独立域调用，
兼容发布后使用当前实现，排队期间发布也会在执行前重新绑定。旧模块不因定时器而延迟退役。

周期以登记时的单调时钟节拍为准，每个定时器最多一个在途调用；完成后跳过错过的节拍，不追赶
积压，不重叠执行。一次性 0 延迟仍经队列。所有者析构/显式取消移除尚未开始的调用；域关闭、
隔离和执行器关闭停止相关定时器；已经开始的同步操作运行到结束。登记和待处理请求有预算上限，
签名变化、配额不足与执行失败给出可观察终态，不自动重试。

API 与状态机见[语言参考](language.md#定时域调用-jokydomain)，所有权和发布不变量见
[架构说明](architecture.md#具名定时域调用)。定时器不是候选事务的一部分，普通 tick 写入不自动
发布出站消息；状态和消息原子发布仍需现有候选提交协议。

验收覆盖手动时钟推进、周期跳过、排队后发布、旧模块退役、签名变化、关闭/取消、时钟回调重入、
失败隔离与配额回收；语言 fixture 覆盖 JIT/解释器/AOT，跨边界测试覆盖三种宿主与两种 Script 后端。
逐指令取消穷举检查任务、请求、共享预算与 arena 回归。

## 6 AOT 与 Script 边界（HR2）

- AOT 主程序拥有执行器、网络资源、准入池和域目录，通过标准库加载 Script 并触发发布；
  Script 的任务、域操作和定时器进入同一执行器，不启动第二个事件循环。
- AOT 与 Script 之间只暴露少量稳定的通用入口，如连接建立、消息到达、tick 和管理指令；
  业务消息的类型注册与分发在 Script 侧完成。入口签名变化才需要重新部署 AOT。
- 入口参数与结果先限定为标量和平面记录，拥有型载荷随域根类型扩展逐类开放。
  不接受裸指针、私有根引用、闭包或跨模块挂起的借用。
- HR2 标量探针复用 `joky/vm`，已把异步调用和按 Script 模块归属的发布接入同一执行器；
  类型化入口契约与平面记录桥接现由 `joky/script.call<A, R>` 提供。
- HR2 先做标量异步探针：AOT 启动 Script 流程，流程挂起时另一任务继续推进，加载并发布 v2，
  旧流程按原代码恢复后通过兼容的具名域操作调用新实现。取消与结果清理也必须跨边界闭合。
  此探针不依赖 HR1 的复杂拥有类型，应在 HR0 安全补齐后优先验证。

### 6.1 HR2 标量异步探针（已实现）

已提供 `vm.call_async_int32(handle, name: String, input: Int32) @suspends -> Int32`，
目标必须是 `fn(Int32) @suspends -> Int32`；名称按值传入，目标签名在执行用户代码前校验。
`vm.publish_domain_code(handle)` 在该句柄绑定的当前执行器上发布，只选取该句柄所加载模块
拥有的域，返回切换数量，失败返回 -1。详细错误约定见[语言参考](language.md#内置标准库-jokyvm)。

每次调用的 continuation 由调用帧拥有，复用宿主执行器的时钟、唤醒与域注册表；不建立第二个
轮询循环，也不递归驱动执行器。等待时释放 VM 借用，AOT 的并行分支可继续工作并加载 v2。
调用已启动时固定模块，新调用解析当前模块；域操作仍遵循 HR0 的逐次兼容检查。
父任务取消会清理整个子流程；关闭 VM 会使未结束调用失效并唤醒，在下一次推进或取消时清理。
已有 `vm.Handle` 仍要求显式 `close`，取消调用不自动关闭可供其他调用共享的 VM。

AOT 分别调用两种 Script 后端；AOT 在删除源码、清空 PATH 后仍可运行。运行时测试另覆盖
同名状态的模块归属隔离、跨执行器拒绝、关闭、运行失败、签名错误及取消时的资源回收。

### 6.2 HR2 类型化入口（已实现）

`joky/script.call<A, R>(handle, name, input) @suspends -> R` 提供一个输入和一个结果的
稳定入口；A/R 各自可为任意标量或最多 64 个标量字段的平面记录，包括 Unit 和空记录。
当前业务可使用 AOT 侧声明的请求/响应记录调用 Script 中同名同字段契约，不依赖两次编译
产生相同的内部类型 ID。完整支持范围和用法见[语言参考](language.md#类型化-script-入口-jokyscript)。

调用方先检查类型资格，运行时再比较目标的挂起属性、参数数量和输入/输出 schema；记录名、
字段名、顺序、类型、可见性及 repr(C) 属性均参与校验。缺失或不兼容入口在执行任何目标
业务代码前拒绝。桥接包只携带有界标量副本，完成、失败、关闭和父级取消均沿同一清理链回收。
不把调用方记录或状态域地址交给 Script。旧流程保留启动模块、新调用解析当前模块、域代码

## 7 通信与组织方式

| 能力 | 结论 |
| --- | --- |
| 出站信箱（HR3-A，已实现） | 有界字节批次附加到候选提交；成功后与状态一起可见。首版只提供满队列或目标关闭时整次拒绝，写出任务只搬运字节；合并/丢弃策略待具体场景再扩展 |
| 域目录（HR3-B，已实现） | 有界 UInt64 ID 到域句柄的弱路由，支持条件替换和移除；具名投影检查查找类型，不保活状态或代码 |
| 准入 | 复用 SC4-A 的有界许可 |
| 通用 Channel | 延后。有具体场景时再按 [服务端并发计划](server-concurrency.md#8-有界准入与通信)的契约实现 |
| 单次应答 | 不需要。请求即函数调用，结果由 `domain.write` 或 `domain.request` 直接返回 |
| Actor | 不作为运行时原语。常驻的 `loop { recv; handle }` 会永久钉住旧代码；如需消息驱动写法，由库把每条消息作为一次独立的域调用交给 `handle(&mut S, msg)` |
| 服务世代与成组排空 | 不作为兼容更新的默认前提。运行时仍需代码版本凭据；契约变化与迁移可显式冻结或排空相关访问集合 |

消息载荷不能携带闭包或代码引用，否则旧代码会随消息被保留。外部效果不在内存原子发布
范围内；可能重复执行的业务使用幂等键或去重，运行时不承诺网络 exactly-once。

### 7.1 HR3-A 出站信箱（已实现）

先交付显式 `outbox.batch` / `outbox.stage` 和 `domain.with_outbox`，以及双域、多域集合的
附加入口。暂存消息只进入独立批次，执行提交时同时检查完整状态凭据与全部目标容量，然后
一起发布根、消息与回执。失败、过期、代码冲突或取消不会产生消息；发布后取消不撤销已确定
事实。直接修改当前根的域操作不自动获得这一保证，高层 `out.send` 写法仍是后续语法方向。

Mailbox 是连接作用域持有的运行时资源，Handle 是可通过 HR2 平面记录入口传入 Script 的弱
身份。接收方异步等待纯字节消息，使用普通 TCP API 写出；信箱关闭清空队列并唤醒接收方，
身份不复用。队列不持有 Script 代码。首版容量不足采用整次拒绝，暂存失败也使整个批次失效，
不透明重试、不悄悄丢消息；业务可据此重建候选或关闭慢连接。

[真实 TCP 写出](../tests/fixtures/outbox_tcp.jk)，以及 AOT/JIT/解释器宿主与两种 Script 后端的
句柄桥接、重载/关闭后消息继续存活。生命周期测试覆盖等待无忙轮询、关闭唤醒、取消撤销，
容量和分配失败后的配额回收，另提供逐指令取消穷举。具体 API 与边界统一见

### 7.2 HR3-B 域目录（已实现）

AOT 作用域通过 `domain.directory(capacity)` 持有唯一 Directory；把平面的 DirectoryHandle
传给 Script。模块不持有可变全局状态，后续 Context 可以显式携带该句柄。首版业务键限定为 UInt64，
同一目录允许不同域类型，通过 `domain.lookup` / `lookup_write` 的具名只读投影校验接收者类型。
投影不执行，目录不保存 Script 模块；原有域代码晚绑定及调用前验证继续生效。

插入拒绝覆盖存活键；替换与移除要求预期的旧域身份一致，防止换房到另一个域后旧清理误删新路由。
目录存储有界、计入执行器共享预算；域关闭不因目录引用而延迟，失效条目在查找或插入时回收。
目录与域各自独立关闭，复制句柄不改变所有权。条件操作不区分同一域的多次绑定世代；它们是即时
目录操作，不与状态根候选联合提交。需要事务性权威路由时，仍由状态域保存和验证对应关系。

[路由验收](../tests/fixtures/directory.jk)覆盖容量、只读权限、条件换房、旧清理保护、弱生命周期；

访问新逻辑，再移除路由并让旧流程退出。另有错误类型拒绝、跨执行器隔离、预算与逐指令取消测试。

## 8 业务写法方向（未冻结）

HR1–HR5 落地后，服务端业务围绕状态域组织：长期状态是 `#state` 记录，域操作写在其 `impl` 中，
规则写成普通函数，流程是 `@suspends` 函数。下例是语法方向的示意，名称与拼写均未冻结，
`text` 块不可执行。声明属性沿用 `#`，`@` 仍只用于签名中的效果标记。

除新提议的结构外，示例沿用现有语法：`while` 循环、`Result.Ok` / `Result.Err` 构造器、
`match` 分支；当前没有 `?` 传播运算符，错误分支用 `match` 提前返回。

```text
import joky/domain.{type Outbox, type Directory}
import joky/net.{type Conn}

// 声明处即检查域根资格，诊断定位到类型而不是首次使用处
#state
struct Room { id: Int64, frame: Int32, members: Array<Member>, cap: UInt64 }
struct Member { player: Int64, conn: Conn, x: Int32, y: Int32 }

#state
struct Player { id: Int64, level: Int32, room: Option<Int64>, conn: Conn }

enum RoomMsg { Frame(Int32), Joined(Int64), Left(Int64) }
enum JoinError { NoPlayer, NoRoom, Full, AlreadyInRoom, Database }

// #state 类型的 impl 方法即域操作：编译器证明同步、不逃逸、不调用宿主
impl Room {
    fn open(id: Int64, cap: UInt64) -> Room {
        Room { id: id, frame: 0, members: Array.new::<Member>(), cap: cap }
    }

    // 运行时按周期调度；每次都是独立调用，发布后下一帧使用新代码
    #every(50)
    fn tick(&mut self, out: &mut Outbox<RoomMsg>) {
        self.frame = self.frame + 1
        step_physics(self)                                  // 普通函数
        var i: UInt64 = 0
        while i < self.members.len() {
            match self.members.get(i) {
            Some(m) => out.send(m.conn, RoomMsg.Frame(self.frame))   // 调用成功后才投递
            None => {}
            }
            i = i + 1
        }
    }

    fn full(&self) -> Bool { self.members.len() >= self.cap }
    fn frame(&self) -> Int32 { self.frame }
}

fn step_physics(room: &mut Room) { ... }

// 目录按 ID 查到句柄，不保活状态；模块级声明方式未定
let rooms: Directory<Int64, Room> = Directory.new()
let players: Directory<Int64, Player> = Directory.new()

// 流程可保存句柄与拥有值；挂起等待期间不持有域状态借用
fn join(pid: Int64, rid: Int64) @suspends -> Result<UInt64, JoinError> {
    let player = match players.get(pid) { Some(h) => h, None => return Result.Err(JoinError.NoPlayer) }
    let room = match rooms.get(rid) { Some(h) => h, None => return Result.Err(JoinError.NoRoom) }
    let level = match db.load_level(pid) { Ok(n) => n, Err(_) => return Result.Err(JoinError.Database) }

    // 块体固定在 join 的代码版本；参与域已切换时拒绝，错误出口的语法尚未冻结
    // mut 表示写权限，省略为只读；块内同名变量变为对状态的引用
    when (mut player, mut room) {
        if room.full() { return Result.Err(JoinError.Full) }   // 先检查，此时尚未修改
        if player.room.is_some() { return Result.Err(JoinError.AlreadyInRoom) }
        room.members.push(Member { player: pid, conn: player.conn, x: 0, y: 0 })
        player.room = Option.Some(room.id)
        player.level = level                                    // 外层值复制或移动进块
        Result.Ok(room.members.len())
    }
}

// 单域访问可直接在句柄上调用方法；调用会挂起一轮，不需要 await
fn frame_of(rid: Int64) @suspends -> Option<Int32> {
    match rooms.get(rid) { Some(room) => Option.Some(room.frame()), None => Option.None }
}

// 状态结构变化：显式迁移，prev.Room 是编译器按归档旧 schema 生成的只读视图
migrate Room from prev.Room {
    Room { id: old.id, frame: old.frame, members: copy_members(old.members), cap: 8 }
}
```

`copy_members` 表示按旧 schema 读取成员并构造独立新存储的迁移辅助函数，不能从只读旧根中
移动拥有字段。`join` 中的内联块展示访问语法，不承诺跨发布继续执行；需要立即热修复的入房
规则应优先写成具名多域操作，在 HR6 提供兼容晚绑定后由流程调用。

AOT 主程序只认识少量通用入口，业务消息由 Script 解码和分发。AOT 代码不参与热更新，
其中的常驻管理循环不会钉住 Script 代码。下例 `game.entry` 必须表示稳定的入口路由句柄，
每条新消息解析当前模块并启动流程，不能把某一版 Script 函数永久保存在连接服务中：

```text
import joky/script.{type Script}
import joky/net

fn main() @suspends {
    let game = match script.load("game/") { Ok(s) => s, Err(e) => return fail(e) }
    let server = match net.listen("0.0.0.0:7000") { Ok(l) => l, Err(e) => return fail(e) }
    parallel {
    | net.serve(server, game.entry("on_message"))   // 连接消息转给 Script 的通用入口
    | admin_loop(&game)
    }
}

fn admin_loop(game: &Script) @suspends {
    while true {
        match admin.next_command() {
        Reload => reload(game)
        Stop => return
        }
    }
}

fn reload(game: &Script) @suspends {
    match script.load("game/") {
    Ok(next) => log(game.publish(next))   // 兼容域切换代码；结构变化则执行 migrate
    Err(error) => log(error)              // 编译或检查失败时保留旧版本
    }
}
```

每项写法都还原为已有或计划中的原语，不引入新的语义保证：

| 写法 | 底层 | 现状 |
| --- | --- | --- |
| `#state` | 现有 `domain_entry` 根资格检查，提前到声明处 | 资格检查已有 |
| `#state` 类型的 `impl` 方法 | 域操作 `fn(&S, ...)` / `fn(&mut S, ...)` | 已有，限单个标量输入 |
| `handle.method(args)` | `domain.read_from` / `write_to`，多参数由编译器打包 | 单输入已有 |
| `when (mut a, b) { }` | 固定版本的块体提取为同步函数，校验全部域绑定后执行 | 短操作原语已有，版本校验与块提取待做 |
| `Outbox.send` | 出站信箱，调用成功后投递（HR3） | 待做 |
| `#every(n)` | 运行时按名字调度的周期调用（HR4） | 显式 after/every 已实现，属性糖待做 |
| `Directory` | ID 到句柄的目录（HR3） | 显式运行时目录已实现，泛型键与模块声明糖未实现 |
| `migrate ... from ...` | 类型可变的候选与修订校验（HR5） | 待做 |
| `script.load` / `publish` | 语言侧入口，底层为 `publish_domain_code`（HR2） | 发布原型已有 |

`when` 的取向：

- 名称取"拿到这些域之后执行"的含义，与 Behaviour-Oriented Concurrency 的 `when` 一致；
  区别是本语言的 `when` 只出现在 `@suspends` 函数中，挂起直到块执行完并返回其值。
  首选上下文关键字：仅在 `@suspends` 函数中以 `when (` 开头时识别，不进入保留字表。
- `when` 提供独占访问，不提供回滚。块内返回前已写入的修改保留；块体运行时失败按现有规则
  隔离被写的域。业务应先检查再修改；需要失败整体回滚时使用候选与提交，另设入口。
- 块体同步、不调用宿主、不嵌套 `when`，`break` / `continue` 不跨出块。外层局部值按值复制
  或移动进块，不能借用。块内 `return` 从外层函数返回，由编译器把提前返回编码为结果标签带回。
- 首版设计采用流程固定版本：块体及捕获值布局属于调用流程的模块。准入和实际执行前都要
  检查全部参与域仍绑定该流程的模块，并校验从准入到执行的代码版本未变；即使新旧布局相同，
  跨发布时也拒绝，不自动换成新块体，也不自动重放。
  拒绝结果如何与块体返回值组合、如何向外层传播，须在语法实现前确定，示例暂未表达该错误出口。
  若以后支持内联块晚绑定，必须另行设计稳定操作标识、捕获值 ABI 和效果兼容检查，单纯提取
  辅助函数不足以保证安全。
- 访问列表写作 `mut player`，不写 `&mut player`：`player` 本身是句柄，借用记号会误读为借用句柄。

其余未定项：对句柄的方法调用是否需要显式标记（倾向只靠句柄类型区分）、出站信箱采用显式参数
还是隐式上下文（倾向显式参数，签名中可见副作用）。这些在 HR0 安全补齐、HR2 标量探针与
HR1 类型扩展后用真实房间示例验证再定，语法糖不替代底层版本协议。

## 9 预算与诊断

- 发布返回切换数量；结构不兼容时指出具体类型。迁移报告逐域区分成功、重做、失败与超时。
- 诊断列出仍存活的旧模块及持有原因：未结束的流程、未切换的域、未领取的结果。
- 迁移的候选字节、模块驻留数和待清理资源分别设限；逻辑字节不等同进程 RSS。
- 协作式执行只能在运行时重新取得控制时观察超时，不能抢占不让出的原生循环。

## 11 行为测试矩阵

以下是跨阶段目标验收矩阵；已实现范围见 HR0 第 3.4 节、HR1 第 3.5 节、HR2 第 6.1–6.2 节、HR3-A 第 7.1 节、HR3-B 第 7.2 节、HR4 第 5 节及 HR5-A/B1 第 4.1–4.2 节，
其余能力不能视为已经验收。

| 场景 | 必须观察到的行为 |
| --- | --- |
| 发布时有挂起流程 | 流程按原代码恢复；此后发出的兼容具名操作执行新代码；固定版本的内联块按版本规则拒绝 |
| 发布前已排队的单域调用 | 签名兼容时执行新代码；不兼容时只失败该调用，域保持健康 |
| 发布前已排队的多域调用 | HR0 遇绑定变化先拒绝且无写入；HR6 后兼容具名操作重绑定，不兼容仍整次拒绝 |
| 只读第四域只更新代码 | 数据修订未变也使旧候选失效；整个提交集合无根替换 |
| 内联块等待期间发布 | 不把旧捕获值交给新版块体；拒绝结果可被流程显式处理，无透明重放 |
| 状态结构变化但没有迁移 | 发布被拒绝，所有域保持原代码与原数据 |
| 迁移期间仍有写入或代码发布 | 完整凭据冲突则在最终发布前有界重建或放弃，不丢失正常写入 |
| 后构造的迁移候选分配或校验失败 | 较早完成的候选也不发布；所有候选按初始化进度清理，无根或绑定部分替换 |
| 迁移最终发布区间 | 没有分配、用户迁移或其他可失败调用，所有根一起可见 |
| 新逻辑写入后切回旧代码 | 数据保持已写入结果；业务兼容检查不能被相同布局替代 |
| 关闭、取消与发布竞争 | 终态唯一；已关闭或失败的域不被发布重新开放 |
| 旧代码的最后持有者结束 | 旧模块退役，资源回到基线 |
| tick 与出站信箱 | 失败的调用不产生可见消息；满队列按策略处理且有界 |

编译器或运行时改动的测试执行生成代码，JIT、解释器与 AOT 三边一致；AOT 已有 HR2 标量/平面记录
调用、加载与发布验收；单域迁移另见第 4.1–4.3 节，多域迁移仍按后续阶段验收。验证范围按 [AGENTS.md](../AGENTS.md#按改动范围验证)选择，
不因阶段结束自动运行 Release 或无关压力测试。

## 12 不做与延后

首版不提供挂起栈迁移、运行时二进制自身热替换、跨线程或跨进程原子升级、崩溃恢复、
任意外部副作用回滚、透明请求重放和不可信脚本隔离。长期状态表示跨请求存活的内存，
不代表已经落盘；持久化与失败域的恢复与热更新正交，另行设计。
