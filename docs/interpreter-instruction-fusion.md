# 解释器立即数运算和比较分支融合：2026-09-27

基线为 `e02cdc7`，已包含借用取指、消除 Label 和局部 Copy 优化。本轮继续优化
解释器内部字节码，共享 typed IR、AOT/JIT、帧槽位布局及挂起协议保持原有实现。
测量仅比较 Joky 自身三个阶段，没有启用外部语言对照。

## 实现

`src/backends/interp/optimize/fuse.rs` 提供两个独立 pass，在 Copy 优化后顺序执行。

### 立即数运算

在基本块内跟踪 Int32 常量；目的槽位写入使原常量信息失效，跳转入口、控制流边界、
Call/Scope 前后清除信息。将右操作数是已知常量的 `Binary` 改为 `BinaryImm`，最后
只删除没有任何剩余读取的整数 Const。返回值、跨块读取和其他消费者都计入使用次数。

例如 `i = i + 1` 从 `Const 1`、`Binary Add` 两条变成 `BinaryImm Add` 一条。
加、减、乘、除和产生 Bool 的六种有符号比较都支持右侧立即数；左侧常量不通过交换
操作数转换，也不折叠 `0 - 1` 等表达式。两种 Binary 共用运算实现，保持 Int32 回绕、
除零错误及 `MIN / -1` 的既有行为。未使用的除法仍执行。

### 比较分支融合

仅在比较与 Branch 紧邻、比较是 Bool 槽位唯一写入者、Branch 是唯一读取者且不存在
直接进入 Branch 的其他控制流时，生成 `BranchCompare` 或 `BranchCompareImm`。
指令在原比较位置读取操作数，直接选择下一 PC，省去中间 Bool 写入和一次分派。

Bool 被返回或在其他位置使用时保留原操作；不跨调用、挂起或其他保留指令融合。
删除指令后统一重映射 Jump 和所有 Branch 的两个目标，包括函数终点。
六种比较使用独立的 Comparison 枚举，避免将非比较操作编码进融合分支。
读取槽位时保留 Int32 类型检查，没有新增 unsafe。

## 字节码数量

下列是正常进入循环体的一轮实际分派次数，不含初始化、最终失败检查和返回：

| 内核 | Copy 基线 | 加入立即数 | 再加入比较分支融合 |
|---|---:|---:|---:|
| 累加 | 6 | 5 | 4 |
| 乘加递推 | 10 | 7 | 6 |
| 分号条件 | 9 | 7 | 6 |

累加内核的循环现在是比较分支、累加、立即数递增、回跳四条。本机 `Instruction`
仍为 72 字节，`Value` 仍为 24 字节；三个函数仍占用 14/18/16 个槽位。
分号条件的计数器写回 Copy 继续保留，本轮没有扩大上一轮的使用次数分析范围。

## 分阶段 Release 复测

环境：Apple M1 Pro / aarch64 / Darwin 25.6.0，Rust 1.97.1。保持原有 Release
配置：opt-level 3、thin LTO、1 codegen unit、debug_assertions=false。
先构建并分别保存三个阶段的二进制，再按“基线、仅立即数、全部融合、全部融合、
仅立即数、基线”的顺序运行。计时期间没有并行编译、测试或采样器。

每轮三个内核、三个 Joky 后端、N=0/100,000；每组 30 个样本，目标批次 50 ms。
编译、链接、加载和预热不计时。下列为 100,000 轮解释执行耗时，汇总取各阶段
两次运行中位数的中位数；下降比例按未舍入数字计算。

| 内核 | Copy 基线 | 仅立即数 | 两项合并 | 总耗时下降 |
|---|---:|---:|---:|---:|
| 累加 | 2.993 ms | 2.835 ms | 2.478 ms | 17.2% |
| 乘加递推 | 4.270 ms | 3.638 ms | 3.323 ms | 22.2% |
| 分号条件 | 3.860 ms | 3.438 ms | 3.055 ms | 20.9% |

立即数阶段分别降低耗时 5.3%、14.8%、10.9%；在此基础上，融合分支再降低
12.6%、8.7%、11.1%。总加速分别为 1.21x、1.28x、1.26x。结果包含新增指令分派和
Rust 优化器生成机器码的整体变化，不能把百分比解释为某条被删除指令的精确成本。

全部融合版两次运行中位数差异分别为 0.41%、1.18%、0.23%。六轮共 3,240 条原始
样本，108 组 min/median/P95/max 均从 elapsed_ns/calls 重算核对。N=0 的解释器
中位耗时约 208–222 ns，仅作入口基线，不用于推断循环吞吐。
P95 是批次平均值分布的 nearest-rank 百分位，不是单次调用 P95。
本结果未提供置信区间，不作为 CI 阈值，也不代表其他类型工作负载的性能。
