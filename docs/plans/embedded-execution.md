# 阶段 10：嵌入式执行、脚本热更新与宿主集成

> 状态：未开始，API 为设计草案。
> 前置：阶段 6、7、8 的模块、宿主 ABI 和 AOT 基础；不依赖跨目标编译完成。
> 阶段 9 影响未来动态 trait 互操作，但不是首轮前置。

## 目标与范围

2026-09-17 调整方向：以可选的 `joky/vm` 支持 AOT 宿主加载 Joky 游戏逻辑、
服务逻辑和脚本包，替换原来的 AOT 函数级 Hotfix 计划。不实现 AOT 宿主自身的
函数替换、原生补丁加载或全局 FunctionSlot 间接调用；AOT 宿主通过稳定接口运行
可重载模块，模块代码的版本管理和安全回收属于本计划。

2026-09-24 再次调整，目标是以最小实现覆盖游戏客户端和服务端目前由 Lua 承担的能力：

1. **单一编译管线**：不另写一套执行语义。可重载模块沿用 MIR → Cranelift IR，
   最后一步按平台选择本机 JIT 或 Pulley 可移植字节码（见[执行架构](#执行架构)）。
   首轮不再自研字节码解释器；只有 Pulley 验证失败时才退回自研 MIR 解释器。
2. **代码热修优先**：首轮只支持"持久状态布局不变"的代码替换，允许新旧版本并存，
   不停服；布局变化的状态迁移放到第二步（见[重载协议](#重载协议)）。
3. **宿主驱动**：提供精简 C API 和宿主逐帧推进的调度模式，便于嵌入 Unity、
   Unreal 与自研引擎（见[宿主集成](#宿主集成)）。

普通 AOT 程序不使用可重载模块时，无需携带 JIT、Pulley 解释器或脚本编译前端。
当前只有 MIR 到本机机器码的 JIT 和 AOT 后端，以下内容均为待实现能力。

| 策划与 Mod 脚本 | effect 权限清单与能力传递，见[愿景 3.4 / 3.5](vision.md#34-能力传递去掉环境权限) | 视平台选择 |

## 执行架构

```text
Joky 源码 -> 检查 -> typed MIR -> Cranelift IR ─┬─> 本机机器码（JIT，进程内编译）
                                                └─> Pulley 字节码包（开发端预编译）
                                                        |
AOT 宿主 -> joky/vm -> 本机 JIT / Pulley 解释器 -> 共享 runtime（jk_* ABI）
```

Effect、挂起、Cown、区域、取消和 Drop 在 Cranelift IR 层已经降为普通代码与
`jk_*` runtime 调用，因此 JIT 与解释执行运行的是同一份 lowering 结果，
语义一致性不依赖第二套实现。

首轮由宿主显式选择 JIT 或解释执行；自动热点编译、解释与机器码执行栈之间的迁移
不属于本计划。现有 MIR 缓存不是稳定的分发格式，字节码包需要另行定义：包含
Pulley 字节码、导出签名、类型布局指纹、effect 与 operation 元数据，以及语言、
包格式、宿主接口和 runtime 的兼容性版本。包内不能保存编译进程的地址或未经
校验的 native 布局。部署端只需字节码加载器和解释器，源码编译前端为可选开发能力。

桌面与服务端可以使用 JIT；普通 iOS 应用以解释执行为基础，不假设拥有 JIT 权限。
解释执行不保证平台允许下载任意逻辑，iOS 和主机平台的发布政策需单独确认。

### Pulley 可行性与风险

Pulley 是 Cranelift 的可移植字节码后端，由 `pulley-interpreter` 执行；执行时
不生成、也不跳转到本机代码，Wasmtime 以它支持无 JIT 平台（参见
[Wasmtime Portable Interpretation](https://docs.wasmtime.dev/examples-pulley.html)）。
原计划按 Cranelift 0.134.3 编写；实施验证前需以 [Cargo.toml](../../Cargo.toml) 的锁定版本重新核对 API。原计划列出的风险：

- 官方说明 Pulley 仍在开发中，字节码细节和 API 会变化。需要锁定版本，字节码包与
  编译器、runtime 版本严格绑定，不承诺跨版本加载。
- Pulley 为 Wasmtime 设计，脱离 Wasmtime 单独嵌入没有成熟先例。需要自行解决：
  - 加载与链接 Pulley 代码，包括指向 runtime 符号的重定位；
  - 字节码调用 `jk_*` runtime 函数的宿主调用机制；
  - 本机代码回调生成代码时进入解释器的跳板。runtime 目前通过函数指针回调
    payload 析构胶水、task thunk、continuation 恢复入口和 handler thunk 等，
    这些位置需要统一经过可替换的入口抽象。
- 解释执行比本机代码慢，幅度需要实测；性能敏感路径保留在 AOT 宿主中。

**验证 spike 的验收**：在 macOS 上把 hello、闭包、`time.sleep`、单 Cown `when`
与 `region` 编译为 `pulley64` 并正确执行，资源计数归零，并给出与 JIT 的性能对比。
spike 失败时退回自研 MIR 解释器：解释器帧位于堆上，挂起天然成立，但必须另行保证
与本机 ABI 和 runtime 回调协议一致，工作量明显更大。

## API 草案

`joky/vm` 提供执行环境、模块加载、宿主绑定和执行生命周期；更高层的
`joky/script` 可在此基础上提供实例、持久状态与重载。模块名和签名在实施时
细化，下表不是已经存在的语言 API。

| 概念 | 责任 |
| --- | --- |
| `Engine` | 选择执行方式和调度模式、注册带类型/effect 信息的宿主接口、配置模块和 provider 可用范围 |
| `Module` | 加载并验证字节码包，或通过可选前端编译源码；持有不可变代码版本 |
| `Function` | 持有经过签名检查的导出句柄和所属模块版本，拒绝关闭后的调用 |
| `Execution` | 表示一次可能挂起的根调用，供宿主查询、等待或取消；不阻塞游戏主线程 |
| `Instance` | 绑定活动模块、持久状态和任务作用域，提供调用、重载及关闭操作 |
| `State` / `Snapshot` | 与脚本代码生命周期独立的版本化数据，支持显式迁移 |

同步调用与可挂起调用分别表达。宿主接口首轮支持数值、Bool、String、Unit
和受控宿主句柄；任意 class、闭包、Cown 或动态 trait 的跨边界互传需单独
定义所有权、类型身份和失效规则。脚本内部的语言能力不因此被禁止。

## 可重载边界

- 可重载范围以模块为单位，在 `joky.toml` 中显式标注；未标注的模块按普通 AOT 构建。
- 宿主调用可重载模块经过一张带版本的入口表，每次跨越边界多一次间接调用；
  可重载模块内部调用、以及它调用宿主函数，仍为直接调用。普通 AOT 调用不因此
  增加函数表间接调用。
- 泛型实例、闭包和 continuation 归属于生成它们的模块版本。
- 持久状态的类型中不得出现可重载模块创建的闭包或 `Dyn` 对象，否则会长期引用
  旧代码；该规则由类型检查执行。

## 宿主集成

### 宿主驱动调度

第三方引擎通常要求脚本在游戏线程上按帧推进。除默认的多 worker 调度外，提供
宿主驱动模式：worker 数为 0，宿主每帧调用一次带时间预算的 `tick`，推进已就绪的
任务与 continuation；reactor 和 blocking pool 仍在后台线程完成 I/O，结果在下一次
`tick` 中交付。渲染等主线程操作不需要额外派发。两种模式运行同一份代码，
调度语义差异（例如 `parallel` 在宿主驱动模式下不并行）需要写入契约。

### 精简 C API

仿照 Lua 的做法，对外 C API 控制在十个左右的函数：创建与销毁 Engine、加载字节码包
或源码、按名称取得导出函数、调用（同步 / 可挂起）、注册宿主函数、`tick`、`reload`、
错误查询。C# 与 C++ 绑定在此之上生成，不直接暴露 runtime 内部结构。

## 并发、标准库与生命周期

- [ ] VM 与宿主共享分配器、调度器和 runtime 注册设施，以实例作用域隔离工作；不能额外加载一套互不知情的 runtime。
- [ ] JIT 与 Pulley 执行均支持结构化并发、Cown、effect、挂起、取消、join 和 Drop，验证异常及取消路径的所有权一致性。
- [ ] 接通字符串、集合等标准模块，以及宿主开放的 timer、file、socket 等 provider；定义模块解析和分发方式。
- [ ] 宿主注册接口显式声明类型、effect 和线程要求；多 worker 模式下，渲染等主线程操作通过派发或命令队列完成，不能从 worker 任意直调。
- [ ] 持久状态使用 Cown 保护或由实例串行更新，不向并发任务暴露无保护的共享可变状态。
- [ ] 函数句柄、闭包、task、continuation、callback 和析构入口持有所属模块版本；关闭时拒绝新调用，取消并等待工作退出后安全回收。
- [ ] 外部 C 回调必须完成注销及排空协议；不能仅凭脚本根调用结束就释放它可能调用的代码。

首轮面向可信脚本。开放 API 的白名单不等于不可信代码沙箱，尤其原始 C FFI
和 native JIT 会扩大宿主访问范围；安全隔离不作为首轮承诺。

## 重载协议

引擎世界、实体和资源由宿主持有，脚本通过受控句柄访问。脚本私有持久状态
由实例持有，可采用数值、字符串、列表和记录等数据表示；不能直接保存旧
脚本对象指针、闭包或 continuation。宿主资源身份如需跨重载保留，应使用
可校验的稳定 ID。跨重载持久化不自动等于磁盘存档。

建议的生命周期入口为首次创建时的 `init`、普通调用入口和新版本可选的
`migrate`。重载不重新执行 `init` 覆盖旧状态。

候选模块先在后台加载、编译并验证字节码与宿主接口，当前实例继续运行。随后按
持久状态的类型布局指纹分为两种重载：

### 代码热修：布局不变（首轮）

持久状态涉及的全部类型布局指纹与当前版本一致时，只替换代码，不做状态迁移：

1. 提交新模块版本；此后经入口表进入的新调用使用新版本。
2. 正在执行或挂起的任务、continuation 继续使用旧版本代码直到结束，不取消。
3. 旧版本的全部代码引用释放后再回收。

新旧版本在切换期间可能交替访问同一状态。这是安全的：布局相同，并发访问仍由
Cown lease 隔离。若某次更新不能接受新旧逻辑交替，宿主可以选择"排空后切换"：
在帧边界或请求边界停止旧版本新调用、等待活动工作退出，再提交新版本。

布局指纹发生变化时，首轮拒绝更新并给出涉及的类型与字段诊断。

### 状态迁移：布局变化（第二步）

1. 在宿主选定的帧边界或请求边界停止接收旧版本新调用；取消并等待活动工作退出，不并行运行新旧版本来修改同一状态。
2. 工作排空后快照当前持久状态，在独立副本上执行候选版本迁移；迁移限制为数据操作，禁止产生宿主外部副作用。
3. 迁移成功后提交新模块和新状态，再开放调用。迁移失败保留旧模块及旧状态，并在新的调用作用域继续服务。
4. 无活动代码引用后回收旧版本；宿主长期持有的旧函数句柄必须有明确的失效与释放规则。

状态版本不兼容且没有可用迁移时拒绝更新。取消导致的正常清理在快照之前完成；
若工作不能安全排空，不得迁移状态或强制卸载旧代码。失败回退不恢复已取消任务的
执行栈；长任务的业务进度应显式保存为数据，再由旧版本或新版本启动新的执行。
新代码投入运行后的代码回退，也不自动撤销已经写入的状态、数据库或网络副作用；
后续版本回退需兼容状态版本或提供显式逆向迁移。

停顿随状态规模增长的问题，后续可改为按 Cown 惰性迁移，见[愿景 5.3](vision.md#53-热更新按-cown-惰性迁移状态)。

- [ ] 10.1：Pulley 验证 spike（验收见[上文](#pulley-可行性与风险)）；通过后固定宿主调用、字节码包格式和受支持类型契约，实现嵌入式加载入口。spike 失败则改为自研 MIR 解释器，并重新评估本阶段范围。
- [ ] 10.2：接通标准库、共享 runtime、结构化并发和可取消执行；实现宿主驱动调度与精简 C API，验证主线程推进及实例资源隔离。

- [ ] 10.4b：状态迁移：实例持久状态、版本校验、显式迁移、停止工作后的模块切换和失败回退。
- [ ] 10.5：完成 AOT 游戏宿主示例、脚本逻辑包替换、服务逻辑修复以及目标平台验收。

## 明确不做

- AOT 引擎或服务器宿主本身的原生函数 Hotfix；未标注为可重载的代码仍通过常规构建发布。
- 首轮自研字节码格式与解释器（Pulley 验证失败时重新评估）。
- 自动迁移存量 class 布局、native frame、解释器执行栈或正在挂起的 continuation。
- 自动热点编译、在线栈替换和解释/JIT 之间的反优化迁移。
- 字节码包跨编译器或 runtime 版本加载。
- 首轮不可信脚本沙箱，以及任意外部副作用的事务回滚。
- 贴图、音频等资源包的下载、签名、原子发布和资源版本协调；这些由游戏包管理层承担。
- 保证任意平台允许下载新逻辑；平台政策验收独立于技术验收。

## 验收

- `--watch` 模式下修改函数体后，运行中的程序使用新逻辑且状态保留；布局变化给出诊断。
- 不包含 JIT 的 AOT 宿主能以 Pulley 执行字节码包；启用 JIT 的宿主通过同一套调用、并发、标准库和资源清理测试。
- 代码热修不停止服务：挂起中的旧版本工作正常完成，新调用进入新版本，旧版本最终被回收且无泄漏。
- 宿主驱动模式下，宿主逐帧 `tick` 能推进挂起任务与 I/O 完成，且不在宿主线程之外执行脚本代码。
- 更换脚本包后使用新逻辑，宿主世界和兼容的实例状态保留；新增状态字段通过显式版本迁移处理。
- 非法字节码、接口不兼容、布局不兼容、编译或迁移失败均有诊断，不提交候选模块和状态。
- 覆盖正在执行、挂起、取消、callback、Cown body 和 Drop；旧工作排空、句柄释放后无旧代码或 runtime 资源泄漏。
- 重载不会在迁移副本中调用外部有副作用的 API，失败后旧实例可接受新调用；不声称恢复被取消的任务。
- 普通 AOT 程序不依赖 VM、JIT 或 Pulley；iOS 解释执行及实际允许的更新方式在目标设备和发布渠道另行验证。
