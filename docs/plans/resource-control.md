# 阶段 5：长期运行的资源控制与实用文件 I/O

当前 API 见[文件 I/O](../stdlib/file-io.md)、[循环与游标](../lang/iteration.md)，实现契约见[资源生命周期](../runtime/resource-lifetimes.md)和[有界迭代](../runtime/bounded-iteration.md)。文中已完成阶段的数字与“无远端 CI”属于当时记录；当前 workflow 见[测试配置](../../.github/workflows/test.yml)，其存在不证明 5.4 长跑已验收。

> 状态：5.0–5.3 已实施并本地验收；5.4 待收尾（2026-09-22）。
> 前置：阶段 4 的任务等待与 blocking pool 准入修复已落地。
> 5.2 有界批量与 5.3 文件读写已落地；5.4 仍缺独立总验收和 Linux 长跑。
> 编译期栈溢出已按左脊迭代 + 嵌套深度诊断处理。
> 目标：真实程序能够持续运行、受控地批量处理文件，并在完成、失败、
> 取消后回收资源。验收以工作流、资源数据和可复现测试为依据。

## 当前基线与范围

- `b056f0f`：结构化任务等待使用 Pending/continuation，避免少量 CPU
  worker 下嵌套 join 死锁；覆盖取消排空和父帧生命周期。
- `50fa95d`：保留固定 blocking worker 和有界执行队列，文件读取在
  饱和时异步等待 FIFO 准入；取消移除等待/排队请求并释放共享路径。
- 上述基线的本地记录：857 个 lib 测试、66 个 CLI 测试通过；文件池
  饱和测试在 1/2/4 CPU worker 下分别重复 20 次通过。历史通过记录
  不替代阶段 5 实现后的复验，也不代表远端 CI 或最新 TSan 已通过。
- 现有 `std/joky/file.jk` 只提供整文件 UTF-8 读取。等待准入避免了
  内部队列饱和错误，但等待任务、参数和读取结果的总内存尚无硬上限。

阶段 5 必须完成 5.0–5.4。先处理验收缺口和生命周期，再增加有界批量
处理、文件读写能力，最后用真实程序验收。已完成的任务等待和准入机制
作为基础复用，不重新列为待实现功能。

## 5.1 控制运行时长期内存增长

- [x] 建立按 runtime scope 和进程观察资源的测试接口，至少区分：活动
      continuation、句柄槽/退役记录、任务组、provider 请求、等待准入
      请求及其持有参数。不能只检查 managed object 数量。
- [x] 审计并移除 `src/runtime/continuation/registries.rs` 原有的永久
      tombstone 和地址复用保留分配。使用只含活动项的 token 表，
      同时维持迟到回调无法命中新对象的保证。
- [x] 形成句柄协议设计并实施：选择进程内永不复用的不透明 token；
      明确 ABI 表示、名字空间耗尽规则、回调校验、表项回收时机及
      provider 接入方式。不得直接清空 tombstone 后继续复用裸指针身份。
- [x] 覆盖迟到与重复完成、取消与回收竞争、槽复用、跨 scope 回调、原生
      Pending 交接，以及运行中的 blocking syscall 晚到结果。
- [x] 审计任务组、handler frame、provider 注册项、timer/reactor 请求的
      终态回收；区分活动工作必需占用、可复用容量、永久历史记录。
- [x] 增加固定并发度的多批次长跑与重复创建/关闭 scope 测试。预先固定
      工作量、热身及采样点，分别记录资源计数、分配量和 RSS。

验收：排空后活动资源归零或回到明确基线；可复用元数据随峰值活动量
稳定下来，不随累计操作次数持续增长。RSS 单独分析分配器缓存，不能
仅凭 RSS 未下降认定泄漏，也不能仅凭 managed object 为零宣称无泄漏。
确实无法中断的在途 syscall 按文档单独计数，返回后验证最终清理。

实现与验收：[资源生命周期与句柄协议](../runtime/resource-lifetimes.md)、
[5.1 长期资源回收记录](../archive/reports/phase5-1.md)。除句柄和 reactor 历史记录外，
长跑还发现并修复 native 预留/终态句柄遗漏释放、JIT 可执行映射及复用
Compiler 的代码积累。5.1 解决固定活动峰值下的回收；任意任务量与整文件
结果的内存上限仍由 5.2/5.3 处理。

## 5.2 提供易用的有界批量并发

已确定并实现 `for item in items { ... }` 收集表达式，以及
`@parallel(limit: N) for (index, item) in items { ... }` 有界并发注解。
输入首版为 `List(T)`；正常尾值收集一次，`continue` 跳过，顺序 bare `break`
返回前缀；并发版首版禁止退出当前循环的 `break`。索引为从 0 开始的 UInt64。

- [x] 定义并实现顺序/并发入口、动态正上限、输入顺序输出、错误和控制流
      规则。无效上限、重复绑定、非 List 输入和重复 owned 捕获有诊断。
- [x] 用共享输入游标和至多 `min(limit, len)` 个固定逻辑任务控制生产；
      每项完成后复用 worker，不创建随输入总数增长的任务历史。TaskWait
      让父任务挂起，I/O 等待复用现有 Pending ABI。
- [x] 批次局部限制；嵌套 limit=1 在 1/2/4 CPU worker 下均可推进。
      迭代内 `branch` 在本次迭代结束、跳过或顺序 break 前排空。
- [x] 与 blocking pool FIFO 准入、取消和失败排空集成。池饱和期间，
      12 项/limit=5 的批次只产生 5 个等待准入请求，放行后无需重试。
- [x] 覆盖索引、空输入、过滤、前缀、Unit/共享/嵌套 List、泛型、闭包、
      混合 CPU/I/O、handler 隔离、嵌套、取消和失败。隔离测试记录实际
      任务创建量与存储峰值，排空后检查进程资源归零。

资源边界：运行时顶层任务额外占用随并发度增长，输入集合及完整输出仍
可占 O(N) 内存；当前丢弃结果也先收集，可用尾部 `continue` 跳过输出。
显式子任务/子批次拥有自己的额度，单次整文件 I/O 的字节数不受迭代额度
限制。取消是协作式的，不撤销已经开始的外部副作用。

实现与验收：[有界迭代协议](../runtime/bounded-iteration.md)、
[5.2 验收记录](../archive/reports/phase5-2.md)、[示例](../../examples/concurrency/bounded_for.jk)。

## 5.3 补齐文件读写能力

### 5.3a 小文件二进制读写

- [x] 增加基于 `Bytes` 的读取和写入，保留现有文本 `file.read` 的兼容
      行为；API 名称、覆盖/追加策略及错误表示在实现前写明。
- [x] 读写复用异步准入与取消协议，实际阻塞 syscall 只在 blocking worker
      上执行。避免为等待请求提前复制完整写缓冲区。
- [x] 明确写入完成的含义：写入系统缓冲区与持久化到存储介质分开说明。
      如提供同步落盘接口，单独定义并测试；普通写入不默认承诺掉电安全。
- [x] 覆盖空文件、非 UTF-8 内容、不存在路径、权限错误、短写和中途失败；
      对难以稳定制造的系统错误使用可控测试后端。

### 5.3b 大文件分块处理

- [x] 增加文件句柄及分块读取/写入能力，定义打开模式、EOF、位置更新、
      所有权、显式关闭与 scope 清理的责任。
- [x] 定义同一句柄并发操作的顺序或拒绝规则，防止隐式文件位置竞争；
      处理 close 与排队/在途 I/O 的竞争及重复关闭。
- [x] 规定写入取消与失败语义：取消可能发生在部分数据已经写入之后，
      不保证回滚。明确部分进度如何报告；禁止自动重试产生重复写入。
- [x] 覆盖排队取消、执行中取消、错误退出、关闭竞争及缓冲区最终释放。
      已启动的不可中断 syscall 可以继续，但不得恢复已取消用户代码。

验收：能够复制二进制大文件并校验内容一致；分块工作流的额外缓冲区
占用随并发度和块大小增长，不随文件大小增长；成功、失败、取消及关闭
路径都有清理证据。整文件便利接口保留其按文件大小分配的明确边界。

## 5.4 用真实程序验收

- [ ] 增加三个可运行工作流：二进制文件复制、限制并发的批量文件处理、
      带超时取消的网络程序。每个示例说明使用方法、预期结果和资源边界。
- [ ] 修复这些工作流暴露的语言组合问题。合法代码应正常编译；当前不
      支持的写法应给出源码位置和可操作诊断，不能只报告底层 verifier 错误。
- [x] 复现阶段 4 记录的大源码编译期栈溢出，定位递归热点并修复，或在
      超出已定义限制时返回受控诊断；覆盖宽并发 arm 和深表达式两类输入。
      64-arm `parallel` 的溢出点是左结合的 `results.0 + …` 树，不是 arm
      宽度；sema / HIR / MIR 对二元运算改为沿左脊迭代。嵌套 `if` 等前缀
      形式超过 64 层时由 parser/sema 给出 `expression nesting exceeds 64`。
- [ ] 在 Linux/macOS、1/2/4 CPU worker 下验证有限工作流；测试设置超时，
      回收失败子进程，使用内容校验和资源计数验证结果。
- [ ] 建立长跑和故障注入验收记录，覆盖完成、失败、取消、慢 I/O、迟到
      回调；对无法中断的 syscall 使用可释放的受控后端，避免测试永久卡住。
- [ ] 更新语言文档、示例和根 README 中过时的能力状态；性能结果记录
      环境与统计方法，区分 JIT 编译开销、执行耗时及排队时间。

## 实施顺序与暂缓项

1. **5.0 → 5.1**：先让验收可信，再解决长期生命周期与句柄回收。
2. **5.2 → 5.3a → 5.3b**：先控制任务生产，再扩展小文件和分块 I/O。
3. **5.4**：示例随各项实现逐步验证，全部完成后进行跨平台与长跑验收。

本阶段暂缓：借用 `self` 跨挂起的所有权扩展、所有 machine-entry 返回
类型的全面放开、timer identity 特判移除、未完成 parent 链压缩，以及
`io_uring`/IOCP 等新后端。只有某项成为上述工作流的实际阻碍时，才记录
证据并调整范围；不把这些长期研究任务自动算作 phase5 的完成条件。
