# 持久实例、数值类型与 Godot 脚本接入开发计划

状态：2026-10-04，基线 `8a03ed7`，**P0–P4、N0–N4、G0–G2 均未开始**。
本文只规划开发，不表示当前 VM 已支持持久实例或浮点，也不包含本轮实现。
文中的接口名称是设计占位，不能作为当前可执行示例。

目标是在官方标准版 Godot 中直接挂载 `.jk` 脚本，由嵌入的 Joky VM 加载和执行。
首版使用 Interpreter；GDExtension 适配库需要构建，用户修改 Joky 脚本不需要 AOT。
JIT 可在后续作为可选执行后端。语言基础仍要求 JIT、解释器和 AOT 语义一致，
AOT 回归不等于要求 Godot 用户采用 AOT 工作流。

本文负责实施决策、阶段依赖和验收。通用数值语法目标以
[syntax.md](syntax.md#101-基础类型与字面量推导)为准；阶段落地后，实际用法进入
[language.md](language.md)，存储与 ABI 不变量进入 [architecture.md](architecture.md)，
字节码格式进入 [interpreter.md](interpreter.md)。不将计划提前写入已实现能力表。

## 1. 当前基础与缺口

| 领域 | 基线已具备 | 本计划需要补齐 |
| --- | --- | --- |
| 值与清理 | 记录、枚举、元组、String、拥有容器、移动和 Drop | 受检的宿主持有根值，以及跨根调用的存储与清理责任 |
| 根执行 | 同步根调用和 CPS 任务管理自己的 arena | 实例寿命独立于调用；临时分配不积累到实例 |
| 嵌入 | Rust VM、有限类型的 C VM/CPS 入口、模块重载和旧代码保活 | 实例构造、方法调用、销毁、类型描述与重入检查 |
| 并发 | `@suspends`、scope/race、定时等待、取消和 stop 协议 | 非阻塞宿主驱动、实例所属任务、帧与事件唤醒 |
| 数值 | Int32/Int64/UInt8/UInt32/UInt64、Rune、整数运算与转换子集 | Float32/Float64、Int8/Int16/UInt16，以及相应调用和存储路径 |
| Godot | 尚无脚本语言适配 | `.jk` 资源、脚本实例、回调、对象句柄和属性桥接 |

原生同步包装入口负责创建并清理 arena；解释器的 Execution 拥有执行 arena。
String 和动态容器的底层分配也登记在任务 arena；当前移动清理项的实现不能直接充当跨域转移。
实现依据见 [根调用与 arena](architecture.md#隐式任务-arena)、
[缓冲区](../src/runtime/buffer.rs)、[清理登记](../src/runtime/cleanup.rs)、
[VM 入口](../src/vm/engine.rs)及[既有借用设计](arena-borrowing-ffi.md)。

## 2. 持久实例的目标模型

### 2.1 三种寿命与一个拥有根

| 对象 | 拥有者与寿命 | 不变量 |
| --- | --- | --- |
| 代码与类型快照 | 模块版本；被实例、调用和析构描述保活 | 重载不改变旧实例的布局、方法和析构代码 |
| 实例状态 | 宿主创建的独立根值，直到显式关闭或 VM 关闭 | 同一脚本的多个实例共享代码，状态互不共享 |
| 调用临时存储 | 一次同步调用或独立异步任务 | 正常完成、失败或取消后清理，不延长到节点寿命 |

实例是一个普通 Joky 记录及其递归拥有的数据，不要求新建类系统、GC、语言级 Rc，
也不要求用户显式传 Arena。宿主只保存不透明、带类型和所属 VM 校验的 InstanceId，
不能取得可长期保存的内部记录指针。概念操作是 create、call、close，最终拼写由 P0 冻结。

InstanceId 标识身份，不代表把根值复制了一份。首版每个根只有一个清理责任方；
句柄需包含或验证 VM 身份和不可混淆的代次，拒绝跨 VM、过期、重复关闭和错误类型。
VM 关闭时关闭全部实例；Godot 的节点销毁负责提前关闭对应实例。
这与可独立于 VmEngine 存活的既有 continuation 契约分开，不能暗中修改旧接口行为。

### 2.2 首版允许持久保存的类型

必须由编译器按完整类型递归检查，不能由宿主声称“这个类型安全”，也不能只检查 Copy。

| 类型 | 开放阶段与要求 |
| --- | --- |
| 已实现整数、Bool、Rune、Unit 及无引用的简单聚合 | P1；Rune 保持合法标量约束 |
| Float32/Float64 和新增整数 | 对应 N 阶段完成后接入，不因根存储按位保存就跳过类型验证 |
| String、无引用元素 Array、含这些拥有字段的记录/枚举/元组 | P2；完整分配与清理描述可转移 |
| Map、StringBuilder 及更复杂的拥有组合 | P3；逐类审核隐藏分配、元素清理和失败状态 |
| `&T`、`&mut T`、视图或递归包含它们的类型 | 首版拒绝；不能保存某次调用的借用 |
| Ptr、任意宿主 opaque 值、函数值 | 首版持久状态拒绝；Copy 不证明外部资源或代码寿命 |
| 受检的引擎对象句柄 | G1 单独接入；具有失效检查，不是直接保存 Node 地址 |

通用持久类型不是 Godot Variant 的别名。脚本状态保留 Joky 静态类型，只有绑定边界做转换。
用户不能通过把 Ptr 塞进整数的未受检通道绕过对象寿命规则。

### 2.3 调用期间的存储转移

首版优先验证“完整拥有根进入调用、返回后重新持久化”的实现路径：

1. 校验句柄、方法、参数、类型版本和调用预算，将实例标记为 Busy。
2. 将根值及其全部拥有分配的管理权交给本次调用；只转移存储登记和清理责任，不调用 Drop。
3. 方法取得受检的短期接收者借用；状态更新和临时分配使用统一、可清理的执行上下文。
4. 正常返回后结束全部借用，由可信类型描述枚举最终状态仍拥有的分配，准备移回持久存储。
5. 清理其他局部值及临时分配；清理和转移全部成功后才发布结果，并恢复 Ready。

这个路径避免首版就在每个字段赋值点加入跨域提升，也避免每帧深拷贝整个状态。
记录的根存储保持稳定，字段地址、内联聚合存储和清理描述不得指向已经退出的帧。
构造采用同样的出口协议：构造成功的根在临时 arena 清理前接管所有存储；失败不发布句柄。
P0 必须先用探针证明这些条件可实现，再确定实际数据结构，不能把“移动”当作现有免费能力。

转移对象包括控制块、载荷、嵌套元素、析构描述及其代码依赖，不能只搬最外层 Buffer。
Map 的表存储和 StringBuilder 的内部数组也必须有可审计的所有权描述。
不遍历普通引用图，不延长整个调用 arena 的寿命；因此持久类型首版排除借用和共享对象图。
普通 alloc 产生的对象没有明确拥有者出口，不能自动提升进实例。

**故障原子性：** 转移分为预检/预留与提交。提交期间不得挂起、调用用户代码或执行会失败的分配。
任意时刻只有一个清理责任方；失败路径记录实际已初始化、已转移的部分，不能双重析构。
调用入口预检失败保持原实例不变；进入用户方法后的执行、析构或出口失败将实例置为 Failed，
释放其剩余资源，只保留诊断和身份记录，不能继续调用或发布部分结果。已有外部副作用不回滚。

**预算：** 实例长期预算、调用临时预算和 VM 总预算分别可检查；同一分配在转移中只计费一次。
根值已有存储在进入调用时不能凭空重新消耗一份 64 MiB 配额，也不能使新分配不再计费。
计算持久出口总额时包含新存入状态的拥有分配；峰值仍受 VM 总预算约束。
预算和登记元数据一并迁移，销毁后必须归零；现有普通根任务预算不随本功能静默改变。

首版枚举成本与拥有分配数量相关，容器扫描还可能与元素数量相关；不宣称逐帧调用是 O(1)。
P0 记录成本模型，P3 再独立测量。以后可优化分配所属域和增量登记，但必须保持相同可观察语义。

### 2.4 方法、借用与重入

首版实例方法同步执行，接收者不逃逸；方法导出描述需证明调用期间获得的状态引用不会被返回、
存入外部长期存储或跨宿主回调保留。复用来源检查与 `@noescape` 能力，必要的根来源扩展放在
共享 IR；不能仅由 Godot 插件构造一个 unchecked 引用。
参数和结果先限已验证标量及复制到宿主的文本，不开放任意宿主记录内存或借用结果。
现有“经引用取得内联字段借用”的限制也需在 P0 审核：状态中的 String/Array 方法调用
需要合法的字段重借用。P2 只开放已经证明的路径，并覆盖 helper、别名和字段替换；
不能为实例方法整体关闭现有借用检查。

同一实例的 read/call/write 均串行。用户代码可能经引擎信号同步回调自己，必须检测 Busy；
首版拒绝这类重入并给出诊断，不递归取得第二个可变借用。不同实例交叉调用也需跟踪真实调用栈，
不能用“单线程”代替检查。执行中的关闭请求延迟到安全出口；不得在回调栈中释放正在使用的状态。

状态转换为 Ready → Busy → Ready，执行失败进入 Failed，关闭经过 Closing 到 Closed。
Failed 只允许读诊断和关闭；关闭无论析构是否报错都使句柄失效，不能为重试再执行一次 Drop。
VM 析构必须继续清理其他实例并保留首个错误的可报告信息，不让一个失败根阻断全部清理。

### 2.5 异步与重载的边界

持久状态不等于一个永不结束的 CPS 根任务。P1–P3 不允许实例接收者借用跨 Pending。
P4 的异步工作持有经过验证的独立输入或实例身份，通过短同步访问段读写状态，等待时归还借用。
已有任务句柄还需核对节点是否存活、实例代次和代码版本；不能让暂停的旧工作写入新建实例。

销毁顺序固定为：禁止新工作 → 取消所属任务 → stop 确认外部访问结束 → 清理任务临时资源
→ 析构实例状态 → 释放代码与类型快照。复用现有同步 stop 契约，异步 draining 不是首版前提。
Godot 的普通帧回调保持同步；较长流程显式创建实例所属任务，不把每帧回调隐式变成重叠任务。

重载先编译并验证新模块，成功才发布。旧实例继续绑定旧布局、方法和 Drop，新实例使用新版本；
编译失败保留旧模块。首版支持修改文件后重新运行，运行中保留状态的迁移不在验收范围。
不能按记录名相同推断布局兼容；以后迁移需独立的版本契约、转换和失败恢复方案。

## 3. 数值类型的范围与语义

### 3.1 交付范围

| 类型或能力 | 计划 |
| --- | --- |
| Float32、Float64 | 优先，分别固定为 binary32 / binary64，不由引擎构建精度改变 |
| Int8、Int16、UInt16 | 补齐 8/16/32/64 位整数族；UInt8 已实现，审计其未开放的 ABI 入口 |
| Bool、Rune | 保持独立类型；不自动参与数值转换 |
| USize、ISize | 后续目标；不作为此次 Godot 接入前置条件，不改变现有 UInt64 长度/下标接口 |
| Vector2/Vector3、颜色、变换 | G1 的普通记录或绑定库类型；不作为新的语言数值原语 |
| Float16、128 位整数、Decimal、定点数、SIMD | 本轮不规划实现；确定性模拟需要时单独设计 |

整数字面量的上下文定型、默认 Int32、同型运算和显式转换继续沿用现有规则。
浮点字面量默认 Float64；明确 Float32/Float64 上下文可接受未定型整数 token，
已定型整数变量不能隐式转为浮点。保留语法草案中“小数点两侧都有数字”的约束，
先支持 `1.0`、`1.5e-3`，不支持 `.5`、`1.`、`1e3` 或类型后缀。
词法检查必须覆盖数字分隔符、指数符号、成员访问点及非法连续 token。

### 3.2 浮点运算与可重复性

- 首版提供同型的加减乘除、一元负号和比较；位运算、移位和 `%` 不接受浮点。
  浮点余数若需要，作为另行定义的具名库函数加入。
- 基本运算采用舍入到最近、偶数优先，支持次正规数；溢出产生无穷，除零和无效运算遵循浮点规则。
  有符号零必须保留；NaN 不等于自身，有序比较遇 NaN 为 false，`!=` 为 true。
- 不启用 fast-math，不重关联表达式、不隐式融合乘加，也不能应用会改变 NaN/有符号零的整数恒等式。
  常量折叠按目标精度计算；Float32 字面量不得先舍入成 Float64 再随意窄化。
- 原始浮点不实现 Eq/Hash，不能直接作为 Map key；作为 Map value 或 Array 元素仍可支持。
  近似比较是独立方法，不改变 `==`；NaN payload 和符号不承诺跨后端保留。
- 运行环境必须满足舍入与次正规数要求。嵌入边界要审核宿主是否改变浮点环境，
  在需要的平台设置并恢复相关状态，或明确拒绝不支持的配置，不能静默接受 FTZ/DAZ 差异。
- 不宣称不同平台的全部数学库调用逐位一致；`sin`、`cos` 等函数采用单独误差规格。
  本阶段不能据此承诺客户端和服务器浮点锁步确定性。

数值字面量超过目标有限范围时编译报错；极小值按规定舍入为次正规数或零。
NaN/无穷通过明确的关联常量或运行结果表达，不能把非法数字 token 当作特殊值。

### 3.3 转换与最小数学库

| 转换 | 目标契约 |
| --- | --- |
| 整数 → 整数 | 扩展现有 wrapping 内建与返回 Option 的受检方法，保持两者区别 |
| 整数 → 浮点 | 具名显式转换；按目标精度舍入，文档说明可能丢失整数精度 |
| Float32 → Float64 | 具名显式转换；有限数值精确扩展，不承诺 NaN payload |
| Float64 → Float32 | 具名显式舍入转换；有限溢出为无穷、下溢按目标规则；另设受检版本时不得暗换语义 |
| 浮点 → 整数 | 先显式选择截断或舍入，再检查结果范围，返回 Option；NaN/无穷/越界为 None |
| 浮点 ↔ 位模式 | 单独的受检宽度匹配接口，如 to_bits/from_bits；不复用数值转换 |

浮点转整数不能直接依赖平台的饱和 cast 或会 trap 的机器指令。
范围判断针对舍入后的数学整数，覆盖 Int64/UInt64 上界在 Float64 中不可精确表示的情况，
不能先把整数 MAX 转成浮点后用 `<=` 判断。对负小数截断成零等边界也必须固定语义。
新增转换函数的最终名称和重载策略由 N0 确定；不把浮点偷偷加入 `int32(...)` 等 wrapping 接口。

首批库能力为 is_nan/is_finite、abs、sqrt、floor/ceil/trunc、明确采用 ties-to-even 的 round，
以及调试所需的浮点格式化。最小数学函数必须定义 NaN、无穷、负零和越域行为。
格式化目标是区域设置无关、有限值可往返到相同精度，并固定 NaN/无穷/负零拼写；
完整解析、三角函数、插值、近似比较和向量算法可后续加入，不阻塞整数状态原型。

### 3.4 后端、布局与宿主 ABI

新增类型贯穿词法/AST、类型推导、共享 IR、常量折叠、布局、解释器值和字节码、
原生 direct/CPS lowering、函数值调用、容器元素、宿主注册与诊断，不能只增加几个二元运算分支。

浮点在内存中使用 4/8 字节及目标平台对齐；内部槽可以保持既有宽度，但存取必须按位编码，
不能数值转换成整数。Float32 的槽高位规范、聚合传参与返回的槽编解码、CPS result 位模式
都在 N0 固定，并在 direct、间接调用和 Pending/恢复之间一致。整数窄位宽也需统一扩展规则。
目前聚合返回路径中的整数截断不能直接用于浮点。

宿主直接调用必须使用正确的浮点寄存器调用约定，禁止把浮点函数地址强转成整数函数调用。
新增受检 VM 调用及注册接口，支持所需的混合标量参数；原有整数 convenience API 继续严格验签。
内部实例调用描述、语言内部聚合 ABI、公开 C ABI 三者分开，不把私有槽布局暴露成 C 记录。
扩展 `#repr(C)` 浮点/窄整数成员和引用参数前，验证 size/alignment/offsetof 与实际 C 编译器；
任意聚合按值 FFI 仍不因数值布局相同而自动开放。与
[FixedArray 计划](fixed-array-storage-ownership.md)共用数值布局结论，不重复设计转换规则。

## 4. 实施阶段与完成条件

每阶段交付代码、行为测试和当前能力文档更新；未满足验收不能只因接口可编译就标记完成。

### 4.1 持久实例线

| 阶段 | 工作与依赖 | 最小验收 |
| --- | --- | --- |
| P0 契约与探针 | 固定受支持类型、句柄、根描述、转移协议、预算、失败状态；探查现有清理链 | 证明拥有根可与临时 arena 分离；覆盖转移每个可失败点、重入和描述寿命；记录遍历成本 |
| P1 简单实例 | 依赖 P0；构造、同步调用和销毁无引用简单记录，checked 根接收者入口 | 两个实例连续调用互不干扰；错类型/过期/跨 VM 句柄拒绝；构造失败不发布，调用失败不能继续；VM 关闭释放根 |
| P2 拥有状态 | 依赖 P1；String、Array 与受支持嵌套记录/枚举/元组、Drop 和预算转移 | 字段反复替换及时释放旧值；嵌套拥有值无双重清理；出口失败安全；短循环中临时和登记存储不随调用次数增长 |
| P3 容器与稳定性 | 依赖 P2；Map/StringBuilder、复杂组合、旧代码保活和压力测试 | Map 扩容/删除、元素 Drop 失败、旧实例重载后执行及销毁；长期预算和元数据回到基线；单独记录转移性能 |
| P4 宿主驱动任务 | 依赖 P2；任务组、非阻塞推进、外部唤醒、时钟注入、短状态访问段 | Pending 不忙轮询或重放；过期唤醒被忽略；挂起不占实例借用；销毁先 stop 后释放状态 |

P0 可先提交独立探针；探针不等于已经交付持久实例。P1 即提供不依赖 Godot 的 Rust 嵌入测试。
P4 只承诺协作式调度：限制轮询次数不能抢占一个不让出的 native 调用，
编译、宿主回调与析构耗时也不能被解释器指令限额自动覆盖。帧预算必须报告真实边界。

### 4.2 数值线

### 4.3 Godot 适配线

| 阶段 | 依赖与交付 | 最小验收 |
| --- | --- | --- |
| G0 脚本语言原型 | P1；锁定实际安装的 Godot 版本及扩展 ABI，注册语言/脚本资源/实例 | 普通 Node 直接挂 `.jk`；解释器执行 `_ready`；两个节点具有独立整数状态；保存场景后重开仍绑定脚本；文件与行号诊断正确 |
| G1 有状态游戏脚本 | P2 + N2 + N3；基础属性、对象句柄、Float64 帧回调和显式向量转换 | 同一脚本控制两个节点；多帧改变状态和属性；修改源码重新运行生效；节点失效检查、重复创建销毁及编辑器停止安全 |
| G2 异步脚本 | G1 + P4；下一帧、物理步、信号、游戏/真实时间与任务所属关系 | 等待信号后继续；暂停时游戏时钟停止而真实超时继续；切场景或删节点先取消任务再释放状态；重复就绪不重复执行 |

Godot 的脚本集成入口参考
[ScriptLanguageExtension](https://docs.godotengine.org/en/stable/classes/class_scriptlanguageextension.html)与
[ScriptExtension](https://docs.godotengine.org/en/stable/classes/class_scriptextension.html)。
仍需实现对应资源加载/保存、脚本实例调用和释放协议；只注册一个自定义 Node 类不满足 G0。
首版可用扩展侧元数据声明脚本根类型、基类和回调映射，具体格式在 G0 开发前冻结，
不要求先把 Godot 继承语义加入 Joky 核心语言。GDExtension 自身卸载前必须排空所有实例与任务。

Godot `int` 是有符号 64 位，`float` 是 64 位；默认 Vector2/Vector3 分量为 32 位，
双精度构建会改变向量精度。绑定必须按实际目标生成并验证转换，不能按名称直接重解释内存。
UInt64 超出 Int64 范围时不能静默塞进 Godot int；Float64 向向量分量的窄化应有明确契约。
依据：[int](https://docs.godotengine.org/en/stable/classes/class_int.html)、
[float](https://docs.godotengine.org/en/stable/classes/class_float.html)、
[Vector2](https://docs.godotengine.org/en/stable/classes/class_vector2.html)。

首轮顺序建议：P0 → P1 → G0，同时按依赖推进 N0 → N1；随后 P2、N2/N3 → G1，
再交付 P3、N4 与 P4/G2。
完整脚本编辑器补全、断点调试、工具脚本、保状态热重载、全部引擎 API 自动绑定、移动端/Web 导出
另设阶段；G0/G1 不能宣称已经全面替代 GDScript。核心语言与存储实现不依赖 Godot。

## 5. 验证矩阵与完成后的文档归属

持久实例必须测试构造、调用、替换、重入、关闭和失败的全部出口。重点包括：

- 无引用类型筛选穿透别名、泛型实参和嵌套聚合；拒绝被隐藏的引用、视图和外部裸资源。
- 第一次调用后状态仍有效；多实例共享代码但不串状态；VM 关闭、句柄代次和重复关闭行为一致。
- 所有转移预检、预留与出口失败点的清理责任；Drop 失败继续必要清理，记录首错、不发布成功结果。
- 重复短调用中临时载荷、arena 登记项、清理元数据均不增长；更换长期字段后旧预算退还。
- 新旧模块并存、加载失败、关闭 VM、代码所有者释放顺序；旧 Drop 不访问已卸载代码。
- P4 增加逐边界取消、迟到唤醒、关闭期间重入、外部 stop 和无副作用重放检查。

数值矩阵按类型 × 运算 × direct/CPS × 后端组织，覆盖常量折叠与运行时计算、
函数值、聚合返回、泛型、容器、宿主往返及源码诊断。有限基本结果按目标位模式核对，
NaN 按分类检查，负零单独检查；数学库采用已声明的误差规则，不以宽泛容差掩盖基础运算错误。
初期跨平台未执行的 ABI 必须列为未验证；单平台通过不能宣称全部 Godot 导出平台可用。

遵守 [AGENTS.md](../AGENTS.md#按改动范围验证)：

- 本次纯规划文档只审查内容、链接和 `git diff --check`，不运行 Cargo 或检查脚本。
- 独立探针按测试改动验证，Rust 格式和 Clippy 加受影响测试；涉及生成代码时覆盖三后端。
- P/N 阶段涉及跨模块语义、ABI、存储或所有权，先针对性测试，提交前运行 `./scripts/check.sh --full`。
- Godot 适配按实际改动范围验证；核心检查不会自动执行 Godot 验收，需另跑场景加载、
  无界面生命周期测试和可视化运行检查。同一版本 full 已通过时不再重复 quick。
- 压力穷举使用已有 ignored/exhaustive 约定；性能独立测量，不加入耗时断言。
