## 1. 基线与首版范围

基线已有拥有型元组解构、枚举递归载荷模式、共享/独占借用式 match，以及消费整个原记录的
单字段移出，当时尚无记录模式。本次实现复用 [patterns.rs](../src/core/ir/patterns.rs)、
[borrowing.rs](../src/core/ir/borrowing.rs) 和 [cleanup.rs](../src/core/ir/cleanup.rs)
的来源及清理机制，不能把多字段解构简单展开成连续字段移出：第一次移出已经消费原记录。

首版交付 `let` / `var` 的完整、重命名、忽略和嵌套记录模式，整体消费式拥有值解构，
共享借用解构，以及枚举 match 载荷中的记录模式。Copy 按值模式可用于已有 CPS 路径；
拥有记录与共享借用解构先限同步函数，但必须支持解释器内部时间片和取消。
独占借用解构、部分移动后继续使用原记录、函数参数模式和解构赋值不属于首版。

## 2. 目标语法

### 2.1 绑定与嵌套

```joky
struct Point { x: Float64, y: Float64 }
struct Segment { start: Point, end: Point }

let Point { x, y } = point
let Point { x: left, y: top } = point
let Point { x, .. } = point
let Segment {
    start: Point { x, y }
    end: _
} = segment
```

- `field` 是 `field: field` 的模式简写；`field: pattern` 可重命名或递归匹配。
  本阶段仅交付模式语法；构造字段简写已在后续实现，见[记录](language.md#记录)。
- `..` 表示忽略所有未列字段，最多一次，必须位于末尾，允许其后的尾随逗号；
  不写 `..` 必须列全字段。`_` 忽略一个字段，不能以两个同名字段或重复绑定名掩盖错误。
- 字段顺序可与声明不同；不存在的字段、重复字段及错配的名义类型均为编译错误。
  `Type {}` 只匹配空记录；非空记录全忽略写 `Type { .. }`。
- 字段间沿用第 1 项的换行或逗号规则。模式没有副作用表达式，不能写默认值或范围查询。
- `let` 产生不可重新赋值的绑定，`var` 产生可重新赋值的绑定；首版不在同一模式内混用
  单字段 `mut` / `var` 标记。`var` 不会把共享引用变成独占引用。
- 类型路径支持模块限定名、透明别名和泛型实例。无显式参数时从右侧名义类型推导；
  显式写法采用现有表达式路径风格 `Pair::<Int32> { ... }`，不能换成新的泛型分隔规则。
- 支持对整个绑定加类型注解，如 `let Point { x, y }: Point = point`；
  冒号在模式内部表示字段映射，在右花括号后表示整体类型，两者不得混淆。
- 右侧只求值一次，所有新名字在整个初始化/解构成功后才进入后续作用域，不能在右侧提前引用。

### 2.2 与其他模式组合

```joky
let (Point { x, y }, label) = pair

match result {
    Ok(Point { x, y }) => x + y
    Err(_) => 0.0
}
```

记录模式本身不可失败；`let` / `var` 中的所有嵌套模式也必须不可失败。
例如在字段内指定某个枚举变体仍可能失败，不能通过 `let` 静默丢弃其他情况。
枚举 match 的载荷中允许记录模式，复用已有覆盖检查；不借本计划开放顶层记录 match、
模式守卫、字面量模式、`if let` 或 `while let`。

### 2.3 私有字段

显式列出的字段（包括 `field: _`）都必须可见；公开类型不自动公开字段。
`..` 可以省略调用方不可见的字段，但不能绑定、查询其名字或借用其内容。
这样外部模块能解构公开字段，并安全消费其余私有状态；所有权与 Drop 限制仍然适用。
没有 `..` 且存在不可见字段时拒绝解构，诊断不泄露不必要的私有字段清单。
模块别名、透明别名、泛型实例和公开泛型函数的定义作用域必须保持同样的规则。

## 3. 值、借用与析构

### 3.1 按值解构

```joky
struct User { name: String, score: Int32 }
let User { name, score } = user
```

Copy 记录复制字段，原值仍可用。拥有型记录整体被消费，绑定的拥有字段转移到新变量，
Copy 字段产生快照，之后不能再读取或修改原记录的任意字段。
忽略的拥有字段在解构结束、下一用户表达式执行前清理，不能继续挂到原变量作用域等待退出。
这与基线单字段移出的剩余字段清理时机不同；本计划不暗中改变已有字段移出语义。

先完成静态检查和运行时必要预检，再准备字段投影与清理责任转移，最后发布全部绑定。
忽略字段按记录自身的析构顺序（声明序，与整个记录直接离开作用域一致）清理；嵌套记录递归遵循同一规则，模式书写顺序不改变清理次序。
新绑定按模式书写顺序发布，正常作用域退出时逆发布顺序销毁，具体证据见第 8 节。
无副作用的投影不得重复执行右侧调用或任一字段初始化。

若初始化或忽略项的 Drop 失败，解构不正常完成：保留首错，继续清理其他未转移项和
已经转移但尚未发布的绑定。任一拥有资源恰好一份清理责任，不能泄漏、重复 Drop，
也不能让后续代码看到半初始化绑定。别把多个标量槽分别转移视作已经转移整个拥有字段。

### 3.2 自定义 Drop

有 Drop 祖先时禁止通过模式移出其拥有字段；这是原有规则在记录模式上的延续。
没有 Drop 祖先时，某个字段自身可以实现 Drop：整体绑定该字段合法，其 hook 随拥有权一起转移；
继续展开该字段并移出其内部拥有者则拒绝。

只复制 Copy 字段、其余用 `_` / `..` 忽略时，不拆掉有 Drop 的记录；
复制完成后对完整被消费值执行正常 Drop，再清理字段。
共享借用解构可读取可见字段，不运行或绕过 Drop。
必须通过 `mem.replace` 等显式方法取走资源时，仍要求原对象保持完整初始化。

### 3.3 共享借用解构

```joky
let User { name, score } = &user
```

沿用共享借用式 match：Copy 字段绑定为值快照，拥有字段绑定为 `&T`，嵌套模式继续投影，
不会把拥有字段从借用对象中移出，也不因 `_` / `..` 清理任何原字段。
支持显式 `&value` 和已有的 `&Record`，后者不能错误地产生双重引用。
若 Copy 字段本身含共享引用，复制后仍传播原引用来源与存储条件。

所有视图追溯到原拥有者，按现有借用规则限制替换、移动、销毁和逃逸。
首版保守借用整个记录，不开放字段互不相交即可独占访问的拆分优化。
局部借用不能返回或放入长期实例，临时拥有记录不能因取引用解构而延长到非法寿命。
对 arena 对象内联字段的投影继续服从当前受支持路径；未支持的路径明确拒绝。
`&mut Record` 的解构首版拒绝，不能暗中降为共享模式或复制独占引用。

### 3.4 暂停、清理与代码保活

首版允许 Copy 按值解构结果进入已有 CPS 帧；拥有记录解构和新的借用投影不得跨语言挂起。
同步 helper 在完成其解构和清理后返回普通受支持结果，仍可被挂起函数调用。
解释器内部时间片不等于语言级 `@suspends`：同步解构也必须在时间片、取消、失败和 VM
销毁时维持清理责任；转移登记的短临界区沿用现有不可中断规则。
旧模块中定义的字段 Drop 必须由旧代码所有者保活，不能在模块替换后调用新布局的 hook。

## 7. D0：模式与责任模型（已冻结，2026-10-07）

实现映射与不变量，作为 D1–D5 的验收基准。行号以冻结时源码为准。

### 7.1 AST 与解析

- `BindingPattern` 新增 `Record { name, type_args, fields, rest, span }`；
  `RecordFieldPattern { name, pattern, span }`，简写 `x` 在解析期脱糖为 `x: x`。
  `PayloadPattern` 新增相同的 Record 变体，供枚举载荷使用。
- 头部解析为点分路径，可选现有 `::<T>` 显式参数，随后必须有 `{`。字段分隔沿用
  `expect_braced_separator`（逗号或真实换行）；`..` 由两个 `Dot` token 组成，最多一次、
  必须位于末位，其后允许尾随逗号。`let`/`var` 的整体类型注解在模式之后，语法不变。
- 绑定名重复在模式内全局判重（`HashSet` 语义，与元组一致）；`_` 不进作用域。

### 7.2 名称、可见性与完备性

- 头部经 `named_type` 解析：模块限定名、透明别名与泛型实例统一走 nominals。
  无显式参数且右侧同 id 时直接采用右侧实例；显式参数经 `instantiate_record`，
  参数数量与右侧 arguments 不符即为错配名义类型，报编译错误。
- 每个显式列出的字段（含 `field: _`）逐个经 `check_field` 可见性检查；
  不存在的字段报 `UnknownName`，重复字段报 `DuplicateDefinition`。
- 无 `..` 时必须列全字段：缺可见字段报缺失清单；存在不可见字段时拒绝解构，
  诊断不列私有字段名。`..` 可省略任何未列字段，包括不可见字段。

### 7.3 绑定发布与清理顺序

- 右侧求值一次；先完成全部静态检查与叶子槽位解析，再按**模式书写顺序**统一发布
  绑定（与元组解构一致），发布前右侧错误已按既有构造失败路径处理。
- 拥有值解构：每个拥有叶子经新增内部 `BufferOp::Detach`（运行时行为与 `Extract`
  相同：转移选定子树的清理责任与标量；借用分析仅消费选定子树，区别于基线
  单字段移出 `Extract` 的整体消费）。全部叶子发布后立即 `BufferOp::End(owner)`：
  忽略字段按记录自身的析构顺序（声明序，与整个记录直接离开作用域一致）释放，
  先于下一用户表达式。
- 新绑定进入 `local_scopes`，作用域退出按既有逆序销毁；`End` 与作用域退出对同一
  owner 的重复结束是幂等的（清理表 `take` 语义）。
- Drop 失败：保留首错并继续清理（`Cleanups::end` 语义）；每个拥有资源恰好一份
  清理责任。RHS 失败时未发布绑定不可见，已求值字段沿用构造失败的既有兜底。

### 7.4 Drop 与借用规则

- 转移拥有叶子的路径经 `check_owner_projection`：祖先实现 Drop 即拒绝；
  字段自身实现 Drop 时整体绑定合法（hook 随拥有权转移），继续向内移出则由同一
  检查在下一层拒绝。仅 Copy 绑定加 `_`/`..` 忽略时不拆 Drop 记录，
  `End` 对完整被消费值正常运行一次 Drop。
- `&Record` 共享解构：根引用经 `PatternProject` 链按存储布局字节偏移投影；
  Copy 字段经 `read_local` 产生值快照，拥有字段绑定 `&Field` 视图，嵌套递归投影，
  不移动、不清理原字段。`&mut` 解构拒绝；引用与拥有解构限同步函数
  （Copy 记录模式不限）。`var` 的共享视图经既有引用复制语义获得可重赋值绑定。
- 借用分析沿用 `Projection::Pattern` 路径判定兄弟不相交；arena 根保持整对象契约，
  与首版保守整记录借用的设计一致。

### 7.5 不可失败与覆盖

- let/var 文法上不可能包含变体模式，嵌套全部不可失败；match 载荷中的记录模式
  coverage 记为 `Any`，不改变可用性分析，复用既有覆盖检查。

## 8. 实施记录（2026-10-07）

实现与第 7 节冻结设计的偏差：

- 忽略字段的释放顺序与 D0 表述不同：实测单个记录离开作用域时其字段按**声明序**
  Drop（见 `record_patterns_baseline_scope_exit_order` 的 [-1, 1, 2]），
  `End` 沿用同一顺序，保证"解构后的忽略项"与"整个记录直接销毁"不可区分；
  绑定叶子仍在作用域退出时按逆发布序销毁。第 3.1 节已同步为记录自身的声明顺序。
- 独占借用解构（`&mut`）在借用入口（`borrow_local`）已被既有规则拦截
  （`let` 根绑定不可独占借用），运行时另有 `Exclusive references cannot be
  destructured` 拒绝。
- Drop 检查精确化为：Drop 记录的拥有字段被绑定/展开即拒绝；字段自身有 Drop 时
  整体绑定合法、继续展开拒绝；仅复制 Copy 字段并忽略拥有字段合法（完整 Drop）。
- `resolve_pattern_heads` 在规范化阶段把同模块别名头部改写为规范记录名，
  模块限定拼写经导入作用域解析；泛型实例化替换穿透模式类型实参。

  忽略/绑定/转移字段的 Drop 事件顺序与恰好一次；构造失败保留首错并继续清理；
  RHS 失败不发布绑定；解释器资源边界取消穷举；VM 销毁兜底清理；
  Copy CPS 挂起恢复；跨模块 pub 字段解构与私有字段/不可见字段拒绝（含 AOT 编译器拒绝）；
  Drop 展开/独占借用/挂起中拥有解构与借用解构的编译期拒绝。
