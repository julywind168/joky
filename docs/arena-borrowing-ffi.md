跨函数的返回依赖和存储前置条件由固定签名规则决定；调用方不分析被调用函数体，
但每个函数体仍必须检查其实现满足签名契约。

## 1. 目标与边界

- Arena 拥有一批内存，按任务或显式子作用域整体释放；没有对象追踪 GC，也不为每个对象维护引用计数。
- 每个同步调用的根任务默认拥有一个隐式 arena。用户不必写 `Arena.new()`；编译器在需要时向函数传递
  隐藏的 arena 能力。显式 arena 只作为需要更短释放范围、测试隔离或宿主集成的高级接口保留。
- `&T` 表示共享只读借用，`&mut T` 表示独占可变借用；编译器检查来源、有效范围和访问冲突。
- 第一版数据引用只来自 arena 分配；`&mem` 是对 Arena 控制块的特殊借用。
  借用普通局部变量需要稳定的局部存储，放在后续阶段开放。
- 生命周期由编译器推导，不提供 `'a` 之类的用户标注。跨函数只使用签名来源规则（见 3.2），
  模块接口不输出函数体借用摘要。
- 同一任务 arena 内的共享引用字段先于 FFI 开放，使链表、树和语法树等对象图可以直接表示。
- 字段访问自动解引用，函数调用自动重借用；不提供 `*expr`、`*const T`、`*mut T`。
  现有乘法运算符 `*` 不受影响。
- 保留 `@suspends` 和 `scope`；第一版仍为单线程协作并发，没有脱离 scope 的任务或多线程共享 arena。
- C 兼容布局是显式选择的类型契约；引用参数经受检查的绑定传成 C 指针。
- 正常结束、跳转、运行时失败和取消都必须正确清理；没有 GC 不意味着没有运行时支持。

第一版不包含任意析构对象、拥有型动态 String、通用可变容器、未封存的循环引用图、可变引用字段、可复用
arena 的 reset、arena 对象的单对象 free、C 聚合按值调用、任意裸地址操作或异步析构。Box / Rc 等
其他所有权形式不是 arena 的实现前提，是否加入另行设计。C 自己分配的内存不属于 arena，后续以
独立的 `ForeignPtr` 所有权模型接入。
完成阶段 0–6 不等于具备通用容器能力；纯 Joky 容器列入独立的
[容器与所有权扩展](#61-容器与所有权扩展)，以动态数组和可变链表验证所需的语言基础。

Arena 适合请求、批次、解析或编译单元。对象不再使用后通常仍占用空间，直到 arena 结束；
长期服务应按工作单元创建 arena，不能把所有临时分配积累到一个全局 arena。

## 2. 使用语法

### 2.1 创建、分配与释放

```joky
struct Point { x: Int32 y: Int32 }

fn run() {
    let point = alloc(Point { x: 1 y: 2 })
    point.x = 3
    print_int(point.x)
}
```

根任务进入时创建隐式 arena，`alloc` 将值放入其中并返回 `&mut Point`。
任务正常完成、失败、取消或 continuation 被丢弃时释放全部分配；挂起期间 arena 随 continuation 保活。
引用不能出现在任务边界的返回值、全局状态或没有保活契约的宿主回调中。

需要更短释放范围时仍可显式创建 arena；这属于高级接口，普通函数不要求用户传递它。

建议的初始 API：

| API | 结果 | 规则 |
| --- | --- | --- |
| `alloc(value)` | `&mut T` | 当前任务隐式分配；返回唯一可变访问能力，追加分配不移动已有对象 |
| `Arena.new()` | 显式 Arena 拥有者 | 高级接口；不可复制，使用通用移动和退出清理机制 |
| `share(view)` 或赋值/参数共享化 | `&T` | 从 `&mut T` 受检地重借用；共享视图存活期间冻结对应的独占访问 |
| `memory.read(view)` | T | 第一版仅支持复制 Copy 的所指值，不移出 arena 对象 |
| `memory.write(view, value)` | Unit | 要求 `&mut T`，替换整个所指值；T 限不含引用的 Copy 数据 |

`alloc`、`share` 和显式 Arena 分配是编译器认可的内建效果，与 `int32()` 等内建转换地位相同，
不是普通库方法。用户函数可以封装或转发它们，但不能把已有共享对象转换成独占引用，也不能声明
不受检查的分配效果。宿主首版不能返回 Joky 引用。
函数体检查和调用点都遵守 3.2 的规则。读写模块暂名 `memory`，不用 `ref`，
以便将来把 `ref` 留给借用模式。

Arena 拥有者在运行时是指向堆上控制块的句柄。隐式 arena 能力不作为用户值暴露，也不能作为字段、
类型实参或分配载荷。显式接口中的 `&mem` 仍是对控制块的特殊借用，不要求局部变量本身有稳定地址。
因此第一版只允许对 Arena 拥有者取 `&`，其他局部位置的借用放到阶段 4。

阶段 1 的可分配类型限定为四种现有整数、Bool、Unit 及由它们组成的记录、枚举和元组，
暂不包括 String 和宿主 opaque 句柄；阶段 2 对包含共享引用的对象开放受检构造（见 3.4）。
Arena 能力不能作为字段、类型实参或分配载荷，也不开放 `&mut Arena`。
零大小值仍有独立的逻辑分配身份；不依赖地址不同来证明借用不冲突，
也不允许对零大小对象进行越界访问。

分配先完整求值实参，再分配和初始化；不得发布未初始化引用。建议首版将分配失败作为
现有运行时失败通道中的错误，执行清理后传播，不返回空引用；可恢复的 `try_alloc` 后续设计。
大小计算溢出和预算超限必须在实际分配前检查，不能静默截断。

每次分配返回不重叠的对象，追加分配不移动已有对象，也不要求长期独占借用整个 arena。

已有借用有效时，不能销毁、替换或移动 Arena 拥有者。隐式任务 arena 不能从用户函数返回；显式
Arena 也不能放入聚合或跨任务返回。无活动借用时的局部移动、按值消费仍按通用移动规则检查。

### 2.2 由调用者提供结果存储

```joky
fn make_point() -> &mut Point {
    alloc(Point { x: 1 y: 2 })
}

fn run() {
    let point = make_point()
    print_int(point.x)
}
```

源代码签名不显示当前任务 arena；编译器内部把它视为一个隐藏的 arena 能力参数。
因此普通函数可以在同一任务内返回任务 arena 中的引用，但任务边界仍拒绝引用结果。
显式 arena helper 仍按 `&Arena` 参数的来源规则检查，不把局部 arena 的对象自动复制到其他 arena。

任务边界上的以下代码必须拒绝：

```joky
fn bad() -> &Point {
    let point = alloc(Point { x: 1 y: 2 })
    point
}
```

上例如果是任务内部的普通辅助函数可以成立；若 `bad` 是任务入口或宿主导出函数，则必须拒绝，
建议诊断：`Task-bound reference cannot escape through this return value.` 借用来源说明应定位到
任务创建和返回引用的位置，不要求用户理解内部 region 编号。

### 2.3 字段访问、绑定与重借用

```joky
fn move_x(point: &mut Point, distance: Int32) {
    point.x = point.x + distance
}

fn move_twice(point: &mut Point) {
    move_x(point, 10)
    move_x(point, 20)
}

fn run() {
    let point = alloc(Point { x: 1 y: 2 })
    move_twice(point)
    print_int(point.x)
}
```

传递已有引用时不必重复写 `&`；调用所需的短暂重借用由编译器生成，调用结束后 point 仍可用。
`&mut T` 可以短暂重借用为 `&T`，反向转换不允许。共享化不是复制，也不是把权限提升；
它是从独占写权限到共享只读权限的单向收窄。若共享视图被赋值、返回或存入对象，原独占访问
必须冻结到共享视图失效；短暂调用重借用则通常在调用结束后恢复。
重借用如果被返回值继续携带，其占用范围随返回值延长，不是一律在调用返回时结束。

`let` / `var` 控制绑定是否可重新赋值，引用类型控制所指对象的访问权限：
`let point = alloc(...)` 允许修改字段，但不允许重新绑定 point。
`point = other` 始终表示绑定赋值，不自动解释成修改所指对象。

```joky
let point = alloc(Point { x: 1 y: 2 }) // inferred &mut Point
point.x = 3
let view: &Point = point                // freezes point while view is live
```

`let` 只控制绑定是否可重新赋值；`&Point` 才控制通过该视图是否可写。

无字段的值或整个对象通过库操作读写：

```joky
fn increment(value: &mut Int32) {
    let old = memory.read(value)
    memory.write(value, old + 1)
}
```

字段访问自动解引用不意味着隐式复制整个对象。复制 `&T` 只复制受生命周期约束的借用，
不会成为新拥有者；`&mut T` 不可复制。第一版不提供引用算术、整数到引用转换和引用地址比较。

### 2.4 词法与解析

- 一元 `&` 和 `&mut` 与 `-`、`!`、`~` 同属一元优先级，右结合；低于调用、字段访问和方法调用，
  所以 `&a.b` 借用字段 `a.b`，而不是对 `&a` 取字段。
- 现有二元 `&` 是按位与。`&` 只在表达式开头的位置解析为借用；换行仍只是空白，
  `a` 换行接 `&b` 解析成 `a & b`，需要分开时写 `a; &b`。这与一元负号的规则一致。
- 词法仍把 `&&` 识别为逻辑与。第一版不支持引用的引用；在前缀位置或类型位置出现 `&&`
  时报错并说明原因。以后若开放多层引用，再规定前缀位置是否拆分该记号。
- 类型文法增加 `RefType = "&", [ "mut" ], Type`，语义层同时拒绝 `& &T`、
  通过类型别名拼出的多层引用，以及引用到不支持的目标；不能仅禁止 `&&` 记号。
- `mut` 在阶段 1 启用为保留字，`unsafe` 在阶段 5 启用；使用这些名称的现有标识符需要改名，
  须加入语法草案的迁移清单。
- `@repr(C)` 只接受这一种固定写法，写在 struct 声明之前，不引入通用属性系统；
  `@suspends` 的位置和含义不变。`extern` 后的调用约定字符串只接受 `"C"`。

以下为对应阶段启用的文法增量，不是当前可用 EBNF；其余规则沿用语法草案：

```ebnf
RefType      = "&", [ "mut" ], Type ;
BorrowExpr   = "&", [ "mut" ], Unary ;
CRecord      = "@", "repr", "(", "C", ")", [ "pub" ], RecordDef ;
CExternal    = "unsafe", "extern", '"C"', "fn", Identifier, Parameters, [ Result ] ;
UnsafeBlock  = "unsafe", Block ;
```

启用时分别为 Type、Unary、Item 和 BlockForm 增加上述备选。阶段 1 的 BorrowExpr 只接受
Arena 拥有者位置且禁止 mut，阶段 4 才开放普通位置；
不是任意临时表达式都能取引用。CRecord 的 RecordDef 以 struct 开始，属性位于 pub 之前；
重复/未知属性报错，第一版 C 记录不带类型参数。CExternal 不接受泛型或 `@suspends`，
挂起宿主仍走单独的适配协议。unsafe 块不关闭借用检查，也不改变块的求值及返回类型规则。

## 3. 不写生命周期标注的静态检查

### 3.1 引用来源

编译器为 arena 拥有者、分配和参数建立内部来源身份，跟踪每个引用的来源集合及共享/独占权限。
类型仍写成 `&Point`，内部来源不是用户泛型实参，也不占用现有泛型专门化的类型参数位置。

函数内部按控制流跟踪：分支合并取来源并集，循环用有限抽象状态迭代到稳定。
拥有者有效范围、对象别名和访问权限分别记录；同属一个 arena 不意味着两个分配互相别名。
循环中的同一分配位置可能执行多次，不能把源码位置直接当成唯一的运行时对象身份。
采用保守合并或新鲜对象抽象，保留编译预算；超限给出诊断，不跳过检查。
局部块、提前返回和循环跳转遵守同一套规则。这是局部控制流分析，不是跨函数摘要固定点分析。

### 3.2 签名来源规则

跨函数调用只看签名，不看被调用函数的函数体：

1. 返回值含引用时，它的有效范围依赖所有含引用参数的来源并集，包括 `&Arena` 和聚合中的
   引用；只在所有依赖都有效时使用。实参产生的重借用随结果延长。没有引用参数、也没有
   隐式任务 arena 或显式 `&Arena` 能力却返回引用的签名先拒绝，即使实现总返回 None，也不提供特例。
2. 返回 `&mut T` 且有 `&mut` 参数时，结果保守地可能与任意独占输入别名，也可能是新分配；
   结果存活期间冻结这些输入，不宣称结果一定是其中一个对象。没有 `&mut` 参数时，
   隐式任务 arena 或显式 `&Arena` 能力才允许返回 `&mut T`，并承诺结果是新分配对象。
3. 函数体逐个检查返回路径：不能返回局部 arena 对象或局部位置的引用；返回依赖必须满足
   签名承诺的有效范围。独占结果必须来自独占参数的合法
   重借用、新分配，或满足相同规则的函数调用。声明本身不会把共享引用变成可变引用。
   无独占输入时还须证明新对象没有逃逸别名，不能同时把它的共享借用存进 arena。
4. 签名中有 `&Arena` 参数，或函数使用当前任务的隐式 arena，意味着函数可以向该 arena 保存共享引用；
   阶段 1 先建立隐式任务内契约，阶段 2 开放含引用对象的实际存储。
   对每个非 Arena 的含引用实参，调用方必须证明其对象存储覆盖每个输入 arena 的有效范围；
   函数体可以据此存储这些输入。此规则也适用于 Unit 返回值，不依赖函数是否实际执行存储。
   对这些实参的共享/独占借用保守地保持到目标 arena 释放，不能只在调用返回时结束。
   来源不足、局部栈来源或权限不足的调用必须拒绝。

第 4 条是独立的存储前置条件：返回依赖的并集不能代替它。多个 arena 参数之间不自动产生
寿命关系；所有非 Arena 引用输入必须覆盖所有目标 arena，无法证明时拒绝。Arena 能力本身
不能存入对象。直接 alloc 保存引用时执行同样的寿命和权限检查；若保存了由独占引用得到的
共享重借用，原独占引用保持冻结到目标 arena 释放。不确定时保留这些借用，即使调用没有返回值。

规则 2 和 3 合起来保证辅助分配函数的结果互不重叠，调用方不需要看函数体：

```joky
fn make() -> &mut Point {
    alloc(Point { x: 0 y: 0 })
}

fn run() {
    let a = make()
    let b = make()
    a.x = 1
    b.x = 2    // Both fresh objects can be modified independently.
}
```

显式 `&Arena` 参数仍可用于多个 arena 之间的高级 helper；隐式任务 arena 只是把同一能力从源代码
签名中隐藏，并不取消来源、别名和存储前置条件。

多个输入可能返回的情况同样由并集处理：

```joky
fn choose(flag: Bool, left: &Point, right: &Point) -> &Point {
    if flag { left } else { right }
}
```

调用方只在 left 和 right 都有效的范围内使用结果，不根据运行时的 Bool 值承诺更长寿命。

与分析函数体相比，签名规则有这些好处：

- 模块接口保存类型、签名和规则版本，不保存函数体借用摘要；实现只要继续满足同一契约，
  不会改变调用方的借用要求。热重载仍需原有类型身份和代码拥有者检查；改变签名规则版本
  必须失效相关编译缓存，不能混用不同规则编译的模块。
- 递归和互递归不需要为摘要做固定点分析。
- 宿主首版不接收 Arena 能力、不返回引用，所以不能靠签名承诺外部指针属于某个 arena。
  引用参数仍需验证真实布局、访问权限、调用期间或 Pending 期间的有效期和取消行为。

已知的保守情形：

```joky
fn attach(mem: &Arena, owner: &mut Point, x: Int32) -> &Point
```

结果被视为同时依赖 mem 和 owner；签名存储规则还要求 owner 的存储覆盖 mem，
其独占借用保守地延长到 mem 释放，即使函数体没有存储引用。可将分配和修改拆成两个函数。
不带 arena 参数的 choose 仍只延长到结果最后使用。只有真实程序证明这些限制阻碍重要用例，
才考虑显式来源标注（见第 7 节），不预先把复杂度交给所有用户。

### 3.3 别名与泛型

同一位置可以有多个共享借用，或一个独占借用；不能同时有冲突访问。
独占借用期间也限制通过原拥有值或父引用访问对象。第一版可以保守地把同一对象的不同字段
视为冲突，不要求立即支持字段拆分借用；不同 arena 分配应可独立借用。

`&mut T -> &T` 的共享化遵守同一规则：短暂参数重借用在调用结束后结束；赋值、返回或存储到
另一个对象的共享视图会冻结原独占访问，不能从 `&T` 重新得到 `&mut T`。

目标是按控制流中的最后一次使用结束借用；早期实现可采用更保守的词法范围，但必须记录由此
拒绝的安全程序，不能为了示例通过而漏掉分支或循环上的使用。

现有泛型只接受 Copy 类型实参，`&T` 属于 Copy，因此必须明确规定：

- `&mut T` 不是 Copy，不能绑定到类型参数。否则泛型函数体可以复制 T，得到两个独占引用。
- 阶段 1 也不允许 `&T` 作类型实参，并拒绝含引用的聚合。
- 阶段 2 开放 `&T` 和含共享引用的 Copy 聚合作类型实参。代入实际类型后检查完整签名，
  包括返回依赖、arena 存储前置条件和可变引用目标限制；函数体每个实例也必须通过检查。
  不能因 T 在泛型源码中不透明就跳过检查：`alloc(value)` 可能保存 T 内的引用，
  `&mut T` 在 T 含引用时也必须按 3.4 的构造/封存规则检查。identity、转发函数、别名和固有方法遵守相同规则。
- 编译器里现有的 Copy 判定需要同步修改，不能让 `&mut T` 或含它的聚合通过。

### 3.4 含引用数据（阶段 2）

阶段 2 允许共享引用进入记录、枚举和元组，从而直接表示对象图：

```joky
struct Node {
    value: Int32
    next: Option<&Node>
}

fn push(head: Option<&Node>, value: Int32) -> &Node {
    share(alloc(Node { value: value next: head }))
}

fn sum(list: Option<&Node>) -> Int32 {
    match list {
        | None => 0
        | Some(node) => node.value + sum(node.next)
    }
}

fn run() {
    let first = push(None, 1)
    let second = push(Some(first), 2)
    print_int(sum(Some(second)))
}
```

push 使用当前任务的隐式 arena；head 内每个引用必须覆盖该 arena 的有效范围。
函数体据此验证 `alloc` 和 `share`；调用方验证条件，不从函数体推导新的跨模块约束。
同一任务中的链可以直接传入；来自更短显式子 arena 的链不能存入任务 arena。
None 没有实际引用依赖，不要求提供虚构的来源。

例如，下列调用在调用点就应拒绝，无需展开 push：

```joky
fn bad_store() {
    let outer = Arena.new()
    {
        let inner = Arena.new()
        let child = share(inner.alloc(Node { value: 1 next: None }))
        let _ = outer.alloc(Node { value: 2 next: Some(child) })
    }
}
```

child 的存储不能覆盖 outer，即使丢弃返回值也不能放行。建议诊断：
`Reference field 'next' cannot be retained by arena 'outer': its storage ends earlier.`

- 含引用的聚合值和引用一样跟踪来源，来源是其中所有引用的并集。构造、解构、match、赋值、
  泛型实例化和跨函数传递都不能丢失来源。
- 引用字段只能是共享引用 `&T`；含引用的聚合保持 Copy，复制的只是借用。`&mut T` 字段仍然拒绝。
- 值存入 arena X 时，每个引用的实际存储必须是 X 本身或确定覆盖 X 的 arena；可依据
  作用域嵌套与受保护的拥有者、或签名存储前置条件证明。不能只按变量创建顺序推断，
  也不能在 X 存活时消费或移动被依赖的外层拥有者。子 arena 引用不能存进父 arena。
- 每次存储还要保留相应借用权限。读取 X 中对象的引用字段可以保守地把有效范围收窄为 X，
  但必须保留可能别名及访问限制，不能把字段读取得到的引用标为新分配。
- `recursive_type` 检查允许经过 `&` 的环：`&Node` 不内联存储 Node，`Option<&Node>` 布局有限。
  不经过引用的环仍然拒绝。
- 含引用的对象先由 `alloc` 产生 `&mut T`，但只能在尚未发布的构造阶段写入引用字段。
  共享视图一旦被返回、存入另一个对象或传给需要 `&T` 的长期调用，原对象必须 `seal`，
  此后只能以 `&T` 访问，不能用字段赋值或 `memory.write` 绕过封存。无引用 Point 可以继续
  保持 `&mut Point` 并独占修改。
- 普通的链表和树可以在构造后立即 `share`；循环共享图需要受检查的构造器（暂名
  `graph.link` / `graph.seal`）。它在没有对外可见共享引用的阶段补齐链接，封存时一次性发布
  `&T` 视图，避免“写入 A 后冻结 B、再无法写回 B”的别名漏洞。循环对象由 arena 一起释放，
  不需要引用计数；遍历循环图仍需算法自己保证终止。
- 循环构造器的目标语义如下，具体参数形式待实现阶段确定：

  ```joky
  let a = alloc(Node { value: 1 next: None })
  let b = alloc(Node { value: 2 next: None })
  graph.link(a, b)
  graph.link(b, a)
  let root: &Node = graph.seal(a)
  ```

  `graph.link` 只接受尚未发布的构造期独占引用；`graph.seal` 完成所有链接的来源检查后，
  一次性撤销这些独占访问并发布共享视图。普通字段赋值不能绕过这两个阶段。
- 局部的按值 Node 可以复制、修改后再次 alloc，每次都重新检查来源和存储条件；已经 `seal`
  的对象不能再修改。经过引用的递归类型仍允许布局有限的环，不经过引用的类型环仍然拒绝。

### 3.5 清理与资源

Arena 的释放由通用退出清理负责。已初始化且仍拥有的资源按依赖和作用域清理，独立资源默认
逆声明顺序；已移动的值不重复释放。`return`、`break`、`continue`、失败路径和部分初始化
都必须经过清理路径。借用先失效，拥有者才能释放。

Arena 初期只回收无析构数据的内存；释放字节不等于关闭文件、socket 或 C 库对象。
这些对象需要单独的拥有包装和资源协议，现有可复制 opaque 句柄不会自动获得资源所有权。
用户析构、异步 close、拥有型 String 和容器不在首版中隐式加入。

## 4. 结构化并发与取消

```joky
fn handle() @suspends {
    let point = alloc(Point { x: 1 y: 2 })

    scope {
        | inspect_left(point)
        | inspect_right(point)
    }
}
```

示例中的 inspect_left / inspect_right 均为返回 Unit 的挂起函数。继续沿用现有 scope 的
实参先求值、分支调用、全部完成后继续的规则，不增加 async / await 或任务句柄语法。
返回 `Result.Err` 仍是业务数据，不自动变成任务失败或取消信号。

借用必须覆盖分支整个执行期间，包括所有 Pending。不能把两次 poll 之间视为借用结束。
即使单线程，也不允许两个分支对同一对象同时持有独占借用；不同分配可以分别独占。
嵌套 scope 不允许借用逃到父范围以外，arena 与 scope 也不必一一对应。

挂起时 arena 拥有者进入 continuation 的受管理状态，对象地址保持稳定。
因为第一版引用只来自 arena，跨挂起的借用天然指向稳定存储；
普通局部位置的借用在阶段 4 开放后，跨挂起仍要等帧内稳定存储方案验证后再允许。

正常路径：子任务全部完成 → 清理子任务 → 释放父 arena。
失败或取消路径：禁止启动新工作 → 请求取消 → 确认所有访问停止 → 清理子任务 → 释放父 arena。
取消请求与取消完成是不同状态；不能在请求取消时提前结束独占借用。

当前运行时通过释放分支/continuation 状态取消任务，没有任意外部异步操作的停止确认协议。
引入异步 FFI 借用前必须扩展这一机制：

- 第一版只接受能在取消入口返回前同步保证停止访问的宿主操作；取消必须幂等、不挂起、不 unwind。
- 无法同步停止的 C 操作暂不接入这种借用接口，不能假定释放 CPS 帧会停止外部 I/O。
- 后续若支持异步取消，需要显式 Cancelling / draining 状态；即使宿主丢弃 continuation，
  也由运行时持有清理操作及全部拥有者，直到停止确认。调度器关闭和错误路径必须覆盖该状态，
  不能靠用户继续 poll 一个已经丢弃的句柄。这属于后续协议，不由本提案默认实现。

宿主返回、VM 关闭、代码重载不能使挂起借用失效。现有无生命周期参数的 continuation 接口
不接受任意借用的宿主局部对象；首版要求任务持有完整拥有者。返回到宿主的引用也不能裸露于
已释放 arena 之外，首版顶层 VM 返回接口继续拒绝引用结果，后续另行提供带拥有者的结果包装。

## 5. FFI：C 布局与引用参数

### 5.1 同步借用接口

```joky
@repr(C)
struct CPoint { x: Int32 y: Int64 }

unsafe extern "C" fn inspect(point: &CPoint) -> Int64
unsafe extern "C" fn update(point: &mut CPoint)

fn run() {
    let point = alloc(CPoint { x: 1 y: 2 })
    unsafe {
        update(point)
        let _ = inspect(point)
    }
}
```

`@repr(C)`、`unsafe extern "C"` 和 unsafe 块是拟议拼写，和现有宿主 `extern fn` 分开定义。
对应 C 声明为：

```c
typedef struct { int32_t x; int64_t y; } CPoint;
int64_t inspect(const CPoint *point);
void update(CPoint *point);
```

非空、对齐正确、已初始化的引用可以映射为指针参数，但 Joky 引用的保证比 C 指针更强。
输入引用由 Joky 调用方提供，首版不从 C 获得引用结果或 Arena 能力。同步绑定契约还必须保证：
只在调用期间访问、不保留指针、
不经别名违反共享/独占权限、不 free/realloc 这块内存、不越界、不跨边界 unwind，
也不通过回调重入造成借用冲突。C 的 const 本身不能证明这些条件。
unsafe 标记承认绑定者的责任，不解除 Joky 侧的借用检查。

首版原生 C 接口仅支持引用输入和已支持的标量/Unit 结果，拒绝返回引用、可空引用、
引用到引用、变参、任意回调和跨调用保存地址。动态缓冲区、String 和 Slice 不自动按单指针传递。

### 5.2 C 所有的分配与释放

C 库如果自行分配对象，不能把返回地址伪装成任务 arena 中的 `&T`。后续资源接口暂名为
`ForeignPtr<T>`，它是不可复制、带分配器身份的拥有句柄：

```joky
let foreign = c.alloc(CPoint)
unsafe {
    c.free(foreign)       // consumes the handle; exactly once
}
```

上例只表示目标所有权关系，具体 C allocator、大小/对齐参数和类型绑定形式在 FFI 阶段确定。

`c.free` 只能消费对应 C 分配器产生的句柄，不能接收 `alloc` 返回的 arena 引用；有任何活动借用时
都必须拒绝释放。任务结束、失败和取消也要释放仍由任务拥有的 `ForeignPtr`，避免把手工 `free`
变成每条退出路径都必须正确复制的协议。若 C 接口需要在调用后保存地址，应保留 `ForeignPtr`，
并通过受检的临时借用传入；不能返回普通 `&T` 或让 C 回调持有 Joky 引用。

`ForeignPtr` 与 arena 的批量释放属于两套所有权模型。使用同一 C 分配器配对 `alloc/free`、
禁止 double free、在取消时等待异步访问停止，都是 FFI 资源阶段的独立验收条件。

### 5.3 布局可验证，但不等于完整调用 ABI

首版 C 记录限定非空、固定宽度整数和兼容的嵌套记录；Bool 编码、空记录、Unit、含引用字段、
带负载枚举、packed、union 和 C 位域后续另行规定。普通记录不因分配进 arena 就自动成为 C 类型。

在 arm64 macOS 的普通 C ABI 下，上述 CPoint 的 x 偏移 0、y 偏移 8、大小 16、对齐 8。
这些数字按目标平台计算，不能推广为所有平台常量。生成对应头文件和断言，由目标 C 编译器验证：

```c
_Static_assert(sizeof(CPoint) == 16, "CPoint size mismatch");
_Static_assert(_Alignof(CPoint) == 8, "CPoint alignment mismatch");
_Static_assert(offsetof(CPoint, x) == 0, "CPoint.x offset mismatch");
_Static_assert(offsetof(CPoint, y) == 8, "CPoint.y offset mismatch");
```

测试文件应包含 stdint.h 和 stddef.h。头文件断言外，还要验证 Joky 写入、C 读取修改、Joky
再读取的往返行为。padding 不参与值语义，布局兼容不等于可直接序列化或用 memcmp 判断值相等。

显式区分内部标量槽布局、可寻址内存布局和调用 ABI。当前聚合的标量槽偏移不是 C 字节偏移，
内部隐藏返回指针也不是通用的 C 聚合返回约定。取引用需要实际物化符合布局的稳定对象；
解释器、JIT、AOT 对该对象的访问必须一致，不能把当前 u64 槽数组直接强转成 C 记录。
首版通过指针传递记录，不实现 C 记录按值参数和返回的寄存器分类规则。

### 5.4 挂起宿主接口

```joky
extern fn host_process(point: &CPoint) @suspends
```

这是 Joky 宿主适配协议，不是普通 C 同步函数加一个标记。绑定层提供 poll、完成和取消协议，
借用覆盖整个操作。满足第 4 节停止确认要求后，才允许在 Pending 期间保留对象地址。
保留对象地址不等于保留 CPS 帧/槽地址；现有不透明帧和禁止跨 poll 保存槽指针的约束继续成立。
新增协议应通过版本或独立注册入口区分，不能改变旧 CPS ABI 的含义。

现有 String 的长度前缀借用 ABI、opaque 句柄以及旧宿主注册接口保持各自契约；
不能用 arena 功能悄悄把它们改成拥有型字符串、资源或任意 C 指针。

## 6. 实现步骤与验收

每阶段单独提交，只有达到验收条件才开放对应语法。新语义检查放在共享 core::ir，
JIT / AOT 共用 native lowering；解释器同步实现，不以单一后端可运行为阶段完成。
各阶段运行 `./scripts/check.sh`，增加行为测试而非只检查生成指令文本。

顺序按用户可见价值排列：先让 arena 里的对象能互相引用，再处理局部借用和外部接口。

| 阶段 | 实现内容 | 验收与开放边界 |
| --- | --- | --- |
| 0：布局基础 | 分离标量槽、内存大小/对齐/字段偏移及调用描述；加入目标平台输入与溢出检查 | 已有程序、CPS、String 和聚合内部 ABI 行为保持一致；覆盖嵌套记录和不同宽度，暂不开放 arena |
| 1：同步隐式 arena 与引用 | 解析 `&T` / `&mut T`；当前任务隐式 arena；内建 `alloc`、`share` 与 memory 读写；来源跟踪、签名来源规则、重借用；显式 Arena 高级接口 | 三后端运行分配、引用传参与返回；追加分配地址稳定；局部逃逸、带借用移动、共享写入和复制独占引用被拒；共享化冻结关系正确；跳转、失败、分配失败只清理一次；暂拒绝局部借用、含引用聚合和跨挂起 |
| 2：含引用数据与封存图 | 共享引用字段；Option / Result / 元组中的引用；`&T` 作类型实参；签名存储前置条件与保留借用；允许经过 `&` 的递归类型；`graph.link` / `graph.seal` | 同任务链表与树的构建/遍历三后端一致；循环共享图只能通过受检构造器封存；跨 arena 方向受检；包装、泛型、跨模块不丢来源与权限；封存后对象只读，`&mut` 字段和可变循环图继续拒绝 |
| 3：任务内 arena 与挂起 | CPS 保留隐式 arena、arena 引用跨挂起、scope 借用检查和同步清理 | 多次 Pending 不重放分配；嵌套分支失败/取消、丢弃 continuation、VM drop 和重载均正确；尚不允许外部异步操作保留引用 |
| 4：局部位置借用 | `&local`、`&mut local` 和字段借用；为被借用位置物化稳定存储，解释器槽压缩、复制传播及 JIT SSA 值需要相应调整 | 借用期间通过原位置的冲突访问被拒；优化不改变被借用位置的行为；局部借用暂不能跨挂起 |
| 5：同步 C 互操作与 ForeignPtr | `@repr(C)`、unsafe 边界、C 引用参数、目标布局验证、宿主适配器、C-owned `ForeignPtr` 的 `alloc/free` | C 布局断言及读写往返覆盖三后端；arena 引用不能交给 `c.free`；ForeignPtr 恰好释放一次并在失败/取消路径清理；拒绝不支持的边界类型及借用返回 |
| 6：异步宿主借用 | 新注册契约、poll/完成/同步停止取消入口、幂等清理和版本区分 | Pending 中对象保活，成功/失败/取消均无迟到访问；反复取消不重复清理；无法同步停止的宿主绑定被拒绝 |
| 7：容器与所有权扩展（规划） | 动态连续存储、受检元素访问、缓冲区独占管理、临时借用及非 Copy 元素的移动与清理；容器算法用 Joky 编写 | 依次验收 `Array<Int32>`、Copy 元素泛型数组、资源型元素及嵌套容器；另验收可变链表的节点增删、借用失效与回收；详见 6.1 |

阶段 0 的落点主要是 core/types 的布局与 parser/ast 的类型描述；阶段 1/2 涉及 core/ir 的
来源跟踪、签名规则检查、退出路径与三个后端的内存访问。阶段 4 还涉及解释器的槽压缩和
复制传播，这些优化不能把被借用的位置当作可以合并或删除的普通槽。
现有 Copy 泛型专门化不能自动承担非 Copy 所有权检查；Arena 和借用方法需要先有受限接口，
再逐步推广通用能力约束。阶段 3/6 涉及 runtime/cps、suspension、scheduler 与解释器宿主适配，
不只是在源码库增加方法。

阶段 1 当前完成的是同步隐式 arena 的最小纵向切片，不包含显式 Arena 高级接口。
根入口负责创建和清理，内部调用经隐藏参数共享 arena，带引用的 helper 不作为宿主入口导出。
&mut 绑定采用移动、调用采用重借用，共享化按最后使用冻结权限；写目标使用延迟激活的预留。
三后端覆盖嵌套对象、跨函数/跨模块调用、Copy 聚合读写、循环跳转、失败清理和分配预算。
当前整个 @suspends 调用链禁止 arena/引用能力；尚无显式 Arena/new/reset、局部取借用或 C 接口。
默认每任务计费预算为 64 MiB，分配对象逐项记录并统一释放；后续再扩展预算配置和分块实现。

阶段 2a 已开放共享引用字段、Option/Result/元组中的引用、共享引用泛型实参和经过引用的递归类型。
同一隐式任务中支持链表、树及共享子节点的无环图，三后端覆盖循环构建、递归遍历、泛型别名和跨模块调用。
含引用对象由 alloc 产生局部构造期 &mut T，share 或隐式共享化立即封存；封存后原独占能力不能恢复。
构造期 &mut T 不能跨函数签名，具体泛型实例同样检查；共享图可以跨内部函数传递或返回。
直接存入 arena 的借用保持到任务结束。调用可分配函数时也保守保留全部引用实参，包括 Unit 返回值。
无分配的只读 helper 维持临时借用规则；分配能力按调用图传播，不推导逐参数存储摘要。
阶段 2b 的 graph.link/graph.seal 循环图构造器及显式跨 arena 方向检查尚未实现。

阶段 0 当前已提供独立的 `Type::memory_layout_for(MemoryLayoutTarget)` 查询，返回对象大小、
对齐、记录/元组成员的字节偏移，以及枚举 tag 和不重叠负载区的位置。固定宽度整数的对齐和
最大对象大小由目标输入决定；引用增加显式指针大小/对齐输入。默认策略为 4/8 字节整数对齐、
宿主指针大小/对齐，大小上限取编译宿主的
`isize::MAX`，不代表自动识别目标 C ABI。内部 Bool 为 1 字节，Unit/空记录为零大小、对齐 1。
布局查询检查大小、算术溢出、成员数和嵌套深度，并缓存共享类型图；含未专门化字段的泛型、
String 和 opaque 类型暂不提供对象布局。现有 scalar slot 偏移和调用约定继续由原实现负责；
此查询本身只描述布局；同步隐式 arena 已使用它，C 聚合按值调用仍未开放。

各阶段至少包含以下行为用例：

- 接受：隐式任务 arena 返回引用；经辅助函数两次 alloc 得到可同时修改的对象；
  顺序调用自动重借用；读取 Copy 值；链表构建与递归遍历；跨模块调用同 arena 的 push；
  共享化后冻结独占访问；显式子 arena 的引用方向受检；修改函数实现但保持签名契约后调用方借用检查不变。
- 拒绝：返回局部 arena/局部栈引用；没有合法分配或输入来源的函数返回引用；借用期间移动/覆盖拥有者；
  共享引用写入；复制独占引用；把已有共享对象转换成 `&mut`；`&mut` 绑定到类型参数；
  未封存的引用对象跨边界发布；`&mut` 字段及其泛型/别名绕过；修改已封存的引用字段；
  子 arena 引用存入父 arena；把独占重借用结果留存后再次冲突访问原引用；
  两个 scope 分支借用同一对象进行修改。
- 签名与权限：Unit 返回的存储函数同样拒绝短寿命输入；同 arena 中保存独占对象的共享重借用
  后不能恢复原独占写入；函数转发、分支合并、memory.read 及聚合复制不丢失冻结关系。
  引用目标含引用时，跨函数签名中的 `&mut T` 即使经泛型实例化产生也要拒绝；无返回依赖的 None 按明确规则处理。
- 解析：借用与按位与的换行消歧；`&&T`、`& &T` 和别名多层引用均拒绝；mut/unsafe
  保留字迁移、固定 C 属性位置、未知属性和无效调用约定的诊断。
- 清理：嵌套块、部分初始化、return/break/continue、运行时错误、预算终止、取消和重复取消，
  用分配/释放计数及事件顺序证明恰好释放一次。
- 挂起：恢复多次、完成与取消竞争边界、宿主重入、重载后旧代码保活、continuation 被丢弃。
- FFI：不同字段位宽、嵌套记录、指针读写往返、绑定取消入口调用顺序；条件允许时加入
  sanitizer 检查；ForeignPtr 的 allocator pairing、double free、失败/取消清理；不能仅凭
  sanitizer 未报错认定静态规则正确。

验证性能应单独进行：分配吞吐、峰值 arena 占用、批量释放延迟和编译器借用分析耗时。
完整正确性检查不提供性能结论，不要求在此文档阶段运行计时基准。

### 6.1 容器与所有权扩展

目标是用 Joky 标准库实现动态数组、链表等容器。push、pop、扩容策略、插入删除和遍历逻辑
写在 Joky 中；编译器与运行时提供通用的分配、布局、元素初始化/访问、移动和清理原语。
容器不各自增加关键字，也不以调用宿主实现的整套容器操作作为源码库完成的验收。
底层存储原语的安全边界、封装方式和具体拼写在实现前确定，普通使用者获得受检接口。

这是阶段 0–6 之外的能力，目前尚未实现；同步容器的必要前提是存储、借用与所有权规则，
不要求先完成异步 FFI。容器跨挂起还需结合阶段 3 验证保活与取消清理。
该规划不改变当前阶段 2b 的循环图构造目标。

| 步骤 | 目标 | 验收 |
| --- | --- | --- |
| 7a：数值动态数组 | 先以 `Array<Int32>` 验证连续缓冲区、长度/容量、受检访问、push/pop 和扩容；建立缓冲区管理权的移动与临时借用 | 空数组、反复扩容、元素顺序、越界、大小溢出和分配失败；禁止复制独占管理权，禁止借用期间使元素引用失效 |
| 7b：Copy 元素泛型容器 | 将数组推广到 Copy 元素，覆盖不同布局及含共享引用的元素；提供元素/切片借用 | 泛型、别名、跨模块不丢元素来源；初始化范围与对齐正确；借用结束后可继续修改，存储的引用满足寿命与权限约束 |
| 7c：拥有资源的容器 | 支持非 Copy 元素、拥有字段、容器嵌套及可独立回收的缓冲区；用可变链表验证节点所有权和链接更新 | 移动不隐式复制；删除、替换和退出恰好清理一次；部分初始化、失败及已开放的挂起/取消路径正确；节点删除不能留下可用的悬空引用 |

动态数组必须保持 `0 <= len <= capacity`，只允许读取已初始化的元素。容量计算及字节大小
需要溢出检查；扩容搬迁、删除或替换不能破坏仍有效的元素/切片借用。存在冲突借用时拒绝
操作，借用结束后允许继续修改。可恢复的分配失败必须保持容器有效；不可恢复失败走统一清理。
数组初期可以只提供方法式受检访问，索引语法和通用迭代器不作为首个实现的前置条件。

即使元素是 Copy，独占管理可变缓冲区的容器本身也不能隐式复制。7a 就需要受限的非 Copy
存储句柄及其封装规则；7c 再推广元素的移动与析构，不能把这些问题全部推迟到支持资源元素时。
含引用的元素需要追踪其实际依赖，不能把缓冲区的拥有权当作元素所指对象的拥有权。

容器的临时共享借用与对象图的永久封存必须区分。阶段 2a 中，含引用对象的 share/隐式共享化
会撤销构造期独占能力；这条规则继续适用于当前对象图。未来读取数组或借用元素不应永久封存
整个容器，也不能仅因容器内部管理存储就禁止再次修改。扩展需建立可验证的独占管理与访问协议，
明确其与 share/seal 的关系，不能只放宽现有共享引用的写权限。

存储策略按业务寿命选择：请求、批次或帧内临时数组可以使用 arena，扩容留下的旧缓冲区
保留到 arena 结束，仍计入任务预算；长期运行、反复增删的容器需要可独立回收或复用的存储。
该能力单独设计，不允许把 arena 引用交给 c.free，也不让 ForeignPtr 自动获得任意缓冲区操作。

只读链表当前已可构造，共享尾部的节点由 arena 统一释放；阶段 2b 增加的是封存后的循环图。
支持运行中插入、删除、重连的可变链表，还需节点所有权与受控访问协议，例如独占拥有链或
由容器管理的节点句柄；具体表示另定，可变循环图不因可变链表验收通过而自动开放。
7a–7c 均以 Joky 源码库和 JIT / 解释器 / AOT 的行为测试验收，资源清理使用计数验证。

## 7. 后续决策

实现过程中允许收紧未支持场景，但不能通过 unchecked 指针或忽略退出路径临时绕过检查。
下列问题在相应扩展前单独确定，不阻塞同步 arena 的最小版本：

- 隐式任务 arena / 显式子 arena 的标准库导入路径、预算配置以及可恢复的分配失败 API。
- 签名来源规则过于保守时，是否增加显式来源标注及其写法。
- `graph.link` / `graph.seal` 的具体形式、同 arena 内的环与自引用构建；可变引用字段和可变循环图仍需单独的运行时能力。
- 容器存储原语、封装边界、独占缓冲区句柄、切片表示及临时借用与封存的区分；
  按 6.1 推进源码库验收，再确定可变链表的节点管理形式。
- 资源拥有包装、显式 close 与一般析构协议，以及拥有型 String 如何复用容器存储基础。
- 外部操作异步取消、scheduler shutdown 的 drain 协议以及安全的宿主结果拥有包装。
- ForeignPtr 的具体类型、可空指针、外部缓冲区、回调和更广泛的 C ABI 支持。

显式生命周期和星号指针语法不列为这些阶段的前置需求。若保守规则确实阻挡重要用例，
先用真实程序说明限制，再评估更精细的推导或显式契约，不预先把复杂度交给所有用户。
