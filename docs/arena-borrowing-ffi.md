# Arena、隐式生命周期与 FFI 设计

状态：设计提案，2026-09-29；尚未实现。本文记录 arena、借用和结构化并发的设计方向，
以及可分别验收的实现步骤。示例中的 Arena、引用、unsafe 和 C 布局标记都是目标能力，
不能作为当前可运行示例。库名称及 FFI 标记在对应阶段实现前再冻结。

当前能力见[语言与内置模块](language.md)，内部布局、宿主 ABI 和 continuation 约束见
[架构说明](architecture.md)。本文细化并更新[语法草案](syntax.md)中的资源设计：
第一版不要求用户写生命周期参数，不引入解引用或裸指针的星号语法。

## 1. 目标与边界

- Arena 拥有一批内存，按作用域整体释放；没有对象追踪 GC，也不为每个对象维护引用计数。
- `&T` 表示共享只读借用，`&mut T` 表示独占可变借用；编译器检查来源、有效范围和访问冲突。
- 局部变量和函数返回引用的生命周期由编译器推导，不提供 `'a` 之类的用户标注。
- 字段访问自动解引用，函数调用自动重借用；不提供 `*expr`、`*const T`、`*mut T`。
  现有乘法运算符 `*` 不受影响。
- 保留 `@suspends` 和 `scope`；第一版仍为单线程协作并发，没有脱离 scope 的任务或多线程共享 arena。
- C 兼容布局是显式选择的类型契约；引用参数经受检查的绑定传成 C 指针。
- 正常结束、跳转、运行时失败和取消都必须正确清理；没有 GC 不意味着没有运行时支持。

第一版不包含任意析构对象、拥有型动态 String、容器、循环引用图、可复用 arena 的 reset、
单对象 free、C 聚合按值调用、任意裸地址操作或异步析构。Box / Rc 等其他所有权形式不是
arena 的实现前提，是否加入另行设计。

Arena 适合请求、批次、解析或编译单元。对象不再使用后通常仍占用空间，直到 arena 结束；
长期服务应按工作单元创建 arena，不能把所有临时分配积累到一个全局 arena。

## 2. 使用语法

### 2.1 创建、分配与释放

```joky
struct Point { x: Int32 y: Int32 }

fn run() {
    let mem = Arena.new()
    let point = mem.alloc(Point { x: 1 y: 2 })
    print_int(point.x)
}
```

`Arena.new()` 创建拥有者，`alloc` 将值放入 arena 并返回 `&Point`。
Arena 是非 Copy 值，离开作用域时释放所有分配。不增加 `arena { ... }` 关键字；
普通块已经可以建立更短的生命周期。示例省略 Arena 和 ref 模块的导入，最终模块路径待定。

建议的初始 API：

| API | 结果 | 规则 |
| --- | --- | --- |
| `Arena.new()` | Arena 拥有者 | 不可复制，使用通用移动和退出清理机制 |
| `mem.alloc(value)` | `&T` | 将当前值复制进独立的稳定存储，第一版 T 限无引用的 Copy 数据 |
| `mem.alloc_mut(value)` | `&mut T` | 同上，但返回唯一可变访问能力 |
| `ref.read(view)` | T | 第一版仅支持复制 Copy 的所指值，不移出 arena 对象 |
| `ref.write(view, value)` | Unit | 要求 `&mut T`，替换整个所指值，第一版 T 仍限无引用 Copy 数据 |

首版可分配类型限定为四种现有整数、Bool、Unit 及由它们组成的记录、枚举和元组，
暂不包括 String 和宿主 opaque 句柄。零大小值仍有独立的逻辑分配身份；不依赖地址不同来
证明借用不冲突，也不允许对零大小对象进行越界访问。

分配先完整求值实参，再分配和初始化；不得发布未初始化引用。建议首版将分配失败作为
现有运行时失败通道中的错误，执行清理后传播，不返回空引用；可恢复的 `try_alloc` 后续设计。
大小计算溢出和预算超限必须在实际分配前检查，不能静默截断。

Arena 控制块通过库封装维护可变分配状态，允许经共享 `&Arena` 分配。每次分配返回不重叠的
对象，追加分配不移动已有对象，也不要求长期独占借用整个 arena。该能力需要编译器认可的
分配来源规则，不能把任意经共享引用的方法都当成可以返回可变引用。

已有借用有效时，不能销毁、替换或移动 Arena 拥有者。首版不允许把 Arena 放入聚合或从用户函数
返回；标准库创建入口 Arena.new 单独提供创建语义。无活动借用时的局部移动、按值消费仍按
通用移动规则检查。自引用拥有者整体移动留待后续。

### 2.2 由调用者提供结果存储

```joky
fn make_point(mem: &Arena) -> &Point {
    mem.alloc(Point { x: 1 y: 2 })
}

fn run() {
    let mem = Arena.new()
    let point = make_point(&mem)
    print_int(point.x)
}
```

编译器推导返回引用依赖输入 arena，调用点将该依赖映射到 `mem` 的拥有者。
不隐式选择当前 arena，也不把局部 arena 的对象自动复制到父 arena。

以下代码必须拒绝：

```joky
fn bad() -> &Point {
    let mem = Arena.new()
    mem.alloc(Point { x: 1 y: 2 })
}
```

建议诊断：`Cannot return a reference to local arena 'mem'.`
借用来源说明应定位到创建 arena 和返回引用的位置，不要求用户理解内部 region 编号。

### 2.3 字段访问、绑定与重借用

```joky
fn move_x(point: &mut Point, distance: Int32) {
    point.x = point.x + distance
}

fn move_twice(point: &mut Point) {
    move_x(point, 10)
    move_x(point, 20)
}

fn run() {
    var point = Point { x: 1 y: 2 }
    move_twice(&mut point)
}
```

从拥有值借用时写 `&point` 或 `&mut point`。传递已有引用时不必重复写 `&`；
调用所需的短暂重借用由编译器生成。可变引用可以短暂降为共享引用，反向转换不允许。
重借用如果被返回值继续携带，其占用范围随返回值延长，不是一律在调用返回时结束。

`let` / `var` 控制绑定是否可重新赋值，引用类型控制所指对象的访问权限：
`let point = mem.alloc_mut(...)` 允许修改字段，但不允许重新绑定 point。
`point = other` 始终表示绑定赋值，不自动解释成修改所指对象。

无字段的值或整个对象通过库操作读写：

```joky
fn increment(value: &mut Int32) {
    let old = ref.read(value)
    ref.write(value, old + 1)
}
```

字段访问自动解引用不意味着隐式复制整个对象。复制 `&T` 只复制受生命周期约束的借用，
不会成为新拥有者；`&mut T` 不可复制。第一版不提供引用算术、整数到引用转换和引用地址比较。

## 3. 不写生命周期标注的静态检查

### 3.1 引用来源与函数摘要

编译器为 arena、可借用局部位置、参数和分配建立内部身份，跟踪引用来源及共享/独占权限。
类型仍写成 `&Point`，内部关系不是用户泛型实参，也不占用现有泛型专门化的类型参数位置。

函数分析产生借用摘要：返回引用可能依赖哪些输入、返回的是重借用还是 arena 中的新分配、
写入了哪些借用位置。调用者使用摘要分析，不要求展开被调用函数的实现。
尤其需要区分“借用整个输入对象”与“从同一 arena 新分配的两个独立对象”：
它们依赖同一拥有者，但不因此互相别名。

```joky
fn choose(flag: Bool, left: &Point, right: &Point) -> &Point {
    if flag { left } else { right }
}
```

此函数的返回来源集合包含 left 和 right；调用方只在两者都有效的范围内使用结果。
不根据调用时的 Bool 值承诺更长寿命。来源合并采用保守规则，不能在不确定时取较长寿命。

同理，从局部参数绑定取地址和返回参数指向的对象不同：局部参数槽在函数结束后失效。
局部块、分支合并、循环、提前返回、函数转发和递归都要保留此区别。
递归调用组使用有限摘要和固定点分析；分析超限必须给出诊断，不能放弃安全检查。

跨模块输出摘要，与已解析的函数、类型身份和模块版本一起缓存。函数签名相同但摘要变化也必须
使使用旧摘要的编译缓存失效；运行中的旧 continuation 保留原模块、摘要对应的代码和数据拥有者。
宿主没有可供分析的函数体，必须提供明确的绑定契约，不能从参数数量猜测返回来源。

### 3.2 别名、容器与分阶段限制

同一位置可以有多个共享借用，或一个独占借用；不能同时有冲突访问。
独占借用期间也限制通过原拥有值或父引用访问对象。第一版可以保守地把同一对象的不同字段
视为冲突，不要求立即支持字段拆分借用；不同 arena 分配应可独立借用。

目标是按控制流中的最后一次使用结束借用；早期实现可采用更保守的词法范围，但必须记录由此
拒绝的安全程序，不能为了示例通过而漏掉分支或循环上的使用。

引用进入 struct、tuple、Option / Result 后，来源和权限也必须随值传播；不能通过包装、解构、
泛型实例化或赋值绕过检查。当前聚合和泛型仅支持 Copy 数据，不能直接把指针标成整数来复用。
第一版先拒绝含引用聚合，后续按独立阶段开放；含 `&mut T` 的聚合不能自动成为 Copy。

向 arena 存入含引用数据时，还必须检查被引用的存储覆盖接收 arena 的有效范围。
首个扩展版本采用这个保守规则，禁止把子 arena 引用存入父 arena，也禁止将局部栈引用存入
可能活得更久的 arena。可变引用字段、同 arena 自引用构建和循环图再单独设计。
从 arena 读出的引用值不得因跨函数或容器复制而丢失这些依赖。

### 3.3 清理与资源

Arena 的释放由通用退出清理负责。已初始化且仍拥有的资源按依赖和作用域清理，独立资源默认
逆声明顺序；已移动的值不重复释放。`return`、`break`、`continue`、失败路径和部分初始化
都必须经过清理路径。借用先失效，拥有者才能释放。

Arena 初期只回收无析构数据的内存；释放字节不等于关闭文件、socket 或 C 库对象。
这些对象需要单独的拥有包装和资源协议，现有可复制 opaque 句柄不会自动获得资源所有权。
用户析构、异步 close、拥有型 String 和容器不在首版中隐式加入。

## 4. 结构化并发与取消

```joky
fn handle() @suspends {
    let mem = Arena.new()
    let point = mem.alloc(Point { x: 1 y: 2 })

    scope {
        | inspect_left(point)
        | inspect_right(point)
    }
}
```

示例中的 inspect_left / inspect_right 均为返回 Unit 的挂起函数。继续沿用现有 scope 的
实参先求值、分支调用、全部完成后继续的规则，不增加 async / await 或任务句柄语法。
返回 `Result.Err` 仍是业务数据，不自动变成任务失败或取消信号。

借用必须覆盖分支整个执行期间，包括所有 Pending。不能把两次 poll 之间视为借用结束。
即使单线程，也不允许两个分支对同一对象同时持有独占借用；不同分配可以分别独占。
嵌套 scope 不允许借用逃到父范围以外，arena 与 scope 也不必一一对应。

挂起时 arena 拥有者进入 continuation 的受管理状态，对象地址保持稳定。暂停函数的可借用
局部位置也需要稳定的存储：不能保留指向可重分配 Vec 元素或已经返回的宿主栈的地址。
第一版跨挂起借用优先限 arena 对象，普通局部借用跨挂起要等稳定存储方案验证后开放。

正常路径：子任务全部完成 → 清理子任务 → 释放父 arena。
失败或取消路径：禁止启动新工作 → 请求取消 → 确认所有访问停止 → 清理子任务 → 释放父 arena。
取消请求与取消完成是不同状态；不能在请求取消时提前结束独占借用。

当前运行时通过释放分支/continuation 状态取消任务，没有任意外部异步操作的停止确认协议。
引入异步 FFI 借用前必须扩展这一机制：

- 第一版只接受能在取消入口返回前同步保证停止访问的宿主操作；取消必须幂等、不挂起、不 unwind。
- 无法同步停止的 C 操作暂不接入这种借用接口，不能假定释放 CPS 帧会停止外部 I/O。
- 后续若支持异步取消，需要显式 Cancelling / draining 状态；即使宿主丢弃 continuation，
  也由运行时持有清理操作及全部拥有者，直到停止确认。调度器关闭和错误路径必须覆盖该状态，
  不能靠用户继续 poll 一个已经丢弃的句柄。这属于后续协议，不由本提案默认实现。

宿主返回、VM 关闭、代码重载不能使挂起借用失效。现有无生命周期参数的 continuation 接口
不接受任意借用的宿主局部对象；首版要求任务持有完整拥有者。返回到宿主的引用也不能裸露于
已释放 arena 之外，首版顶层 VM 返回接口继续拒绝引用结果，后续另行提供带拥有者的结果包装。

## 5. FFI：C 布局与引用参数

### 5.1 同步借用接口

```joky
@repr(C)
struct CPoint { x: Int32 y: Int64 }

unsafe extern "C" fn inspect(point: &CPoint) -> Int64
unsafe extern "C" fn update(point: &mut CPoint)

fn run() {
    let mem = Arena.new()
    let point = mem.alloc_mut(CPoint { x: 1 y: 2 })
    unsafe {
        update(point)
        let _ = inspect(point)
    }
}
```

`@repr(C)`、`unsafe extern "C"` 和 unsafe 块是拟议拼写，和现有宿主 `extern fn` 分开定义。
对应 C 声明为：

```c
typedef struct { int32_t x; int64_t y; } CPoint;
int64_t inspect(const CPoint *point);
void update(CPoint *point);
```

非空、对齐正确、已初始化的引用可以映射为指针参数，但 Joky 引用的保证比 C 指针更强。
同步绑定契约必须保证：只在调用期间访问、不保留指针、不经别名违反共享/独占权限、
不 free/realloc 这块内存、不越界、不跨边界 unwind，也不通过回调重入造成借用冲突。
C 的 const 本身不能证明这些条件。unsafe 标记承认绑定者的责任，不解除 Joky 侧的借用检查。

首版原生 C 接口仅支持引用输入和已支持的标量/Unit 结果，拒绝返回引用、可空引用、
引用到引用、变参、任意回调和跨调用保存地址。外部拥有的内存以后通过专门的资源句柄或
ForeignPtr 类库类型接入，不要求为此引入星号语法。动态缓冲区、String 和 Slice 不自动按单指针传递。

### 5.2 布局可验证，但不等于完整调用 ABI

首版 C 记录限定非空、固定宽度整数和兼容的嵌套记录；Bool 编码、空记录、Unit、含引用字段、
带负载枚举、packed、union 和 C 位域后续另行规定。普通记录不因分配进 arena 就自动成为 C 类型。

在 arm64 macOS 的普通 C ABI 下，上述 CPoint 的 x 偏移 0、y 偏移 8、大小 16、对齐 8。
这些数字按目标平台计算，不能推广为所有平台常量。生成对应头文件和断言，由目标 C 编译器验证：

```c
_Static_assert(sizeof(CPoint) == 16, "CPoint size mismatch");
_Static_assert(_Alignof(CPoint) == 8, "CPoint alignment mismatch");
_Static_assert(offsetof(CPoint, x) == 0, "CPoint.x offset mismatch");
_Static_assert(offsetof(CPoint, y) == 8, "CPoint.y offset mismatch");
```

测试文件应包含 stdint.h 和 stddef.h。头文件断言外，还要验证 Joky 写入、C 读取修改、Joky
再读取的往返行为。padding 不参与值语义，布局兼容不等于可直接序列化或用 memcmp 判断值相等。

显式区分内部标量槽布局、可寻址内存布局和调用 ABI。当前聚合的标量槽偏移不是 C 字节偏移，
内部隐藏返回指针也不是通用的 C 聚合返回约定。取引用需要实际物化符合布局的稳定对象；
解释器、JIT、AOT 对该对象的访问必须一致，不能把当前 u64 槽数组直接强转成 C 记录。
首版通过指针传递记录，不实现 C 记录按值参数和返回的寄存器分类规则。

### 5.3 挂起宿主接口

```joky
extern fn host_process(point: &CPoint) @suspends
```

这是 Joky 宿主适配协议，不是普通 C 同步函数加一个标记。绑定层提供 poll、完成和取消协议，
借用覆盖整个操作。满足第 4 节停止确认要求后，才允许在 Pending 期间保留对象地址。
保留对象地址不等于保留 CPS 帧/槽地址；现有不透明帧和禁止跨 poll 保存槽指针的约束继续成立。
新增协议应通过版本或独立注册入口区分，不能改变旧 CPS ABI 的含义。

现有 String 的长度前缀借用 ABI、opaque 句柄以及旧宿主注册接口保持各自契约；
不能用 arena 功能悄悄把它们改成拥有型字符串、资源或任意 C 指针。

## 6. 实现步骤与验收

每阶段单独提交，只有达到验收条件才开放对应语法。新语义检查放在共享 core::ir，
JIT / AOT 共用 native lowering；解释器同步实现，不以单一后端可运行为阶段完成。
各阶段运行 `./scripts/check.sh`，增加行为测试而非只检查生成指令文本。

| 阶段 | 实现内容 | 验收与开放边界 |
| --- | --- | --- |
| 0：布局基础 | 分离标量槽、内存大小/对齐/字段偏移及调用描述；加入目标平台输入与溢出检查 | 已有程序、CPS、String 和聚合内部 ABI 行为保持一致；覆盖嵌套记录和不同宽度，暂不开放 arena |
| 1：同步借用 | 解析 `&T` / `&mut T`、借用表达式；建立位置/来源、共享/独占、重借用和函数摘要；实现稳定局部存储及读写操作 | 正反用例覆盖字段、整个值、参数转发、多个返回来源、递归、跨模块和循环；暂拒绝跨挂起和含引用聚合 |
| 2：同步 arena | Arena 非 Copy 拥有者、局部移动、退出清理、分块分配、alloc/alloc_mut 及受限泛型接口 | 三后端运行分配与引用返回；追加分配地址稳定；局部逃逸/带借用移动被拒；跳转、失败、分配失败只清理一次 |
| 3：任务内 arena | CPS 保留拥有者、arena 引用跨挂起、scope 借用检查和同步清理 | 多次 Pending 不重放分配；嵌套分支失败/取消、丢弃 continuation、VM drop 和重载均正确；尚不允许外部异步操作保留引用 |
| 4：同步 C 互操作 | `@repr(C)`、unsafe 边界、C 引用参数、目标布局验证和宿主适配器 | C 布局断言及读写往返覆盖三后端；错误结果先检查再消费；拒绝不支持的边界类型及借用返回 |
| 5：异步宿主借用 | 新注册契约、poll/完成/同步停止取消入口、幂等清理和版本区分 | Pending 中对象保活，成功/失败/取消均无迟到访问；反复取消不重复清理；无法同步停止的宿主绑定被拒绝 |
| 6：含引用数据扩展 | struct/tuple/Option/Result 的隐藏来源关系、泛型摘要和存储约束；先支持受限共享引用字段 | 包装/解构/赋值/跨模块后依赖不丢失；短寿命引用不能存进长寿命 arena；非 Copy 聚合单独处理 |

阶段 0 的落点主要是 core/types 的布局与 parser/ast 的类型描述；阶段 1/2 涉及 core/ir 的
位置和值区分、函数摘要、退出路径与三个后端的内存访问。现有 Copy 泛型专门化不能自动承担
非 Copy 所有权检查；Arena 和借用方法需要先有受限接口，再逐步推广通用能力约束。
阶段 3/5 涉及 runtime/cps、suspension、scheduler 与解释器宿主适配，不只是在源码库增加方法。

各阶段至少包含以下行为用例：

- 接受：调用者提供 arena 返回引用、两个新分配分别可变借用、顺序调用自动重借用、读取 Copy 值。
- 拒绝：返回局部 arena/局部栈引用、借用期间移动/覆盖拥有者、共享引用写入、复制独占引用、
  把独占重借用结果留存后再次冲突访问原引用、两个 scope 分支借用同一对象进行修改。
- 清理：嵌套块、部分初始化、return/break/continue、运行时错误、预算终止、取消和重复取消，
  用分配/释放计数及事件顺序证明恰好释放一次。
- 挂起：恢复多次、完成与取消竞争边界、宿主重入、重载后旧代码保活、continuation 被丢弃。
- FFI：不同字段位宽、嵌套记录、指针读写往返、绑定取消入口调用顺序；条件允许时加入
  sanitizer 检查，不能仅凭 sanitizer 未报错认定静态规则正确。

验证性能应单独进行：分配吞吐、峰值 arena 占用、批量释放延迟和编译器借用分析耗时。
完整正确性检查不提供性能结论，不要求在此文档阶段运行计时基准。

## 7. 后续决策

实现过程中允许收紧未支持场景，但不能通过 unchecked 指针或忽略退出路径临时绕过检查。
下列问题在相应扩展前单独确定，不阻塞同步 arena 的最小版本：

- Arena/ref 的标准库导入路径、预算配置以及可恢复的分配失败 API。
- 含引用公开类型的隐藏来源参数如何编码到模块接口；递归类型和可变引用字段的精度。
- 资源拥有包装、显式 close 与一般析构协议，动态 String/容器如何选择存储。
- 外部操作异步取消、scheduler shutdown 的 drain 协议以及安全的宿主结果拥有包装。
- ForeignPtr、可空指针、外部缓冲区、回调和更广泛的 C ABI 支持。

显式生命周期和星号指针语法不列为这些阶段的前置需求。若保守规则确实阻挡重要用例，
先用真实程序说明限制，再评估更精细的推导或显式契约，不预先把复杂度交给所有用户。
