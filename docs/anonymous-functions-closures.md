# 匿名函数与闭包开发计划

状态：2026-10-06，基线 `3ff4563`。**C0–C6 未开始；本文为目标设计，不代表当前已实现。**
这是语言基础补齐的第 3 项；第 1 项见[模块常量与字段语法](module-constants-record-syntax.md)，
第 2 项见[记录解构](record-destructuring.md)。本页代码均为目标语法示意，
不能据此认为当前 map / and_then 已能接收捕获闭包。

## 1. 基线与首版目标

当前同步及挂起的语言函数值已经实现，类型为 `fn(A) -> R` / `fn(A) @suspends -> R`。
它们没有捕获环境；[function_values.rs](../src/core/ir/function_values.rs) 负责受检间接调用。
Option / Result 已有接收同步函数值的 map / map_err / and_then，但闭包和可调用能力约束未实现。
当前静态 trait 也没有 trait 自身的类型参数，不能假定现有 trait 求解器已支持 Fn 家族。

首版交付同步匿名函数、参数上下文推导、借用捕获、`move` 捕获、局部重复或消费式调用，
以及可接收闭包的泛型同步 helper 和 Option / Result 组合方法。
首版不开放闭包跨语言挂起、捕获闭包返回类型、闭包存入记录/容器/持久实例、dyn callable、
宿主保存回调、C 回调 ABI、异步闭包或用户手写 Fn 实现。
非捕获闭包转成已有函数指针后，可沿用函数指针的已支持存储范围。

闭包和记录解构可以分别实施；闭包环境的内部字段不要求先开放用户记录解构或 dyn trait。
首版最终集成采用第 1 项确定的新字段语法。

## 2. 匿名函数语法

```joky
let add = fn(a: Int32, b: Int32) -> Int32 {
    a + b
}

let increment = fn(x: Int32) { x + 1 }
let mapped = Some(3).map(fn(x) { x * 2 })
let answer = (fn(x: Int32) { x + 1 })(41)
```

表达式写作 `fn(parameters) [-> Type] { body }`，省略具名函数的名称。
参数分隔仍必须使用逗号，允许尾逗号；首版参数只接受标识符，不支持参数模式、默认实参、
可变参数或匿名函数自己的泛型参数。可引用外围泛型参数，仍在定义作用域检查能力。

- 参数可逐个标注类型；未标注者从调用位置的期望签名推导。没有足够上下文时要求注解，
  不根据函数体猜参数类型，也不根据后面的第一次调用反向给已绑定闭包定型。
- 未写返回类型时，由已知期望返回类型和函数体末尾表达式/显式 return 统一推导；
  空块为 Unit，分支须同型，不增加隐式数值转换。不存在正常返回且无期望类型时要求注解。
  这与当前具名函数省略返回注解即为 Unit 的规则不同，不改变具名函数。
- `return` 返回当前闭包；`break` / `continue` 只能作用于闭包自身的循环，不能跳出外围函数。
  具名局部函数声明及自递归闭包不在范围内；初始化中的闭包不能捕获尚未完成绑定的自身。
- 花括号是必需的，不同时引入 `x => expression` 或 `|x| expression`。
  与已有 fn 类型的区别由类型/表达式上下文确定，不能改变 match / parallel 中 `|` 的含义。
- 每个匿名函数表达式有独立、不可直接书写的具体环境类型。同一语法位置在一次泛型实例中
  类型稳定；不同语法位置即使签名相同也不同，不隐式合并成公共动态类型。

调用参数的期望类型应在检查匿名函数体前传入。对于 `map<T, U, F>` 一类调用，先由接收者
或其他实参确定 T，再检查闭包参数与返回，最后确定 U 和 F；循环且无唯一解的推导报告错误。
限制推导与实例化工作量，不引入无限制的全局约束搜索。

## 3. 捕获与可调用能力

### 3.1 普通 fn：自动借用

```joky
let offset = 10
let shift = fn(x: Int32) { x + offset }

var count = 0
var tick = fn() { count = count + 1 }
tick()
tick()
```

自由局部变量按使用方式自动捕获：只读为共享借用，写入为独占借用。
捕获 Copy 变量也不悄悄改成快照；需要创建时快照用 `move fn`。
从捕获变量消费非 Copy 值的普通 fn 首版拒绝，并提示显式使用 move 捕获。
引用类型的捕获必须保留其原来源、可变性和重借用限制。

借用在闭包创建时建立，存续到闭包被销毁或按现有可证明规则结束其使用；
借用未结束时，原绑定不能进行冲突写入、替换、移动或销毁。
首版按整个根绑定捕获，不做独立字段捕获；同时访问同一根的多个字段仍只有一个捕获项，
需要写入时统一为独占借用。不能借字段路径绕过私有性或 Drop 祖先限制。
模块常量、类型和具名函数不是局部存储，不创建环境捕获。

### 3.2 move fn：创建时转移

```joky
let offset = 10
let shift = move fn(x: Int32) { x + offset }

let message = "hello"
let report = move fn() { println(message) }

let payload = "owned"
let take = move fn() -> String { payload }
let result = take()
```

`move` 捕获所有实际用到的自由局部根：Copy 值复制，拥有值移动，未使用的变量不捕获。
引用按其现有复制/移动规则处理，move 引用不等于移动或延长它指向的对象寿命。
非 Copy 源在闭包创建后不可继续使用；环境销毁时释放仍持有的资源。
`move` 成为保留字，C1 必须盘点并迁移旧标识符及文档，不引入第二套显式捕获列表。

move 仅决定捕获方式，不决定调用次数。只读环境仍可重复调用；消费捕获值的调用会消费闭包。
上面的 report 由函数体实际使用方式判定能力，take 则属于消费环境的调用。

### 3.3 Fn / FnMut / FnOnce

| 能力 | 调用如何取得环境 | 典型行为 |
| --- | --- | --- |
| `Fn(A) -> R` | 共享借用 | 只读捕获，可重复调用 |
| `FnMut(A) -> R` | 独占借用 | 修改捕获，可重复调用 |
| `FnOnce(A) -> R` | 消费环境 | 可以移出拥有捕获，只保证一次调用 |

满足 Fn 的环境也满足 FnMut 和 FnOnce，满足 FnMut 的环境也满足 FnOnce。
不把 FnOnce 理解为“必须调用一次”：未调用即被丢弃的环境也必须正确清理。
裸语言函数指针满足同步的三种能力，仍不具有捕获环境。

直接调用选择具体闭包所需的最弱环境访问方式；FnMut 局部需要 `var` 或受检的 `&mut F`，
不能通过不可变 `let` 环境修改捕获。FnOnce 按值调用消耗原值，第二次调用为移动后使用。
闭包环境首版统一按移动值处理，不因为全部捕获为 Copy 就自动复制环境；
调用 Fn / FnMut 的自动借用不等于移动，非捕获到 fn 的转换是单独规则。
同一 FnMut 环境不允许重入形成两个独占调用，FnOnce 不允许重入消费两次。

### 3.4 泛型接口与非逃逸

可调用能力采用编译器识别的专门约束，建议写法如下；C0 冻结解析、身份和预置名称规则。
它们不能伪装成当前无参数普通 trait，不以实现完整 trait 泛型或 dyn 为前提。

```joky
fn apply<T, U, F: FnOnce(T) -> U>(value: T, transform: F) -> U {
    transform(value)
}

fn twice<F: FnMut() -> Unit>(action: &mut F) {
    action()
    action()
}
```

普通函数参数和返回类型仍必须明确。约束检查保持定义时验证、单态化身份、有限实例化及
三后端签名一致性；FnMut 需要的可变性不能因经过泛型被擦除。
首版不接受 `dyn Fn`、`impl Fn` 返回类型、显式 Fn impl 或把未知闭包类型当作裸函数指针。

捕获中携带的引用是函数值的真实借用来源，不能只检查参数表上的 `&T`。
首版借用闭包只能局部调用，或交给经检查的同步非逃逸 helper；编译器必须证明被调方不会
把环境或其捕获引用放进返回值、容器、实例、其他逃逸闭包或宿主保存位置。
普通同步函数已按参数推导不逃逸保证；本计划将同一分析扩展到可调用环境参数
（包括按值传入的 F），检查环境内隐藏引用。上面的 apply/twice 应由函数体自动证明，
无需使用者重复标注。可选的 `@noescape(transform)` 或无参数 `@noescape` 仍可固定接口契约，
必须检查，不能仅相信标注；无函数体的可调用接口仍需明确契约，不能仅从 Fn 能力推出不逃逸。
返回普通无引用结果或调用方已有来源的参数引用仍按现有规则验证。
闭包首版不能返回指向自己捕获环境的引用，不能靠 Fn(A) -> &T 省略其所需的来源关系。

### 3.5 与 fn 指针的边界

不捕获任何局部的同步匿名函数，在期望类型为匹配的 `fn(A) -> R` 时允许转换，生成普通
隐藏语言函数；不接受签名不匹配、宿主 extern 或效果擦除。
捕获闭包不能转为 fn 指针，即使优化器发现捕获为常量或环境最后变为空也不能改变类型规则。
旧 fn 指针的布局、调用 ABI 和已验证的同步/挂起行为保持兼容。

## 4. 环境布局、失败与存储

环境包含按确定顺序排列的捕获及其类型/借用/清理信息；顺序按源码中自由根首次出现确定，
而非 HashMap 遍历顺序。C0 冻结嵌套闭包的捕获传播和去重规则，内层不能取得外层没有的权限。
环境不自动 Box 化，不需要 GC、Rc 或 dyn；物化的字节及清理登记计入现有预算。
零捕获闭包可没有数据环境；不能把零字节大小当作取消借用或清理语义的依据。

三后端共用类型明确的环境布局和私有入口约定，调用包含环境及普通实参。
JIT/AOT 共享 native lowering，解释器保持等价访问和清理；AOT 对象必须使用可重定位符号，
不能包含编译器进程中的环境或入口地址。入口、布局、Drop 与旧模块代码所有者一起保活。
生成类型和入口的标识须纳入泛型实例身份，并受编译数量/深度/布局限额约束。

创建闭包只建立捕获，不执行函数体。预检与空间预留在破坏源拥有权之前完成；确需分步
初始化时，失败仅清理已经取得的捕获，未取得的仍由原绑定负责。不能发布半初始化环境。
按值替换闭包、提前返回、循环跳转、调用失败及取消都使用同一清理责任模型；
FnOnce 调用中已移出的字段与环境剩余字段分别负责一次，多个 Drop 失败保留首错。
捕获中有自定义 Drop 记录时只能按已有整体移动/访问规则操作，不能隐式拆坏该记录。

同步执行仍会被解释器切片或取消，环境须保活且捕获初始化不重放；登记转移临界区不可暂停。
首版捕获闭包不进入语言 CPS 帧，也不作为 parallel / race 分支参数；
已有非捕获函数指针的挂起能力不代表带环境的新类型已获得挂起支持。

## 5. 标准库接入

在可调用约束和隐藏借用检查通过后，将 Option.map / and_then、Result.map / map_err /
and_then 的同步回调参数推广到合适的 FnOnce 约束，保持原有 fn 指针调用可用。
Some/Ok 路径调用次数准确；未调用分支也消费并清理按值传入的闭包环境。
输入拥有载荷转交、未选载荷清理、闭包失败和回调环境析构都须保持各自责任。

不同时引入 Iterator、Array.map、懒求值默认值 API 或 trait 默认方法；需要时另行扩展。
仅展示 `.map(fn(...))` 能解析不足以完成本阶段，必须执行带捕获的真实标准库调用。

## 6. 开发阶段

| 阶段 | 工作 | 验收门槛 |
| --- | --- | --- |
| C0：类型与责任模型 | 冻结语法、推导、Fn 约束身份、捕获顺序、借用和调用 ABI | 能解释三种能力、嵌套捕获与失败清理；明确 noescape 检查及所有拒绝边界 |
| C1：非捕获匿名函数 | AST、表达式解析、上下文推导、隐藏入口、fn 转换、move 保留字迁移 | 三后端直接/间接调用、局部控制流、泛型外部参数；缺注解、签名不符及非法跳转拒绝 |
| C2：同步借用捕获 | 环境来源、共享/独占捕获、局部 Fn / FnMut 调用 | 读取/修改与重复调用正确；逃逸、冲突、重入、自捕获与非 Copy 消费拒绝 |
| C3：move 与消费式调用 | 拥有捕获、环境移动、FnOnce、构造与析构失败 | 未调用/调用成功/失败/取消恰好清理一次；移动后误用拒绝，预算归还 |
| C4：泛型可调用与标准库 | Fn 家族约束、能力蕴含、隐藏引用检查、组合方法推广 | 带捕获的 Option/Result 三后端执行；旧函数指针兼容；未调用分支清理及能力负例通过 |
| C5：生命周期与稳定性 | 嵌套闭包、泛型实例、限额、解释器切片、旧模块保活 | 固定种子模型与相关 Release 取消/清理穷举；无编译期地址泄入 AOT |
| C6：集成与发布 | 示例、真实语法/布局/字节码文档与能力入口 | full 与 stress 发布验收，C0–C5 全部有证据后标首版完成 |

阶段前后必须明确支持范围；C2/C3 的局部可调用能力内部表示须与 C4 的约束一致，
不先交付一种之后必须更换所有权语义的闭包。共享运行时或解释器修改影响 Godot 时补跑适配器检查。

## 7. 验证矩阵与后续边界

三后端覆盖零/单/多捕获、同根多字段、嵌套闭包、Copy/拥有值/引用、Float32/Float64、
泛型上下文和标准库调用；浮点环境保护必须覆盖新增入口，不能因闭包内部 ABI 漏掉守卫。
同时检查调用次数、创建时不执行函数体、左右求值顺序、Drop 事件、预算恢复、旧代码保活。
负例覆盖未知参数类型、不同闭包类型合并、Fn/FnMut/FnOnce 不满足、不可变环境修改、
二次消费、借用逃逸、间接隐藏引用、私有字段、闭包自身引用及未支持的存储/挂起/FFI。

遵守 [AGENTS.md](../AGENTS.md)：纯计划只审查内容、链接和 `git diff --check`，不运行 Cargo。
实现先做针对性生成代码测试；环境布局、所有权或调用 ABI 变化运行 full 和相关 Release 穷举；
发布另跑 stress。AOT 必须独立执行，不只调用 Rust helper；未跑平台与性能测量单独列出。
完成后 language.md 记录真实语法，syntax.md 更新 fn 表达式及约束文法，architecture.md /
interpreter.md 记录环境、入口及清理不变量；README 只登记实际交付。

未来挂起闭包保留现有效果位置，目标写作 `move fn() @suspends -> Int32 { ... }`，
可调用约束也必须保留 `@suspends`。首版明确拒绝该匿名函数效果，不隐式推断或擦除。
后续需单独验收环境进帧、捕获借用跨 Pending、stop/取消、代码保活及结构化并发。
闭包返回/聚合存储、Box/dyn callable、宿主回调适配、显式捕获列表和用户可调用类型分别立项。
