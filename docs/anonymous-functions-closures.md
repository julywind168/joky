状态：2026-10-07，C0 设计核对基线 `a2026fb`。**C0 已冻结；C1–C6 已完成验收，同步局部首版完成。**
首版支持同步局部匿名函数、借用/move 捕获、Fn/FnMut/FnOnce 与 Option/Result 回调。
实现规则见 [language.md](language.md#同步匿名函数与闭包)，阶段证据见第 10 节。
2026-10-24 的同步拥有闭包存储与返回扩展见第 12 节；下文 C0–C6 是历史首版边界。
这是语言基础补齐的第 3 项；前两项见[模块常量与字段语法](module-constants-record-syntax.md)
与[记录解构](record-destructuring.md)。下文保留设计推导与冻结契约，挂起闭包与借用环境逃逸仍属后续范围。

## 1. C0 基线与首版目标

在 C0 基线中，同步及挂起的语言函数值已经实现，类型为 `fn(A) -> R` / `fn(A) @suspends -> R`。
它们没有捕获环境；[function_values.rs](../src/core/ir/function_values.rs) 负责受检间接调用。
该基线的 Option / Result 已有接收同步函数值的 map / map_err / and_then，闭包和可调用能力约束尚未实现。
当前静态 trait 也没有 trait 自身的类型参数，不能假定现有 trait 求解器已支持 Fn 家族。

首版交付同步匿名函数、参数上下文推导、借用捕获、`move` 捕获、局部重复或消费式调用，
以及可接收闭包的泛型同步 helper 和 Option / Result 组合方法。
首版不开放闭包跨语言挂起、捕获闭包返回类型、闭包存入记录/容器/持久实例、dyn callable、
宿主保存回调、C 回调 ABI、异步闭包或用户手写 Fn 实现。
非捕获闭包转成已有函数指针后，可沿用函数指针的已支持存储范围。

闭包和记录解构可以分别实施；闭包环境的内部字段不要求先开放用户记录解构或 dyn trait。
首版最终集成采用第 1 项确定的新字段语法。

## 2. 匿名函数语法

```joky
let add = |a: Int32, b: Int32| -> Int32 {
    a + b
}

let increment = |x: Int32| { x + 1 }
let mapped = Some(3).map(|x| { x * 2 })
let answer = (|x: Int32| { x + 1 })(41)
```

表达式写作 `|parameters| [-> Type] { body }`，零参数写作 `|| [-> Type] { body }`。
参数分隔仍必须使用逗号，允许尾逗号；首版参数只接受标识符，不支持参数模式、默认实参、
可变参数或匿名函数自己的泛型参数。可引用外围泛型参数，仍在定义作用域检查能力。

- 参数可逐个标注类型；未标注者从调用位置的期望签名推导。没有足够上下文时要求注解，
  不根据函数体猜参数类型，也不根据后面的第一次调用反向给已绑定闭包定型。
- 未写返回类型时，由已知期望返回类型和函数体末尾表达式/显式 return 统一推导；
  空块为 Unit，分支须同型，不增加隐式数值转换。不存在正常返回且无期望类型时要求注解。
  这与当前具名函数省略返回注解即为 Unit 的规则不同，不改变具名函数。
- `return` 返回当前闭包；`break` / `continue` 只能作用于闭包自身的循环，不能跳出外围函数。
  具名局部函数声明及自递归闭包不在范围内；初始化中的闭包不能捕获尚未完成绑定的自身。
- 花括号是必需的，不同时引入 `x => expression` 或 `|x| expression`。
  与已有 fn 类型的区别由类型/表达式上下文确定，不能改变 match / join 中 `|` 的含义。
- 每个匿名函数表达式有独立、不可直接书写的具体环境类型。同一语法位置在一次泛型实例中
  类型稳定；不同语法位置即使签名相同也不同，不隐式合并成公共动态类型。

调用参数的期望类型应在检查匿名函数体前传入。对于 `map<T, U, F>` 一类调用，先由接收者
或其他实参确定 T，再检查闭包参数与返回，最后确定 U 和 F；循环且无唯一解的推导报告错误。
限制推导与实例化工作量，不引入无限制的全局约束搜索。

## 3. 捕获与可调用能力

### 3.1 普通闭包：自动借用

```joky
let offset = 10
let shift = |x: Int32| { x + offset }

var count = 0
var tick = || { count = count + 1 }
tick()
tick()
```

自由局部变量按使用方式自动捕获：只读为共享借用，写入为独占借用。
捕获 Copy 变量也不悄悄改成快照；需要创建时快照用 `move |参数|`。
从捕获变量消费非 Copy 值的普通闭包首版拒绝，并提示显式使用 move 捕获。
引用类型的捕获必须保留其原来源、可变性和重借用限制。

借用在闭包创建时建立，存续到闭包被销毁或按现有可证明规则结束其使用；
借用未结束时，原绑定不能进行冲突写入、替换、移动或销毁。
首版按整个根绑定捕获，不做独立字段捕获；同时访问同一根的多个字段仍只有一个捕获项，
需要写入时统一为独占借用。不能借字段路径绕过私有性或 Drop 祖先限制。
模块常量、类型和具名函数不是局部存储，不创建环境捕获。

### 3.2 move 闭包：创建时转移

```joky
let offset = 10
let shift = move |x: Int32| { x + offset }

let message = "hello"
let report = move || { println(message) }

let payload = "owned"
let take = move || -> String { payload }
let result = take()
```

`move` 捕获所有实际用到的自由局部根：Copy 值复制，拥有值移动，未使用的变量不捕获。
引用按其现有复制/移动规则处理，move 引用不等于移动或延长它指向的对象寿命。
非 Copy 源在闭包创建后不可继续使用；环境销毁时释放仍持有的资源。
`move` 成为保留字，C1 必须盘点并迁移旧标识符及文档，不引入第二套显式捕获列表。

move 仅决定捕获方式，不决定调用次数。只读环境仍可重复调用；消费捕获值的调用会消费闭包。
上面的 report 由函数体实际使用方式判定能力，take 则属于消费环境的调用。

### 3.3 Fn / FnMut / FnOnce

| 能力 | 调用如何取得环境 | 典型行为 |
| --- | --- | --- |
| `Fn(A) -> R` | 共享借用 | 只读捕获，可重复调用 |
| `FnMut(A) -> R` | 独占借用 | 修改捕获，可重复调用 |
| `FnOnce(A) -> R` | 消费环境 | 可以移出拥有捕获，只保证一次调用 |

满足 Fn 的环境也满足 FnMut 和 FnOnce，满足 FnMut 的环境也满足 FnOnce。
不把 FnOnce 理解为“必须调用一次”：未调用即被丢弃的环境也必须正确清理。
裸语言函数指针满足同步的三种能力，仍不具有捕获环境。

直接调用选择具体闭包所需的最弱环境访问方式；FnMut 局部需要 `var` 或受检的 `&mut F`，
不能通过不可变 `let` 环境修改捕获。FnOnce 按值调用消耗原值，第二次调用为移动后使用。
闭包环境首版统一按移动值处理，不因为全部捕获为 Copy 就自动复制环境；
调用 Fn / FnMut 的自动借用不等于移动，非捕获到 fn 的转换是单独规则。
同一 FnMut 环境不允许重入形成两个独占调用，FnOnce 不允许重入消费两次。

### 3.4 泛型接口与非逃逸

可调用能力采用编译器识别的专门约束，冻结写法如下；解析、身份和预置名称规则见 9.1–9.2。
它们不能伪装成当前无参数普通 trait，不以实现完整 trait 泛型或 dyn 为前提。

```joky
fn apply<T, U, F: FnOnce(T) -> U>(value: T, transform: F) -> U {
    transform(value)
}

fn twice<F: FnMut() -> Unit>(action: &mut F) {
    action()
    action()
}
```

普通函数参数和返回类型仍必须明确。约束检查保持定义时验证、单态化身份、有限实例化及
三后端签名一致性；FnMut 需要的可变性不能因经过泛型被擦除。
首版不接受 `dyn Fn`、`impl Fn` 返回类型、显式 Fn impl 或把未知闭包类型当作裸函数指针。

捕获中携带的引用是函数值的真实借用来源，不能只检查参数表上的 `&T`。
首版借用闭包只能局部调用，或交给经检查的同步非逃逸 helper；编译器必须证明被调方不会
把环境或其捕获引用放进返回值、容器、实例、其他逃逸闭包或宿主保存位置。
普通同步函数已按参数推导不逃逸保证；本计划将同一分析扩展到可调用环境参数
（包括按值传入的 F），检查环境内隐藏引用。上面的 apply/twice 应由函数体自动证明，
无需使用者重复标注。可选的 `@noescape(transform)` 或无参数 `@noescape` 仍可固定接口契约，
必须检查，不能仅相信标注；无函数体的可调用接口仍需明确契约，不能仅从 Fn 能力推出不逃逸。
返回普通无引用结果或调用方已有来源的参数引用仍按现有规则验证。
闭包首版不能返回指向自己捕获环境的引用，不能靠 Fn(A) -> &T 省略其所需的来源关系。

### 3.5 与 fn 指针的边界

不捕获任何局部的同步匿名函数，在期望类型为匹配的 `fn(A) -> R` 时允许转换，生成普通
隐藏语言函数；不接受签名不匹配、宿主 extern 或效果擦除。
捕获闭包不能转为 fn 指针，即使优化器发现捕获为常量或环境最后变为空也不能改变类型规则。
旧 fn 指针的布局、调用 ABI 和已验证的同步/挂起行为保持兼容。

## 4. 环境布局、失败与存储

环境包含按确定顺序排列的捕获及其类型/借用/清理信息；顺序按源码中自由根首次出现确定，
而非 HashMap 遍历顺序。嵌套闭包的捕获传播和去重规则见 9.4，内层不能取得外层没有的权限。
环境不自动 Box 化，不需要 GC、Rc 或 dyn；物化的字节及清理登记计入现有预算。
零捕获闭包可没有数据环境；不能把零字节大小当作取消借用或清理语义的依据。

三后端共用类型明确的环境布局和私有入口约定，调用包含环境及普通实参。
JIT/AOT 共享 native lowering，解释器保持等价访问和清理；AOT 对象必须使用可重定位符号，
不能包含编译器进程中的环境或入口地址。入口、布局、Drop 与旧模块代码所有者一起保活。
生成类型和入口的标识须纳入泛型实例身份，并受编译数量/深度/布局限额约束。

创建闭包只建立捕获，不执行函数体。预检与空间预留在破坏源拥有权之前完成；确需分步
初始化时，失败仅清理已经取得的捕获，未取得的仍由原绑定负责。不能发布半初始化环境。
按值替换闭包、提前返回、循环跳转、调用失败及取消都使用同一清理责任模型；
FnOnce 调用中已移出的字段与环境剩余字段分别负责一次，多个 Drop 失败保留首错。
捕获中有自定义 Drop 记录时只能按已有整体移动/访问规则操作，不能隐式拆坏该记录。

同步执行仍会被解释器切片或取消，环境须保活且捕获初始化不重放；登记转移临界区不可暂停。
首版捕获闭包不进入语言 CPS 帧，也不作为 join / race 分支参数；
已有非捕获函数指针的挂起能力不代表带环境的新类型已获得挂起支持。

## 5. 标准库接入

在可调用约束和隐藏借用检查通过后，将 Option.map / and_then、Result.map / map_err /
and_then 的同步回调参数推广到合适的 FnOnce 约束，保持原有 fn 指针调用可用。
Some/Ok 路径调用次数准确；未调用分支也消费并清理按值传入的闭包环境。
输入拥有载荷转交、未选载荷清理、闭包失败和回调环境析构都须保持各自责任。

不同时引入 Iterator、Array.map、懒求值默认值 API 或 trait 默认方法；需要时另行扩展。
仅展示 `.map(|value| { ... })` 能解析不足以完成本阶段，必须执行带捕获的真实标准库调用。

## 9. C0：类型与责任模型（已冻结，2026-10-07）

本节是 C1–C5 的冻结契约；这里的 AST / IR 名称描述概念模型，实际实现使用私有名义
`Record.closure` 与可擦除的移动标记。当前可执行示例与行为证据见第 10 节。

### 9.1 解析与名称边界

在现有文法上增加以下产生式；这里的 `Type`、`Block`、`Name`、`Arguments` 沿用
[syntax.md](syntax.md#11-核心语法ebnf)，当前核心文法已加入这些同步产生式。

```ebnf
AnonymousFunction = [ "move" ], ( "||" | "|", ClosureParameter,
                    { ",", ClosureParameter }, [ "," ], "|" ), [ "->", Type ], Block ;
ClosureParameter  = Identifier, [ ":", Type ] ;
CallableBound     = ("Fn" | "FnMut" | "FnOnce"), "(",
                    [ Type, { ",", Type }, [ "," ] ], ")", "->", Type ;
Bound             = Name | CallableBound ;
TypeParameter     = Identifier, [ ":", Bound, { "+", Bound } ] ;
GroupedAnonymous  = "(", (AnonymousFunction | GroupedAnonymous), ")" ;
ImmediateCall     = GroupedAnonymous, Arguments ;
```

- `AnonymousFunction` 和 `ImmediateCall` 加入表达式 Primary；`fn` 后有名字仍只属于
  已有声明位置，表达式位置不开放具名局部函数。`move` 在 C1 成为词法保留字。
- C1 支持 `(|x: Int32| { x + 1 })(41)`，也支持先绑定再按现有名字调用。
  后续语法收敛已统一调用后缀：`factory()(x)`、`(f)(x)` 及直接字面量共用调用规则，
  同一行的独立表达式要求分号分隔。旧相邻表达式源码已迁移，当前规则见 language.md。
- `Fn` / `FnMut` / `FnOnce` 是编译器内建、不可遮蔽的类型约束名称，独立于 prelude
  开关；不是词法关键字，不占值或字段名称空间。C4 拒绝同名类型、trait、类型参数及
  类型导入别名，并盘点迁移旧源码。只接受上述非限定拼写，不开放导入、别名、
  `module.Fn(...)`、`Fn<T, U>`、裸 `F: Fn` 或在普通类型位置写 `Fn(...)`。
- 匿名函数参数不接受 `_` 模式、`self` 接收者、默认值、属性或自身类型参数。
  C1 对 `move` 标识符的迁移包含测试中嵌入的 Joky 源码；不能误改 Rust 的 `move`。
- 首版匿名函数和 callable bound 均为同步。解析遇到 `@suspends` 应在该效果处报告
  尚不支持，不降级为同步；未声明效果也不能在函数体调用挂起入口。

### 9.2 类型身份、能力与泛型定义检查

AST 用独立的 `AnonymousFunction` 节点保存捕获方式、可选参数/返回注解、函数体和
源码范围。普通 trait 名称约束与 `CallableBound { kind, params, ret, effect }` 分开表示；
不能把后者塞进现有 `TypeParameter.bounds: Vec<String>` 或通过拼接字符串模拟身份。

每个闭包具有内部 `ClosureId = (模块身份, 外围具名定义身份, 匿名表达式序号, 外围泛型替换)`。
模块身份属于被编译的源码快照，不是文件名；序号按该具名定义内源码顺序编号（包含嵌套
字面量），重复规划复用，不同具名函数中的第一个字面量不会撞号。
泛型替换包含所有外围参数的规范化类型，包括未被捕获但影响函数体的参数。
透明别名不制造新身份，不同模块、不同字面量、不同具体实例不合并；重载后旧模块保持旧身份。
运行时循环多次执行同一字面量创建不同的值，但具有同一类型。

闭包类型保存签名、最弱调用能力、确定的捕获布局和来源摘要；环境类型与已有
`Type::Function` 分开。所有闭包值（含零捕获）均非 Copy，可整体移动，不可隐式复制；
其内部布局为空也不能放宽此规则。零捕获闭包满足 Fn；转成 `fn` 后才是 Copy 函数指针。

callable bound 身份为内建能力枚举及规范化的参数、返回、效果类型，不注册为普通 trait。
同一参数可以与普通 trait 用 `+` 组合；多个 callable bound 必须签名和效果完全一致，
相同约束去重，能力取最强要求（Fn 强于 FnMut，FnMut 强于 FnOnce）。不同签名拒绝，
首版没有可调用重载、参数逆变或返回协变。普通 trait 的孤儿规则和重叠规则不因此改变，
用户不能为任意类型手写 callable impl。

| 检查时可见的能力 | 经 `F` 调用 | 经 `&F` 调用 | 经 `&mut F` 调用 |
| --- | --- | --- | --- |
| Fn | 共享借用，保留 F | 允许 | 共享重借用，保留 F |
| FnMut | 需要 `var`，独占借用，保留 F | 拒绝 | 独占重借用，保留 F |
| 仅 FnOnce | 消费 F，不要求 `var` | 拒绝 | 拒绝移出借用 |

具体闭包直接调用采用自身最弱能力；模板按声明的保证检查。例如只声明 FnOnce 的模板
不能调用两次，即使某次实参是 Fn；声明 FnMut 的模板也不能因某次实参是 Fn 而省略可变性。
`&F` 在 F: Fn 时可作为 Fn 实参；`&mut F` 在 F: Fn 时可作为 Fn 实参、在 F: FnMut 时
可作为 FnMut 实参，均继承能力蕴含规则；F 仅满足 FnOnce 时不生成借用适配。
消费这样的引用实参只消费引用，不能据此移出被指向的环境。
同步语言函数指针满足三种约束；挂起指针不满足同步约束，裸宿主指针不参与证明。

C4 允许闭包作为具有 callable bound 的泛型参数实参；F 的抽象检查按移动值处理，
不得套用 Copy 假设。未使用模板也要检查调用、移动、借用和能力；具体实例复核布局、
隐藏引用、效果和清理。无 callable bound 的泛型参数首版不接收闭包，不能借 `identity<T>`
绕过闭包返回/存储禁令。F 的可用操作限调用、局部移动/借用/销毁及交给受检 helper，
普通类型参数 T/U 的既有规则保持不变。

### 9.3 有界上下文推导与转换

推导与运行时求值分离：类型提示可以提前读取其他实参的已知类型，不能执行表达式、
提前转移拥有权或重新执行闭包体；运行时仍先 callee、后各实参，从左到右各求值一次。

1. 收集显式泛型实参、接收者及非闭包实参的已有类型，沿用现有默认字面量规则，先确定
   callable bound 中可确定的输入类型。绑定的 `fn(...) -> ...` 注解或直接参数的函数类型
   也能提供期望签名；不从后续调用回溯修改已经绑定的闭包。
2. 将签名传入匿名函数，再合并逐个参数注解。每个输入必须在检查函数体前唯一确定，
   冲突报错；`let f = |x| { x + 1 }` 与 `(|x| { x + 1 })(41)` 均缺少参数上下文而拒绝。
   立即调用的实参不反向给 callee 定型，补 `x: Int32` 即可。
3. 返回注解优先约束函数体；没有注解时使用已知期望返回类型，尚未确定时由所有正常
   返回路径统一推导，包括显式 return、块末尾及空块 Unit。分支必须同型，发散分支
   不贡献结果；无正常返回且无任何返回类型提示时拒绝，不推导出新的 Never 类型。
4. 用结果填充 U 等尚未确定参数，用 ClosureId 填充 F，再验证能力和借用效果。
   多个闭包参数按源码顺序反复处理已具备输入提示者；一轮无进展且仍有未定输入即拒绝，
   提示补注解/显式类型实参。不利用待检查函数体猜输入类型，也不做无界候选搜索。

不为普通泛型调用新增“从外层返回类型反推所有实参”的机制。`apply(value, |x| { ... })`
与 Option/Result 方法按上述局部顺序即可确定输入；引用外围刚性参数的闭包体仍在原定义
作用域检查，不能依赖某个实例才具备的操作。

当期望类型明确为匹配的同步 `fn` 时，零捕获闭包可转换；包括直接字面量和已绑定的
零捕获闭包值。转换消费该闭包值，生成使用现有函数值 ABI 的隐藏入口；类型匹配精确，
不会把捕获闭包常量折叠成函数指针。没有期望类型时保持独立闭包类型，不因分支中的两个
字面量签名相同而合并；显式把各分支转换成相同 fn 类型后才可合流。

### 9.4 捕获发现、嵌套传播与借用期限

捕获依据解析后的局部绑定身份，不能只按名字去重。参数、本层局部绑定和内层新绑定
不属于本层自由变量；初始化完成前新名字不可见，同名外层绑定仍按通常词法规则解析。
没有外层绑定时引用自己的初始化名报未知名，不创造自递归入口。

按源码从左到右深度优先访问函数体，包含嵌套字面量的函数体，记录每个自由根的首次
出现位置；内层需求先分析再向外传播。根在捕获列表中的首次位置固定，后来从共享升级
为独占不改变顺序。静态分支中可引用的自由变量也计入，优化消除代码不能改变类型或布局。
多个字段合并到同一根；访问路径的可见性和 Drop 祖先检查仍逐次执行。

嵌套环境必须通过直接外层所持有的值/借用取得自由根，不越级读取原调用者的存储。
自由根仅在内层使用时，仍触发外层捕获；若根在外层体内声明，需求止于外层局部，
不会变成外层自己的捕获字段。各层独立决定捕获方式，并向外传播所需权限：

| 内层对根的需求 | 普通外层闭包 | move 外层闭包 |
| --- | --- | --- |
| 只读借用 | 外层共享捕获；内层重借用 | 外层持有值；内层借用该字段 |
| 写入/独占借用 | 外层独占捕获，能力至少 FnMut | 内层独占借用字段，外层能力至少 FnMut |
| move Copy 值 | 从外层共享捕获读取快照 | 从外层字段复制快照 |
| move 非 Copy 值 | 拒绝从借用捕获移出，提示外层也用 move | 外层转移字段，外层能力为 FnOnce |

例如普通外层创建并局部调用一个修改 count 的内层，即使外层没有直接赋值，也必须独占
捕获 count；move 外层创建消费 payload 的 move 内层时，payload 在外层创建时先移入
外层，调用外层时才转给内层。内层的 `move` 不能自行把普通外层的借用升级为拥有。
借用引用时同时保留引用绑定及其目标来源；重借用独占引用不复制独占权限。

捕获借用在环境创建时建立；局部嵌套环境的借用不得超过外层环境或原来源的寿命。
首版以词法作用域结束/显式消费为基准，仅复用现有已证明的提前结束规则，不承诺新的一般
最后使用分析。移走环境会转移借用责任；调用 Fn/FnMut 后捕获借用仍随环境存活。
临时闭包在完整调用结束后销毁；FnOnce 消费调用完成清理后结束其捕获借用。
环境自身被借用期间禁止移动/替换；同根引用别名仍由现有来源冲突检查处理。

### 9.5 环境不逃逸与调用实参的效果

在现有 [borrowing.rs](../src/core/ir/borrowing.rs) 的返回/保存来源分析中增加环境来源，
覆盖按值 F、`&F`、`&mut F` 和嵌套环境中的引用；不能因参数表没有 `&T`、布局为零、
或刚性 F 尚无具体字段就认为无引用。模板中的环境使用独立的符号来源，实例化后绑定
实际捕获来源，最终效果证明成功前不能发布隐式借用。

区分两个检查对象：helper 如何使用 F，以及 F 被调用时如何使用普通实参。
Fn 家族只赋予调用方式；helper 仍必须从函数体证明只局部持有、调用、销毁 F，或转交
同样被证明的同步 helper。返回 F、返回其隐藏引用、存入容器/实例/宿主、交给未知保存
位置均不能满足此证明，显式 `@noescape(F参数名)` 也必须由同一分析验证。

首版受检闭包入口另有统一环境约束：不能发布环境自身、保存其借用到更长寿命位置，
也不能返回捕获引用（包括 move 捕获的引用）。FnOnce 可把捕获的**无引用拥有值**作为
普通结果转交；这不等于泄露环境借用。普通实参的引用可按已有来源规则返回，不能借此
混入捕获来源。内层在外层调用结束前销毁的局部借用不是逃逸。
此规则在所有闭包定义处验证，不由优化或某个调用点免除。

因此 `apply` 可证明对 transform 环境不逃逸：调用受检入口后销毁/转交其无引用结果，
无需用户标注。这个证明**不同时承诺 value 参数不被回调保存**；抽象 callable 调用对
普通实参的返回/保存效果仍保守，已知具体闭包可用其受检摘要精化。现有函数指针仍沿用
保守间接调用效果，不因满足 Fn 就新增 `noescape` 保证。所有模板和实例均有最终检查，
同一来源同时流入其他未受约束实参时不得被环境侧证明删除。

传播、递归固定点及预算失败继续采用现有分析框架；未知宿主/trait/间接保存点没有自动
保证。无函数体接口只接受已有受信且可检查的边界契约，本计划不新增宿主回调契约入口。

### 9.6 布局、私有入口与三后端边界

环境是静态具体类型，字段按 9.4 的捕获顺序布局：借用捕获保存受检引用，move 捕获保存
实际值。每字段保留类型、对齐、偏移、原来源和清理信息；复用普通类型布局与溢出检查。
拥有位/初始化状态属于清理元数据，不向源码暴露为可访问字段。环境本身无用户 Drop，
其字段中已有 Drop 的值按原规则整体处理。

闭包值不必携带入口指针或 vtable；ClosureId 在编译期选择具体入口，泛型 helper 单态化
后也直接选择对应入口。冻结的逻辑调用协议为 `entry(env, args...) -> result`：Fn 的 env
是共享借用，FnMut 是独占借用，FnOnce 是拥有责任转交。弱能力适配只能增强限制，
不能复制环境；以 FnOnce 调用 Fn/FnMut 的适配入口负责在调用结束后销毁接收的环境。

原生私有入口的物理参数顺序固定为 **env 地址、普通参数的现有标量展开、可选聚合结果
缓冲地址、arena 地址**；即使零捕获也保留 env 参数位，零捕获入口不得解引用它。
所有闭包私有入口统一带 arena，上述统一传参不意味每个函数都分配；标量/Unit 返回
复用原生既有规则，聚合结果由调用方提供，先检查错误再读取。环境地址和清理记录在
调用期间稳定；FnOnce 的地址不是借用权限，清理责任在不可暂停的提交点转到被调方。
不借现有 C 签名、公开宿主签名或 `EntryAbi` 暴露此协议。

解释器使用同一类型布局、调用模式、结果与清理语义，以模块内入口标识和受检环境位置
执行；不存原生代码地址。环境需要取地址时使用有预算的稳定存储，不能保存会因寄存器
压缩/activation 移动而失效的槽地址。原生可以用稳定的局部存储，解释器可以用其 activation
管理的存储；各后端的物化环境与清理元数据均纳入资源限额，无隐式 Box/GC 或引用计数。

转为 fn 时生成单独无环境包装，使用既有函数值 ABI：原生入口符号加隐藏 arena，
解释器为模块内 callee 索引；旧同步及挂起函数指针布局完全不改。AOT 的入口和清理函数
均用可重定位符号，环境仅在程序运行时建立；模块代码所有者覆盖隐藏入口、布局与 Drop
依赖，不能把编译器指针或跨模块不稳定序号写入对象文件。

C1–C5 的新增类型深度、实例数、实例依赖深度分别纳入 256、4096、32 上限；闭包
隐藏入口和所需适配入口也计入生成数量预算，不能因不具名而绕过额度。捕获字段数、
环境字节数和清理项计入已有槽位/布局/运行时预算，所有计算先检查溢出。多轮推导和
捕获传播共享编译工作量预算，耗尽报告资源限制，不发布不完整类型或效果证明。

### 9.7 调用、构造和失败的清理责任

callee 先求值并建立共享/独占调用借用或 FnOnce 的消费临时值，再从左到右求值实参。
实参不能重入同一 FnMut/FnOnce、替换被借用环境或再次取得已消费环境；不引入两阶段
借用。实参求值失败也必须清理已消费到临时位置的 FnOnce，调用体尚未执行。

环境创建先验证全部捕获并预留存储/清理容量，再按捕获顺序初始化；资源转移与其登记
在同一不可暂停临界区提交，所有字段成功后才发布闭包绑定。移动不会运行用户代码，
借用捕获不会执行函数体；部分初始化失败不恢复已经发生的源移动或其他副作用。

| 时刻/路径 | 唯一清理责任与恢复行为 |
| --- | --- |
| 预检/预留失败 | 源绑定仍负责全部拥有值；释放预留，环境不可见 |
| 第 k 项捕获前失败/取消 | 环境构造临时项负责已取得的前缀；源绑定负责尚未取得项，均只清理一次 |
| 环境已发布但未调用 | 环境负责所有拥有捕获；借用字段仅结束借用，不销毁其目标 |
| Fn/FnMut 成功或失败 | 被调方结束本次调用借用；调用方仍持有环境，任务失败时由其清理路径销毁 |
| FnOnce 实参失败/尚未进入入口 | 调用临时值负责环境和已求值的拥有实参；源闭包已经不可用 |
| FnOnce 入口接收成功 | 被调方负责剩余字段；移出的字段把责任原子转给局部、内层环境或结果临时值 |
| 结果已计算但退出 Drop 失败 | 不向调用方发布成功结果，清理结果临时值及剩余环境，保留首错 |
| 按值传入 helper 但分支未调用 | helper 仍负责销毁环境，例如 None/Err 未选中的回调 |
| 环境替换 | 先完成新 RHS 到临时值，再销毁旧值，成功才安装新值；旧值 Drop 失败时清理新临时值 |
| 提前 return、break、continue、任务取消或 VM 销毁 | 按退出作用域逐个取走仍登记的清理责任；已转交项不能再清理，不重放捕获或调用 |

不同局部环境按既有局部绑定逆序清理；单个环境内仍持有的字段按捕获声明顺序清理，
与普通记录的字段声明序一致，部分初始化只遍历已登记字段。字段中自定义 Drop 先按原有
记录规则执行，再释放其内部拥有资源；不能因为环境可消费就拆出 Drop 记录的拥有字段。
多个 Drop 失败继续清理其余项并保留第一个错误；已有调用错误优先于随后清理错误。
只读、零字节或无拥有字段的环境仍保留其借用/消费状态，不要求伪造拥有资源来登记它。

解释器时间片只在上述转移临界区之外让出，保存完整进度与环境责任；取消走同一清理表，
不重新执行初始化。同步入口的浮点环境、运行时错误和取消检查复用既有约定。

### 9.8 首版拒绝边界与阶段验收用例

以下是 C0 冻结的正反例清单；当前实现证据见第 10 节，C0 的“完成”只表示规则已确定。

| 边界 | 要接受的行为 | 要拒绝的行为 | 验收阶段 |
| --- | --- | --- | --- |
| 语法/控制流 | 明确输入、返回推导、闭包内 return/循环 | 缺输入提示、返回冲突、跳到外围循环、自递归、匿名泛型、@suspends | C1 |
| 身份/转换 | 同一语法位置实例稳定、零捕获转 fn | 不同字面量默认合流、捕获转 fn、错误签名/效果 | C1–C2 |
| 借用/权限 | 共享读取、var 环境重复修改 | 捕获存活时冲突访问、let 调 FnMut、共享引用写入、重入独占 | C2 |
| 所有权 | move 快照、整体移动、FnOnce 移出无引用拥有值 | 普通捕获消费非 Copy、创建后用已移动源、二次调用、拆坏 Drop 祖先 | C2–C3 |
| 泛型/标准库 | Fn 能力蕴含、apply/twice 自动证明、Option/Result 捕获回调 | 未使用模板非法操作、FnOnce 调两次、宿主指针冒充 callable、未知保存效果 | C4 |
| 嵌套 | 传播自由根、同根去重、内层局部调用/清理 | 内层越权、返回内层环境、内层借用活着时移动外层 | C2–C5 |
| 返回/存储 | 局部绑定/赋值、受检同步 helper、局部嵌套捕获 | 闭包返回或放入元组/记录/枚举/容器/arena/持久实例；隐式分配/Box/dyn | C2–C5 |
| 来源 | 返回普通实参允许的引用、返回无引用拥有结果 | 返回捕获引用、指向环境字段的引用、间接藏入结果的环境来源 | C2–C5 |
| 挂起/宿主 | 同步 helper 被现有 CPS 调用，环境完全留在其同步内部 | 在 @suspends 函数体内创建/持有闭包环境，环境进 CPS 帧/join/race 参数，FFI/宿主保存 | C2–C5 |
| 生命周期 | 未调用/失败/取消各资源恰好一次，旧模块代码保活 | 重放初始化、丢失清理登记、错误后读取成功结果、AOT 编译期地址 | C3–C5 |

首版在 `@suspends` 函数内仅允许**直接零捕获字面量在已知 fn 期望类型下立即转换**，
转换后按旧函数指针规则使用；不物化独立闭包环境。即使源码看起来环境在第一次挂起前
已用完，也不新增跨 CPS 的局部生命周期证明。同步函数内的闭包仍需通过解释器切片与取消
验收。以上限制对 move、无引用捕获和零字节环境同样有效，不能只检查“是否含引用”。

实施阶段的历史开关：C1 的 move fn 仅接受零捕获；C2 接受普通借用捕获并对非空 move 捕获报告未实现；
C3 开放 move 捕获。C1–C3 遇到 callable bound 报未实现，不退化为普通 trait；
C4 才开放其解析/定义检查与标准库迁移。C5 加强嵌套、限额和生命周期覆盖，不能在 C2/C3
先跳过已经支持的嵌套环境所必需的安全检查。

## 12. 同步拥有闭包存储与返回（2026-10-24，已完成）

目标：不含借用的 move 闭包可作为泛型记录的字段，整体移动、借用调用及消费；
允许同步泛型函数返回其接收的闭包或包装记录，允许匿名函数推导返回的拥有闭包类型。
闭包即使只捕获 Copy 数据或零捕获，仍为不可复制的移动值；包装记录继承这个性质。
捕获中嵌套的闭包也必须满足同一存储资格，move 一个引用不会使它获得存储资格。

具名函数的返回类型仍须可明确书写，本阶段不引入 impl Fn、dyn callable 或具名函数
返回类型推导。普通借用闭包保留局部及受检同步 helper 用法，不开放返回或聚合存储。
闭包及包装记录不得进入容器、枚举、元组、arena、持久实例、宿主 ABI 或挂起帧。
回调本身仍同步；迭代组合器作为后续标准库工作，不与本阶段混合。

复用静态闭包入口和既有聚合布局、所有权及清理机制，不增加隐式 Box 或动态分派。
验证覆盖 Fn/FnMut/FnOnce、嵌套记录、返回及替换、未调用销毁、错误清理、移动后使用、
借用捕获拒绝与其他边界；执行 JIT、解释器、独立 AOT、相关 Debug 取消穷举及默认检查。


设计提交 `f5389bc`。实现支持无引用 move 环境的泛型实参、记录字段、透明别名、同步返回，
以及匿名工厂和泛型 callable 回调返回新环境的类型推导。存储资格遍历拥有容器的元素类型，
捕获含引用的数组不会因外层只有拥有句柄而被误判为无引用。原始借用闭包与抽象 callable
参数继续保留符号借用来源；记录中的 callable 字段在具体实例化时复核存储资格。

实现复用空拥有句柄作为可存储环境的私有移动身份；该槽恒为空，不分配对应缓冲区载荷，
使零捕获及纯 Copy 捕获的包装记录也能沿用所有权、用户 Drop 和清理组规则。匿名工厂的结果
由受检函数体确定具体环境身份；只返回环境的工厂不生成不可书写签名的函数指针转换包装。

CLI 304 项通过 / 8 项忽略，其他默认集成测试及三后端 while/Map 短输入正确性通过。
