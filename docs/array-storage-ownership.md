## 1. 范围与已有实现的衔接

当前实现 `Array<T>`（T 为受支持的 Copy 类型，或无引用内容的拥有型记录、枚举）：连续存储、长度/容量、受检读写、push/pop、扩容、管理权移动、临时借用及元素/切片视图。
数组算法写在 `src/stdlib/array.jk`；编译器提供缓冲区类型及受检存储原语，运行时只负责分配与底层访问。
不新增数组关键字、索引语法或用户 unsafe 指针操作。

当前实现有三个必须正面处理的边界：

- 函数、记录、枚举及别名可使用拥有型实参，元组可包含 Copy 数据或拥有者；数组拥有者非 Copy。7c.5 已开放一个或多个拥有字段加无引用 Copy 元数据的记录，不能用可复制的 Ptr 或普通 Copy 记录模拟所有权。
- Array 已成为带私有 Buffer 字段的名义结构体，普通 `impl<T> Array<T>` 提供关联函数及 self / &self / &mut self 方法；原模块函数继续兼容。
- `uses_arena` 表示分配效果及普通引用的任务期存储契约；`needs_arena` 独立表示分配/回收需要的隐藏任务上下文。数组扩容需要分配，
  但不得因此把对数组拥有者的临时借用延长至任务结束；第 5 节规定独立、按类型判定的契约。

首版限同步创建、移动和借用；现阶段已补充无引用元素 `Array<T>` 跨普通语言挂起的拥有者转移。
这类数组可以作为 `@suspends` 参数、返回值和中间值，三后端共用 CPS 清理；数组视图、含引用元素数组和用户自定义拥有记录
不能跨语言挂起或进入 scope/race，所有数组也不能进入宿主边界。
解释器内部时间片暂停同步 helper 不算语言级挂起，仍必须正确保活和清理。

7b.1 支持 Int32、Int64、UInt32、UInt64、Bool、Unit、Ptr 及由它们组成的有限记录、元组和枚举。
7b.2 支持普通共享引用及含它们的 Copy 聚合，保留元素引用来源；7b.3 提供受检的元素/切片借用。7c.1 实现显式释放和扩容时旧载荷回收；7c.2 开放单一拥有字段的记录包装与数组方法，7c.3 允许附加无引用 Copy 元数据。7c.4 增加同步 Drop 与作用域清理，7c.5 扩展多拥有字段记录，7c.6 增加消费式字段提取与完整记录的字段替换；7c.7 开放整体移动的拥有型记录数组元素，可继续使用原记录的部分移出仍属后续 7c。
Copy 数组的 get/pop 返回 T 的复制值；borrow/slice 则返回受拥有者约束的存储视图，不公开原始地址。String、宿主 opaque 类型、独占引用及数组视图元素仍拒绝。拥有型元素可使用 borrow_ref 只读借用，或 take_last / pop 整体移出，详见 7c.7 / 7c.8 / 7c.9。

## 2. 公开接口

显式导入 `joky/array`，不加入默认 prelude。`Array.new::<T>()` / `Array.with_capacity::<T>(n)` 构造数组；
拥有型数组接口另见 7c.7；其余同名方法把下表首个数组参数作为接收者，支持 `values.push(x)`、`values.get(i)`、`values.release()`。
`&self` / `&mut self` 自动借用，`self` 消费拥有者；原有以下模块函数全部兼容，可混用两种风格。

| 接口 | 结果与规则 |
| --- | --- |
| `array.new::<T>() -> Array<T>` | 创建空数组，len/capacity 均为 0 |
| `array.with_capacity::<T>(capacity: UInt64) -> Array<T>` | 创建 len 为 0、容量为指定值的数组；不初始化元素 |
| `array.release(values: Array<T>)` | 消费无活动借用的拥有者，立即释放其当前载荷和控制块、退还预算；不能再次使用 values |
| `array.len(values: &Array<T>) -> UInt64` | 返回已初始化元素数 |
| `array.capacity(values: &Array<T>) -> UInt64` | 返回无需重新分配即可容纳的元素数 |
| `array.is_empty(values: &Array<T>) -> Bool` | 等价于 len 为 0 |
| `array.get(values: &Array<T>, index: UInt64) -> Option<T>` | 越界返回 None，否则复制元素；结果不携带数组借用 |
| `array.set(values: &mut Array<T>, index: UInt64, value: T) -> Bool` | 越界返回 false 且不修改数组，否则替换并返回 true |
| `array.push(values: &mut Array<T>, value: T)` | 必要时扩容，在已初始化前缀后追加一个元素 |
| `array.pop(values: &mut Array<T>) -> Option<T>` | 空数组返回 None，否则复制末元素并缩短已初始化前缀 |
| `array.reserve(values: &mut Array<T>, additional: UInt64)` | 保证 capacity 至少为 len + additional；不改变 len |

7b.3 另提供以下借用接口；Element 和 Slice 分别从 joky/element、joky/slice 显式导入，后者建议命名为 slices：

| 接口 | 结果与规则 |
| --- | --- |
| `array.borrow(&Array<T>, UInt64) -> &Element<T>` | 借用一个已初始化元素 |
| `array.borrow_mut(&mut Array<T>, UInt64) -> &mut Element<T>` | 独占借用一个已初始化元素 |
| `array.slice(&Array<T>, start: UInt64, end: UInt64) -> &Slice<T>` | 共享借用半开区间 [start, end) |
| `array.slice_mut(&mut Array<T>, start: UInt64, end: UInt64) -> &mut Slice<T>` | 独占借用半开区间 |
| `element.read(&Element<T>) -> T` | 复制所借元素 |
| `element.write(&mut Element<T>, T)` | 替换所借元素，保留既有共享引用存储规则 |
| `slices.len(&Slice<T>) -> UInt64 / slices.is_empty(&Slice<T>) -> Bool` | 读取切片长度/是否为空 |
| `slices.get(&Slice<T>, UInt64) -> Option<T>` | 复制元素，越界返回 None |
| `slices.set(&mut Slice<T>, UInt64, T) -> Bool` | 替换元素，越界返回 false |
| `slices.borrow(&Slice<T>, UInt64) -> &Element<T>` | 借用切片中的元素 |
| `slices.borrow_mut(&mut Slice<T>, UInt64) -> &mut Element<T>` | 从独占切片重借用元素 |
| `slices.slice(&Slice<T>, start: UInt64, end: UInt64) -> &Slice<T>` | 借用子区间，索引相对当前切片 |
| `slices.slice_mut(&mut Slice<T>, start: UInt64, end: UInt64) -> &mut Slice<T>` | 独占重借用子区间 |

borrow/borrow_mut 必须满足 index < len；slice/slice_mut 必须满足 start <= end <= len。
空切片合法，非法借用构造通过带位置的运行时错误终止任务；与 get/set 的 None/false 不同。

长度、容量和索引用 UInt64；转为目标地址宽度之前必须检查，不使用截断转换。
容量/大小溢出、预算超限或底层分配失败走现有运行时错误通道；不返回伪造的空数组。
get/set 的越界是正常业务结果，不终止任务；内部存储原语仍必须独立检查边界。

构造函数必须显式写元素实参，如 `Array.new::<T>()` / `Array.with_capacity::<T>(n)`（或原模块函数）；
不从返回注解或后续 push 反推类型。其他函数从数组实参推导 T。旧的无类型参数构造调用需补齐类型。

可运行示例：

```joky
import joky/array as array.{type Array}

fn answer() -> Int32 {
    var values: Array<Int32> = array.new::<Int32>()
    array.push(&mut values, 20)
    let view = &values
    let first = array.get(view, 0).unwrap_or(0)
    // view 最后使用后恢复修改权限，不永久封存数组。
    array.push(&mut values, 22)
    let moved = values
    // values 已移动；只有 moved 持有管理权。
    first + array.get(&moved, 1).unwrap_or(0)
}
```

局部拥有者遵循现有绑定权限：`var` 才能取 `&mut`；`let` 可读取、共享借用或移动。
已持有 `&mut Array<T>` 的 helper 可直接调用修改函数，沿用调用重借用，不必再次取引用。

## 3. 类型、表示与封装

### 3.1 受限的缓冲区类型

编译器认识非 Copy 类型族 `Buffer<T>`；7b.1 将 7a 的 Int32 限制推广到无引用 Copy 元素，7b.2 再开放普通共享引用元素。
`joky/array` 导出名义结构体 `Array<T>`，其唯一字段 `storage: Buffer<T>` 默认模块私有。
用户不能构造、读取、赋值或借用这个私有字段，只能使用公开函数和普通 impl 方法。
类型声明可以保存未实例化的别名模板，但每个实际应用都须检查元素限制；不能利用未调用模板、
别名或跨模块转发绕过限制。数组函数及私有原语沿用刚性参数模板检查和编译期单态化，
不新增 trait 或约束语法。未使用的模板同样检查所有权，具体实例再次检查元素资格与内存布局。

Array 的 T 是元素类型；`Array<T>` 本身仍不是 Copy。7c.7 起可作为泛型函数、记录和别名的类型实参；
可进入一个或多个拥有字段的记录，可进入 enum（包括 Option/Result），可进入元组，不能进入 arena 对象或 graph。仍不开放包含数组视图的聚合，
不开放把数组视图绑定为普通泛型实参；透明别名及形参明确写 Array<T> / &Array<T> 的泛型 helper 可以转发拥有者或视图。
这些限制按解析后的真实类型递归检查，不只匹配 Array 名称。

Buffer 没有公开字段、记录构造语法、可用的零值或与 Ptr/整数/普通引用的转换。
`alloc`、`memory.read/write`、字段投影、C 布局和旧宿主注册均不能复制或解释其控制块。
用户新增同名类型、模块、extern 或 impl 不会得到缓冲区能力。

`Element<T>` 与 `Slice<T>` 是编译器拥有的借用目标类型，只能以 & / &mut 使用；
不能按值构造、传参、返回或放入数组及聚合。三种目标按真实类型区分，保持相同封装边界。
`&Element<T>` 借用数组存储，不能解释为普通 &T；尤其当 T 本身含共享引用时，
它与 element.read 返回的普通引用具有不同来源和寿命，不引入普通嵌套引用能力。

### 3.2 拥有字段与模块私有字段

7c.2 允许 `struct Batch<T> { values: Array<T> }`（字段默认私有），也允许再用一个拥有字段包装 Batch。
7c.3 进一步允许一个拥有字段加任意数量的无引用 Copy 字段，拥有字段不必在首位：

```joky
struct Batch<T> {
    version: UInt64
    values: Array<T>
    sorted: Bool
}
```

元数据可为数值、Bool、Unit 或无引用 Copy 聚合，泛型实参会在特化后重新检查；
普通共享引用也不能作为元数据。7c.5 已开放多个拥有字段，各字段可有不同的元素类型；7c.6 支持提取字段并消费整个原记录，不开放可复用的部分记录。
元数据可直接读取/赋值，也可经借用包装读取/赋值；本阶段只开放拥有字段的重借用，不开放元数据字段借用。
若路径上的祖先均无 Drop，可提取任意完整拥有字段；这会消费整个记录，随后不能读取或修改兄弟字段和元数据，
不能只写回拥有字段来复活记录；var 可整体重新赋值。var 也可在记录仍完整时替换拥有字段；
所选字段自身可以实现 Drop，祖先实现 Drop 时仍禁止提取/替换。
活跃字段视图保守地借用整个拥有记录，不提供字段间独立借用。
记录本身非 Copy，按值传参、返回和赋值整体移动全部底层缓冲区能力；移动后不可复用原记录。
局部可变包装可重新赋值；借用包装不允许按值取出或替换拥有字段，必须通过 `&wrapper.field` / `&mut wrapper.field` 重借用。
包装与字段视图沿用全缓冲区别名检查、元素引用来源、临时借用与任务期内容保留规则。

字段默认仅定义模块内访问；`pub` 修饰后才对其他模块开放。
旧 `private` 修饰已拒绝，`private: Int32` 仍是名为 private 的普通字段。构造、投影、字段赋值和借用均按记录声明身份检查权限，
跨模块方法、泛型实例与别名保持定义作用域，消费方不能借拼写或实例化取得底层访问权。

普通 impl 同时适用于包装类型。数组方法转发既有模块算法，避免旧模块调用额外实例化一层方法，
保持原有泛型实例预算；扩容策略仍只有一份 Joky 源码实现，7c.7 使用受检前缀搬迁原语。Element/Slice 继续使用模块函数。
7c.4 已增加同步 Drop，7c.7 已增加整体移动拥有型数组元素；无引用元素数组的普通语言级挂起已开放，
其余拥有记录、视图和结构化并发边界仍不开放。

### 3.3 运行时表示

Buffer 拥有者是指向任务 arena 中稳定控制块的内部句柄。只有一个字段的包装链及其借用复用这个句柄，不增加记录堆分配。
混合拥有记录按值保留平铺字段；局部绑定和按值参数使用编译器私有的稳定存储，原生后端使用函数栈，
解释器使用随 activation 回收、跨时间片保持的局部存储。包装混合记录的单字段外层也使用这种表示。
混合记录的借用指向整条记录，投影到单字段 Array/Buffer 包装时加载拥有句柄；所有拥有槽都追踪移动状态和元素引用来源，整体移动与清理按组执行。
私有存储布局不开放给 alloc、memory.read/write、数组元素或宿主 ABI；自动 Drop 复用这些私有布局。
控制块记录：

- 当前连续载荷的内部地址；容量为 0 或元素大小为 0 时无载荷分配。
- 已初始化长度 len 和 capacity，满足 `0 <= len <= capacity`。
- 元素布局由编译器的 MemoryLayout 确定，控制块保存受检大小/步长和对齐；不允许源码指定任意布局。

零大小元素仍有逻辑长度、容量和初始化前缀；容量上限为 isize::MAX，不能无限追加或跳过越界检查。
非零大小元素按 isize::MAX / 元素步长限制容量。所有分配还需满足任务预算。

创建空数组也创建独立的控制块，并计入任务预算。拥有者移动只转移访问能力，控制块不搬迁。
普通同步调用及解释器内部时间片使用同一控制块；原生槽或解释器 Value 中的位复制不能产生
第二个语言层拥有者，IR 必须明确区分移动与 Copy。此表示是内部 ABI，不进入生成的 C 头文件。

元素视图保存经过边界检查的内部载荷地址，不分配任何元数据。
切片及子切片各在同一任务 arena 分配一个私有头部，复用 Buffer 的布局保存起始偏移、长度和元素布局；
不复制载荷，不公开容量或扩容能力。切片头部及分配记录计入预算并保留到根任务结束，
即使视图已最后使用也不立即回收；重复创建切片可能耗尽预算。

首版沿用任务 arena 的 64 MiB 计费策略；控制块、载荷、对齐和分配记录均按现有规则计费。
扩容迁移期间同时计费旧存储和新存储；成功 replace 后立即释放旧载荷及临时 source 控制块并退还预算。
array.release 消费拥有者并释放其当前载荷和控制块。pop 不缩容量；7c.4 起拥有者离开作用域或被覆盖也会自动释放。
切片头部及失败时尚未登记到清理帧的部分分配在根任务终止时兜底回收。
管理权的结束与物理存储回收是两件事；内存仍存在不代表旧拥有者或视图仍可使用。

## 4. 移动与临时借用

### 4.1 拥有者的流转

绑定、赋值、按值传参及返回 Array 都执行移动；原位置随后不可使用。
已有借用存活时不能移动、覆盖或结束其拥有者。var 可在借用结束后重新赋值；旧管理权随覆盖结束，
7c.4 起旧分配立即析构并回收；显式 array.release 可以提前结束拥有者；
也不赋予其他句柄访问权。release 不能接收 &Array、Element 或 Slice，按值调用遵守既有移动/分支/借用检查。

同步内部函数可以返回新建数组，或返回按值接收的数组；不得从 `&Array` / `&mut Array` 中取走管理权。
返回拥有者仅能依赖已消费的拥有者输入、当前任务的新分配或 take_last 从独占借用数组中移出的元素，不能从任意引用或 Ptr 制造。
没有按值拥有者输入的拥有者结果必须来自新建或受检移出；有输入时保留所有可能来源的并集。
调用方只使用签名契约，函数体必须证明每条返回路径满足契约；同一任务内转移不延长根任务寿命。

分支合流后，只有所有到达路径都已初始化且未移动的位置可用；循环回边、break/continue、
提前 return 和赋值重初始化执行同样的数据流检查。实参按现有顺序求值，移动和借用从该实参
准备时生效；`consume(values, values)` 不能通过等到整次调用结束才标记移动而获准。

### 4.2 数组视图

`&values` / `&mut values` 是对缓冲区管理权的受检视图，引用稳定控制块，
不借用保存句柄的栈槽。共享视图可复制，独占视图只可移动或重借用；视图的有效范围
仍受拥有者和上层借用约束，不因控制块在 arena 中而自动拥有任务期寿命。

共享视图存活时允许其他共享读；修改、移动、覆盖拥有者必须等到冲突视图最后使用之后。
独占视图阻止其他冲突读写，短暂的调用重借用结束后恢复父视图。首版按整个缓冲区检查冲突，
不证明动态索引互不重叠，也不借用内部 len/capacity 字段。

视图可以通过明确声明数组类型的同步 helper（包括元素泛型）传递和返回；返回依赖沿用签名中引用输入的来源并集，不能返回函数
内部拥有者或按值拥有者参数的视图。拥有者离开其有效作用域后，先前视图不能再用。
`share` 对独占数组视图只收窄当前借用权限，最后使用后可恢复父权限；`share(values)` 不能
消费拥有者来制造永久共享对象。既有含引用对象图的 share/seal 规则不变。

显式借用采用当前求值顺序，不新增两阶段借用特例。例如在 `array.push(&mut values, ...)`
的后续实参中再次读取 values 应拒绝；需要先算出复制值，再发起独占调用。

### 4.3 元素与切片的存储借用

元素、切片及其派生视图均保留最初整个缓冲区的身份及父借用链，不按索引或区间拆分冲突。
即使区间不重叠或切片为空，也不能同时发起冲突的独占访问。活动存储借用阻止通过拥有者进行
冲突的 set/push/pop/reserve、移动、覆盖或结束；reserve 即使无需分配也遵守签名借用规则。
借用结束后权限恢复。独占切片可向下重借用元素/子切片，子视图最后使用前不能冲突访问父视图。

结构修改在活动借用期间被禁止，因此不需要额外运行时版本号来挽救失效地址；
地址仍在 arena 中不是有效借用的证明。共享/独占视图可经明确形状的泛型 helper、透明别名和跨模块转发，
返回依赖仍取签名引用输入的保守并集；不能返回局部或按值拥有者的派生视图。

## 5. 分配效果与不可存储的数组视图

缓冲区创建、扩容与切片头部分配使调用链具有 `uses_arena`。分配和回收另传播 `needs_arena`，用于传递同一任务的 arena 和预算。
仅执行 release/replace 的 helper 不因此新增分配效果；接受无引用元素数组及普通局部引用的 release helper 仍可使用临时借用。
拥有者或视图出现在函数签名时，该函数只可作为内部函数；VM/AOT 入口、回调及所有宿主 ABI
均拒绝这些类型。隐藏的 arena 能力与宿主导出检查不能只覆盖现有 Reference 类型。

数组视图是由目标类型决定的独立借用类别：**不能存入任何任务期对象或拥有字段**，
只能按声明的数组签名继续借用或通过声明的视图结果返回。因此，即使函数会分配，数组视图输入也不
适用原有普通引用的任务期保留规则；无携带借用的结果时，在调用结束后归还权限。
函数体、调用点和模块边界都必须检查这一契约，不能仅对 array.push 名称白名单放行。

普通 `&Point`、`&mut Int32` 及含普通引用的 Copy 聚合继续遵守原有存储前置条件。
若同一 helper 既接受数组视图又接受普通引用，只有数组视图按新类别处理；分配能力仍可能
让普通引用保留到任务结束。不把 `uses_arena` 全局改成“不会保留参数”。

get/pop、element.read 和 slices.get 不延长数组存储借用；含引用的复制结果保留所存引用的来源。
元素/切片视图结果则延长相应输入借用并回溯到原始拥有者，不能套用复制值的规则。
通过普通 memory 原语读写这些内部目标、请求原始元素地址或将视图藏入聚合均被拒绝。

### 5.1 含共享引用元素的来源与存储契约

7b.2 允许 Array<&T> 及包含普通共享引用的 Copy 记录、元组、枚举；T 也可为经过共享引用间接递归的封存图类型。
元素只是复制指向稳定 arena 对象的引用，与 7b.3 借用数组元素存储的能力分开追踪。数组本身仍可修改；
含引用元素不会把 &mut Array<T> 当成普通含引用对象的构造期能力，也不会永久封存控制块。

- 控制块身份与内容引用来源分别追踪。移动/返回拥有者保留内容依赖；load/get/pop 结果继承内容来源，
  不依赖数组视图的临时借用。复制出的引用可在数组扩容、替换、pop、移动、覆盖或离开作用域后继续使用。
- store/initialize_next 检查每个引用标量的存储条件并保留借用；replace 将源内容依赖合并到目标稳定控制块。
  内容按整个数组保守合并，不按索引或枚举分支精确区分。覆盖、pop、truncate、replace 及拥有者结束都不释放已保留借用。
- 调用带有**含引用元素的可写数组输入**（按值拥有者或独占视图）的函数时，所有普通引用实参都按可能存入 arena 处理。
  这条契约由规范化后的签名决定，独立于 uses_arena；不分配的 set、泛型 wrapper 及跨模块别名同样适用。
  即使索引越界、数组为空或 helper 实际未存储，也不利用被调函数体放宽存储前置条件。
- 可分配调用仍沿用现有普通引用存储契约；两类调用都拒绝保存局部栈借用，并把合法普通引用借用保留到根任务结束。
  数组控制块视图不适用任务期保留规则。无引用元素数组的不分配 helper 也不因此新增普通引用存储限制。
- 可写数组和返回拥有者的内容来源保守合并所有输入普通引用及输入数组的内容；返回普通共享引用时，
  数组参数贡献内容来源，普通引用参数沿用既有签名来源规则；返回数组视图保留既有的签名范围引用依赖（包括普通引用参数），不从按值拥有者返回视图。
  参数数组内容使用独立来源，在调用点代入实际内容依赖；不将内容引用误认为控制块别名。

因此，先存入 share(p) 后再 memory.write(p, ...) 会被拒绝，即使已将元素 pop 或覆盖。
局部变量的 &local 不能通过 push、set、含引用聚合或任意层 wrapper 存入数组。
泛型实参推导不隐式把 &mut T 变成 &T；将 alloc 结果作为共享元素时显式使用 share。
不允许独占引用元素、数组视图元素、拥有型嵌套容器或将控制块藏入引用聚合。

## 6. 底层存储原语与源码算法

内部模块为 `joky/internal/buffer`，仅编译器绑定的标准库定义作用域可调用；
能力按定义身份传递，不能通过用户文件路径、导入别名、重导出或同名 extern 获得。
Array 名义结构体及 Element、Slice 别名可公开，但 Array 的存储字段保持私有，底层函数不能被普通模块直接调用或取函数地址。
标准库源码同样接受移动和借用检查；每个存储原语自身保持初始化及边界不变量。

| 原语（以下 B 表示 Buffer<T>） | 必须保证的契约 |
| --- | --- |
| `allocate<T>(capacity: UInt64) -> B` | 检查目标大小、对齐及任务预算；返回 len 为 0 的新拥有者 |
| `len(buffer: &B) -> UInt64` / `capacity(buffer: &B) -> UInt64` | 只读控制块元数据 |
| `capacity_limit<T>() -> UInt64` | 返回当前目标的布局/地址范围可表示的最大元素数，不承诺预算足够 |
| `load(buffer: &B, index: UInt64) -> T` | 仅允许 index < len；禁止读取未初始化容量 |
| `store(buffer: &mut B, index: UInt64, value: T)` | 仅允许 index < len；不改变初始化范围 |
| `initialize_next(buffer: &mut B, value: T)` | 要求 len < capacity；写入后才把 len 增加 1 |
| `truncate(buffer: &mut B, new_len: UInt64)` | 只允许 new_len <= len；不能通过增大 len 发布未初始化值 |
| `replace(destination: &mut B, source: B)` | 消费 source，把其载荷/len/capacity 转入 destination 的稳定控制块；释放旧载荷与 source 头部，不复制管理权 |
| `release(buffer: B)` | 消费拥有者，从当前任务登记中移除其载荷和头部、释放并退还预算；不释放元素引用的对象 |

新增存储原语按源签名保持独立身份：borrow/borrow_mut、slice/slice_mut、element_load/element_store、
slice_len/slice_load/slice_store、slice_borrow/slice_borrow_mut、subslice/subslice_mut，共十三种。
其运行时 ABI 可复用：元素借用复用受检 load 取得地址，切片创建共用受检 slice helper；
element_load/element_store 用元素地址读写，不能把载荷地址误当作 Buffer 头部。
Slice 的 len/load/store 复用头部操作，写入不改变长度。
只有 allocate 及四种切片构造原语标记分配效果；元素借用与读写均不分配。

原语中的违规边界和初始化操作以明确的运行时错误终止任务，带源码位置；禁止忽略、环绕或
以 null 代替结果。UInt64 到地址宽度、元素数乘步长及偏移加法都要检查。
replace 要求 source 无活动借用，destination 只有当前独占借用及其合法父链；
目标原载荷及 source 头部从任务登记中移除后按原分配 Layout 释放，source 管理权失效；不公开旧地址或任意 free/realloc 能力。
release/replace 的原生 helper 接收隐藏 arena，回收前检查任务登记；失败验证不修改两个拥有者。
登记项使用 swap_remove 删除，不保留不断增长的空洞；当前查找是 O(任务内活动分配数)，不承诺常数时间回收。
登记记录移除只释放存储，不撤销已经保留的共享引用借用；被复制出的内容引用仍可使用。
这些是通用存储操作，不引入运行时 ArrayPush、ArrayPop 或数组扩容策略函数。

存储 IR 显式保留元素类型，capacity_limit 也按其类型实参单态化。参数槽位按实际宽度累计，
沿用 Unit 的参数占位和聚合的扁平槽位规则。后端按 MemoryLayout 的标量偏移读写，填充字节不作为值读取。
原生 helper 先检查边界、返回仅编译器可见的内部地址，检查错误后才访问；initialize_next 的所有字段
写完后由私有 commit helper 发布长度。解释器在降低时缓存布局，在一条指令内完成写入与长度提交。

源码算法确定为：

1. get/set 先比较 index 与 len，再执行 load/store；pop 先判断非空，load 最后一个值，
   再 truncate 到 len - 1。只公开 Copy 元素，缩短前缀不需要调用元素析构，也不提前释放元素引用的任务期借用。
2. reserve 首先检查 `additional <= capacity_limit - len`，再求和；越界请求用可表示的
   `capacity_limit + 1` 交给受检 allocate 失败，不依赖 UInt64 环绕。容量已足够时直接返回。
3. 需要扩容时，空容量的候选值为 `min(4, limit)`；非空时选择两倍容量，若翻倍会超出 limit
   则选 limit。新容量取候选值与所需容量的较大者；先比较再运算，不能依赖整数环绕。
4. 分配临时缓冲区，用 Joky 循环逐个 load 旧前缀并 initialize_next 新前缀。全部完成后才 replace，
   迁移期间不发布临时拥有者或未初始化元素；旧长度和载荷在提交前保持有效。
5. push 调用 reserve(1)，然后 initialize_next。扩容策略、循环和业务返回值都留在源码库。

任一步不可恢复失败均走已有错误清理路径；旧缓冲区、临时缓冲区和部分初始化存储都由
同一任务 arena 回收。当前不开放可恢复分配 API；若将来开放，失败返回前必须仍有有效旧数组，
并单独规定失败的临时分配是否继续计费。

- **失败与回收**：控制块分配、载荷分配、扩容临时缓冲区及部分复制后的失败注入；
  正常退出、运行时失败、预算终止均按分配计数证明根任务恰好回收一次。

  任务取消、直接 drop、VM drop/重载后的旧任务均覆盖清理与代码 owner 保活。

  无引用元素数组可进入普通顺序 `@suspends` 及 scope/race，但不能因为内存仍在 arena 中就放宽借用边界。

### 7c.4：Drop 与作用域清理

显式导入 joky/drop.Drop，声明 impl Drop for Owner { fn drop(&mut self) { ... } }。
编译器按 trait 声明身份识别它，普通用户同名 trait 不改变语义；Drop 不加入 prelude。
该阶段仅接受单一拥有字段记录及无条件泛型 impl，7c.5 再扩展多拥有字段；Copy 类型与条件 Drop impl 被拒绝。

共享 IR 生成拥有值登记与退出清理；局部、参数和临时值都纳入管理。移动转移登记，
覆盖先清理旧值；return/break/continue 结束相应作用域。完整值运行自身 hook，
再运行嵌套拥有字段的 hook，最后归还唯一 Buffer 存储。部分构造只清理已初始化字段。
有 Drop 的记录禁止显式调用析构及移出/替换拥有字段，仍允许整体移动、元数据更新和字段重借用。

JIT/AOT 使用同一套 native lowering，解释器使用相同的运行时清理登记；登记先移除再回调，
失败仍继续处理后续 hook/拥有者并保留首个错误。解释器取消按激活树后序清理，保持父局部存储存活；
参数接收、结果接收和登记不能被内部时间片打断。回调保留旧模块，因此重载和 VM 销毁不影响待清理值。
私有析构快照按登记点分配，计入单函数 64 KiB 局部存储上限；循环复用，不累计增长。
析构回调重入上限为 32；解释器每个 hook 另有独立的 1,000,000 指令清理额度，
避免任务已耗尽预算时跳过全部清理，也避免析构死循环。超限报 ResourceLimit 并继续释放缓冲区。登记表保存活动拥有者，
顺序表按函数的拥有槽位保存首次登记顺序，重赋值和循环不累计增长。它们使用宿主分配，
不计入任务 arena 的 64 MiB 载荷预算，也不承诺常数时间移动/清理。

验收见 tests/fixtures/dropped_owners.jk 与 src/vm/drop_tests.rs：三后端覆盖逆序、嵌套、
覆盖、提前返回、循环跳转、部分初始化、析构失败与预算复用；解释器枚举时间片取消和指令耗尽边界，
验证已构造资源恰好清理一次。多拥有字段由下节 7c.5 开放；拥有型元素的普通顺序跨语言挂起另有专门三后端验收，
scope/race 中的数组视图、引用型拥有者和其他拥有容器仍留待后续阶段。


### 7c.5：多拥有字段记录与部分构造清理

记录可以包含多个拥有字段，各字段可具有不同的元素类型，并可嵌套其他拥有记录；
其他字段仍必须是无引用 Copy 元数据。泛型参数仍限 Copy，Array 的元素范围不变。

完整记录作为一个清理组整体移动、传参、返回和覆盖；IR 的移动一次转移全部标量与清理责任，
解释器不会在字段之间暂停。先运行父记录 hook，再按字段声明顺序递归清理各拥有字段，
每个字段的 hook 完成后释放其底层 Buffer。父 hook 运行时所有字段都仍有效，
更新子记录的元数据会被后续子 hook 观察到。某个 hook 失败后继续清理剩余字段，保留最早错误。

字段初始化保持源码求值顺序。完整构造前，每个已初始化字段独立登记；构造成功后合并为完整组。
若后续字段失败或执行 return/break/continue，按已初始化字段的逆初始化顺序清理，
不运行未完成外层记录的 hook。完整记录的字段析构顺序不受初始化表达式排列影响。

7c.5 初版只允许整体移动含多个底层 Buffer 的记录；7c.6 在下节补充消费式字段提取与字段替换。元数据读写和拥有字段的共享/独占重借用可用，
借用检查保守地覆盖整个拥有记录，不承诺兄弟字段的独立可变借用。
别名、泛型及浅层引用身份保存全部元素类型，后续字段中的共享引用也遵守任务期保留契约。

验收见 tests/fixtures/multi_owners.jk 与 src/vm/multi_owner_tests.rs：JIT、解释器和独立 AOT
覆盖不同元素类型、嵌套析构顺序、元数据更新、整体移动/覆盖/返回、部分初始化和失败继续清理。
跨模块泛型保留私有身份；解释器逐指令验证取消、预算耗尽、重载及 VM 销毁后已构造资源只清理一次。

### 7c.6：消费式字段提取与字段替换

无需新增语法：let chosen = value.field 提取所选完整拥有子树，var 记录可写 value.field = replacement。
首个、中间或末尾字段均可选，也支持嵌套字段、临时记录和包含多个缓冲区的子记录。
路径上的祖先记录必须都没有 Drop；所选字段自身可以实现 Drop，析构责任随所选值转移。

字段提取消费整个原记录：兄弟字段、元数据、再次提取、整值移动和字段赋值均不可再用。
剩余字段保留自动清理责任，在原作用域退出、失败或整体重新赋值时按原声明顺序清理。
var 可以整体重新赋值；这不是 Rust 式的部分移动记录，不允许只补回缺失字段后复用。

字段替换先完成右侧求值，再立即析构旧字段，成功后原子转入新值并更新稳定存储。
兄弟字段保持有效，后续 hook 观察新字段的元数据。右侧失败时旧记录仍完整；旧字段析构失败时，
原记录剩余字段和右侧新值仍各自清理，保留最早错误。右侧不能先消费原记录再通过字段赋值复活它。
借用记录不允许替换拥有字段；活跃字段视图仍借用整个记录，不增加字段间独立借用。

清理组保留固定的缓冲区序号，被提取的字段留下空位，防止首字段移出改变组身份或重复析构。
解释器的提取、替换和清理登记之间不会暂停；新快照分配失败时仍保留旧 hook 与清理责任。
清理快照保存 hook 所需的元数据；普通共享元素引用的来源和任务期保留规则均不缩短。

验证首/中/末字段、嵌套子树、临时值、返回、分支/循环、重新赋值、析构顺序及失败路径。
解释器逐指令取消与预算耗尽、重载/VM 销毁、快照分配失败验证已构造资源恰好清理一次；
编译拒绝已消费记录复用、Drop 祖先、活跃借用冲突和通过借用替换，跨模块泛型保留私有身份。


### 7c.7：整体移动的拥有型数组元素

首个纵向切片支持 `Array<OwnedRecord>`，包含混合/多拥有字段、Drop 及嵌套数组；底层元素内容递归要求无引用。
元素以私有 storage_layout 存储，普通 memory/FFI 布局继续禁止拥有者，枚举与元组支持拥有载荷。
泛型函数、方法、记录及别名允许拥有型实参，实例化后重新验证移动和字段限制。

push/initialize_next 转移整个元素；set 先求值右侧，再完整清理旧元素并提交新值，越界的实参在退出时清理。
原生 checked helper 与解释器指令在检查、写入、清理登记和提交长度之间不执行源码调用或暂停。
`take_last` 返回末元素 T，空数组报运行时错误；没有隐式复制，移出后原数组仍完整可用。
7c.8 起 pop 也可移出拥有型元素；7c.9 提供借用整个原数组的 borrow_ref，只读引用拥有型元素。get、Element 视图仍仅用于 Copy 元素，拥有型切片见 7c.12。

扩容容量策略仍在 Joky 源码；新增 transfer 原语把已初始化前缀搬迁到足够容量的空缓冲区，所有检查先于修改。
新分配失败时原数组保持有效；成功搬迁后源长度归零，replace 释放旧载荷/临时头部，元素不运行 Drop。
缓冲区保存元素拥有字段偏移和 Drop 回调描述；回调接收当前载荷地址，扩容后不依赖旧载荷或调用方栈快照。
底层拥有者的描述随其自身保留，嵌套数组可独立回收。释放前逐元素逆索引清理，记录内部保持已有父 hook/字段顺序。
失败替换先完成全部旧元素清理，清空拥有者 lanes 并标记失败替换位置，任务结束时跳过已析构槽，继续清理兄弟元素和新实参。
最早错误保持不变；描述在释放控制块前显式销毁，避免 arena 原始字节回收漏掉解释器代码保活引用。

解释器 take_last 在移出同一指令内登记原载荷上的临时清理责任，随后安装独立局部快照。
快照分配失败仍可运行完整原 hook；安装成功后结果不依赖父数组载荷。
同步 helper 的内部时间片、取消、预算失败和重载仍需恰好一次清理；无引用元素数组的普通语言级挂起已单独验收，
拥有型视图和其他拥有者仍留待后续阶段。

### 7c.8 通用拥有型枚举

任意 enum 的零/单载荷变体可保存 Array、拥有记录或嵌套拥有枚举，Option/Result 不作特殊处理。
实例按特化后的实际载荷判断所有权；Copy 实例保持复制语义，拥有实例按值整体移动。
拥有实例中的其他载荷要求无引用 Copy 数据或拥有者；拥有型元组遵循同一规则；共享/独占借用匹配已开放，enum 自身的 Drop 实现仍未开放。

布局继续使用 Int32 标签和各变体独立载荷区。未激活的缓冲区 lanes 为 null，清理登记保留其固定序号但不释放它们。
载荷 Drop 描述附带所有外层 enum 标签条件，解释器、JIT 与 AOT 在取间接地址前检查条件；仅激活的载荷运行 hook。
数组的元素清理描述也保存这些条件，因此可保存无引用的拥有型枚举或含它的记录；空变体不等于已析构元素。
失败替换用独立位置标记，含空变体的记录仍运行自身 Drop。

按值 match 消费 enum，当前载荷转交给分支绑定；忽略模式在分支退出时清理载荷。
Copy 分支结果先保存再结束 enum 存储；提前 return、失败和取消沿用作用域清理。
Array.pop 使用受检 take_last 原语后构造 Some，空数组返回 None，不复制拥有型元素。
Option/Result 的基础方法消费拥有型接收者并清理未选中的实参；Option.zip 支持拥有型元组载荷。
元组按实际成员决定 Copy / 移动，消费式解构将被绑定的拥有型子树分别转移，忽略项立即清理；
嵌套成员的 Drop 保留，引用自由的拥有型元组可作为 Array 元素。

解释器在函数参数、返回值及 match 提取之间转移原清理登记，新快照失败仍保留原 hook。
hook 保活其局部存储及编译模块，避免接收方快照分配失败、重载或 VM 销毁后失去析构数据或代码。
验证覆盖三后端、跨模块泛型、嵌套/空变体、覆盖与析构失败、逐指令暂停/取消、指令及内存预算。


### 7c.9 拥有型数组元素的只读借用

`array.borrow_ref(&values, index)` / `values.borrow_ref(index)` 返回拥有型元素的 `&T`，
读取 Copy 字段、调用共享借用方法及派生内部拥有字段引用；不移动元素、不转移清理登记、不额外分配。
内部 checked load 验证已初始化索引；内联拥有记录/枚举/元组引用其原载荷地址，
单字段拥有包装链与嵌套 Array 使用已存储的底层缓冲区句柄，保持既有 `&T` 表示。

静态分析沿用 borrows_storage 的来源传播及签名级输入依赖，派生引用借用整个原数组；
不证明不同索引不重叠。最后使用前拒绝修改、搬迁、移出、释放、移动及覆盖原数组。
引用可在同步 helper 中传递/返回；不能借用局部数组逃逸，也不能写入聚合或任务期存储，
不能经共享引用取得独占访问；语言级挂起和宿主 ABI 继续拒绝。
此接口只支持拥有型元素；Copy 元素沿用 Element/Slice API，拥有型独占引用见下节，拥有型切片借用见 7c.12。
枚举元素现可直接共享匹配 `match values.borrow_ref(index)`，递归载荷引用保留整个原数组的借用依赖；
匹配不移动元素或触发 Drop，完整语义见[枚举与模式匹配](language.md#枚举与模式匹配)。

借用不创建资源清理责任，数组继续按原顺序析构元素；越界、失败、取消及重载均保留原 Drop。
行为测试覆盖 JIT、解释器及独立 AOT 的多共享视图、共享方法、嵌套拥有字段与数组、单字段包装，
以及借用后的权限恢复、越界、提前返回与 Drop 失败。解释器另覆盖逐指令暂停/取消、指令预算、
分配预算及重载/VM 销毁；跨模块泛型引用保留消费者的名义身份和布局。


### 7c.10 独占元素借用与枚举匹配

`borrow_mut_ref(&mut Array<T>, UInt64) -> &mut T` 以受检索引取得拥有型元素，复用 borrow_ref 的原存储布局。
可写 Copy 字段、调用独占方法及修改嵌套数组；拥有型替换与旧值转移见下节。
借用期间约束整个原数组，不证明不同索引独立，最后使用后恢复权限。

`match &mut value` 或匹配已有 `&mut Enum` 将各载荷绑定为 `&mut T`，包括 Copy 数据。
递归模式携带结构路径来证明同一模式的兄弟成员不重叠，同时保留父枚举和来源数组依赖。
返回标量引用也保留可回收存储的来源，禁止逃逸至任务期对象；泛型名义引用先恢复实际类型再检查能力。
共享匹配继续复制 Copy 载荷，引用数组复制出的既有共享引用仍与容器存储独立。
语义与示例见[枚举与模式匹配](language.md#枚举与模式匹配)。

三后端测试覆盖原地更新、嵌套/泛型/跨模块引用、Copy 和零大小载荷、别名冲突、越界、提前退出、Drop 失败；
解释器另覆盖逐指令取消、指令/分配预算及重载后旧代码保活。arena Copy 枚举验证 Pending、多次恢复、失败与取消。

### 7c.11 通过独占引用替换拥有值

`memory.replace` 将新值转入原存储，并返回旧值；`Option.take` 仅是源码标准库方法。
编译器先准备有清理登记的临时所有者，再执行不调用用户代码、不分配的交换。
内联拥有型聚合交换完整存储；单字段包装链交换稳定缓冲区头部的内容，保留借用身份。

拥有型局部与 Drop 快照使用存储描述符，延迟读取当前的句柄、枚举标签与钩子地址。
父 Drop 执行后才读取子拥有者，允许钩子内替换子字段。移动与字段拆分转移描述符，
解释器还保活承载描述符的局部存储，使下一次快照分配失败或逐指令取消时仍能清理旧值。
数组元素复用同一描述符协议。借用检查继续阻止冲突载荷视图、父值修改及返回局部视图。
语义和示例集中见 [language.md](language.md)；三后端覆盖替换、Drop、失败和取消路径。


### 7c.12 拥有型元素的切片借用

Slice 可借用无引用内容的拥有型元素，沿用受检半开区间和整个原数组的借用依赖。

单字段包装链返回稳定缓冲区句柄，内联记录、枚举和元组返回元素存储地址。
切片头部不登记元素清理，不转移拥有权；memory.replace 复用既有原子交换协议。

### 7c.13 不保序数组删除

Array.swap_remove 的索引检查、末元素补位和 Option 构造写在 Joky 中；
编译器新增内部 swap_elements(&mut Buffer<T>, UInt64, UInt64) -> Unit。
运行时先验证两个索引均在已初始化前缀内，再交换完整元素字节，保留 padding 和初始化状态。
同索引和零大小元素不访问载荷；交换不分配、不调用用户 Drop，不改变 len/capacity，
元素的清理描述符继续由原数组持有。交换后复用 take_last 的原子移出及清理责任转移，
拥有型局部快照失败或内部暂停仍走既有清理路径。源码 API 契约见 [language.md](language.md#数值动态数组)。

### 7c.14 保序数组删除与插入

remove / insert 全部写在 Joky 标准库中，不新增编译器或运行时原语。
remove 将目标依次交换到末位置，再调用 take_last；insert 先检查 index <= len，
完成 push 的扩容/初始化，再反向交换到目标位置。每次交换保持完整的已初始化前缀，
拥有权一直由数组负责；取消可发生在任意交换之间，无半初始化洞或临时复制的拥有者。
两者的移动工作与受影响的元素数及元素大小成正比。详细边界和实参消费契约见
[language.md](language.md#数值动态数组)。

共享引用内容保活、嵌套数组、枚举/元组和 Drop 顺序。无效插入消费传入的资源但不修改数组；
实参求值顺序、右侧失败、参数 Drop 失败和移出值 Drop 失败在三后端一致。

### 7c.15 批量清理与元素交换

truncate / clear / swap 用 Joky 标准库封装既有原语，不增加编译器或运行时 ABI。
truncate 先比较目标长度与 len，避免把增长请求交给仅允许缩短的内部原语；
clear 调用 truncate(0)。运行时删除前先缩短已初始化前缀，按索引逆序运行元素清理，
某个 hook 失败仍继续清理删除范围，终止任务后清理剩余前缀。
外层控制块和载荷容量保留，已删除元素的子存储独立回收并退还任务预算。
swap 检查两个索引后调用整元素交换原语，同索引无需搬迁；越界正常返回 false。
详细语义见 [language.md](language.md#数值动态数组)。
