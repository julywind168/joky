# 解释器局部 Copy 优化：2026-09-27

本轮以 `fd9a803` 为基线，只优化解释器字节码生成。共享 typed IR、AOT/JIT、运行时
执行器、槽位布局及挂起协议保持原有实现。此次未启用外部语言对照，也未合入立即数
运算或比较分支融合，以便独立测量 Copy 优化的收益。

## 实现和安全边界

实现位于 `src/backends/interp/optimize.rs`，在初始字节码生成后执行：

1. 标记跳转入口、控制流边界、Call 和 Scope 前后的位置。
2. 在基本块内传播 Copy 的源值。每个源槽位带写入版本；源被改写后，旧映射失效。
   传播只做单层替换，不跨块、不跨调用和挂起，也不修改 Call/Scope 的参数引用。
3. 统计整个函数的读写，包括其他块、调用参数和隐式返回。反向移除自复制和目标没有
   任何剩余读取的 Copy；不删除算术，因此未使用的除零表达式仍然失败。
4. 当一个标量计算/常量是临时槽位的唯一写入者，且紧邻 Copy 是其唯一读取者时，
   直接将结果写入赋值目标。中间不能存在其他保留指令、跳转入口或恢复边界。
5. 压缩指令流并重映射全部跳转目标，包括指向被移除指令和函数终点的目标。

例如循环体内的 `total = total + i` 从两次读取 Copy、一次 Binary、一次写回 Copy，
缩减为一次 `Binary Add total, total, i`。执行器先读取两个输入、检查错误再写结果，
所以允许目标与输入相同。跨赋值、跨循环及跨 Pending 仍被使用的快照保留。

这是保守的使用次数分析，不是完整的跨块活跃变量分析。分号条件中的计数器临时值
还被比较读取，因此仍保留一次写回 Copy。String 常量和函数调用不参与直接目标合并。
没有新增 unsafe，也没有删除运行时类型检查。

## 字节码数量

下列是正常进入循环体的一轮实际分派次数，不含初始化、最终失败检查和返回：

| 内核 | 基线 | Copy 优化后 | 循环内剩余 Copy |
|---|---:|---:|---:|
| 累加 | 12 | 6 | 0 |
| 乘加递推 | 16 | 10 | 0 |
| 分号条件 | 14 | 9 | 1 |

本机 `Instruction` 仍为 72 字节，`Value` 仍为 24 字节；槽位数量仍为 14/18/16。
收益来自减少执行工作，不应解释为帧压缩或消除每轮堆分配。

## Release 复测

环境：Apple M1 Pro / aarch64 / Darwin 25.6.0，Rust 1.97.1。使用原有 bench Release
配置：opt-level 3、thin LTO、1 codegen unit、debug_assertions=false。

先完成两个版本的构建并保存基准二进制，再按“基线、优化、优化、基线”顺序运行。
每轮包含三个 Joky 后端、三个内核、N=0/100,000；每组 30 个样本，目标批次 50 ms。
计时期间没有并行编译、测试或采样器。编译、链接、加载和预热不进入计时。

以下均为 100,000 轮解释执行耗时；汇总取两次运行中位数的中位数：

| 内核 | 基线 | Copy 优化后 | 加速 | 耗时下降 |
|---|---:|---:|---:|---:|
| 累加 | 5.052 ms | 3.022 ms | 1.67x | 40.2% |
| 乘加递推 | 6.358 ms | 4.286 ms | 1.48x | 32.6% |
| 分号条件 | 5.926 ms | 3.905 ms | 1.52x | 34.1% |

优化版两次中位数差异分别为 0.64%、0.76%、2.32%。四轮共 2,160 条原始样本，
72 组 min/median/P95/max 均按原始 elapsed_ns/calls 重算核对。P95 仍是批次平均值
分布的 nearest-rank 百分位，不是单次调用 P95。本结果没有置信区间，不作为 CI 阈值。

## 验证与复现

新增 8 个优化器测试和 2 个 VM 行为测试，包括：原始/优化字节码差分执行、96 组
确定性生成的赋值序列各配 5 种输入、嵌套循环与快照失效、多用途临时值、跳转入口与
末尾目标重映射、Int32 回绕及除零、重复 Pending、模块重载/释放和不重放副作用。
既有 String 生命周期、scope、取消及宿主失败测试继续通过。

`cargo fmt -- --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test` 和
`cargo test --release` 均通过。Debug/Release 各为 103 个库测试、20 个 CLI 测试，
另有 1 个默认忽略的字节码诊断。两个保存的 Release 基准二进制都完成了
N=1,000/65,536/65,537/100,000 的三后端正确性校验。

```sh
cargo test --lib dump_while_bytecode -- --ignored --nocapture
cargo test --release --bench while -- --iterations 1000,65536,65537,100000
cargo bench --bench while -- --iterations 100000 --samples 30 --sample-ms 50 --output target/benchmarks/copy-optimization
```

后再开始交替计时。本轮本地原始样本、二进制、哈希、补丁和构建日志位于已忽略的
`target/interpreter-copy-investigation/`，不随 Git 分发。报告中旧版二进制的运行时 Git
元数据反映当前目录，因此另存 `baseline-revision.txt` 和 `binary-hashes.json` 标识版本。
