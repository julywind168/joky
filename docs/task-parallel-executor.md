# 可选多线程任务执行器设计与实施计划

状态：2026-10-24，设计草案，尚未实现，TP0–TP5 均待完成。
本文规划同一任务树中 `parallel`、`race` 分支及 `branch` 的多线程并行执行，
并保留宿主可选的单线程模式。当前语义仍以 [language.md](language.md) 为准；
现有实现与 ABI 不变量见 [architecture.md](architecture.md)。

本计划承接[结构化并发计划](structured-concurrency-scopes.md)，不以多个隔离 VM
并行执行独立根任务替代分支并行。它与[服务端状态域计划](server-concurrency.md)分工：
本文负责任务调度、跨线程资格和生命周期；状态访问及多域原子提交继续遵守状态域协议。
公开配置名称、原生桥签名和存储布局在 TP0 冻结，本文不提供已可调用的 API 或可执行示例。

## 1. 目标与边界

- 保留 `@suspends`、`parallel`、`race`、`scope`、`branch` 的源语言形式。
- 多线程模式中，同一根任务的静态分支、动态子任务及其后代可在不同 worker 同时执行。
  每个任务同一时刻最多有一个执行者；父子关系决定汇合与取消，不决定必须在同一线程运行。
- 单线程模式不创建任务工作线程，继续由宿主 poll 或阻塞驱动器推进。
  Godot 默认采用该模式，保留主线程宿主回调、帧预算和本地资源能力。
  既有文件/DNS 服务的后台 I/O 线程不属于任务工作线程，不因本配置改变。
- JIT、解释器、AOT 共用任务生命周期协议；两种模式都保证借用、拥有结果和资源清理正确。
- 默认保持单线程；多线程必须显式启用。执行器创建时确定模式，有活任务时不允许切换。
  将单线程 continuation 交给多线程执行器也必须经过准入验证，不能绕过线程资格检查。

首版不要求运行中的任务迁移、工作窃取、抢占式终止、跨进程执行或确定性回放。
可先将每个子任务分配到固定 worker，但不能把整棵任务树固定到同一个 worker 来充当分支并行。
同一任务树的多个分支必须有实际同时执行的验收证据。

## 2. 两种模式的可观察行为

| 构造或行为 | 单线程模式 | 多线程模式 |
| --- | --- | --- |
| `parallel` | 保留源码顺序轮询 | 分支独立调度，全部完成后汇合；结果位置仍按源码顺序 |
| `race` | 保留首个按轮询顺序观察到的完成或失败 | 由同步仲裁点选择首个被接纳的完成或失败，不承诺源码顺序胜出 |
| `branch` | 保留主体挂起或汇合后推进子任务的规则 | 捕获与登记提交后可立即由另一 worker 执行，与主体后续代码重叠 |
| `scope` | 主体及全部后代完成后返回主体末值 | 相同；等待期间不占住 worker 阻塞其他任务 |
| 失败及取消 | 保留既有清理与传播顺序 | 请求相关后代停止，等待执行和外部访问结束、清理完成后传播 |
| 副作用 | 保留现有模式中的顺序保证 | 无额外顺序保证，已发生的副作用不回滚 |

静态分支的实参仍按源码顺序求值一次；全部输入及拥有责任准备完成后，才允许任何分支执行。
动态分支先完成捕获快照、移动与清理责任转移，再发布到调度队列。发布前失败只清理已准备的
输入，不留下可执行的半初始化任务。批量发布与组关闭竞争时也必须保持这条不变量。

`race` 的 Result.Err 仍是正常返回值；运行时失败参与终态仲裁。多线程模式下，
其他分支可能已经执行、完成甚至产生副作用，不能依赖“靠前分支立即成功则后续分支绝不执行”。
仲裁选定结果后仍须等待败方清理；清理失败沿用错误传播及已获结果回收规则。
多个并发错误的具体诊断选择需在 TP0 固定，不能由未同步的数据竞争决定。

跨 scope 的 return、break、continue 仍先汇合再跳转；branch 不脱离所属作用域。
两种模式共享结构化生命周期和结果类型规则，但不承诺相同的 race 胜者或副作用顺序。
多线程模式即使只有一个 worker，也按多线程资格与调度契约处理，不等同于本地模式。

## 3. 从父帧轮询改为任务调度

当前原生 `lower_concurrent` 生成父帧依次调用子帧的代码；动态子任务由 CPS 任务树遍历推进。
解释器在自身执行状态中管理分支。HostExecutor 管理根任务，线程安全 TaskWaker 只负责通知，
不赋予帧跨线程访问能力。相关实现入口：

- [原生 lowering](../src/backends/native/lower.rs)
- [CPS 帧与动态任务](../src/runtime/cps.rs)
- [Continuation](../src/runtime/suspension.rs)
- [宿主执行器](../src/runtime/executor.rs)
- [解释器](../src/backends/interp/mod.rs)

目标协议将子任务注册、就绪、恢复、结果发布、汇合、取消和清理交给统一运行时边界。
单线程策略保留现有推进顺序；多线程策略将可执行子任务交给 worker。解释器必须拆分可独立
恢复的分支执行状态，不能只把一个共享 Execution 放到多个线程上调用。

### 3.1 调度和结果交接

- 每个任务有稳定身份、所属作用域、就绪状态和唯一执行权；通知与 poll 竞争不能重复执行
  或丢失唤醒。执行期间到达的通知应在返回 Pending 时仍可被观察。
- 任务注册表、队列和作用域元数据只在短临界区内访问；执行生成代码、宿主回调、Drop、
  stop 或等待 I/O 时不持调度锁。重入不得递归启动同一个任务。
- 子任务将结果写入自己的完成存储，再以同步协议发布终态；父任务收取后才取得拥有责任。
  不允许多个 worker 直接并发写父帧的结果槽、done 标记或 cleanup 表。
- 父任务等待 join 时返回 Pending，子任务结束后唤醒父任务。不能让全部 worker 阻塞等待
  各自排队的子任务；单 worker、深层嵌套和就绪队列饱和时也必须取得进展。
- 外部等待绑定到实际等待的任务，或通过能精确定位后代的路由唤醒；不能只唤醒根并假设
  根会重新遍历所有分支。定时器与 I/O 就绪也遵守唯一执行权和迟到通知失效规则。

任务数、分支数、队列项和等待记录需要有界准入。内部队列满时不能占住 worker 等待空位；
发布前预留额度，失败受控退出并清理。已有根数限额的含义保持明确，新增子任务额度另行定义。
完成和取消需预留可靠的通知路径，不能因普通任务队列已满而丢失终态。

## 4. 跨线程资格与宿主边界

现有借用检查已排除分支间冲突访问，但它不证明资源、共享控制块、回调及析构可跨线程。
编译器需要分别描述“可以转移到另一线程”和“可以被多个线程共享访问”的资格，
先作为内部能力推导；是否开放源级 trait 另行决定。

- 移动捕获检查值及其完整拥有树的转移资格，包含资源回收和用户 Drop 的调用效果。
- 共享借用检查目标共享资格；独占借用检查独占访问与线程转移资格。共享引用、Copy、
  无引用结果或 UInt64 句柄都不能自动视为线程安全，尤其需要检查其实际控制块和注册表。
- 资格沿普通调用、挂起调用、分支、泛型实例和间接调用传播；函数值、闭包与动态分派元数据
  必须保留约束。未知或未声明的宿主能力按本地能力处理。
- 根入口、输入、返回值、代码所有者及绑定的宿主描述符在准入时共同检查。
  加载时保存静态资格证据，入口准入验证当前绑定；热更新不能让后续调用绕过检查。
- 单线程执行器继续接受本地能力。多线程入口不满足要求时在执行前给出受控诊断，
  不能先运行一部分再发现线程不兼容，也不默默退回单线程掩盖不支持的能力。

当前 VmEngine、模块保活和描述符大量使用 Rc；帧包含裸上下文指针，标准 VM 句柄也绑定创建线程。
应拆分编译/加载的本地控制状态与可共享的不可变执行代码及元数据，并审计释放线程。
不能对现有 Continuation 或整个 VM 直接添加 unsafe Send/Sync 来跳过所有权证明。
线程局部错误、代码身份、时钟及浮点环境在每次执行边界建立和恢复；返回 worker 前
把错误移入任务结果，避免线程复用污染其他任务。

Godot 默认继续在主线程驱动本地执行器。若以后允许 Godot 显式启动并行计算任务，
这些入口只能使用经验证的可跨线程能力；访问引擎对象需要另外定义主线程消息桥，
本阶段不自动转发任意 Godot 调用，也不要求现有 Godot API 全部变为线程安全。

## 5. 内存、预算与持久状态

当前子帧共享 Rc<UnsafeCell<Arena>>，安全依据是顺序 poll。多线程必须重新建立该证明，
并同时覆盖 Buffer 控制块、清理表、稳定计费句柄、宿主借用和外部请求状态。
仅将 Rc 改成 Arc，或仅串行化分配，都不足以证明运行时安全。

优先评估任务私有分配分片与同步共享元数据；短临界区分配也是候选，但不能锁住整段任务执行。
具体布局由 TP0 探针确定，必须满足：

- 根任务可达对象保持稳定地址；分支完成、join 或取消不能提前回收仍可访问的任务期对象。
  分片的存活期可以长于分支，不得把分支结束等同于 arena 结束。
- 分支私有帧和 cleanup 由唯一执行者操作；跨任务拥有值通过明确的交接点转移。
  引用访问除借用互斥外，还需保证发布与收取之间的内存可见性。
- 任务及实例峰值预算使用同步预留和退款协议，并发分配不能各自通过检查后合计超限。
  失败、败方完成、取消和最后销毁都只能退款或释放一次。
- 所有 worker 及外部回调停止访问后才能释放根存储、代码和宿主资源。

现有 Domains、实例、TCP reactor 与 VM 句柄不因任务调度并行而自动支持跨线程。
第一阶段可将这些能力标为本地，使不依赖它们的分支先获得并行资格。
后续可通过所属线程代理或受检并发访问协议扩展，但不能暴露现有 RefCell 注册表给 worker。
域内短操作、联合快照、多域提交及出站消息发布的原子性继续由状态域协议保证，
不能用多个独立域锁替代整组提交契约。未接通能力的限制必须写入实际交付范围。

## 6. 取消、race 与关闭

取消至少区分请求已登记、执行者已停止、外部访问已停止、清理完成四个事实。
具体状态编码待定；任何观察者都不能把“取消标记已设置”当作存储已经可释放。

1. race 仲裁、父取消或失败关闭相应作用域的登记入口，并向相关任务及后代发布停止请求。
2. 尚未开始的任务撤销执行；正在执行的任务在安全点退出，返回执行权后才能清理。
3. 在正确线程执行 stop/Drop，确认宿主跨 Pending 的借用访问结束，回收败方结果与等待记录。
4. 全部相关后代完成清理后，才解除借用、恢复父流程或报告关闭完成。

正常 join 等待成功，失败 join 等待取消后的清理；race 选出胜者与 race 向父流程交付结果
是两个不同时间点。清理屏障通过 Pending 和唤醒实现，不阻塞 worker 等待另一个 worker。
已有同步 stop 可继续在指定执行者上运行，但只能在该任务不再执行时调用；不默认放宽
宿主 stop 的线程、noescape 或释放协议。

解释器与原生代码都需要覆盖长计算的取消安全点，包括挂起函数调用的同步长循环。
检查点必须位于拥有责任一致的位置；若需要让出执行权，编译方案还需保存可恢复状态，
不能把同步函数的本机栈当成现成 continuation。检查取消与公平时间片是不同能力，
不承诺硬实时取消或任意位置抢占。检查点密度、同步调用链展开清理方案由 TP0 确定。
阻塞或不返回的宿主调用无法被安全强制终止；并行资格声明必须说明这一进展限制。

多线程宿主取消接口应能区分请求受理与清理完成，提供可驱动的关闭完成观察方式；
不能沿用“cancel 返回即已释放全部资源”的假设。单线程既有同步取消及重入延迟规则保持。
销毁时不能遗留游离线程继续访问代码或帧，也不能在 worker 内 join 自己。
关闭的请求、驱动、等待与最终释放责任必须在 TP0 连同 Drop 行为明确。

## 7. 配置、ABI 与兼容

宿主选择模式和 worker 数，并配置任务/分支准入与执行预算。CLI 和独立 AOT 主程序需要
相应的显式配置入口，具体参数名待定；默认行为保持单线程。配置为一名 worker 的多线程
执行器也需要验证嵌套汇合和事件等待，不能依赖至少两名 worker 才能运行正确。

原生编译产物记录所需的任务协议版本和线程资格元数据；旧 AOT 对象或宿主描述符不得
被无条件解释为新版。涉及 CPS 私有桥或布局变化时明确要求重编译，并拒绝不兼容组合。
JIT 与 AOT 使用相同 native lowering 和运行时桥。模块热更新只能替换新调用入口，
旧任务及其析构所需代码必须保活到最后一次执行和清理结束。

单线程无需创建 worker 或为本地宿主资源强加 Send/Sync。共享协议可能引入新的元数据
成本，不能在尚未测量时承诺零开销；性能测量按 benches/README.md 独立进行。
编译时是否提供彻底移除多线程后端的选项另行决定，宿主运行时可选是本计划必需能力。

## 8. 分阶段实施与退出条件

| 阶段 | 范围 | 退出条件 |
| --- | --- | --- |
| TP0 契约与探针 | 冻结准入资格、任务状态、发布/唤醒/取消交接、arena 策略、安全点、关闭与 ABI 方案 | JIT/解释器/AOT 独立探针验证同一根的两个分支同时执行及取消后清理；列清不支持的宿主能力 |
| TP1 统一子任务协议 | 静态分支和动态 branch 接入注册、完成、汇合协议；接通本地执行策略 | 单线程顺序、结果、重入取消、资源与 Godot 路径保持；三种分支从本阶段一起覆盖 |
| TP2 跨线程内存与资格 | 分支执行状态、共享代码、分配/计费、捕获及宿主能力检查 | 静态拒绝矩阵与绑定准入一致；跨线程拥有交接、失败回收和代码保活成立 |
| TP3 多线程执行 | 固定 worker 分配、分支就绪/等待、完成仲裁、取消安全点与清理屏障 | 三后端真实分支并行；嵌套 parallel/race/branch、单 worker、队列压力均能推进 |
| TP4 嵌入与资源集成 | 明确配置、关闭、热更新及选定 I/O/状态能力接入；保留 Godot 本地模式 | 线程归属、外部停止和销毁均有证据；公布能力支持表与受控拒绝行为 |
| TP5 验收与参考更新 | 补齐并发交错、所有权/取消穷举及文档迁移 | 按已支持范围完成 Debug 验证，更新 language/architecture/interpreter；不再把设计目标写成已实现能力 |

TP0 探针只证明关键机制，不等于产品交付；TP1–TP3 不可只完成根任务并行就标记通过。
工作窃取与活任务迁移是后续优化，不作为本阶段正确性依赖。

## 9. 验证要求

- 真并行：在同一根任务内通过受控同步探针记录不同执行线程及重叠执行区间，覆盖
  parallel、race、branch。同步等待设诊断超时避免测试挂死，不以耗时加速比判定正确。
  另执行实际 CPU 计算并验证结果，不能只启动两个后台 I/O 请求作为证明。
- 结构化语义：输入求值一次、捕获发布后父子重叠、结果按位置组装、动态后代汇合、
  跳转穿过 scope、失败传播及 race 败方资源回收。单线程用例保留现有顺序断言，
  多线程断言允许的终态集合和安全不变量。
- 交接竞争：登记与关闭、唤醒与 Pending、完成与取消、两个 race 终态同时发布、
  父任务准备等待与最后一个子任务完成，以及终态后的迟到通知。
- 生命周期：运行中取消、同步长循环安全点、宿主 Pending/stop、拥有结果、析构错误、
  热更新代码保活、队列满和并发预算边界。确认清理一次、退款一次、外部访问先停止。
- 进展：一名 worker、多层嵌套、全部分支等待 I/O、队列容量耗尽、关闭时仍有运行任务；
  不以提高 worker 数掩盖嵌套等待死锁。
- 能力隔离：本地资源在单线程合法，多线程准入拒绝；传递调用、间接调用、析构及新模块
  不能绕过资格；Godot 回调和清理仍在主线程。

生成代码的行为覆盖 JIT、解释器、AOT；共享前端拒绝矩阵集中验证，避免各层重复全部组合。
普通测试保留可控短交错与资源边界，长交错模型及取消扫描进入默认忽略的 exhaustive_ 组。
实现阶段按 AGENTS.md 先跑针对性行为测试，再执行默认 Debug 检查及相关 Debug 穷举；
不自动跑 Release 或无关压力用例。竞争检测工具可补充证据，不能代替内存与所有权证明。

本次仅记录设计，未运行实现探针、性能测量或后端验收，也不声明任何阶段已经完成。
