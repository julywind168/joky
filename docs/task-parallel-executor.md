# 可选多线程任务执行器设计与实施计划

状态：2026-10-25，TP0–TP7 已完成，当前支持范围见第 14.1 节；TP6 聚合值交付见第 16 节，TP7 数组交付见第 17 节。
生产执行器默认 Local，可显式选择 Parallel。早期冻结决策与探针边界见第 10 节，
TP1 的最终交付与验证见第 11.5 节，TP2 交付与限制见第 12 节，TP3 见第 13 节，TP4 模式与支持表见第 14 节，TP5 最终验收见第 15 节；第 11.1–11.4 节保留历史切片记录。
源码名称已由 `parallel` 迁移为 `join`，不改变本文执行器阶段与行为契约。
其他并发关键词与组合器建议见 [语法设计 §8.1](syntax.md#81-后续并发构造与组合器仅设计)，目前只记录，不纳入 TP0 实现。

本文规划同一任务树中 `join`、`race` 分支及 `branch` 的多线程并行执行，
并保留宿主可选的单线程模式。当前语义仍以 [language.md](language.md) 为准；
现有实现与 ABI 不变量见 [architecture.md](architecture.md)。

本计划承接[结构化并发计划](structured-concurrency-scopes.md)，不以多个隔离 VM
并行执行独立根任务替代分支并行。它与[服务端状态域计划](server-concurrency.md)分工：
本文负责任务调度、跨线程资格和生命周期；状态访问及多域原子提交继续遵守状态域协议。
公开配置名称、原生桥签名和存储边界在 TP0 冻结，见第 10 节；多线程配置已在 TP4 实现，
第 11 节单独记录已接入 lowering 的私有 Local 任务桥，不能作为普通 C 宿主组包 API。
具体内存字段偏移由实现及布局测试生成，不另维护一份手写 CPS 帧布局。

## 1. 目标与边界

- 保留 `@suspends`、`join`、`race`、`scope`、`branch` 的源语言形式。
- 多线程模式中，同一根任务的静态分支、动态子任务及其后代可在不同 worker 同时执行。
  每个任务同一时刻最多有一个执行者；父子关系决定汇合与取消，不决定必须在同一线程运行。
- 单线程模式不创建任务工作线程，继续由宿主 poll 或阻塞驱动器推进。
  Godot 默认采用该模式，保留主线程宿主回调、帧预算和本地资源能力。
  既有文件/DNS 服务的后台 I/O 线程不属于任务工作线程，不因本配置改变。
- JIT、解释器、AOT 共用任务生命周期协议；两种模式都保证借用、拥有结果和资源清理正确。
- 默认保持单线程；多线程必须显式启用。执行器创建时确定模式，有活任务时不允许切换。
  将单线程 continuation 交给多线程执行器也必须经过准入验证，不能绕过线程资格检查。

首版不要求运行中的任务迁移、工作窃取、抢占式终止、跨进程执行或确定性回放。
可先将每个子任务分配到固定 worker，但不能把整棵任务树固定到同一个 worker 来充当分支并行。
同一任务树的多个分支必须有实际同时执行的验收证据。

## 2. 两种模式的可观察行为

| 构造或行为 | 单线程模式 | 多线程模式 |
| --- | --- | --- |
| `join` | 保留源码顺序轮询 | 分支独立调度，全部完成后汇合；结果位置仍按源码顺序 |
| `race` | 保留首个按轮询顺序观察到的完成或失败 | 由同步仲裁点选择首个被接纳的完成或失败，不承诺源码顺序胜出 |
| `branch` | 保留主体挂起或汇合后推进子任务的规则 | 捕获与登记提交后可立即由另一 worker 执行，与主体后续代码重叠 |
| `scope` | 主体及全部后代完成后返回主体末值 | 相同；等待期间不占住 worker 阻塞其他任务 |
| 失败及取消 | 保留既有清理与传播顺序 | 请求相关后代停止，等待执行和外部访问结束、清理完成后传播 |
| 副作用 | 保留现有模式中的顺序保证 | 无额外顺序保证，已发生的副作用不回滚 |

静态分支的实参仍按源码顺序求值一次；全部输入及拥有责任准备完成后，才允许任何分支执行。
动态分支先完成捕获快照、移动与清理责任转移，再发布到调度队列。发布前失败只清理已准备的
输入，不留下可执行的半初始化任务。批量发布与组关闭竞争时也必须保持这条不变量。

`race` 的 Result.Err 仍是正常返回值；运行时失败参与终态仲裁。多线程模式下，
其他分支可能已经执行、完成甚至产生副作用，不能依赖“靠前分支立即成功则后续分支绝不执行”。
仲裁选定结果后仍须等待败方清理；清理失败沿用错误传播及已获结果回收规则。
多个并发错误按第 10 节的仲裁规则选择，不能由未同步的数据竞争决定。

跨 scope 的 return、break、continue 仍先汇合再跳转；branch 不脱离所属作用域。
两种模式共享结构化生命周期和结果类型规则，但不承诺相同的 race 胜者或副作用顺序。
多线程模式即使只有一个 worker，也按多线程资格与调度契约处理，不等同于本地模式。

## 3. 从父帧轮询改为任务调度

TP1 已将本地静态分支的登记与轮询选择接入共享 LocalTaskGroup；原生 `lower_concurrent`
仍生成父帧调用所选子帧的代码，解释器仍在自身执行状态中持有各分支激活。
两后端均先把完成值与清理责任放入独立结果包，组选择并成功停止子树后，父流程才一次性收取。
动态子任务的本地登记共用 LocalTaskScope，推进仍遍历 CPS/解释器任务树。
输入包与执行槽现已分离，准备时固定受检入口和清理责任；静态与动态 scope 共用终态/drain 状态。
版本化原生桥负责责任交接，Local 的生成轮询驱动继续使用同一共享选择策略。
HostExecutor 管理根任务，线程安全 TaskWaker 只负责通知，
不赋予帧跨线程访问能力。相关实现入口：

- [原生 lowering](../src/backends/native/lower.rs)
- [CPS 帧与动态任务](../src/runtime/cps.rs)
- [Continuation](../src/runtime/suspension.rs)
- [宿主执行器](../src/runtime/executor.rs)
- [解释器](../src/backends/interp/mod.rs)

目标协议将子任务注册、就绪、恢复、结果发布、汇合、取消和清理交给统一运行时边界。
单线程策略保留现有推进顺序；多线程策略将可执行子任务交给 worker。解释器必须拆分可独立
恢复的分支执行状态，不能只把一个共享 Execution 放到多个线程上调用。

### 3.1 调度和结果交接

- 每个任务有稳定身份、所属作用域、就绪状态和唯一执行权；通知与 poll 竞争不能重复执行
  或丢失唤醒。执行期间到达的通知应在返回 Pending 时仍可被观察。
- 任务注册表、队列和作用域元数据只在短临界区内访问；执行生成代码、宿主回调、Drop、
  stop 或等待 I/O 时不持调度锁。重入不得递归启动同一个任务。
- 子任务将结果写入自己的完成存储，再以同步协议发布终态；父任务收取后才取得拥有责任。
  不允许多个 worker 直接并发写父帧的结果槽、done 标记或 cleanup 表。
- 父任务等待 join 时返回 Pending，子任务结束后唤醒父任务。不能让全部 worker 阻塞等待
  各自排队的子任务；单 worker、深层嵌套和就绪队列饱和时也必须取得进展。
- 外部等待绑定到实际等待的任务，或通过能精确定位后代的路由唤醒；不能只唤醒根并假设
  根会重新遍历所有分支。定时器与 I/O 就绪也遵守唯一执行权和迟到通知失效规则。

任务数、分支数、队列项和等待记录需要有界准入。内部队列满时不能占住 worker 等待空位；
发布前预留额度，失败受控退出并清理。已有根数限额的含义保持明确，新增子任务额度另行定义。
完成和取消需预留可靠的通知路径，不能因普通任务队列已满而丢失终态。

## 4. 跨线程资格与宿主边界

现有借用检查已排除分支间冲突访问，但它不证明资源、共享控制块、回调及析构可跨线程。
编译器需要分别描述“可以转移到另一线程”和“可以被多个线程共享访问”的资格，
先作为内部能力推导；是否开放源级 trait 另行决定。

- 移动捕获检查值及其完整拥有树的转移资格，包含资源回收和用户 Drop 的调用效果。
- 共享借用检查目标共享资格；独占借用检查独占访问与线程转移资格。共享引用、Copy、
  无引用结果或 UInt64 句柄都不能自动视为线程安全，尤其需要检查其实际控制块和注册表。
- 资格沿普通调用、挂起调用、分支、泛型实例和间接调用传播；函数值、闭包与动态分派元数据
  必须保留约束。未知或未声明的宿主能力按本地能力处理。
- 根入口、输入、返回值、代码所有者及绑定的宿主描述符在准入时共同检查。
  加载时保存静态资格证据，入口准入验证当前绑定；热更新不能让后续调用绕过检查。
- 单线程执行器继续接受本地能力。多线程入口不满足要求时在执行前给出受控诊断，
  不能先运行一部分再发现线程不兼容，也不默默退回单线程掩盖不支持的能力。

当前 VmEngine、模块保活和描述符大量使用 Rc；帧包含裸上下文指针，标准 VM 句柄也绑定创建线程。
应拆分编译/加载的本地控制状态与可共享的不可变执行代码及元数据，并审计释放线程。
不能对现有 Continuation 或整个 VM 直接添加 unsafe Send/Sync 来跳过所有权证明。
线程局部错误、代码身份、时钟及浮点环境在每次执行边界建立和恢复；返回 worker 前
把错误移入任务结果，避免线程复用污染其他任务。

Godot 默认继续在主线程驱动本地执行器。若以后允许 Godot 显式启动并行计算任务，
这些入口只能使用经验证的可跨线程能力；访问引擎对象需要另外定义主线程消息桥，
本阶段不自动转发任意 Godot 调用，也不要求现有 Godot API 全部变为线程安全。

## 5. 内存、预算与持久状态

当前子帧共享 Rc<UnsafeCell<Arena>>，安全依据是顺序 poll。多线程必须重新建立该证明，
并同时覆盖 Buffer 控制块、清理表、稳定计费句柄、宿主借用和外部请求状态。
仅将 Rc 改成 Arc，或仅串行化分配，都不足以证明运行时安全。

优先评估任务私有分配分片与同步共享元数据；短临界区分配也是候选，但不能锁住整段任务执行。
TP0 选定分支分片、根保留和同步预算方案；真实 Arena/Buffer 布局在 TP2 实现，必须满足：

- 根任务可达对象保持稳定地址；分支完成、join 或取消不能提前回收仍可访问的任务期对象。
  分片的存活期可以长于分支，不得把分支结束等同于 arena 结束。
- 分支私有帧和 cleanup 由唯一执行者操作；跨任务拥有值通过明确的交接点转移。
  引用访问除借用互斥外，还需保证发布与收取之间的内存可见性。
- 任务及实例峰值预算使用同步预留和退款协议，并发分配不能各自通过检查后合计超限。
  失败、败方完成、取消和最后销毁都只能退款或释放一次。
- 所有 worker 及外部回调停止访问后才能释放根存储、代码和宿主资源。

现有 Domains、实例、TCP reactor 与 VM 句柄不因任务调度并行而自动支持跨线程。
第一阶段可将这些能力标为本地，使不依赖它们的分支先获得并行资格。
后续可通过所属线程代理或受检并发访问协议扩展，但不能暴露现有 RefCell 注册表给 worker。
域内短操作、联合快照、多域提交及出站消息发布的原子性继续由状态域协议保证，
不能用多个独立域锁替代整组提交契约。未接通能力的限制必须写入实际交付范围。

## 6. 取消、race 与关闭

取消至少区分请求已登记、执行者已停止、外部访问已停止、清理完成四个事实。
状态协议见第 10 节；任何观察者都不能把“取消标记已设置”当作存储已经可释放。

1. race 仲裁、父取消或失败关闭相应作用域的登记入口，并向相关任务及后代发布停止请求。
2. 尚未开始的任务撤销执行；正在执行的任务在安全点退出，返回执行权后才能清理。
3. 在正确线程执行 stop/Drop，确认宿主跨 Pending 的借用访问结束，回收败方结果与等待记录。
4. 全部相关后代完成清理后，才解除借用、恢复父流程或报告关闭完成。

正常 join 等待成功，失败 join 等待取消后的清理；race 选出胜者与 race 向父流程交付结果
是两个不同时间点。清理屏障通过 Pending 和唤醒实现，不阻塞 worker 等待另一个 worker。
已有同步 stop 可继续在指定执行者上运行，但只能在该任务不再执行时调用；不默认放宽
宿主 stop 的线程、noescape 或释放协议。

解释器与原生代码都需要覆盖长计算的取消安全点，包括挂起函数调用的同步长循环。
检查点必须位于拥有责任一致的位置；若需要让出执行权，编译方案还需保存可恢复状态，
不能把同步函数的本机栈当成现成 continuation。检查取消与公平时间片是不同能力，
不承诺硬实时取消或任意位置抢占。检查点位置、同步调用链展开清理方案见第 10 节。
阻塞或不返回的宿主调用无法被安全强制终止；并行资格声明必须说明这一进展限制。

多线程宿主取消接口应能区分请求受理与清理完成，提供可驱动的关闭完成观察方式；
不能沿用“cancel 返回即已释放全部资源”的假设。单线程既有同步取消及重入延迟规则保持。
销毁时不能遗留游离线程继续访问代码或帧，也不能在 worker 内 join 自己。
关闭的请求、驱动、等待与最终释放责任按第 10 节连同 Drop 行为区分。

## 7. 配置、ABI 与兼容

宿主选择模式和 worker 数，并配置任务/分支准入与执行预算。CLI 和独立 AOT 主程序需要
相应的显式配置入口，拟定名称见第 10 节；默认行为保持单线程。配置为一名 worker 的多线程
执行器也需要验证嵌套汇合和事件等待，不能依赖至少两名 worker 才能运行正确。

原生编译产物记录所需的任务协议版本和线程资格元数据；旧 AOT 对象或宿主描述符不得
被无条件解释为新版。涉及 CPS 私有桥或布局变化时明确要求重编译，并拒绝不兼容组合。
JIT 与 AOT 使用相同 native lowering 和运行时桥。模块热更新只能替换新调用入口，
旧任务及其析构所需代码必须保活到最后一次执行和清理结束。

单线程无需创建 worker 或为本地宿主资源强加 Send/Sync。共享协议可能引入新的元数据
成本，不能在尚未测量时承诺零开销；性能测量按 benches/README.md 独立进行。
编译时是否提供彻底移除多线程后端的选项另行决定，宿主运行时可选是本计划必需能力。

## 9. 验证要求

- 真并行：在同一根任务内通过受控同步探针记录不同执行线程及重叠执行区间，覆盖
  join、race、branch。同步等待设诊断超时避免测试挂死，不以耗时加速比判定正确。
  另执行实际 CPU 计算并验证结果，不能只启动两个后台 I/O 请求作为证明。
- 结构化语义：输入求值一次、捕获发布后父子重叠、结果按位置组装、动态后代汇合、
  跳转穿过 scope、失败传播及 race 败方资源回收。单线程用例保留现有顺序断言，
  多线程断言允许的终态集合和安全不变量。
- 交接竞争：登记与关闭、唤醒与 Pending、完成与取消、两个 race 终态同时发布、
  父任务准备等待与最后一个子任务完成，以及终态后的迟到通知。
- 生命周期：运行中取消、同步长循环安全点、宿主 Pending/stop、拥有结果、析构错误、
  热更新代码保活、队列满和并发预算边界。确认清理一次、退款一次、外部访问先停止。
- 进展：一名 worker、多层嵌套、全部分支等待 I/O、队列容量耗尽、关闭时仍有运行任务；
  不以提高 worker 数掩盖嵌套等待死锁。
- 能力隔离：本地资源在单线程合法，多线程准入拒绝；传递调用、间接调用、析构及新模块
  不能绕过资格；Godot 回调和清理仍在主线程。

生成代码的行为覆盖 JIT、解释器、AOT；共享前端拒绝矩阵集中验证，避免各层重复全部组合。
普通测试保留可控短交错与资源边界，长交错模型及取消扫描进入默认忽略的 exhaustive_ 组。
实现阶段按 AGENTS.md 先跑针对性行为测试，再执行默认 Debug 检查及相关 Debug 穷举；
不自动跑 Release 或无关压力用例。竞争检测工具可补充证据，不能代替内存与所有权证明。

## 10. TP0 冻结决策与探针记录

### 10.1 入口和能力

配置名称采用 `ExecutionMode::Local` 与 `ExecutionMode::Parallel { workers }`，workers 必须
大于零；这是待实现的宿主配置，不新增语言关键字。CLI 计划使用 `--task-workers N`，缺省为
Local，显式 N=1 仍为 Parallel。AOT 驱动通过同一含版本号的执行配置建立运行时；不读取
隐式环境变量改变模式。现有 HostExecutor 的默认构造和 Godot 配置保持 Local。

本地控制对象与跨线程提交句柄分开：宿主控制对象负责加载、关闭及线程回收，提交句柄只
接受通过准入验证的入口与输入包。普通 Continuation 保持本地类型，不添加整体 Send/Sync。
首版任务在分配的 worker 创建、恢复和销毁；调度消息传递任务身份、输入包和完成包，
不传已有 Rc 帧树。共享代码必须在提交前完成冻结，并保活到所有 worker 和清理结束。

内部资格名称采用 `Transfer`、`Share` 和调用效果 `Local` / `ParallelSafe`，不是用户可写 trait。
Transfer 还包含最终析构线程合法性；Share 包含共享读取可能触及的内部元数据。
能力推导对实际实例化后的类型与调用图取固定点，递归调用不能靠“尚未访问”被判定安全。
不透明指针、描述符、VM/domain 句柄和外部资源默认 Local。旧宿主注册不自动升级。
本地能力的存在不拒绝整个模块，只拒绝拟在 Parallel 执行的不可证明入口。
间接目标须携带证据，未知动态目标不能在父入口预检后绕过约束。

| 能力 | 首个生产并行切片的准入目标 | TP0 证据 |
| --- | --- | --- |
| 标量输入、结果与纯算术 | 允许，代码及完整调用链通过资格检查 | 三后端生成 CPU 计算，两个 worker |
| 分支内分配、分支内释放 | 私有分配分片加根预算 | 三后端实际 arena 分配与清理 |
| 跨分支拥有值、借用及共享分配 | 需完成存储树、控制块、计费及发布审计后开放 | 仅安全 Rust 的不可变分片模型，未证明生产 Buffer/引用安全 |
| 普通 extern、宿主 Drop、CPS stop | 旧注册 Local；新的显式声明和描述符验证通过后开放 | 仅固定测试回调已人工审计，无通用资格实现 |
| TCP、文件/DNS 资源、Domains、持久实例、VM 句柄 | 维持 Local，逐项实现协议后扩展 | 没有跨线程资源准入证据 |
| Godot 对象和回调 | Local；计算桥另行扩展 | 本次未改 Godot，也未运行 Godot 集成验收 |

### 10.2 任务状态与交接

任务状态采用 `Prepared → Ready → Running → Waiting`，Waiting 可再次进入 Ready；
执行结束进入 `Stopping → Cleaned`。成功/失败/取消结果独立保存，Cleaned 表示可收取终态，
不把返回结果和清理完成压成同一状态。取消是独立的请求位，可在任一非 Cleaned 状态设置。

每个任务控制记录的状态、通知世代、入队标记在同一短锁内更新；不先采用多变量无锁协议。
同一控制锁负责发布数据的可见性。worker 取得 Running 后独占执行存储，释放锁再进入代码。
Running 期间的 wake 增加通知世代；返回 Pending 时比较取得执行权时的世代，若变化则
重新入队，否则进入 Waiting。Waiting 收到 wake 进入 Ready；重复 wake 合并，Cleaned 的
迟到 wake 无效。队列消费必须复核状态，不能仅凭队列项取得执行权。

静态分支先预留全部任务记录和捕获包，再在作用域锁内一次发布；动态 branch 单次发布。
关闭与发布用同一个作用域锁仲裁：关闭后不接受新登记，发布前失败由准备方清理，
发布后责任完全属于作用域。调度事件使用已预留的任务记录，不因普通提交队列已满而丢失。

作用域锁记录单调递增的终态序号。race 由首个被接纳的成功或运行时失败决定主结果；
join/scope 以首个被接纳的失败作为主错误并取消剩余任务。外部取消通过同一锁登记，
先于结果被接纳则结果不再交付。正常值已选定但败方清理失败时改为失败并回收该值；
已有主错误不被次级清理错误覆盖。清理错误也按接纳序号选择，不能由源码槽写入竞争决定。

### 10.3 分配与取消安全点

选择“分支私有分片、根保留分片所有权、同步共享预算”。各 worker 独占分片的可变分配记录，
根保存分片的保活凭据；分支退出可回收自身帧/拥有值，但不能撤销仍被任务期引用使用的存储。
普通对象访问依赖借用及 Transfer/Share 资格，元数据更新依赖独占或同步，二者不能互相替代。
跨分支清理和嵌套容器的具体布局仍须在 TP2 审计，不能把本次不可变数组模型直接套到 Buffer。

单一预算可用 checked CAS 预留，退款与唯一租约析构绑定。任务/实例等多个预算同时存在时
以稳定顺序在短锁内整组检查和预留，失败全部回滚；禁止先无条件增加后检查限额。
元数据、帧、捕获和结果存储均纳入预算，分片保留期间不得提前退款。

取消检查点固定在生成函数入口、循环回边、调用返回及挂起恢复边界；分配/拥有交接中间
不能插入检查。同步 helper 也传播隐藏任务取消上下文，使用受控取消状态沿现有失败清理
路径逐层退出，不做跨 FFI 的异常展开、longjmp 或强杀线程。清理阶段屏蔽新的中途取消，
保留原取消原因。取消状态须与普通用户错误区分，不能伪装成成功返回值。
单纯检测取消不必保存同步栈用于恢复；公平时间片若需要挂起该栈，另作编译变换。

TP0 的源代码显式调用 `probe_cancel` 并返回哨兵值，只验证生成计算能从受控边界退出且清理；
自动插入检查点、同步调用链取消传播、递归展开与清理失败均属于 TP3 的生产验证责任。

### 10.4 关闭和原生桥边界

并行控制对象提供 `request_close`、`is_closed`、`wait_closed` 三类操作：请求关闭拒绝新任务
并登记取消；Closed 必须等全部任务、外部访问和清理完成；阻塞等待只能从非 worker 的宿主
控制线程调用。提交句柄 Drop 只释放句柄，不隐式等待；最后一个控制对象 Drop 在控制线程
请求关闭并等待 worker 退出。控制对象保持本地且不能交给任务，避免 worker join 自己。
不返回的宿主调用仍可能阻塞关闭；本阶段不声称有强制终止或有界关闭时延。

私有桥使用独立的 `__joky_task_*_v1` 协议族，和现有 CPS v1 的单线程树遍历区分。
冻结的操作边界为 scope_open、child_prepare、publish、join、take_result、request_cancel、
drain、scope_release；具体实现与头文件在 TP1 与 lowering 一起落地，禁止提前导出空实现。
所有身份都使用单调不复用的运行时 token，不把可复用裸指针作为任务身份。
输入与结果按编译器生成的类型布局描述符封装，桥仅在调用期间访问调用者槽地址，
发布后保存独立捕获包。子帧在所属 worker 构造，不共享父帧 slots/cleanup。
take_result 成功才转移拥有责任，重复收取受控失败；scope_release 只接受已 drain 的作用域。

CpsFrame 继续是由运行时管理的 opaque 帧，不向 C 宿主开放调度锁、Rc/Arc 或手写字段偏移。
新对象记录任务协议版本、完整帧槽数、捕获/结果布局以及线程资格；缺少证据的旧对象只允许
Local 使用，不得准入 Parallel。更新私有布局必须整批重编译，不允许新桥解释旧帧。
探针仍使用旧 CPS 桥和同步 stop，它没有实现这一新 ABI。

以下为冻结的私有 C ABI 签名，表中名称统一加 `__joky_task_` 前缀和 `_v1` 后缀。
`u64` 对应 uint64_t，usize 对应 size_t，i32 对应 int32_t；指针只在本次调用有效。
这些入口只允许编译器生成代码在已建立的任务上下文中调用，不是普通 C 宿主自行组包接口。

| 名称 | 参数 | 返回 | 责任交接 |
| --- | --- | --- | --- |
| scope_open | kind: u32, capacity: usize | u64 | kind 为 Join=0、Race=1、Dynamic=2；成功创建父任务所属作用域及预留额度，0 表示失败 |
| child_prepare | scope: u64, entry: u64, lanes: const u64*, count: usize | u64 | 按已验证入口描述符复制捕获槽并准备清理责任；成功返回子 token 并接管输入拥有责任，失败返回 0 且输入仍归调用者 |
| publish | scope: u64, children: const u64*, count: usize | i32 | 同一临界区发布全部指定 Prepared 子任务；静态作用域必须一次发布所有分支，动态作用域逐次发布单个子任务 |
| join | scope: u64 | i32 | 关闭登记并挂起父任务，等待全部成功或失败后的清理；race 则等待仲裁与败方清理 |
| take_result | scope: u64, child_index: usize, lanes: u64*, count: usize | i32 | 仅在 join 成功后按精确布局写入未初始化输出槽并转移一次拥有责任；race 的 child_index 固定为 0 表示获胜结果 |
| request_cancel | scope: u64 | i32 | 只登记取消并唤醒相关执行者，不承诺已经清理 |
| drain | scope: u64 | i32 | 等待全部后代与外部访问停止、清理结束，期间保留帧、存储和代码 |
| scope_release | scope: u64 | i32 | 仅已 drain 的作用域可销毁；释放未收取结果，失败不得提前移除仍在用的状态 |

状态返回码为 Complete=0、Pending=1、Failed=2、Cancelled=3。仅 join/drain 返回 Pending；
其他调用非法状态或额度不足返回 Failed 并设置任务错误。open/prepare 的 0 失败同样设置错误。
entry 是当前代码快照的受检入口 token，不是可解引用的裸函数地址；入口描述符关联完整
参数/捕获/结果类型布局、frame_slots、poll 入口、清理入口、线程资格和代码保活凭据。
scalar lanes 不能单凭位值重建这些元数据。准备方在成功 prepare 后立即撤销自己的清理登记，
这个交接段不可插入取消点；失败 prepare 不消费输入。publish 失败后由作用域回收已准备的包。
take_result 失败不写输出、不转移拥有责任；成功后父帧先登记结果清理，再释放作用域。
scope_release 的成功也只能发生在相关清理无遗漏之后，不能用错误返回掩盖仍运行的任务。

  Execution 拆分仍是 TP2 责任。fixture 只有两个固定标量输入，不代表完整捕获资格已实现。

## 11. TP1 实施记录

### 11.1 本地动态登记基础

首个实现切片将 JIT/AOT 的动态作用域与解释器的动态作用域接入同一
[LocalTaskScope](../src/runtime/task_scope.rs)，取代两套独立的登记表、轮询游标和完成项压缩逻辑。
这不是新的多线程配置，也不表示 TP1 已完成。

- 发布前由后端完成捕获快照和拥有责任准备；发布失败退回待发布对象，后端负责清理，
  原生 lowering 在发布桥返回后立即检查错误。汇合开始后关闭登记，不能再发布子任务。
- 动态子任务使用进程内单调不复用的 ChildId；分配耗尽受控失败，不回绕。登记压缩、
  解释器激活槽复用或其他作用域的新任务均不改变既有身份；未知、已完成和同轮重复完成/轮询报告被拒绝。
- 本地模式仍按登记顺序推进，主体挂起时运行子任务轮次，汇合中的作用域由汇合点推进。
  解释器指令切片不重置进行中的汇合游标。完成项及时回收，历史登记不占用活动子任务配额。
- 登记表只负责所属关系与本地轮次；生成代码执行、宿主 stop、拥有结果和清理由各后端既有路径承担。
  原生帧与解释器激活状态仍是本地存储，没有为现有 Rc 帧或 Continuation 添加 Send/Sync。

验证复用既有作用域、捕获、失败、回收、重载及取消测试；扩展已有 CLI 轮次用例，
使动态后代同时处于普通调用、join 和 race 下，在 JIT、解释器与独立 AOT 上比较精确副作用顺序。
新增登记表测试覆盖关闭后责任退回、身份耗尽、压缩后的迟到完成、跨作用域身份隔离与汇合游标。

本切片交付时，TP1 仍须完成静态 join/race 的统一登记、结果交接和仲裁，以及第 10.4 节冻结的
版本化入口描述符和原生桥。此切片的 ChildId 尚未作为 C ABI token 暴露；没有提前导出空的

### 11.4 本地静态组的 drain 屏障

本切片把静态 join/race 的结果收取移动到子树清理成功之后。共享 LocalTaskGroup 明确区分
尚未开始、正在 drain、清理成功与清理失败，不再把 Selected 当作可交付状态。

- 原生 `__joky_cps_concurrent_drain_v1` 和解释器 drain 先移出待停止子树，释放元数据借用，
  再执行 stop/Drop；相关子帧、动态后代和外部借用停止后才记录成功。
- 正在清理时不能再次 drain，也不能提前收取或释放。成功后的 drain 重试不再执行回调。
  多个清理错误保留第一个；失败状态固定该错误，后续收取和 drain 重试都返回它。
- 清理失败不把任何结果写入父槽，未收取包仍有完整清理责任；失败后的组可以销毁以回收包。
  `ConcurrentFinish` 保留组释放边界，原生 release_children 拒绝释放尚未完成 drain 的静态组。
- 解释器在停止子树前移除父记录中的子索引，避免失败后的整体回收重复访问已释放激活。
  正常结果收取、错误回收与逐指令取消仍使用同一组及结果包记录。

新增生成代码回归在 race 败方的 stop 中尝试收取、再次 drain 和提前释放，三个操作均受控拒绝，
原来的 drain 正常完成后父函数返回正确结果。共享状态与原生桥测试另外验证首个清理错误、
失败重试不重做清理、失败后不交付结果及最终回收。

当前 drain 仍是本地同步操作，依赖没有并行执行者、同步 stop 返回即结束外部访问的既有契约。
本切片没有实现多线程异步 drain、根任务取消仲裁或第 10.4 节的版本化任务桥。
动态 scope 的 Unit 子任务仍由既有汇合路径停止和回收；独立捕获包、受检入口描述符和统一的
失败/取消协议继续推进，TP1 保持“进行中”。

### 11.5 捕获、入口与版本化 Local 协议

第 10.4 节八个入口的 Local 实现已落地。作用域创建、prepare/publish、join/drain、
结果收取和释放均接入实际 lowering；取消入口与根帧回收使用同一终态和清理协议。声明见
[joky_cps.h](../include/joky_cps.h)，实现见
[protocol.rs](../src/runtime/cps/protocol.rs)。原生入口 token 由受检的只读模块描述符登记；
额外的 context/current_scope 私有适配负责绑定当前 Local 帧及查找词法作用域。
每次可能嵌套调用后重新绑定上下文，原生错误传播同时保留原有 CPS 状态码契约。

- prepare 先验证入口、作用域和精确输入布局，完成全部可能失败的清理快照，再在无取消点的
  交接段移动清理登记。失败仍由调用方负责；成功后包由作用域负责，publish 失败也不遗失包。
  静态批次拒绝漏项、重复、外来及重排 token；动态作用域逐项发布，开始汇合后关闭准备与发布。
- 原生捕获包与可执行帧槽分离。首次 poll 才安装执行槽；间接入口在 prepare 前固定，后续
  轮询不再读取父帧的参数或函数值。解释器准备激活保存独立输入、清理登记和固定的 Rc callee；
  宿主编码参数与 text view 也在执行前独立保存。尚未执行的包取消时不会调用宿主 poll。
- 布局记录版本、参数/结果的物理槽与存储布局、拥有/借用标志；原生额外记录捕获清理键映射。
  AOT 数据包含 relocation，没有编译进程地址。未知版本、非 Local 资格、帧容量不符和残缺布局
  均被拒绝。清理入口由编译器检查过的捕获登记及结果收集代码关联，不从裸 lane 位值推断。
- 入口、作用域与准备子任务 token 单调不复用。旧 token 不会因 Vec 压缩、槽复用或新作用域
  创建指向另一对象；跨父任务入口和作用域 token 被拒绝。解释器入口属于固定模块快照。
- 静态组与动态 scope 共用终态仲裁及 drain 状态。执行错误先于清理错误保留；取消后迟到完成
  不恢复成功。动态失败路径先移出后代再清理，回调期间不能重入 join、推进轮次或打开 scope。
- Local 静态驱动仍由生成代码执行共享组选择的子入口，并按类型把返回值登记到独立包；
  版本化 join/drain 确认清理屏障。收取验证精确输出长度、完成状态和一次性责任，失败不写输出；
  race 对外只接受获胜结果索引 0。成功收取在返回前把拥有登记移入父帧，之后才允许释放 scope。
- request_cancel 只登记停止；drain 完成回收，重复 drain 不重复 stop/Drop。未发布包同样经过清理，
  未 drain 的 scope 不能释放。生产实现仍是串行 Local，异步 worker drain 属于 TP3。

代码保活边界保持明确：解释器包持有快照 callee；原生 Local 入口借用当前 CPS 调用的代码凭据，
由根任务的 JIT 模块、已注册 AOT 所有者或不安全原生调用方保留至全部清理结束。
元数据复制不等于机器码所有权。可跨线程共享的代码所有权、arena 分片和 Transfer/Share 准入

### 12.1 冻结与准入

共享 IR 对完整实例化类型进行 Transfer/Share 检查，展开间接 nominal 定义；共享引用要求目标 Share，
独占引用不能获得 Share，嵌套共享引用也不能绕过这个要求。游标含共享可变位置，保持 Local。
直接调用、静态分支、动态 branch 和析构依赖一起做单调固定点传播；互递归不会因尚未访问而获得资格。
未知依赖、未审计宿主、函数值/动态分派、显式 arena、域操作均保守拒绝。
资格失败仅拒绝并行准备，不阻止整个模块按原有 Local 模式加载。

JIT 在 finalize 后保留独立的共享代码所有者，编译器的可变状态不进入执行对象。
代码所有权容器使用同步类型；执行过程中不持有其锁。解释器只将不可变字节码、常量和布局表改为 Arc，
worker 在本地重建 callee 表、入口 token、帧、清理栈和宿主适配器；不在 worker 重新编译源码。
未准入的解释器宿主位置成为不可调用项。普通 VM、Continuation、Arena 控制状态和 Rc 清理回调仍不跨线程。
热更新只影响新准备；已冻结的任务不读取 VM 当前模块或当前宿主表。

`register_parallel_suspending_fn` 是显式不安全契约，要求标量签名、完整帧槽数、可跨线程销毁的 Arc 代码所有者，
以及可在不同线程并发调用的全部传递依赖。首版进度仅保存在已声明的标量槽中，不允许 host_data、host_context、
stop hook 或保留 waker；这些能力需另行审计。旧注册与旧 AOT/Rc owner 不自动升级，替换注册只影响后续加载。
AOT 的 `parallel_entry` 返回编译器资格与实际出口符号；`prepare` 还要求调用方以不安全契约绑定该对象的准确入口、
同版本运行库和线程安全代码所有者。完整布局本身不能替代资格或代码保活。

### 12.2 存储和交接

各执行者在本地创建 Arena 分片，根通过同步登记表保留分片。载荷地址不移动，分片结束不等于分配结束。
独占拥有值可以由接收线程在同一根下释放；普通任务期存储及分配记录容量保留至根的最后一个凭据释放。
分配/释放只短暂锁住登记及计费元数据，不锁住任务执行。

共享预算按稳定身份排序、去重并一次取得全部计费锁，全部预检通过后才预留；失败没有部分扣款。
独占 lease 负责恰好一次退款。预算覆盖对齐载荷、分片/根登记、帧与准备槽、任务布局、分支登记、捕获、结果和
Buffer 清理描述；分配记录容量另行保留费用，不随单个载荷释放而提前退款。
这里计量的是规定的运行时存储与元数据费用，不是宿主分配器的 RSS；代码编译和共享可执行代码不计入任务存储预算。
每个新根仍有 64 MiB 默认上限，可以另加多个共享 `TaskBudget`；多个根共享同一个预算也不能各自预检后超额。

拥有包带唯一清理责任和存储根凭据。Buffer 控制块使用稳定的同步元数据 lease，禁止将本地 Budget 裸指针、
资源、Rc 析构回调或清理中间态放入跨线程拥有包。已审计的无钩子嵌套拥有树可转移，错误根收取失败不改变责任，
重复收取被拒绝；未发布包可以在任意接收线程丢弃。可转移不代表可以并发访问同一独占值。
String 输入使用真实 Buffer 拥有交接；输出转换成独立宿主 String，结果费用随输出包保留至取走或销毁。
Buffer 初始化后若在清理登记前失败，分配记录负责兜底释放同步计费凭据；这条路径只释放已审计的线程安全元数据，
不能在根销毁线程调用语言 Drop 或 Rc 回调。回归同时检查费用归零和预算 Arc 的最后引用销毁。

### 12.3 当前嵌入边界

Rust 的 `VmEngine::prepare_parallel_task` 只冻结一个受检入口与输入，不执行用户代码。
`PreparedParallelTask` 可交给 worker；`start` 在接收线程创建不可转移的 `ParallelExecution`，
后续 resume、取消（Drop）及清理都留在该线程。成功结果通过 `ParallelOutput` 交回，`into_value` 将所有权交给宿主。
入口包首版支持标量参数/结果，以及零参数或单个 String 参数返回 String；任意聚合、借用及资源的外部组包尚未开放。
内部类型资格与外部组包能力是两个独立检查，不能拿一个类型的 Transfer 结果绕过入口包限制。

Godot、VM 句柄、持久实例、Domains、TCP/文件/DNS 及普通宿主注册仍走 Local。
本阶段不增加执行器模式配置，也不改变现有 Godot 主线程驱动。任务池、唤醒、异步取消屏障和
自动将三种分支派往 worker 由 TP3/TP4 接续；新版私有存储布局要求 AOT 对象与运行库一起重新编译。

## 13. TP3 固定 worker 的生产分支调度

Rust 的 `PreparedParallelTask::submit(&ParallelExecutor)` 现已把受检根和同一根下的
`join`、`race`、`branch` 接入生产任务池。JIT/AOT 共用原生任务桥，解释器使用独立的
远端分支等待状态；没有重新编译源码或发送已有 Rc 帧树。直接 `start` 仍是 TP2 的
线程本地驱动，既有 VM/HostExecutor 与 Godot 默认路径保持 Local。

### 13.1 发布、进展与仲裁

任务固定分配给 worker，构造工厂和完成包可转移，帧、清理表与宿主适配器在所属 worker
创建和销毁。就绪队列、任务状态与通知世代通过短锁同步；运行期间的通知在 Pending
交接时重新检查，重复通知合并，Cleaned 后的通知无效。任务清理及代码调用均在锁外。
任务登记有全池上限，静态批次全部预留并一次发布；额度不足受控失败，不阻塞 worker
等待队列空间。子任务完成通知复用已有登记，不依赖新的提交额度。

父任务在等分支或清理屏障时返回 Pending。单 worker 下，多层 join/race/scope 可轮流推进，
没有阻塞等待自身排队的子任务。动态 branch 发布后即可与主体后续代码重叠。
作用域在子任务发布终态时仲裁并立即通知败方取消，不等待父任务重新取得执行权；否则
父任务所属 worker 正在执行长循环时，会把取消也挡在该循环之后。

race 保留首个被作用域接纳的终态，join/scope 保留首个失败；原始失败优先于后续取消。
父任务只在全部后代完成清理后交付终态，取消请求与清理完成分别观察。成功结果和败方
拥有值均有唯一责任；失败、未启动包和容量不足路径也经过清理及退款。

### 13.2 自动取消检查点与支持范围

原生 CPS 根及其传递同步调用图插入取消检查点，覆盖入口、循环控制流和调用返回/恢复边界；
检查避开拥有值交接与清理登记之间的区间。同步调用沿错误通道逐层清理并返回，取消使用
独立的 `Cancelled` 错误码，不返回哨兵成功值。解释器在非清理指令边界检查同一请求。
Drop 执行期间屏蔽新的取消；任意宿主调用仍须自行返回，不支持强杀线程或硬实时取消。
不被 CPS 调用的独立同步标量 AOT 对象仍可不依赖任务运行库。

当前生产子任务包开放标量、String 输入和结果，String 捕获及结果转移真实拥有 Buffer。
引用、其他聚合、函数值、动态分派及资源仍在根准入时保守拒绝；分支内部可使用已获资格的
本地临时数据。TP2 的一般 Transfer/Share 类型分析不等于任意类型的生产跨线程组包已经开放。
AOT 可通过不安全的 `declare_parallel_host` 声明精确标量 CPS 导入契约；最终链接的符号、
帧布局、线程安全性及全部代码依赖必须由调用方保证，旧导入仍保持 Local。

统一模式配置、CLI/AOT 驱动、选定等待能力和支持表由 TP4 接续。私有布局及检查点符号有变化，
AOT 对象和运行库需要一起重新编译。

## 14. TP4 显式模式、嵌入与等待能力

执行配置现为 `ExecutionMode::Local`（默认）和 `Parallel { workers }`；
`ExecutionMode::create(max_tasks)` 创建对应的 `TaskExecutor`，Local 包装既有 HostExecutor，
Parallel 建立固定池。worker 数为 1–256，Parallel 任务上限包含全部活跃根及子任务；
Local 沿用根任务上限，两者都必须大于零。
模式在构造时固定；N=1 仍采用 Parallel 资格、结果和生命周期规则。

Rust 仍在本地 VM 中加载/热更新及 `prepare_parallel_task`；受检包可通过
`ParallelExecutor::submitter()` 返回的 `ParallelSubmitter` 在其他宿主线程提交。
提交句柄可克隆，Drop 不等待。`ParallelTask::wait` 仅允许非 worker 的宿主线程调用，
worker 内阻塞等待受控拒绝。控制对象不可 Send，也不能在 worker 内构造；
`request_close` 关闭准入并请求取消，`is_closed` 观察全部任务清理完成，
`wait_closed`/控制对象 Drop 在宿主线程回收全部 worker。关闭后提交拒绝并回收输入包。

CLI 的 `run` 和 `build` 接受 `--task-workers N`，缺省仍为 Local。Parallel 的 `main`
必须是无参数的 `@suspends` 函数，返回 Unit 或 Int32；拒绝重复、零、超界及非数字配置。
AOT 的 `ParallelEntry::standalone_main_v1` 只为已获编译器资格的入口生成驱动，
使用 [joky_executor.h](../include/joky_executor.h) 的版本化配置和入口描述，携带链接期符号和真实帧槽数。
运行库校验版本、大小、模式及结果种类，并受检分配声明的帧槽；错误配置不调用入口、不写输出。
C 桥的 Local 模式沿用旧阻塞驱动器及其限额，`max_tasks` 只配置 Parallel；
该桥仍有明确的不安全静态链接契约，不能拿任意函数指针伪造跨线程资格；无环境变量隐式切换模式。

### 14.1 当前支持表

| 能力 | Local | Parallel |
| --- | --- | --- |
| join/race/branch 与多层 scope | 原有顺序推进 | 固定 worker 分支调度，单 worker 也可推进 |
| 标量、String、Array、嵌套元组/struct/enum（含 Option/Result）输入/结果 | 支持 | 受检包；完整类型树无引用、资源或自定义 Drop |
| List/Map/Set、FixedArray、引用、函数值跨任务包 | 按原有规则 | 尚未开放 |
| 分支内部已获资格的临时存储 | 支持 | 私有分片、共享根预算，生命周期见 TP2/TP3 |
| task.yield_now / task.sleep_ms | 原有宿主时钟与 wake | 已审计内置绑定；真实单调时钟、定时唤醒实际等待的任务 |
| 显式 ParallelSafe 标量 CPS 宿主 | 支持 | 不安全契约，代码 Arc 保活；必须自行返回，不提供强制中断 |
| 普通 extern、stdout、文件/DNS/TCP、Domains、持久实例、VM 句柄 | 原有能力 | 根执行前拒绝 |
| Godot 对象与回调 | 主线程驱动、原有预算 | 尚未开放主线程消息桥，保持 Local |

首批外部等待能力选择定时器。deadline 只存在任务记录中，不保留帧地址；worker 在没有
就绪任务时等待条件变量或最近截止时间，无逐定时器线程和定时空轮询。取消通知可提前唤醒，
终态移除等待记录。一次 Pending 期间的通知仍按世代检查，不能覆盖或丢失。
文件、网络及状态资源的跨线程协议没有因此自动完成，继续在准入时拒绝。

新增拥有值边界回归检查失败/取消/收取后再次收取，以及独立 AOT 的 String 输入和结果交接。
长组覆盖 512 轮提交/关闭交错和生产包预算失败扫描；预算扫描在首次完整成功及归零断言后停止。
这些受控交错与穷举提供当前支持范围的证据，不声称枚举所有 OS 线程交错或完成竞争检测器验证。

验收补齐作用域保留记录的独立计费：动态 scope 仍保存已完成任务的位置，不能仅用活任务数
估算这些容量。未启动工厂先从锁内取出，再在锁外释放；回归同时验证锁外 Drop、唯一释放和
预算归零。原生子任务错误在发布前绑定被冻结代码的 SourceMap，避免直接向父任务传播失败时
绕过根 continuation 的源码补全；VM 销毁后错误仍能定位原文件。

三后端受控重叠回归另覆盖 race 败方析构失败，以及外部取消 join/长循环主体时的子任务析构失败。
取消状态不能掩盖真正的清理错误，已有主错误则不被后续错误覆盖。父 scope 可能先于后代清理退出，
因此子任务错误同时保存在父任务控制记录中，不依赖 scope/结果句柄继续存活；即便已选定 race
成功值或已登记取消，仍先完成清理屏障，再报告错误并回收成功包。

第 1–10 节保留设计目标与冻结契约，第 11–15 节记录各阶段的实际交付。

## 16. TP6 跨任务聚合值

状态：TP6.1–TP6.4 已完成，第 14.1 节为当前支持表。
目标是在同一任务树的 join/race 参数、结果和 branch 移动捕获中传递业务数据，
支持元组、普通 struct、普通 enum（包括 Option/Result），允许递归嵌套标量和 String。
不新增语法，不改变默认 Local、race 的首个终态语义，也不在本阶段实现 first_ok。

### 16.1 准入与边界

- 检查实例化后的完整存储树，保留 nominal 类型身份、字段顺序、枚举标签及实际泛型参数。
  别名按已解析的真实类型判断，不能只看最外层名称或 Copy 标记。
- 首批允许的叶子为现有标量和 String。整个值必须无引用、无外部资源、无自定义 Drop，
  也不能含函数/闭包、dyn、裸指针、显式 Arena 或未解析的递归存储。
  自定义 Drop 的拒绝覆盖所有字段和枚举变体，而不是仅检查运行时激活的变体。
- Array/List/Set/Map、FixedArray、资源和共享借用不随聚合包自动开放；它们有独立布局及
  清理协议，后续分别审计。已获资格的分支内部临时值继续按原规则使用。
- 内部子任务与宿主根入口分别检查。前者使用编译器证明的签名和物理布局；后者使用
  安全的宿主值表示及精确类型匹配，不能让宿主手写原始 lanes、清理表或地址绕过检查。
  本次同时交付两条路径；CLI main 仍限制为无参数、返回 Unit/Int32 的挂起入口。
- JIT、解释器和 AOT 对同一源码具有相同准入结果；某后端未支持的类型保持共同拒绝。
  Local 的既有聚合、引用、资源及 Godot 主线程能力不受新的 Parallel 拒绝规则影响。

### 16.2 交接与存储契约

编译器生成受检的包布局，明确标量槽、聚合值类别、尺寸/对齐、输入与结果位置、枚举有效
分支及拥有字段。不能根据一个指针大小、单槽数量或父帧目的槽猜测聚合值的表示。
需要扩充私有布局协议时明确版本边界，并要求 AOT 对象和运行库一起重编，拒绝旧新混用。

Copy 聚合在发布前形成独立快照；拥有聚合把实际激活的 String 拥有责任交给输入/结果包。
未激活的枚举 payload 不解释为指针，也不参与清理。复制到目标 worker 的本地表示前，
包保留完整布局、存储根和预算；不跨线程传递 Rc 帧、清理回调或原位置的可变别名。

所有可失败步骤都必须有唯一清理责任：准备一部分字段后失败、登记/发布失败、未启动取消、
结果构造失败、race 败方、父 scope 提前退出和收取失败，均清理已初始化的有效字段一次。
交接后的源清理登记必须同时失效；成功收取后包不再拥有这些字段，重复收取受控失败。
跨字段准备、转换和预留成本计入根预算；不能通过嵌套聚合绕过包元数据和临时双份存储计费。
