# SHA-256

`import joky/crypto/sha256`。SHA-256 的压缩、填充和摘要生成均以普通 Joky
代码实现，使用 `UInt32` 位运算及显式回绕加法，不调用 Rust `sha2` 或 native
密码学 provider。摘要是 **32 字节原始 Bytes**。

| API | 返回值 | 语义 |
| --- | --- | --- |
| `sha256.digest(data: Bytes)` | `Result(Bytes, String)` | 一次性计算摘要 |
| `sha256.new()` | `Sha256` | 创建独立的增量状态 |
| `state.update(&self, data: Bytes)` | `Result(Unit, String)` | 追加任意长度的数据，空块也合法 |
| `state.finish(self)` | `Bytes` | 加入最终 padding 并消费状态，返回摘要 |

```joky
import joky/crypto/sha256

fn main() -> Result(Unit, String) {
    let state = sha256.new()
    state.update(b"a")?
    state.update(b"bc")?
    let result = state.finish()
    println(result == sha256.digest(b"abc")?) // true
    Ok(())
}
```

`finish` 消费唯一所有权，之后再次 `update` 或 `finish` 会在编译期被拒绝。
通过 `sha256.new()` 创建状态；压缩方法、字段和构造参数属于实现细节，
不应直接修改或调用。状态没有跨 I/O 挂起的借用方法。

实现针对字节输入：最大总长度为 `2^61 - 1` 字节，保证位长度小于 `2^64`。
`update` 在修改状态前检查累计长度，超出限制返回 `Err` 并保持原状态。
最后的八字节长度和摘要中的八个 32 位字均按大端序输出。

增量处理只保留不到 64 字节的待处理数据、固定大小的消息调度和摘要状态，
不会累积历史输入。底层 `Bytes.slice` 和 `MutBytes.to_bytes` 会复制每个小块，
因此这里的固定额外内存不代表零拷贝或硬件加速。

完整[示例](../../examples/basics/crypto.jk)将摘要转成 Base64；输出格式由调用者选择。
当前模块只提供 SHA-256；HMAC 和 PBKDF2 由[后续工作](../plans/backlog.md#postgresql-驱动)承接。

## 验证

[标准向量](../../tests/fixtures/sha256.jk)覆盖空输入、`abc`、多块消息和一百万个 `a`。
[CLI 测试](../../tests/cli/crypto.rs)还用独立的 Rust `sha2` 计算预期值，对比二进制消息
在 55/56/57、63/64/65、119/120/121 等填充与分块边界，以及九种分块长度下的摘要。
Rust `sha2` 只在该测试中充当参考实现。

```bash
JOKY_TEST_AOT=full cargo test --test cli crypto
```

该命令覆盖 JIT、debug AOT、release AOT；标准向量还覆盖缓存 JIT。
AOT runtime 的准备方法见[开发指南](../../CONTRIBUTING.md#运行测试)。

算法依据：[RFC 6234](https://www.rfc-editor.org/rfc/rfc6234.html) 第 4–6 节。
