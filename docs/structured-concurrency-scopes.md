## 1. 目标与概念分工

当前 `scope` 是一个预先列出全部分支、等待全部完成的组合表达式。新的 `scope` 要允许
普通顺序代码与动态创建的子任务共存，因此采用不同名字，避免同一个关键字对应两种主体执行方式。

| 构造 | 主体与创建方式 | 正常完成条件 |
| --- | --- | --- |
| `parallel { \| a() \| b() }` | 静态列出的调用分支；先准备全部实参，再轮询 | 全部分支完成 |
| `race { a(), b() }` | 静态列出的竞争分支；保留现有轮询规则 | 首个观察到的成功，取消并清理其余分支 |
| `scope { ... }` | 主体顺序执行，可在条件、循环中创建子任务 | 主体结束且全部所属子任务完成 |
| `branch { ... }` | 捕获输入、登记子任务，当前流程继续 | 表达式登记成功即返回 Unit；子任务由所属作用域等待 |

四者共享父子任务、失败传播和取消清理机制。任务组是内部运行时概念，不新增公开的
`TaskGroup` 类型、游离任务句柄或 `detach` 操作。继续沿用 `@suspends`，不增加 async/await。
所有构造表示协作式并发，`parallel` 不承诺多线程、多核同时执行或 CPU 循环公平性。

## 2. parallel 重命名与迁移

目标写法：

```joky
fn run_pair(a: Int32, b: Int32) @suspends {
    parallel {
        | nested(a, b)
        | read(b, 2)
    }
}
```

第一阶段只改变源语言名称，保留现有行为：

- 至少一个分支；每个分支为返回 Unit 的 `@suspends` 调用，保留已有函数值和成员调用能力。
- 按分支源码顺序、实参从左到右准备全部输入，之后才开始轮询。
- 全部成功才返回 Unit；首个观察到的失败使任务失败并取消剩余工作。
- 分支借用、拥有值转移、arena 预算、race 顺序、取消与代码保活规则均保持原契约。
- `parallel` 和 `race` 自身就是完整任务边界，不要求额外包一层新 `scope`。

这是一次源代码迁移。实现提交同时迁移标准库、示例、fixture、测试、工具和当前能力文档。
检查 `parallel`/`branch` 作为既有标识符的冲突，更新关键字及解析诊断。
旧 `scope { | ... }` 给出明确诊断，例如 `Use parallel for pipe-separated branches`；
不默默解释成新语义，也不长期保留两种 scope 主体。历史验收记录可保留旧名称并注明版本。

实施时内部 IR/CPS 沿用了旧命名；后续统一为 `Concurrent` / `ConcurrentKind`，
其中 `ConcurrentKind::Join` 表示完成策略；
应清楚区分静态分支组合与新增的顺序主体，不能仅修改关键字映射就宣称完成新 scope。

## 3. 新 scope 与 branch 的语言契约

### 3.1 顺序主体与 Unit 结果

```joky
fn work(a: Int32, b: Int32) @suspends {
    scope {
        let input = prepare(a)
        branch { nested(input, b) }

        update()
        branch { read(b, 2) }
        finish_preparation()
    }
    finish()
}
```

`scope` 主体遵循普通块的求值顺序；`let`、赋值、条件、循环和调用依次执行。
执行到 `branch` 时才创建子任务。未执行的条件分支不创建任务，也不转移其捕获值。
`branch` 后的代码无需等待这个子任务结束，但整个 scope 结束前必须完成汇合。

首版 `scope`、`branch` 正常结果均为 Unit，能正常到达末尾的主体必须满足 Unit 类型；
`scope {}` 与 `branch {}` 合法。branch 主体可以包含任意已支持的顺序代码，
可以调用同步或挂起函数，不要求第一条或最后一条表达式为挂起调用。
不提供 branch 结果句柄、scope 值聚合或动态 race。

这些构造仅允许在 `@suspends` 上下文中使用。即使某条路径没有实际挂起，
也不能凭运行时是否 Pending 绕过效果检查。析构和同步清理函数不能创建 branch。

### 3.2 所属关系与函数边界

branch 绑定当前函数内最近的任务作用域。普通 `{}`、`if`、`while` 不创建任务作用域；
嵌套的显式 scope 创建新作用域，内层完成前必须清理其全部子任务。

每个 branch 块是独立子任务入口，自带管理其后代的隐式作用域。因此 branch 内部可以
继续创建 branch，父分支必须等这些后代完成才能向外报告成功。race 判断某个分支胜出时，
必须包含该分支自身的结构化后代完成，不能把仍有活后代的主体返回当成胜出。

任务作用域不通过普通函数调用动态继承。一个函数不能因为调用者恰好位于 scope 中，
就把自己的 branch 偷挂到调用者；被调用函数需要声明自己的 scope。
函数体内没有合法所属作用域的 branch 为编译错误。branch 块的隐式作用域只属于该块，
不赋予其调用的函数额外权限。

### 3.3 捕获与借用

branch 块由编译器检查自由变量，并降低为私有子任务入口及捕获参数；不因此开放通用闭包值。
首版采用创建时快照与移动规则：

- Copy 值在执行 branch 表达式时复制。后续修改外层变量不会改变已经捕获的值。
- 非 Copy 拥有值在创建时移动，父流程此后不能使用已移动的值；不隐式 clone。
- 捕获的外层绑定在分支内作为输入，不能直接赋值以修改外层 `var` 槽。
  分支要修改自己的局部变量时显式声明 `var`；经受检可变引用访问对象遵循原有规则。
- 引用保留既有来源与权限检查。允许现已支持的 arena 引用及共享引用聚合；
  不开放局部栈借用、Slice/视图或任意 `&mut` 接收者跨 Pending。
- 不按字段隐式拆分拥有捕获；首版按整个绑定检查移动与借用。捕获类型能否跨挂起，
  必须复用现有类型资格检查，不能因为内部使用环境记录而绕过不支持类型的限制。

借用检查必须同时覆盖已创建子任务、后续主体和其他子任务。即使实现先执行主体、稍后才轮询
子任务，也不能据此允许冲突访问。普通分支借用至少持续到所属任务作用域结束；
有分配能力的调用仍遵循已有的更长任务期保留规则，join 不提前解除这种借用。
循环创建分支时检查跨迭代冲突，不能只检查单次循环体。

例如下面是必须拒绝的目标反例，假设 `target` 是允许进入分支的 arena 可变引用：

```joky
scope {
    branch { write(target, 1) }
    write(target, 2)
}
```

动态任务可能晚于普通局部块结束，因此不能通过延长一个 CPS 帧的物理寿命来冒充借用合法。
首版不支持的捕获应在共享语义检查中拒绝，并定位到捕获或冲突使用处。

### 3.4 创建与首次执行顺序

建议首版固定为“登记后继续主体”，不在 branch 表达式内部内联执行子任务：

1. 按固定顺序取得捕获快照、检查容量并建立清理责任；捕获布局使用源码首次使用顺序。
2. 子任务登记成功后进入待运行队列，branch 表达式返回 Unit，继续主体。
3. 主体实际挂起、显式让出或进入 scope 汇合时，才轮询登记的子任务。
4. 同一作用域按创建顺序轮询子任务，跳过已结束的任务；一轮中 Pending 的任务不被反复重试。

再次推进作用域时，先推进尚未完成的主体，再按登记顺序推进子任务；主体已经结束时只推进
子任务。主体轮次中新建的子任务在该轮轮到子任务时可参与。嵌套调用按同一规则递归解释，
实现必须用受管理状态保存轮次、游标和完成标志。

同步调用、普通循环或立即完成的挂起调用不隐式让出。解释器指令切片返回宿主时保存当前
逻辑游标，不能仅因后端不同就改变上述轮询次序；切片也不构成 native 抢占承诺。
这些规则让三后端可用确定的副作用轨迹验证“何时创建、何时首次执行、何时恢复”。

捕获求值与分支体调用求值必须区分：`branch { send(make_value()) }` 中的 `make_value()`
属于子任务执行，不能提升到登记时运行。需要提前求值时，用户先写 `let value = make_value()`。
已有 parallel/race 的“全部实参先求值”保持不变，两者不能通过简单文本展开互相替换。

### 3.5 正常退出、提前跳转与失败

| 出口 | 要求 |
| --- | --- |
| 主体正常结束 | 停止该主体追加任务，等待已登记的全部子任务与后代，清理后返回 Unit |
| 主体 `return` 越过 scope | 先求值并保存返回值；从内到外完成被越过 scope 的汇合与清理，然后返回 |
| `break` / `continue` 越过 scope | 保存跳转目标，完成被越过 scope 的汇合与清理，再跳转 |
| branch 内 `return` | 只结束当前子任务主体；首版只允许 Unit，仍须等待其后代 |
| branch 内 `break` / `continue` | 只允许跳转到该 branch 内定义的循环，不能跳回父流程 |
| 主体或任一子任务失败 | 停止创建工作，取消相关任务树，完成清理后传播首次观察到的错误 |
| 父任务取消或 race 淘汰 | 取消作用域及后代，完成 stop 和拥有清理后才能释放所借用存储 |

`return`、`break`、`continue` 属于正常控制流，不隐式变成取消。提前返回也可能等待很久；
有意让主流程结束时停止伴随工作，应使用 race 表达竞争关系。
如果汇合期间出现失败，原先保存的正常返回/跳转不再生效；暂存的拥有返回值也必须被清理。
`Result.Err` 仍是普通业务数据，不自动触发取消。

正常汇合只关闭主体继续创建工作的通道，不应禁止已存在子任务在自己的隐式作用域内创建
后代。失败或取消才递归关闭整棵任务树的创建入口。第一次终态确定后不得恢复普通执行。

## 4. 运行时与三后端实现边界

现有静态分支相关入口包括 [解析 AST](../src/core/parser/ast.rs)、
[共享 IR 检查](../src/core/ir/calls.rs)、[解释器执行](../src/backends/interp/execute.rs)。
原生 JIT/AOT 共用 `backends/native` 的 CPS 生成与运行时；必须一起实现，不能只改解释器。

新增状态至少区分：主体正在执行、主体已结束正在汇合、正在取消、已完成/失败。
登记、轮询、汇合、取消使用同一套子任务身份与父子关系；公开类型名和具体指令名留给实现，
这里不冻结新的 ABI 或手写 CPS frame 布局。

实现应满足以下不变量：

- branch 登记只发生一次。Pending 恢复不重复捕获、移动、创建任务、实参求值或副作用。
- 捕获环境及子帧必须先有清理责任，再对调度器可见。容量预检、分配、部分构造失败时，
  每个拥有值仍恰好有一个清理责任；从未轮询的分支也必须能完整取消。
- 取消先禁止新工作，按现有同步 stop 契约停止外部访问，再清理子帧与捕获环境。
  父存储与代码快照在最后一个使用者结束前保持有效。
- 复用登记槽时防止旧身份指向新任务；深层取消与汇合不依赖无限宿主递归。
- 已完成任务及时归还帧及登记容量；循环不断创建和完成任务不能无限积累墓碑或历史清理项。
  活任务、嵌套深度和捕获分配需要明确额度，超限返回受控错误而不是无限增长。
- 不为每个 branch 增加独立任务 arena。沿用根任务 arena 与共享预算；scope 结束不等于
  释放该根的全部分配，也不重置其预算。元数据额度与 arena 载荷额度分别说明。
- JIT 与独立 AOT 使用相同布局与清理协议，AOT 不嵌入编译进程地址；解释器遵循相同可观察语义。
- 清理中发生错误仍继续必要 stop/Drop；保留原始执行错误，后续清理错误沿既有报告机制处理。

不把“主体后缀搬进一个新的 parallel 分支”当作完整实现：这种降低必须另外证明捕获时间、
借用范围、条件/循环创建、非局部跳转、失败与资源限额全部等价。

## 5. 与 P4 及后续 Godot 接入的关系

本设计与 Godot 接入兼容，前提是语言等待与宿主驱动之间遵守以下边界：

- scope 的汇合是可挂起操作。未完成工作暂时无法继续推进时返回 Pending，把线程交还调用者，
  不在 scope 实现内 sleep、忙轮询或运行一个阻塞式事件循环。
- CLI 可以继续用阻塞驱动器推进根任务；外部引擎由 P4 提供非阻塞推进、唤醒与时钟。
  驱动方式不同，任务归属、失败传播及取消语义不变。
- 宿主拥有根任务，根任务拥有结构化后代。P4 的“任务组”应复用这些机制，
  不增加绕过作用域清理的第二套脚本并发规则。
- 接入持久实例时，等待期间不持有实例的 `&mut State`。异步流程通过经过验证的身份和
  独立输入运行，短同步调用访问状态；语言 branch 的捕获规则不能使实例接收者逃逸。
- 宿主销毁所属对象时，先禁止新根任务，取消并 stop 全部所属工作，再释放实例状态和代码。
  迟到唤醒需验证任务身份及代次；取消完成后不能重新执行任务。

因此纯语言的重命名及 scope/branch 可以先于 P4 交付。它们不自动提供帧等待、信号订阅、
游戏时钟或实时帧预算；这些属于 [P4/G2](persistent-instances-numerics.md#4-实施阶段与完成条件)。
协作式执行不能抢占不让出的 native 调用，poll 次数上限也不等于毫秒上限。
本计划不修改 Godot API，不规定异步根入口的名字。

## 7. 验证矩阵

验收测试必须执行生成代码，不能只比较 AST 或 IR。JIT、解释器和真实独立 AOT 共用语义 fixture；
模拟宿主事件使用可控唤醒，不依赖真实时间或线程竞争来判定正确性。

| 类别 | 必须覆盖 |
| --- | --- |
| 迁移 | parallel/race 参数准备顺序、函数值分支、共享/独占借用、旧 scope 迁移诊断 |
| 主体与动态创建 | 空 scope、零/一/多 branch、条件、循环、嵌套作用域、子任务再创建子任务 |
| 捕获 | 创建时 Copy 快照、拥有值只移动一次、未执行路径不移动、重叠借用拒绝、局部引用拒绝 |
| 调度 | 创建后主体继续、主体真正 Pending 后子任务推进、创建顺序、全部 Pending 返回、已完成分支跳过 |
| 恢复 | 连续多次 Pending、嵌套普通调用、显式让出、指令切片，不重放捕获、登记或副作用 |
| 退出 | 正常 join、跨 scope 的 return/break/continue、branch 局部 return、暂存拥有返回值在失败时清理 |
| 竞争与失败 | race 包含带动态后代的分支、同轮成功/失败、主体失败、子任务失败、永不完成分支被取消 |
| 清理 | 从未轮询就取消、外部 stop 先于存储释放、Drop 失败继续清理、部分捕获/登记失败 |
| 稳定性 | 任务/深度/内存限额、槽复用、重复创建完成的元数据基线、深层迭代取消、旧代码保活 |

## 8. 文档落地与后续扩展

实现时同步更新 `syntax.md` 的文法、设计摘要与阶段状态；实际可用语法及示例进入
`language.md`，父子任务/借用/清理不变量进入 `architecture.md`，字节码及解释器状态机进入
`interpreter.md`。README 只更新已验收能力。本文保留决策、阶段验收证据和后续工作。

非 Unit 分支结果、任务句柄、主动取消单个分支、动态 race、局部借用跨挂起、通用闭包、
多线程执行与异步 draining 均为后续独立设计，不能借本次语法改名默认开放。
