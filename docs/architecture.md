# 架构与嵌入约束

Joky 保持单个 Rust crate。公开入口为 `parser`、`aot::AotCompiler`、`vm::VmEngine`、
`runtime`，以及根模块的类型、签名和结构化错误。源码目录表达当前职责，不预设拆包计划。
使用方式见 [README](../README.md)，语法见 [语言与内置模块](language.md)。

## 模块与依赖

```text
source → core::parser → AST → core::prepared::PreparedModule → core::ir::ModulePlan
                                                           ├─ backends::native → JIT / AOT
                                                           └─ backends::interp → bytecode

stdlib → modules::ModuleRegistry → core::resolver::BindingRegistry
vm     → registry + backends + runtime::Continuation
cli    → public parser / VmEngine / AotCompiler
```

| 目录 | 职责 |
| --- | --- |
| `src/core/` | 词法、AST、导入解析、类型/签名、诊断及后端无关 IR |
| `src/backends/native/` | JIT/AOT 共用的 Cranelift 符号声明、数据对象及 direct/CPS lowering |
| `src/backends/jit/` | JIT 初始化、入口导出和可执行代码所有权 |
| `src/backends/aot/` | AOT 状态管理、导入布局和对象文件输出 |
| `src/backends/interp/` | 字节码生成/优化、静态绑定、迭代执行和诊断 |
| `src/modules/` | 将纯声明元数据与可选 native entry、owner 组合成不可变注册快照 |
| `src/runtime/` | 原生 ABI、CPS 帧、continuation、协作调度及拥有文本/旧文本适配 |
| `src/stdlib/` | `joky/vm` 实现、标准绑定、option/result/integer/array/map/string/eq/hash/check 源码库及 JIT 地址的弱所有权索引 |
| `src/vm/` | checked embedding API、加载发布、宿主注册和执行限额 |
| `src/cli/` | 参数、入口检查、诊断渲染、原生链接及产物发布 |

`core` 的生产代码不依赖 Cranelift、运行时或具体执行后端；跨后端行为测试可以使用它们。
JIT 和 AOT 共享 `backends::native`，解释器直接消费 `core::ir`。内部代码使用实际模块路径，
`lib.rs` 只保留面向嵌入方的公开 re-export。

`BindingRegistry` 保存声明、模块路径和符号索引；`ModuleRegistry` 增加 native 实现与生命周期。
两者的区别是数据边界，不是两套解析器。resolver 直接接收同一份声明快照；没有仅作转发的
provider trait。标准库每线程初始化一次 registry，以 `Rc` 共享，裸指针和 owner 不要求 Send/Sync。

## 语义与代码生成

`core::parser` 根模块保存公共入口、诊断和共享 token 游标；`module` 负责导入顺序与顶层分派，
`declarations`、`types`、`patterns`、`atoms`、`expressions`、`control_flow` 和 `attributes`
按语法职责扩展同一个 Parser。调用与方法调用共用参数列表规则，各语法模块共享泛型作用域与分支上下文。

词法器借用原始 UTF-8 源码，以字节位置为唯一游标；关键词和数字直接从切片解析，
标识符及解码后的字符串由 AST 所有。`Span` 保存文件身份 SourceId 与半开字节范围；源码文本由 SourceFile / SourceMap 的共享快照保存。
`parser::Diagnostic` 转为 `Error` 时统一保留 Parse 阶段、行号和范围，CLI 在最后一步渲染。

`TypeRegistry::resolve_aliases` 收集模块全部记录、枚举及别名，迭代遍历类型依赖图并检测环，统一改写函数签名和
所有局部注解，保留原始源码范围；返回的 AST 不再携带别名声明。别名使用编译期定义映射，
不会修改宿主注册器；参数/返回值等编译后元数据只保存实际类型。所有类型声明都检查，即使没有使用。
VM/AOT 在内置调用重写及 ABI 检查前执行该步骤，CLI 也在检查 main 和已注册 extern 签名前执行。
直接处理 AST 的嵌入方可以调用同一个公开 API，输入 AST 保持不变。
parser 的 `Module.type_aliases`、`Module.records`、`Module.enums` 保存独立声明和源码范围；手工构造 Module
的 Rust 调用方需要初始化这些字段。记录及枚举声明具有独立身份，克隆 AST 保留身份，新解析生成新身份。类型与值名称分开解析，类型别名不会出现在函数导出列表或对象符号中。

泛型别名的 `TypeAlias.type_params` 使用声明局部的刚性 Copy 参数。内部 `TypeDefinition` 区分
已解析类型和 `AliasTemplate`；模板目标在定义作用域中规范化，导入绑定保留模板及参数身份，
调用点只替换参数，不按消费者的同名类型重新绑定。未使用的实参也检查 Copy 约束。
`core::types::specialization` 复用元组 / 记录 / 枚举的有界替换，规范化阶段单独缓存最多 256 个不同
别名应用（含刚性参数应用）；重复应用复用目标，参数最多 64 个，目标沿用 65,536 槽 / 256 层上限。
模板不进入构造查找、可执行 `Type`、IR 或 ABI；透明展开不创建名义身份或运行时符号。

core::imports 绑定 prelude 与源码导入；resolver 绑定宿主模块，并只在导入 `joky/vm` 时重写其受限调用形式。
`PreparedModule` 为 VM 和 AOT 统一执行类型规范化、宿主名称解析及绑定声明校验，持有本次编译的
AST、类型环境和绑定声明快照。宿主绑定提供完整 CPS frame 布局后，再生成 `ModulePlan`；
原生 lowering 只接收已检查的 plan。编译产物保留源码和代码所有者，不保留准备对象。
`ModulePlan` 统一检查声明、调用、返回类型、赋值权限、作用域和挂起约定。
`FunctionPlan` 保存 typed slots、操作、对应源码范围、控制流标签及挂起状态。
三个后端消费相同结果，不在 lowering 中重新推导语言类型。
`core::types::walk` 为只读类型检查提供按 Arc 指针去重的迭代遍历。`Arguments` 跟踪函数签名、
引用目标、元组元素和名义类型实参；`Storage` 另包含名义类型的标量布局与内部缓冲元素。
泛型未解析检查和名义身份校验使用前者，存储类型校验使用后者，并保留原有错误遍历顺序。
双类型匹配、类型替换与深度计算仍保留各自的比较、重建及路径深度规则。

lexer 解析十进制、`0x`、`0b` 和数字间单下划线，整数 AST 保留幅值及直接负号，类型检查从局部上下文确定八种整数后按各自范围验证。
浮点 token 要求小数点两侧都有十进制数字并验证可选带符号指数；上下文确定 Float32 / Float64，无约束默认 Float64，超出目标有限范围的字面量在类型检查拒绝。
`core::integer::IntegerType` 集中定义整数位宽、符号及字面量范围，语义检查与原生 lowering 共用这些信息。
`core::float` 提供共享的 IEEE 运算内核，常量折叠与解释器共用；原生 lowering 使用目标 FPU 指令，不启用 fast-math 或代数重写，NaN、有符号零与次正规数按 IEEE 语义保留。
`runtime::float_env` 在共享 IR 规划、后端编译、解释器执行及受检宿主调用期间建立标准
浮点环境，退出时恢复调用线程的控制位和状态标志。ARM64 保存 FPCR/FPSR，x86_64 保存
Rust/Cranelift 标量运算使用的 MXCSR；标准环境采用最近偶数舍入、关闭 FTZ/DAZ 并屏蔽
浮点异常。其他架构目前在构建时明确拒绝，不提供无保护的后备路径。
原生后端在完成的 CFG 上为含浮点值或外部/间接调用的函数插入相同的入口/出口保护，
覆盖 direct、CPS、私有实例桥和所有失败返回；外部调用后重新建立标准环境。
纯整数内部调用无需因此引入运行时依赖。守卫只保存在本次原生栈/SSA 中，Pending 前即恢复，
不存入 continuation；重入调用逐层恢复各自的宿主环境。独立 AOT 浮点对象也需要链接运行时。
数学原语（sqrt/floor/ceil/trunc/round-ties-even、to_bits/from_bits）经共享 IR 的 `Op::Float`
下发三后端，标准库 `joky/float` 的私有占位函数按身份绑定内建，与 `rune_from_valid_u32` 同一机制；
受检浮点转整数在库内以 2 的幂精确边界比较实现，最后的截断走信任内建映射到 `Convert`，
范围已在数学上证明后饱和转换不可能触发。
共享 IR 的定型提示只查看类型，不执行表达式；实际规划始终按源码顺序，绑定完成即固定类型。
字段、载荷、元组元素和返回值的预期类型向内传递，分号丢弃项没有结果上下文。
公开 AST 的 `Literal::Int32` / `Literal::Int64` / `Literal::UInt32` / `Literal::UInt64` / `Literal::Float32` / `Literal::Float64` 表示已经定型的值，源码解析产生 `Literal::Integer` / `Literal::Float`。
这会把 Int32 范围错误从解析阶段移到 TypeCheck；超出 UInt64 最大幅值的文本仍在解析阶段拒绝。

必须保留的语义约束：

- 可变绑定读取生成快照，后续赋值不能改变已求值的操作数或实参；求值顺序从左到右。
- Unit 不产生机器值；普通 ABI 省略 Unit 参数，CPS 参数槽仍保留原始位置。
- 普通 lowering 通过 Cranelift Variable 构造 SSA，补齐循环回边后封闭块；
  CPS 使用槽位和独立恢复状态。表达式序列只影响规划顺序，不增加执行指令。
- 恢复继续当前子调用，不重算参数或重放副作用；每轮循环重新创建其 parallel/race 子帧。
- String 字面量通过可重定位数据对象输出，不能把编译进程地址写入 AOT 对象。
- `joky_cps_`、`__joky_cps_`、`joky_vm_`、`joky_runtime_`、`__joky_runtime_`、
  `__joky_string_`、`joky_string_result_` 与 `__joky_user_text_v2_` 保留给 runtime 或版本化出口。

结构化并发在 AST 和共享 IR 中统一表示为 `Scope`，`ScopeKind::Join` 对应 `parallel`，
`ScopeKind::Race` 对应 `race`。两者共用参数求值、Unit 挂起分支约束、借用检查和能力传播。
Join 等全部分支完成，Race 在按源码顺序观察到首个完成时释放全部子帧，再继续父函数；
首个观察到的失败仍沿既有失败路径传播。原生后端复用 `__joky_cps_release_children`，
解释器沿平坦激活表迭代释放未获胜分支的子树并归还帧额度，保留祖先和无关兄弟分支。
取消清理分支拥有的 String；普通 arena 对象仍到根任务结束才回收，已有副作用不撤销。旧 CPS ABI 保持原契约，
异步借用 v1 将强制 stop 回调接入同一帧释放路径，在父任务恢复前确认外部访问停止。

顺序主体的动态任务作用域使用三个专属操作：`TaskScopeEnter` 压入作用域记录，
`TaskBranch` 把 branch 主体编译出的私有入口（`__joky_task_N`，捕获即参数）连同
登记时快照的捕获一起登记，`TaskJoin` 挂起等待该作用域全部子任务完成。
每个 abrupt exit 越过作用域时被改道到该作用域自己的汇合点，汇合后再跳转原目标；
借用分析为引用捕获建立按作用域标记的保留借用，在对应 `TaskJoin` 处解除，
可分配入口仍沿用任务期保留契约。调度上，主体挂起导致的每次根推进先恢复主体，
再按先序遍历（作用域外层在前、登记顺序在内）推进子任务各一次；汇合中的作用域
由其汇合点自行轮询，调度轮跳过。取消沿既有迭代释放路径处理动态子树；
解释器动态子任务计入 `max_frames`，原生后端按帧限额拒绝超限登记并返回受控错误。

记录、枚举和元组分别规范化为 `Type::Record` / `Type::Enum` / `Type::Tuple`，与 `Type::Named` 的宿主 opaque 标量区分。
`core::types::layout` 统一解析记录、枚举和别名的依赖图，生成成员类型、偏移及扁平标量布局，
拒绝无限布局、非 Copy 成员和超限布局。枚举布局先存一个 Int32 标签，再为每个变体保留
独立的载荷区，宽度为 `1 + sum(payload slots)`；不做重叠 union 存储或类型重解释。
构造初始化全部槽，未选载荷区置为 0 / false；选中载荷按其类型复制，避免 SSA 未定义读取。
标签只由受检构造产生，宿主不能注入裸枚举值。

元组按有序元素类型比较，透明别名在嵌套位置也展开；类型依赖扫描进入元组元素，
所以元组不会隐藏别名环或无限内联布局。`Type::tuple` 供 Rust 嵌入方构建未解析注解，
`resolve_aliases` 验证 Copy 元素、计算布局，并在无名义声明的模块里也执行规范化。
共享零大小元组图的规范化和比较缓存已访问节点，避免指数展开；诊断类型名输出有大小上限。
元组布局为各元素标量宽度之和，保持元素顺序，没有运行时元组对象或新增 native ABI。
`core::ir::tuples` 先求完整初始化器、检查所有模式叶子，再发布新绑定；var 叶子复制到独立存储，
`_` 不创建绑定，零大小和被丢弃元素的副作用仍执行。

IR 的聚合 slot 描述一段连续标量槽；构造、快照、赋值和分支合并展开为普通标量操作。
Unit、空记录及仅含零大小元素的元组不占值存储，但仍参与类型检查和副作用求值；独立 Unit 参数保留旧占位。
`core::ir::enums` 校验模式、穷尽性和可达性后，把 match 降为标签比较、分支及结果复制，
被匹配表达式求值一次，载荷绑定指向稳定快照。最后一个穷尽分支无需重复测试标签；
正常完成的分支才参与结果类型合并。首版按源码顺序测试，尚无跳转表优化。

同步原生内部调用展开聚合参数，聚合返回增加最后一个隐藏结果指针，没有机器返回值；
调用者分配临时结果区，每个标量占一个 64 位槽，低位编码沿用原标量规则。
浮点标量在槽间按位编码：Float64 存 64 位 IEEE 位模式，Float32 存零扩展的
32 位位模式；槽间移动只做位搬运，不做数值转换，原生侧经 bitcast 拆装。
CPS result、聚合槽与内存布局使用同一编码，挂起恢复后位模式不变。
CPS 保持 `CpsFrame` ABI：聚合结果位于 slots 中参数区之后的固定区域，普通标量仍写 result。
父帧在子任务完成且错误检查通过后复制结果，再释放子帧；Pending 只重新轮询。
记录、枚举和元组复用该协议，它不是 extern/宿主 ABI；公开调用继续使用标量包装函数。
聚合值本身不增加堆对象，解释器及 CPS 原有的激活帧分配仍然存在。

解释器的局部变换、跳转/源码映射、静态适配器和帧存储见 [解释器设计](interpreter.md)。
这些优化不改变共享 IR；死值不能成为删除有错误或副作用操作的理由。

## 同步局部借用

core::ir::locals 在规划前扫描取借用的标识符，在相应绑定建立时为无引用 Copy 值物化稳定位置。
按拼写保守匹配可以使同名但不被借用的局部值也物化；不同声明仍有独立身份，分支不改变绑定表示。
参数、解构叶子及 match 载荷使用相同规则。Binding 的原值槽保留类型信息，place 保存隐藏引用；
后续整值/字段读写经 ReadMemory / WriteMemory，读取生成独立快照，写入沿用预留与权限检查。
不能把 Cranelift SSA 值或可移动的解释器 Value 槽地址作为语言引用。

Op::Local 建立区别于任务 arena 的函数局部来源，Op::EndLocal 标记词法作用域结束。
块、条件、逻辑右侧、match 输入和分支、graph 块及 break/continue 离开的局部范围均发出标记。
borrowing 在 CFG 上拒绝超出原绑定范围的活跃视图，函数返回和任务存储操作拒绝局部来源；
聚合、泛型和调用结果沿用现有来源传播规则。隐藏 place 是存储身份，不作为竞争借用；
对原位置的实际访问仍检查全部活跃视图。借用检查后删除 EndLocal，保留操作与源码范围的对应。
局部存储不产生 uses_arena，不向 helper 的调用者增加任务期存储契约。

Op::Project 为内联记录字段建立地址和借用，保存根引用、字段路径及是否为写预留。
local_path 统一解析借用和直接字段访问，field_target 校验各级记录字段；不会经过引用解引用。
借用预扫描物化根对象，Project 不额外分配存储。原生和解释器都按 memory_field_path 的字节偏移
生成字段地址，零大小字段可处于对象末端，不依赖地址不同证明独立性。
borrowing 的 Origin 保存根身份与字段名路径，路径前缀表示同一位置或父子重叠；
引用可能来源集合按根和路径排序，用合并扫描检测重叠，编译工作量预算计入路径长度。
只有已证明的 Local 根缩小访问路径；arena 和参数来源维持整对象契约。
直接字段读写及预留同样检查精确位置，整体访问覆盖所有子位置；复制、聚合、分支合并及调用结果
保留可能路径的并集。最后使用、祖先权限和固定签名依赖不变，存储及作用域检查仍看根身份。

JIT/AOT 的同步函数以显式 Cranelift 栈位置实现 Local，按 storage_layout 对齐并初始化。
挂起函数的 Copy Local 在 IR 检查和模板删除后预留固定 CPS 槽区，每个声明至少占一个 u64 槽；
`frame_slots` 包含这段存储。地址来自稳定的帧 slots 分配，不能来自某次 poll 的机器栈。
循环重入复用该声明的存储，恢复后直接读写原位置，不重放初始化。
解释器激活帧独立拥有稳定分配，按声明目标槽缓存地址；循环重入只重新初始化，同一函数递归调用
各自拥有存储。词法借用先结束，底层存储可保留至函数返回；正常完成、失败或取消都随帧释放。
源程序允许挂起点之间的局部借用；CFG 活跃性和来源检查拒绝 Copy 局部引用跨挂起调用、parallel/race、
branch 注册或 scope join，包括作为挂起调用实参和藏在 Copy 聚合中的引用。完整存储树无引用的拥有对象引用
可跨挂起，继续使用这些稳定位置；容器内部引用另外按来源拒绝。
隐藏 place 和编译器写预留可跨挂起，实际借用仍遵守最后使用规则；因此赋值的右侧可以挂起，
不会因该变量曾被借用而改变合法性。解释器内部时间片暂停保活对应帧。
含局部引用的函数跳过解释器仅针对值的优化与槽压缩，后续优化需证明位置身份不变。
每个具体函数的被借用存储按各声明的 max(size, 1) + align - 1 求和，CPS 的 align 至少取 8，编译期上限为 64 KiB；
刚性泛型模板推迟到具体实例检查，不代表整个调用栈或进程内存限额。


### 拥有值引用与挂起

无引用拥有对象沿用稳定 Local/CPS 存储，不新增运行时 ABI。整个对象的引用可跨挂起，
异步形参需由函数体证明不返回、不保留其借用。借用效果固定点覆盖挂起函数、静态分支与动态子任务，
按源参数而非展开后的槽序号传播；动态/未知调用保持保守。隐式实参借用仍限同步调用。

Reference 的 interior 标记区分整个拥有对象与可重分配容器内部的元素/Slice。
Storage 的借用 intrinsic 设置标记，重借用、投影和 CFG 合流保留标记；模块固定点同时推导
返回引用是否可能指向内部存储，调用者再合并实参来源，泛型/递归 helper 无法抹去来源。
未知拥有型返回视图保守处理；普通宿主引用沿用既有 ABI 的存储契约。
语言挂起、parallel/race、branch 和 join 检查活跃引用，拒绝任何 interior 视图。

现有冲突与词法范围检查保持拥有者存活；动态分支将捕获借用登记到所属 region，join 才解除。
固定 CPS 位置、调用栈和清理链负责正常完成、失败、取消及重载后保活：先清理子调用，再清理父拥有者。
引用不获得额外清理责任，取消不会撤销已完成的字段修改；mem.replace 更新后的拥有字段仍恰好清理一次。
宿主 Array/Slice、Copy 局部引用、dyn 和引用存储规则不因这一能力放宽。


## 隐式任务 arena

Type::Reference 保存目标 Copy 类型与共享/独占权限；共享引用可进入 Copy 聚合，独占引用不可以。
Joky 含引用签名仍沿用内部调用约定；对外仅开放显式同步 C 借用输入，不进入旧宿主 ABI。
core::ir::memory 规划分配、共享化和字段/整对象读写，Type::memory_scalars 将对象字节布局映射到标量槽。
Bool 为一字节，Unit 不读写内存；字段的对象字节偏移与 IR 槽偏移保持分离。
公开/私有布局与标量位置查询在入口对完整类型图检查一次 dyn 禁止条件，递归布局不重复扫描子树；
函数签名、引用目标、buffer 元素及零大小类型的名义参数仍在检查范围内。
MemoryLayoutTarget 显式描述引用的指针大小/对齐，默认使用宿主指针布局；不据此声称 C 兼容。

core::ir::borrowing 对 CFG 做引用活跃性与来源/移动状态分析。调用结果按签名依赖引用输入；
独占结果只能别名独占输入或新对象。可能来源取并集，允许访问的祖先关系取交集，循环分配点保守合并；
分析有槽数、指令数和工作量预算，超限拒绝编译。写目标预留允许 RHS 只读访问，最终写入时检查独占权限。

来源分析逐个追踪聚合中的引用槽，包括未选枚举载荷的空来源、构造/复制/解构/返回和内存读写。
写入 arena 的借用独立于槽活跃性保留到任务结束；对象内容来源用于字段读取，不把读取视为新分配。
含引用对象共享化时撤销其构造期独占能力；跨函数的构造期独占签名拒绝，包括泛型实例。

core::ir::graph 在词法作用域内区分构造句柄与普通引用：只有组内 graph.alloc 建立的句柄可用作
连接端点和根；禁止普通观察、逃逸、嵌套构图及跨块跳转，组操作只出现在构图块顶层。
GraphOp::Link 更新组内内容来源而不提前发布共享借用；GraphOp::Seal 一次撤销全部句柄并保留组的共享借用。
借用检查完成后，专用操作才展开为现有 Reference/WriteMemory/Literal，三个后端复用原有 arena 内存实现。
构造句柄的新分配与不可观察性由前端保证，不能把普通引用送入这些操作；外部初始化引用仍走普通存储借用检查。
块中途失败沿用任务级清理，不需要按图遍历或逐节点引用计数，源码范围在展开时保留。

FunctionInfo::uses_arena 从实际分配沿普通调用和 Op::Scope 分支边传播，区别于仅有引用值的函数。
FunctionInfo::needs_arena 另传播隐藏任务上下文需求，涵盖分配与独立回收；仅回收不新增普通引用存储契约。
引用能力也沿这两类边传播，原生回调检查不能因嵌套 parallel 而丢失能力约束。
分配能力代表普通引用输入的存储契约：调用方保守保留普通引用实参，不使用逐参数函数体借用摘要。
数组拥有者及视图不可存储，不因分配能力而被任务期保留；其返回依赖仍接受签名检查。
不分配的只读 helper 仍可按结果最后使用结束借用。两种能力均可进入 @suspends 调用链及 parallel 分支；
宿主引用输入只对独立的同步 C 和异步借用 v1 开放。
Op::Scope 在父函数 CFG 中表示整个 fork/join，所有分支实参中的引用槽同时作为活跃性输入。
这也使较早的参数快照在后续参数求值/挂起期间保持借用，不能被冲突访问或移动。
borrowing 在该操作检查全部分支的访问后，再保留具有分配能力的分支输入；多个共享读取合法，
独占借用要求来源与其他分支不重叠。普通借用结束于整个 join，存储借用则保留到任务结束。
带引用签名（包括聚合中的引用）的函数只有内部入口。
原生同步内部函数在已有参数（含聚合结果指针）后增加隐藏 arena 指针；对外包装入口保持原签名，创建 arena、
调用主体后不论错误标志都执行清理。不使用 arena 的代码不增加参数或包装。__joky_arena_ 前缀保留。
解释器由 Execution 独占 arena，原始引用仅在受检内部槽中；分配函数和含引用操作的函数暂时跳过仅针对值的优化和槽压缩。
未选枚举载荷使用内部空引用占位，不能由语言代码构造可解引用的空引用；解释器读取前亦检查空指针。

原生 CPS 入口保持单个 CpsFrame 指针的 ABI，不经过同步 arena 包装。分配能力沿语言调用链传播，
有该能力的入口在分派恢复状态前通过 __joky_cps_arena 获取稳定 arena；首次创建、后续轮询复用。
父帧在创建子帧前已经持有 arena，子帧继承其 Rc<UnsafeCell<Arena>>，只对 arena 控制块计数，不对对象计数。
单线程顺序 poll 和分配 helper 的短期独占访问构成 UnsafeCell 契约；宿主借用 v1 可以保留受检对象地址，但不能获得 Arena 能力或保留帧/槽地址。
__joky_cps_finish 在成功或失败退出时同步释放子帧及当前帧的 arena 所有权，保留结果槽供调用方读取。
子帧完成时父帧仍持有 arena，因此返回引用不会失效；parallel 分支也共享根任务 arena，
分支或整个 join 完成都不回收分配或重置计费预算；根帧终止则立即回收全部对象。
Continuation 对非法 CPS 状态和错误通道失败同样收尾；丢弃 pending 帧通过所有权自动回收。
解释器的 Execution 在 Pending 保留 arena，在完成/失败时先释放活动帧再释放 arena；poll 预算让出不重放分配。
graph 块即使出现在挂起函数中，其内部表达式仍按同步效果检查，封存结果可以跨后续挂起使用。

runtime::arena 管理独立、对齐且不移动的分配，正常返回及失败统一释放，没有逐对象引用计数或 GC。
对象布局溢出、系统分配失败及默认 64 MiB 计费超限经错误通道传播，分配错误保留源码范围。
计费含管理条目但不承诺进程 RSS 上限；解释器帧和原生递归栈继续遵守既有约束。
尚未开放 arena 配置、显式 arena、独立对象回收或 arena 对象中的非 Copy 拥有字段。

## 数值数组与私有缓冲区

`joky/array.Array<T>` 是含私有 `Buffer<T>` 字段的非 Copy 名义记录，元素支持有明确布局的 Copy 数据（含零大小类型、普通共享引用及聚合）及无引用内容的拥有型记录。
拥有者和数组视图没有公开内存布局。拥有者可以进入拥有记录及泛型实参；视图不能存入聚合，两者均不能进入普通 alloc/graph 或宿主 ABI。
含这些类型的函数只能是内部同步函数；分配能力仍可传播给只接收普通结果的挂起调用者。

`core::imports::sources::SourceKind` 给受信任的源码定义分配权限，普通导入入口不能选择它。
仅 BufferStorage 定义将 Buffer/Element/Slice 别名和 `FnDef::buffer_intrinsic` / `buffer_element` 绑定到编译器身份；
仅 BufferLibrary 定义能导入私有存储模块。这些权限不从模块路径、文件名、用户属性或同名 extern 推导。
公开数组、元素及切片模块不重导出私有导入，规范化函数保留定义作用域。

`BufferOp::Move/Borrow/End` 表达拥有者转移、控制块视图及词法管理权结束；
`BufferOp::Extract` 消费整个源记录并转移单个字段；`BufferOp::Detach` 是记录解构的
字段分离：运行时转移与 Extract 相同（`__joky_cleanup_extract_field`），借用分析只
消费选定子树，剩余字段的责任保留到显式 `End`。Detach 先拒绝源的活跃/保留别名，
再为分离后的唯一拥有子树建立独立分析根，避免调用返回的保守共同来源造成兄弟拥有者冲突。
新根计入函数拥有存储，不能通过拆构返回局部视图；容器内容引用依赖迁移到新根，
普通引用槽保持原来源，不缩短 arena 保留借用。多个拥有字段尚在同一子树时仍整体保守；
`BufferOp::Storage` 携带按私有定义签名验证过的存储操作及具体元素类型；无值参数的布局原语也保留类型实参。CFG 检查追踪拥有者及其派生视图，
移动使源能力失效，局部拥有者来源不能经视图返回。allocate 与 slice/subslice 构造传播 uses_arena，
会失败的原语传播 may_fail；数组视图不可存储，分配不会将它们保留到根任务结束。
普通引用继续使用既有存储契约；另对含引用元素的可写数组输入（拥有者/独占视图）施加签名存储前置条件，
使不分配的 set 及其泛型/跨模块 wrapper 也不能保存栈借用。此规则不改变 uses_arena 的分配效果含义。

borrowing::State.contents 将缓冲区控制块身份与内容引用来源分开；参数内容有独立来源，调用点代入实际内容依赖。
store/initialize_next 保留元素借用，replace 合并源内容，get/pop 继承内容来源而非控制块视图借用。
拥有者移动/返回及可写参数调用传播内容；按整个数组保守合并，不按索引区分，也不因 pop/覆盖/结束而释放任务期借用。
含引用元素不会将数组独占视图归入普通对象的构造期封存规则；数组仍可在临时视图最后使用后继续修改。
7b.3 通过 BufferElement / BufferSlice 表示借用专用目标，`Element<T>`/`Slice<T>` 没有按值语义。
borrow/slice 复制原始缓冲区身份并延长父借用链，所有冲突仍按整个缓冲区判断；不采用独立版本号或区间拆分。
element.read / slices.get 复制元素内容来源，element.write / slices.set 保留任务期存储借用。
类型解析恢复视图中内联元素的名义布局，跨模块按声明身份解析，普通引用目标仍保持间接身份。
这些能力拒绝进入聚合、普通 Copy 泛型、alloc/graph、memory 原语、直接挂起和宿主边界。

`runtime::buffer::Buffer` 是 arena 内稳定的 data/len/capacity/element-layout 控制块，空数组也有独立计费控制块。
元素布局复用 MemoryLayout，载荷大小以受检 UInt64 转换、容量乘步长及 Layout 验证；
零大小元素不分配载荷，逻辑容量仍有上限。load/store 仅访问初始化前缀，
initialize_next 写入后才递增长度，truncate 只能缩短。replace 消费源拥有者，
更新目标原控制块并释放旧载荷与源控制块。7c.1 的 release 消费拥有者，释放当前载荷与头部。
两者从当前任务登记表移除分配项，按原 Layout 释放并退还预算；剩余登记项由根任务失败/取消/正常结束兜底清理。
登记查找当前是线性的，删除使用 swap_remove，不积累空记录；普通 arena 对象没有公开 free。
7c.4 起普通绑定退出、覆盖及被忽略的拥有者执行自动清理；7c.7 进一步清理数组中的拥有型元素。
元素借用复用受检 load 得到内部载荷地址，不分配。切片/子切片各分配一个 arena 计费的 Buffer 头部，
保存偏移后的 data、区间长度及原始元素布局，不拥有或复制载荷；头部随根任务统一回收。
7c.7 已开放整体移动的拥有型记录数组元素及嵌套数组；元素使用私有 storage_layout，泛型实例化重新验证所有权。
缓冲区持有元素 Drop 描述，按当前载荷地址清理；transfer 在成功分配后原子搬迁初始化前缀，take_last 转移末元素。
set/退出/失败逐元素回收，逆索引执行 Drop，并保留第一错误。拥有型 Option 使用相同清理描述；无引用拥有值可跨语言挂起，元素视图仍限同步。

二十五种源码原语保持独立签名身份，native lowering 另按 runtime_symbol 复用底层 helper ABI。
运行时不实现 push/pop 或扩容策略；这些算法及搬迁循环来自 `src/stdlib/array.jk`。

native lowering 通过私有 `__joky_buffer_` helper 检查分配和访问范围，检查错误后才解引用内部地址。
元素按 MemoryLayout 的标量偏移读写，不把填充字节当值；initialize_next 写完所有字段后才由 commit helper 发布长度。
解释器在降低时缓存布局，存储原语参数沿用 Unit 占位与聚合多槽位规则。
解释器同样使用这些控制块，Buffer 指令只在完成后推进 PC；它们跳过值优化及槽压缩，
内部时间片不重放分配、初始化或迁移。成功、错误、预算耗尽、取消和旧任务丢弃均通过根 arena 统一清理。
独立 AOT 测试实际链接新运行时并执行；公共数组例子还经过 CLI 的 JIT/解释器/native 验收。

## 泛型函数的编译边界

parser 为每个函数类型参数创建独立的 `Type::Parameter` 身份，`FnDef.type_params` 保存声明，
`Expr::Call.type_args` 保存显式实参（空列表表示推导）。手工构造 AST 的 Rust 调用方需要初始化这些新字段；
克隆保留参数身份，重新解析创建新身份。类型别名规范化时使用函数局部的临时参数环境，
参数可进入元组及枚举类型应用，但不写入宿主类型注册器。

`core::ir::generics` 管理一个只存在于编译期间的上下文。`ModulePlan` 先登记签名，
以刚性参数检查每个泛型模板，包括未使用者，再规划普通函数并迭代处理实例队列。
推导只读取类型提示；按实参源码顺序收集已有类型，再为未定参数尝试整数字面量默认类型，
实际求值与副作用仍由原调用规划执行。模板只具有 Copy 能力，不能依赖某次具体实例的运算或字段。

实例键是模板名和规范化类型实参，透明别名共享实例，名义类型保持区别。入队前先写缓存，
因此同型递归和互递归不会无限生成代码。每次编译中泛型实例与隐藏闭包入口共享 4096 个生成预算，
包括所用标准库实例；新实例依赖链最多 32 层。缓存命中不扣新额度，数量和深度超限分别诊断；
数量诊断包含已有实例、闭包入口及本次请求数。泛型和闭包规划复用同一预算检查。
实例化替换签名及函数体内全部类型注解、显式类型实参，重新建立具体元组 / 枚举布局，
再使用现有 `FunctionPlan` 检查并规划；共享类型图使用节点缓存避免指数展开。
模板计划被丢弃，最终计划只含具体函数，错误传播元数据在实例齐全后统一计算。

内部函数使用保留前缀 `__joky_generic_`。原生后端从计划而非原 AST 声明和生成函数，
实例使用 `Linkage::Local`；解释器把实例保存在内部 callee 列表。两者均从公开入口和签名查询中排除模板与实例，
宿主通过具体签名的普通包装函数调用。刚性参数不得进入 native / host ABI，
不新增字节码指令、运行时类型标签、C helper 或 CPS 帧协议。
编译上下文及模板 AST 不进入 continuation；具体代码沿用所属模块的保活机制。

## JSON 派生

`core::json_derive` 在根模块和源码依赖的导入绑定前消费 `#derive(ToJson, FromJson)`，
补入或复用标准库导入，直接构造普通 impl AST。派生名固定指向内置 JSON trait，
临时变量使用源码不可拼写的名字；所有生成表达式保留属性或原字段 Span，不添加伪源码位置。
消费过的属性不重复展开，模块再次规范化不增加 impl；其他属性仍由原校验器处理。

布局解析之后，`types::projections::json_derive` 按字段和现有 impl 条件反推类型参数约束，
保持名义身份、别名、Map 键能力及可表示的关联等式。推导使用独立的 256 次义务展开/32 层预算，
失败候选也计入共享工作量；
同型递归复用义务，持续类型增长受限。无条件派生分别检查自己的字段，不为嵌套普通 struct
重复展开整棵声明树。推导出的绑定只进入生成方法的 DefinitionScope，避免改变用户代码的方法查找。
条件 impl 的关联等式检查保留已登记的调用方刚性参数，不接受未登记的外来参数。

生成方法调用现有 Context 对象/字段 helper；正常的类型、借用、noescape、错误传播与 Drop
检查继续生效。ToJson 的 Copy 字段先复制到局部再借用，拥有字段直接借用；`FnDef.json_encode`
只标记这一编译期选择，在刚性检查和具体实例规划时按替换后的字段类型生成普通表达式。
相同泛型字段实例化为 Copy 或拥有型时不共享错误的访问方式。JIT、解释器与 AOT 共用这些计划，
没有新的运行时 codec 原语、反射表、字节码或 ABI。

## 参数化记录、枚举与布局

`RecordDef.type_params` / `EnumDef.type_params` 使用声明局部的刚性参数身份；未解析的类型应用用
`Type::Applied(Arc<TypeApplication>)` 保存，避免扩大每个 Type / Slot 的大小。
`Expr::Field.type_args` 仅用于 `Option.None::<Int32>` 等空载荷构造；手工构造 Field 的调用方需初始化该字段。
载荷构造复用 `Expr::Call.type_args`，投影和赋值拒绝显式类型实参。
`Expr::Record.type_args` 保存 `Pair::<Int64> { ... }` 的显式参数；手工构造 Record 表达式的调用方需初始化该字段。

`core::types::layout` 的声明依赖图按泛型声明的实际字段/载荷替换实参，遇到引用或拥有
Buffer 控制块便结束内联布局路径；不按 Array/Map 名字放行。无限内联环仍拒绝。
被擦除、未存储的泛型参数仍保留依赖检查，不能借 phantom 参数隐藏别名循环。
`core::types::indirect` 在引用及缓冲区元素边保存浅层名义身份；字段访问、泛型推导、
元素操作及清理描述符需要布局时，从模块名义表物化完整定义。缓冲区元素身份不保存拥有子图，
所有权及元素资格由完整定义单独检查，不能将身份的空标量表当作 Copy 元素布局。
元素图按有限身份图验证，非正规泛型展开仍受 256 实例/层限额约束。
物化缓存共享类型节点，不形成 Arc 拥有环，也不重复展开零大小类型 DAG。
浅层目标明确标记为 indirect，直接查询其对象布局报错，避免被误当成零大小对象。
持久实例准入另遍历物化后的完整存储与实参图；Ptr、callable、引用和视图不能隐藏在元素身份后通过准入。

记录及枚举模板以自身刚性参数建立符号布局，
未实例化的模板也验证字段 / 载荷类型、重复字段 / 变体和布局限制。
`core::types::specialization` 为函数、记录与枚举共用类型替换，按声明 ID 与规范化实参缓存实例。
具体实例保留原声明模板引用用于再次替换；相等性比较声明 ID 及实参，不依赖实例分配地址。
元组、记录与枚举参数的比较、替换、有效性及名义身份检查使用访问缓存，避免共享类型图指数展开。

规范化与 IR 规划使用独立的临时实例缓存，每阶段记录、枚举各上限 256；函数局部类型环境共享所属阶段缓存，
宿主注册器不保留它。65,536 槽 / 256 层限额包含实例字段和载荷，phantom 类型参数也参与嵌套深度限制。
记录 / 枚举构造以字段 / 载荷、显式实参及预期类型推导实例；泛型函数形参与具体实例按声明 ID 及类型参数统一。
两类构造共用先具体类型、后默认值的推导协议，字段提示按源码顺序传播局部绑定，不执行任何副作用。
函数定义检查期间符号载荷参数不需要机器常量，丢弃该计划；具体实例重新规划并初始化全部载荷槽。
字段偏移、标签、平铺载荷、AggregateCall、CPS 帧与失败协议保持不变，三后端无需泛型聚合专用指令。

记录解构规划位于 `core::ir::record_patterns`，与 `core::ir::patterns` 共享 `CheckedPattern`
树和字段可见性检查。静态检查顺序固定：头部名义解析（nominal 表、透明别名展开、
泛型实例化）→ 字段存在/可见/重复与完备性 → 嵌套形状 → Drop 展开拒绝。
`..` 只影响完备性检查；绑定名判重与元组模式一致。拥有值解构按模式书写顺序发布绑定，
拥有叶子经 `BufferOp::Detach` 转移清理责任，全部叶子发布后 `BufferOp::End` 释放忽略项，
清理顺序与该记录直接离开作用域一致；RHS 失败沿构造失败路径，无半初始化绑定可见。
借用解构在同步函数内经 `PatternProject` 链按存储字节偏移投影（`Projection::Pattern`
路径证明兄弟不相交），Copy 字段读快照、拥有字段保持 `&Field` 视图，不运行 Drop。
`suspends` 函数拒绝拥有记录与借用解构；Copy 记录解构走普通 CPS 帧。可见性检查经
`definition_scope.records` 判定同模块权限，诊断不列举不可见字段名。

## 固有成员与源码库

`Module.implementations` 保存 `ImplDef`、方法和关联常量；任意表达式接收者由装箱的 `Expr::MethodCall` 保存，
已有点分调用在 IR 阶段区分局部值、类型和宿主模块。类型规范化先检查具体 Copy 目标，
或按顺序完整应用 `ImplDef.type_params` 的名义记录 / 枚举目标；拒绝别名、特化及无约束目标。
`Self` / `self` 在解析时关联目标类型；泛型 Self 构造及命名空间保留目标名称与类型实参，不能拼成带尖括号的字符串名称。
AST 的手工构造者需初始化 implementations、traits 及 type_params，并遍历 MethodCall 的接收者。

`core::ir::members` 将方法登记为 `Type.method` 内部普通函数，所有签名先登记再检查全部函数体。
类型提示只负责静态查找，实际求值复用普通调用：接收者占首个实参，保持快照及从左到右求值。
`parallel` 复用相同解析过程。原生方法使用 Local linkage，解释器放入内部 callee 列表，公开入口不包含成员。
AST 保留 impl 参数与方法独立参数各自的列表和声明身份；类型规范化按两层作用域检查，禁止遮蔽 impl 参数或目标名称。
成员收集时按 impl、方法的顺序拼接内部模板参数，复用 `core::ir::generics` 的刚性检查、签名替换、完整实参缓存与队列限额。
方法查找按名义声明 ID 匹配，成员名称和可见性键使用不含类型实参的规范名称；完整目标约束使该查找不涉及特化选择。
实例接收者 / 显式绑定的类型命名空间提供 impl 实参，成员后的显式列表只绑定方法参数；未绑定命名空间的列表绑定两层参数。
成员调用先校验源码实参数量，受保护的内部调用可只提供 impl 前缀，剩余方法参数复用泛型函数推导；普通函数仍不接受部分显式实参。
方法元数据区分按值、共享及独占接收者；解析 &self / &mut self 为普通引用 Param，不新增 IR 或运行时 ABI。
实例查找对引用接收者解析一层目标类型；已有引用复用普通参数重借用，局部值的借用接收者降为受检的 & / &mut 表达式。
局部预扫描记录候选接收者根、内联字段路径及方法名，在绑定类型已知时查询实际成员种类，再决定是否建立稳定 Local 存储；
不能仅凭同名方法存在就给按值接收者分配地址。接收者先于显式实参求值，普通调用的快照、借用冲突及返回来源规则不变。
临时值借用、自定义解引用和通过 arena 引用取内联字段借用仍未开放；引用接收者本身可沿既有 CPS 调用和 parallel 路径使用。
链式调用的返回提示使用替换后的签名。模板按定义模块检查，实例中的具体类型身份按当前消费模块校验，
源码名称和私有成员查找仍固定在定义作用域，避免外部类型实参被误拒或调用者同名类型改变模板含义。
参数化聚合上的方法可从泛型函数调用，无约束参数本身仍不能获得猜测的方法能力。

`core::ir::constants` 迭代排序常量依赖并拒绝环，用共享 FunctionPlan 检查受限标量表达式，再计算其直线 IR。
模块常量与关联常量共用这张图：声明身份由 `ConstantOwner` 区分（模块路径或名义类型），
`ImportScope.constants` 把每个合法拼写映射到声明身份键，依赖边与求值结果均按键复用，
别名与菱形引用不重复展开。单个表达式限 256 个语法节点，依赖链限 32 层；
已计算常量只插入类型明确的字面量，不复制依赖子树。模块常量可引用 selector 导入与限定名，
解析发生在声明模块的导入作用域内。不会执行用户函数、宿主代码或产生 CPS 状态。
普通整数规则同样约束编译期算术，非法除法/移位在编译期报错；浮点在标准浮点环境 Guard 内
按目标精度折叠。泛型 impl 常量仍限固定整数 / Bool，检查时保留 impl 参数作用域，
但每个成员只求值一次，不按类型实参生成常量实例。

`core::imports` 在类型解析前绑定默认 prelude 和显式源码模块；`Module.scope` 保留不可变的 ImportScope。
`core::imports::sources` 按显式依赖顺序解析内嵌源码，检测缺失模块和依赖环。标准库缓存首次使用时初始化，
每个模块只解析一次；TypeRegistry 及其克隆共享已规范化 AST、导出绑定和声明身份。
`option.jk` / `result.jk` 定义普通枚举及状态判断、默认值、组合和载荷转换方法；它们按值、急切求值，不引入特殊短路或运行时指令。
Result 的 ok / err 返回标准 Option，依赖关系仅为 `result → option`；依赖类型及构造器不经 result 重导出。
`integer.jk` 显式导入 Option 及其构造器并定义整数成员。
`prelude.jk` 的选择性导入列出默认导出，整数成员通过其模块依赖提供。标准库模块自身不隐式导入 prelude。
内嵌标准库函数按生成代码中的依赖闭包展开，未使用的实现不会占用具体泛型实例额度。
受信任标准模块的 extern 依赖也按实际使用保留；仅提供 IO prelude 不要求嵌入宿主注册 stdout，
调用 `print`/`println` 时仍必须提供匹配的宿主绑定。用户源码中的 extern 继续按声明校验。
内嵌模块描述表规定是否重导出选中成员，以及无别名整模块导入的兼容简写。
构造器作用域按裸名称保存候选集合，多个枚举的同名成员不在声明或模块加载时互相覆盖。
公开导出集合只纳入公开枚举，定义作用域则包含私有枚举。类型限定名先按名义身份解析；
表达式中的裸名称或模块限定短名必须只有一个候选，选择性导入也要求唯一候选。
`match` 的无限定成员模式沿用被匹配枚举的上下文，限定名及重命名导入仍检查枚举身份。

用户源码声明默认私有，`pub` 控制导出，公开枚举同时导出构造器；记录字段默认私有，
`pub` 字段方可跨模块读取、写入与构造，`pub struct` 不连带公开字段；模块常量默认私有，
仅公开常量进入 `exports.constants`，私有常量不进入消费者的任何拼写表。
成员可见性由定义作用域与公开成员集合共同检查。

类型、构造器和函数别名保存原声明绑定；IR 在局部遮蔽检查后查询，解析器不再替换标识符 token。
依赖声明使用规范化模块名称；名称查找只接受当前作用域中的绑定，不把规范名当成额外导入。
库函数、方法和常量保留各自的 DefinitionScope，
包含定义模块的导入、名义类型和可见成员。用户模块的同名值、类型、函数或额外 impl 不会补入库的作用域。
函数特化保留定义作用域，库内函数与方法不成为 VM 或原生模块的公开入口。
依赖合并去重且与导入顺序无关；重复规范化不重复加载，也不会重新应用 prelude 开关。
注入时只克隆并重定位 AST 的诊断范围：显式依赖归属于 import，隐式 prelude 使用空范围，缓存不受影响。

宿主模块的函数别名映射到 registry 原名称；注入的 extern、CPS 完整帧大小、native symbol 和 owner 均保持原绑定。
宿主签名中的 opaque 类型按模块记录导出名，类型别名不改变 ABI。
VM 特殊调用先检查源码中的局部根，再转为用户无法拼写的内部调用名，避免用户的 `vm` 变量捕获另一个模块别名。
默认 prelude 可经 TypeRegistry、VmEngine、AotCompiler 和 CLI 关闭；VmEngine 的开关只作用于后续加载，
AotCompiler 只允许在编译开始前修改配置。

`core::imports::files` 为每次编译构建用户模块依赖图，与内嵌库共用绑定、规范化及依赖合并逻辑。
文件 provider 把模块路径映射到入口目录下的 .jk 文件；显式 ModuleSources provider 只访问调用方提供的快照。
两种 provider 都检测完整依赖环并限制 128 层深度；菱形依赖只解析一次。源码模块在自己的宿主声明环境中解析，
共享宿主绑定只合并一次，且不向调用方泄漏别名。用户源码的 Span 不重定位；编译错误附带所需 SourceMap，
JIT 模块和解释器 bytecode 持有共享源码快照，continuation 保留原版本。
原生失败通过新增的带 SourceId helper 传回文件身份，保留原有双偏移 helper 的 C ABI；
JIT 的同步与挂起错误附带源码映射，解释器另保留逐文件调用栈。AOT 的独立错误输出仍是消息与字节范围。
`VmEngine::type_registry` 提供只读声明快照，CLI 显式调用 `resolve_file`，
然后把同一 AST 交给 VM 或 AOT，避免二次解析丢失模块依赖。

方法、常量和受检转换不新增运行时指令、C ABI、帧表示或类型标签；失败、Pending、取消及旧代码保活均走既有调用协议。

## 静态 trait 与约束检查

`Module.traits` 保存方法签名、可选默认体及关联项集合，`TraitDef.self_parameter` 的刚性身份兼作 trait 身份；
`TypeParameter.bounds` 保存结构化 trait 路径、具名关联等式与位置。`ImportScope.traits` 将路径 / 别名绑定到同一声明身份，
`DefinitionScope` 保留 trait 和 impl 的定义环境，菱形依赖只追加一次声明。
trait 方法不会混入固有成员的可见性集合，避免间接暴露另一模块的私有固有方法。

`core::ir::traits` 在成员收集时绑定全部参数约束、检查实现完整性与签名、孤儿规则和重叠实现。
trait 要求产生仅供检查的泛型签名，以 Self 替换接收者及普通参数 / 返回值；这些签名没有运行时代码。
条件实现仍使用现有完整名义目标，证明过程递归检查 impl 参数约束，缓存重复义务并限制依赖深度和数量。
普通泛型调用在推导实参后检查约束；受约束固有常量在读取时检查目标类型实参。

刚性模板规划时，点调用将所选 trait 身份按源码 Span 记录到成员表。具体实例重新规划时复用此选择，
再按目标类型挑选实现，防止实例类型的同名固有方法或其他 trait 改变模板语义。
`Trait.method::<Self>(...)` 可显式指定能力与 Self，实参推导和检查复用现有泛型调用流程。
借用局部变量的预扫描使用同样的选择，避免同名借用方法让按值调用误生成 Local 存储。

抽象要求保守标记为可能失败、可能分配 / 保留引用；无方法体，故不被普通方法效果初始化覆盖。
所有未使用模板仍参与存储效果和借用检查。具体实例直接调用实际 impl 方法，固定点分析计算真实效果，
继续区分 `uses_arena`（分配 / 普通引用存储契约）与 `needs_arena`（包含释放的隐藏 task context）。
抽象要求随模板从最终模块移除；后端仅看见普通调用，无新增操作码、ABI、vtable 或运行时类型标记。

`TraitMethod.body: Option<Expr>` 区分要求与空默认体，名称、签名和体保留原位置。
收集时为所有方法保留保守的抽象签名，默认体另生成刚性 Self 模板；全部模板先检查，再规划具体函数。
最终方法表覆盖优先，缺项取默认，仍缺必需项则拒绝。默认实例保留 trait 作用域，覆盖体保留 impl 作用域。
泛型实例沿用普通入口缓存和数量限额，方法相互调用不递归复制 AST。noescape 仍按参数位置继承。

`core::types::projections` 在别名与布局之前建立本次编译的声明、impl 头和参数定义环境。
投影绑定身份为 `(基础类型, trait Self 参数 ID, 关联项序号)`，显示路径和 span 不参与类型等价。
源码中的具名等式保持 Type 结构，按定义作用域绑定；同一 trait 的导入别名不能产生不同约束身份。
布局依赖发现包含投影目标，并丢弃发现期间产生的浅布局实例，避免前向关联类型留下零槽占位。
类型替换、别名展开和泛型推导使用同一规范化入口；投影不反向推导基础类型。
普通 trait 证明也使用此环境，条件 impl 的关联等式不会被成员选择或空泛型函数绕过。
声明和 impl AST 由同一次编译的环境以 Rc 共享，切换导入作用域不深拷贝方法体。
参数表同样共享；dyn 资格检查添加临时 Self 参数时通过写时复制隔离，不修改其他作用域的参数身份。

求解请求共享活动栈、不同义务集合及结果缓存，包含投影基础类型的规范化和进入的别名展开。
根深度为 0，深度超过 32 或第 257 个不同义务报 ResourceLimit；缓存保留依赖高度，命中也检查当前深度。
别名实例缓存进入请求时重放展开，避免遗漏依赖验证。
关联环报告活动链，错误不缓存；环境和缓存不跨编译、失败加载或模块快照共享。
刚性投影保留为 TypeProjection，模板布局占位不提供具体 Copy、无引用或可挂起保证；
实例按实际类型复核，未确定的投影不能进入原生布局或宿主 ABI。这些静态 trait 实例由三后端生成普通静态调用。

借用型 dyn 使用 `DynInterface` 描述规范化身份和声明顺序的方法槽，关联绑定仍走同一求解环境。
`DynTable` 以本次编译产物内的具体 Self 与接口身份复用，保存最终默认/覆盖实例的有序入口。
整张表的入口均纳入 native 可达性闭包；AOT 使用只读数据和函数地址重定位，不写入编译进程地址。
共享计划在发布前核对表、具体接收者与完整 FunctionSignature；方法入口统一使用隐藏 arena/task context，
借用权限与 noescape 采用声明契约，调用保守地允许失败和分配。

视图的内部槽顺序为 `(data, table)`。ReferenceType 的内部 lanes 让参数展开、局部复制、
分支合流和帧保存占两个槽；lanes 缓存不参与语义类型身份。数据槽仍是带 dyn 接口和共享/独占权限的引用类型，表槽没有对象来源。
DynErasure 保存原引用、目标和 Span；Reference 重借用在擦除与调用处保留完整 origins、字段路径、
loans、ancestors、invalid 和 storage。加载槽入口后，数据接收者仍作为显式借用实参共同检查别名冲突。
显式 `&*view` / `&mut *view` 复制两分量并建立相应权限的 Reference 贷款；共享方法通过
独占视图调用时采用共享权限，允许其余实参中的合法共享重借用。dyn 分支合流后建立统一贷款身份，
保留所有入边来源，不改变来源路径的冲突规则或全局祖先交集规则。
关联绑定只描述接口签名，不能作为视图存储拥有缓冲区的证据；挂起函数内的同步局部视图
仍由活跃性与来源分析限制；无引用拥有对象可跨挂起借用，元素/Slice 视图须在语言挂起边界前结束。
默认体内部继续静态调用具体 Self 的最终方法；接口返回的 Copy/拥有/聚合值使用普通调用约定和清理。
视图与方法表没有原对象的 Drop 或所有权入口，方法失败仍保留首错并执行原有清理。

同步 helper 需要不逃逸证明；语言挂起和并发边界继续拒绝活跃 dyn，不依赖来源是否在 arena。
解释器时间片暂停保留帧、稳定底层存储、受检表和整个模块；旧任务由原快照继续执行。
公共 dyn 字节布局、extern、持久存储与宿主 ABI 仍拒绝；内部双槽承载不提供稳定 C ABI。
组合、资源限额与代码保活的三后端证据见[验收记录](borrowed-dyn-trait.md)。

## 出站信箱与候选发布

信箱注册在执行器的 Domains 中，以进程内单调且不复用的 token 查找 Weak<Mailbox>；
语言侧 Mailbox 是唯一关闭所有者，复制 Handle 不延长打开状态。连接作用域负责持有/取消
接收任务与 TCP 写出资源，信箱自身不持有 socket、Script 模块或业务对象。

Batch 拥有有界字节副本与至多 256 条暂存记录，附加到单候选、双候选的首候选或多域 Proposal。
队列环形存储在 create 时预分配，批次的目标临时表在 batch 时预分配。提交准备阶段验证全部
根凭据，并为重复目标累计容量需求；只在全部满足后进入根替换、消息移动和回执赋值区间。
该区间不分配、不调用用户代码、不挂起；唤醒和退役根清理在回执确定后执行。所有结构与字节
按执行器的共享状态预算计费，批次和消息各自携带计费所有者，移动到队列不重复计费。

暂存失败会污染整个批次，防止调用方忽略错误后提交消息前缀。满队列不等待、不自动重试；
跨队列任一失败不产生部分投递。接收等待只注册一个 waker，由独占 Mailbox 借用约束并发接收；
stop 在帧清理时撤销等待。完成接收先分配 MessageOwner 再出队，再复制到任务的 Array<UInt8>，
避免把运行时存储或模块所有权交给业务。消息纯数据化允许 Script 卸载后继续写出。

私有域操作分发追加 Outbox 编号 43–53；字节数组边界检查 Array<UInt8> 名义包装和单 Buffer
布局。原生返回数组使用参数之后的聚合结果槽，解释器返回同一拥有指针；公开 CPS 帧 ABI 不变。
API、拒绝结果与在途取消边界见[语言参考](language.md#提交式出站信箱-jokyoutbox)。

## 加载与代码所有权

`VmEngine` 保存当前不可变模块、宿主注册和类型环境。只有解析、类型检查、宿主校验和编译
全部成功后才发布替换产物并递增版本；失败保留旧入口与签名。
`ModuleId` 是同一 VM 内的加载版本，不是全局唯一编号。
公共 `function_signature` 返回副本；内部调用检查借用元数据，避免每次解释调用复制参数列表。

JIT 模块拥有导出入口、元数据、可执行内存及外部代码依赖；最后一个 owner 释放时先回收
生成代码，再释放依赖。Continuation 持有创建时的模块，重载、替换宿主注册或销毁 VM
不会使旧调用失效。编译上下文、AST 不进入 continuation。

上述保证是旧代码及布局保活，不是跨版本状态迁移。重载本身不改变既有域的代码绑定；
宿主显式发布后，结构兼容的域才切换到当前模块，见[状态域核心](#状态域核心)。
语言侧 `joky/vm.call_async_int32` 已提供 HR2 标量桥接：Call 由 CPS host_context/stop 唯一拥有，
包含 continuation、关闭控制与调用帧的外部存储计费。它在当前任务的执行器上下文中推进，
传递子流程的 wake/deadline，不递归 poll 执行器；等待期间不持有 VmEngine 借用。
子 continuation 固定代码、参数和返回类型，在清理完成后才交付 Int32；父帧取消时一并释放。

`joky/script.call<A, R>` 复用上述 Call 生命周期，支持标量及最多 64 个标量字段的平面记录。
编译器生成同步 schema/pack/unpack helper：稳定契约编码忽略每次编译的名义 ID，保留
记录名称、字段顺序、名称、可见性、repr(C) 和标量类型；两端完整匹配后才创建子 continuation。
调用者拥有私有 Packet（包装 `Buffer<UInt64>`），逐槽复制输入与结果；String 契约与包都由
普通 CPS 清理链负责。挂起时只保留该包的独占借用，不暴露业务记录地址或域根引用。
包容量固定为 64 槽且纳入 arena 配额，临时复制也受此上限约束。Unit/空记录允许零数据槽，
不混淆普通参数的 Unit 占位槽与返回槽。原生后端从已完成帧的结果区取值，解释器保留根聚合
结果的标量副本；子流程停止后调用者才解包。私有原生操作分发新增 ScriptCall（编号 42），
沿用已有 CPS ABI 和执行器入口，不改变公开帧布局。

句柄首次异步调用或发布绑定域注册表的 Weak 身份，禁止跨执行器复用。会话只保存模块与调用
控制块的 Weak 索引，不额外保活旧代码；发布时暂时升级仍存活的模块，先按模块归属过滤域，
再应用 HR0 整批兼容检查，避免改变其他脚本或 AOT 宿主的同名状态。关闭先移除公开句柄，
再标记调用失效并唤醒；不会在重入的子流程栈上强行析构 continuation。生命周期、限制与
入口能力见[热更新开发计划](aot-script-hot-reload.md#62-hr2-类型化入口已实现)。

一个 `AotCompiler` 只接受一次编译尝试。编译失败后禁止继续追加或输出对象。
registry 的固定 symbol 及显式 C 导入不受导出前缀影响；普通源码定义和旧 extern 可通过 prefix 隔离原生符号。
AOT 允许只有 symbol 的绑定，由系统链接器解析；VM 加载缺失 native entry 的绑定会失败。

模块注册先验证重复路径、名称、固定 symbol、direct/CPS 一致性、入口及完整帧大小，
成功后一起发布元数据、opaque 类型和 native 实现。签名声明不能覆盖既有 registry ABI。
VM 只收集源码 extern 依赖，导入内置模块时 resolver 会注入该模块的全部声明。
解释器只为实际使用的导入要求适配器；这不等于任意 ABI 都能执行。

## 持久实例根

P1–P3 实例由 `VmEngine` 的独立注册表拥有；ID 包含 VM 身份和不复用的单调序号。
每个根持有完整名义类型、稳定存储和不可变 LoadedModule 快照。根在模块依赖之前释放，
模块重载不会改变旧根布局或函数解析；清理不依赖 VM 当前模块。

共享 IR 在普通 ABI 的引用入口隐藏之前，单独标记合格实例入口：源码顶层同步函数、
无引用记录构造，或首参具有推导或显式契约证明的不逃逸同型根引用。引用目标补全为实际类型描述，
准入遍历名义实参、零大小字段和 Buffer 元素；String、无引用 Array、嵌套记录/枚举/元组、
Drop、Map、StringBuilder 和注册的 Resource 可持久化；任何引用/视图/Ptr/函数/opaque 仍拒绝。
Map 的五个私有 Array（buckets、keys、values、hashes、positions）和 StringBuilder 的
私有 Array<UInt8> 均是编译器描述的普通拥有字段，无额外隐藏堆分配。Map 活元素的 key/value
递归清理描述随各自 Buffer 保留，rehash 仅替换索引 Array；删除、替换和 clear 的失败状态
沿用 Buffer 的已初始化/failed_store 协议。清理失败时仍释放其他容器与递归子拥有者。
既有借用检查必须通过，不导出裸接收者地址，也不改变普通 `internal` 和 C/VM 导出规则。

JIT/AOT 使用私有三指针桥：输入位槽、输出位槽、调用者管理的 arena。桥调用真实寄存器
ABI 的函数体，需要 arena 时传入第三参数，普通公开入口仍使用原有包装。
解释器的实例调用借入同一调用 arena，在成功取出结果或失败清理后归还，不能自行释放
仍属于根的分配。根按 `storage_scalars` 写入稳定的 compiler-private 布局；纯值布局不变。
混合拥有记录接收根地址，透明单拥有字段包装接收控制块地址，遵守原有借用表示。

根清理描述复用构造 IR 的专门化 Drop hooks、拥有偏移及枚举 guards，绑定相应模块的
原生地址或解释器回调；不保留构造调用的局部快照。每个 Buffer 的元素描述随控制块保留。
原生拥有返回在局部清理全部成功前保留清理责任，局部 Drop 失败必须释放待返回值。

调用入口预检/预留后将除根对象外的持久分配登记迁入调用 arena。出口通过根拥有偏移和
Buffer 元素描述迭代遍历最终拥有图，只选控制块、载荷和递归子拥有分配，校验登记与重复项。
转移先验证源登记、目标配额并预留 Vec，再执行不分配、不回调、不挂起的提交；地址不变。
清理责任始终属于根描述，迁移不执行 Drop。出口留下的普通 arena 分配当次销毁，
不会保留整个调用 arena，也不深复制拥有载荷。测试故障点覆盖预检、预留前与提交前。
当前登记扫描/转移成本 O(k·n + k²)，不承诺恒定逐帧成本；性能优化留待测量。

注册表查找只短期借用 map，执行用户代码时持有单实例独占状态借用；同实例重入返回 Busy 错误。
执行中 close 从注册表移除 ID，活跃调用保活根至出口并拒绝发布结果。
入口预检失败不修改状态；方法执行、局部析构或出口失败先在调用 arena 清理根，再释放
剩余临时存储，保留首错及 Failed 身份。构造失败不发布 ID。根 Drop 失败继续释放字段；
VM 析构继续清理其他实例，独立 `InstanceCleanupReport` 可以在 VM 销毁后报告首个清理错误。

长期额度计费根存储、固定实例/根描述项、Buffer 元素描述项及持有的 arena 分配。调用额度只增加已有拥有
分配之外的额外 arena 余量；共享峰值额度计算所有实例与活跃实例调用的合计，同一登记
迁移不重复计费。释放立即退还共享 arena 计费；持久计费在成功出口更新。
默认额度见 [Rust 嵌入持久实例](language.md#rust-嵌入持久实例)。这些逻辑额度不等于 RSS，
不包含 Rust 容器预留容量、解释器局部栈、代码、诊断和其他普通 VM 任务；普通任务规则不变。

## 状态域核心

SC1/SC2 当前实现位于 `vm::state_domains`，与实例注册表、实例任务组分开。共享 IR 为
符合实例调用 ABI 的入口附加 `domain_entry` 证明：根必须是非泛型、非闭包的普通记录，
字段允许标量、String 及标准库 `Array<标量>`，不允许用户 Drop；接收者引用通过已有
不逃逸检查。同步操作的 IR 白名单按直接调用图求不动点，允许受检存储操作与标量临时
分配，外部宿主、间接调用、任务及清理 hook 均不能传递进入操作。
源码不能用注解自行宣称这个证明；未知或新增 IR 操作默认不获得资格。

根拥有独立 arena、精确名义类型和当前代码的 LoadedModule 快照。复用既有三指针实例桥及布局初始化，
不复用公开 InstanceId；方法从域当前绑定的模块解析。句柄包含 VM 注册表身份、不复用
序号和只读/可写能力；没有裸指针，也不保活根。

`publish_domain_code` 是唯一改变域代码绑定的入口。记录名义 id 每次加载重新分配，
跨版本按结构判断兼容：同名，字段名、可见性、标量槽偏移逐一相同且类型递归兼容。
先校验全部存活且健康的域，任一同名记录结构变化则整体拒绝；随后只替换模块、名义类型
并递增该域的代码版本号，根存储、修订号与身份不变，旧模块在释放注册表借用后丢弃。
代码版本余量在整批预检中确认，任一耗尽则整体拒绝，不允许回绕。
调用方用自身签名编码输入和解码结果：源码读写与 request 在准入时检查调用方签名与域当前代码兼容；
请求根记录自身运行的模块，供其内部 `domain.read/write` 做同样检查。单域排队登记保存提交时的
代码版本号，执行时版本变化则重新解析并核对签名，不兼容只让该调用失败，不隔离状态。
pair 登记、候选写域等路径仍有同模块约束。pair/access 排队时捕获全部参与域的代码版本，
执行前先校验版本与模块，任一变化以 InvalidCall 拒绝，不暴露根地址、不隔离状态。
完整晚绑定仍待 HR6，当前规则见[热更新计划 HR0](aot-script-hot-reload.md#34-hr0-版本校验)。Owner 与 Request 只持注册表 Weak 引用，
VM 销毁后不会延迟根释放。关闭责任唯一，重复关闭幂等。

请求登记保存独立标量位槽，首槽在排队期间为零。出队后才解析根地址，同步执行结束即清零；
状态引用不进入结果，结果只允许标量。正常写操作在入口检查修订号余量，成功返回后推进；
只读失败保留根，写失败释放根并保留 Failed 身份，同时终结该域尚未执行的申请。
宿主 API 检查失败和修订耗尽不执行操作体。运行时失败没有回滚保证。

FIFO 队列、活跃及已完成未领取的请求共用有限登记数和逻辑字节额度。取消与 Request Drop
物理移除队列项；已完成结果不被迟到取消或关闭覆盖。领取或丢弃结果才退还登记额度。
状态额度计费根 arena，固定域项由数量上限约束；请求额度计费固定 Request 项、方法名及输入位槽。
这些不是 RSS 上限，不计编译元数据、Rust 容器预留、解释器局部栈和诊断展开。

域操作使用私有零槽 continuation 与 TaskEnvironment 进入同一个 HostExecutor 就绪队列，
没有第二个轮询器，也不修改 CPS 帧 ABI。短操作完成写入结果后才唤醒发起根；内部 turn
不进入用户 completion 列表，但消耗同一任务数和 poll 配额。注册表弱引用绑定执行器，
域或结果存活时拒绝更换执行器；等待 token 验证执行器身份并限制每个请求只有一个等待根。

每个关联请求在首次 poll 前登记唯一域所有者，同时拥有独立 fail-fast 组、CPS 根和 arena。
TaskEnvironment 在 resume/dispose 期间安装动态域上下文，不持有状态引用。普通根失败只
取消自身结构化后代；写 turn 失败才隔离状态并取消域内其他请求。访问上下文绑定正在执行的
continuation 根身份；宿主嵌套运行的其他根不能继承权限，即使它们来自同一模块。嵌套返回
或展开时恢复外层身份，dispose 阶段禁止提交新工作。注册表不在调用 stop
或取消执行器任务时保持借用，关闭重入不会造成 RefCell 冲突。Closing 先拒绝准入，再取消
排队项及关联组；group.running 归零且执行器不再持有根后才移除状态并报告 Closed。
VM 销毁先禁止新的域工作并执行同一关闭协议。

源码 `domain.read/write` 由可信库身份绑定为编译器 intrinsic，只接受命名同步操作。
共享 IR 在 noescape 和效果不动点之后检查 domain_entry；排队捕获只含操作身份和独立
标量输入，不含可逃逸接收者或通用闭包。文本 CPS 适配器在帧中唯一拥有 DomainRequest，
通过 host_stop 取消或丢弃结果；终态先清除 stop/context 再释放，避免重复取消。适配器在准入前
再次验证返回类型及读写模式，私有入口也不能绕过状态类型、权限和效果检查。
源码 Owner 是不可复制的托管资源，释放回调执行同一关闭协议；读写句柄以不复用 token
表达能力，低位区分权限，不保存根地址。注册表归执行器所有，HostExecutor 的副本共享
同一内部状态；注册表到执行器、Owner 到注册表均为弱引用。普通 block_on 和独立 AOT
阻塞驱动也推进同一内部队列，并合并其定时器。

源码 request 为独立根保留一个有界回执，取消等待帧会撤销该根；清理根及其 arena 后
才发布成功、失败、取消或关闭结果。回执与短操作共享请求数量和逻辑字节额度。
解释器根的执行限制传递给子请求及短操作，动态代码所有者与限制在嵌套返回时恢复。
JIT/解释器从活根取得不可变模块快照；独立 AOT 使用编译器发出的只读模块描述表 v2，
以重定位保存名称、标量输入输出及平面拥有记录签名、记录名义身份、受检实例桥和 CPS 入口及完整帧大小。
描述表是编译器内部 ABI，不接受源码整数伪造；原生调用者必须让代码和表存活到根及其
关联请求全部清理。解码只重建元数据，不重新编译操作或引入另一执行器。

源码标量捕获使用受信任 IR 编解码，覆盖所有整数宽度、浮点、Bool、Rune 与 Unit。
泛型模板先检查形状，每个具体实例必须通过标量资格检查。Unit 无载荷，但保留实参求值。
请求桥升级为私有 `__joky_domain_poll_v2`：四个参数槽后放置 `(Int32, UInt64)` 结果槽，
分别保存状态码和完整载荷，不新增结果分配，不改公共 CPS 帧布局。旧 v1 对象须重新编译，
不能把旧四槽调用交给新桥。拥有根扩展另将模块描述表升级为 v2，不能混用旧 v1 描述对象。
解释器按同一结果槽复制两项值；Bool 挂起根也以 0/1 编码。额度、访问、域失败与普通请求失败
由结构化错误码分类，不解析诊断文本；域终态在请求清理完成时决定，发布后保持不变。

标量投影快照复用同一 FIFO 短操作队列；成功结果同时记录执行时修订，收取时不重读修订，
避免把旧值与新版本配对。调用者收取后将标量位、执行器/域身份和修订封装进受信任资源，
不保留根地址、状态 arena 或模块所有权。资源用 ExternalCharge 与 Buffer 清理接线计入调用
任务预算；排队取消、结果交接失败或部分分配失败均归还各自额度。版本检查只读取注册表元数据，
不授予访问权限。私有 v2 桥追加快照操作编号，既有编号和帧布局不变。

平面拥有候选由受检构造器在独立 Arena 中产生，保留原域身份、修订、名义类型及 LoadedModule。
构造不借用活根；新旧 arena 共享注册表状态预算，保留各自的预算所有权。源码适配器消费
完整 Snapshot，私有资源保存候选；回执 Buffer 与外部资源记录均在准入前分配。

短操作与提交共用 Request 注册表、受理序号和执行器 trampoline，Work 区分两种载荷。
候选移入已预留请求后才进入队列；关闭、取消或准入失败销毁候选。最终校验后，发布区间只
移动根、写入新修订和已预留回执终态，随后释放旧 arena 并唤醒等待者。提交不执行用户代码。
完成回执仍占请求额度，wait 不收走记录；回执析构才移除记录，未发布时同时取消队列任务。
取消或关闭只改变待定请求，不能把已发布的 Committed 改写为 Cancelled 或 Closed。
私有 v2 桥追加候选与回执操作，既有操作编号和帧布局不变。

HR1 状态资格展开完整存储图，包括 Buffer 后面的名义定义、泛型实参与零大小字段；
允许嵌套记录、元组、非拥有枚举及 Array/Map 的拥有元素，排除引用、资源、指针、闭包、
用户 Drop、拥有枚举与递归图。展开有深度和节点数上限，空容器也不能隐藏不合格类型。
入口证明允许受检文本、Buffer 和标量临时 alloc，直接调用链仍排除宿主、挂起、间接调用及
清理 hook。私有 AOT v2 描述递归编码 Buffer 元素和类型实参，追加元组/非拥有枚举标签；
缓存键包含名义身份及完整实参编码，解码重建拥有槽、枚举标签与聚合布局。
兼容发布递归比较 Buffer、元组和枚举结构；解释器枚举全部 instance 入口，包含 internal
拥有类型入口，确保与 JIT 一致。多域访问与联合快照仍限标量根，不隐式复制拥有图。

`state_domains::storage::Root` 统一创建与候选的存储路径。构造直接使用独立 arena，返回后用
`Buffer::owning_allocations` 找到完整根图；受信任的 `Arena::retain_allocations` 无分配地回收
图外已结束清理的临时存储，不把整个计算过程的分配留下。短操作在该根 arena 中同步执行，
写成功后重新筛选图；只读调用提前保存活分配集合，失败也能无分配地回收临时数据并保留根。
写失败仍隔离域并清理整根。此机制不允许状态持有借用，因此图外临时地址不能成为长期状态。
根的拥有槽描述计入状态预算；容器元素的清理描述递归释放子拥有者，不运行用户代码，
因此代码发布后旧容器的释放不依赖旧模块回调。
发布只移动已准备的 arena 包，载荷地址及预算所有者保持不变，无需在发布时逐项迁移。

提交有效期使用独立的 `CommitDeadline` 资源，保存执行器注册表身份与 `Instant`，不持有
执行器、域或根；候选包仅复制这两个值。资源计入任务预算，包内凭据不另行分配。
私有 v2 桥追加 DeadlineAfter/CommitBefore 操作，既有编号及公共帧布局不变。
执行器即将处理有期限提交时重新读取自己的 Clock，不复用 poll 开始的定时器扫描时间。
时钟属于宿主回调，调用时不借用域注册表；返回后重新读取请求终态、域状态、权限、到期和
修订，再进入无用户回调的发布区间。这样时钟重入引发的关闭或取消也能阻止发布。
到期不登记定时器，不抢占计算；只有受理的提交在调度时确定 Expired，回执终态仍保持不变。

[服务端并发计划](server-concurrency.md#119-sc2-范围验收)。

SC3 的联合短操作复用同一个 Request/受理序号及 executor trampoline，Work::Pair 保存
2–64 个受检句柄、模式签名、标量位槽与固定模块快照。双读别名共用同一域依赖，可写别名拒绝；
关闭或写失败通过请求的完整参与集合查找待定工作，不再只检查主域。没有单独的每域队列、
跨等待持有的许可或第二个调度器；当前所有短操作在同一线程的 FIFO 中同步执行。

联合快照复用 Work::Pair 的同步执行区间：调用投影前捕获完整 ReadSet，投影与版本读取
之间保持注册表借用。成功后保存到 Request.observed_reads；收取结果只转交凭据，不重新采样。
ReadSet 内联保存首域和一个可选依赖，更多依赖由带预算凭据的不可变 Rc 尾部保存，重复身份
归一化。身份序号不可复用；凭据记录句柄、修订与代码版本，先验证整个集合的身份和生命周期，
再检查数据与代码版本，任一变化返回 Conflict。单域操作也在执行区间内保存完整凭据，领取
结果时不重新采样。HR0 已覆盖只读依赖代码发布导致旧候选失效；未来 schema 迁移还需验证
schema 身份。代码凭据尾部按扩展后的 Version 大小计费，排队访问的版本数组计入请求预算。
SnapshotOwner 与 CandidateOwner 携带整个集合，候选发布前验证全部依赖。
Request::touches 同时匹配候选中的只读依赖，使关闭和
失败能取消完整申请；已完成回执保持不变。联合快照新增私有 SnapshotPair 操作，公共 CPS
帧与 AOT 模块描述版本不变；解释器将其返回值按受管资源接收。

共享 IR 证明所有状态引用不逃逸、入口同步无宿主调用、各根都为无用户 Drop 的普通标量
记录，并复用三指针类型化实例桥。持久实例 receiver 资格不扩展为多引用入口；解释器只为
已获得 domain_entry 的多域签名额外接受该桥。AOT 模块描述 v2 已能表达这些引用签名；
私有 v2 调用桥追加 Pair 操作，其帧包含五个参数槽、结果仍使用 frame.result，既有 Request
的四参数加双结果槽布局不变。

执行时先预检所有域及修订余量，再填入根地址并调用；同步调用完毕清零地址槽。只有标量根
能参与，所以调用 arena 不会成为长期根的拥有存储，也不会发生跨根 arena 的拥有值交换。
调用 arena 与域根共享状态预算，返回或失败时独立释放。失败隔离全部可写参与域，随后在
注册表借用之外取消相关 executor 作业与请求组；只读域不隔离。后续拥有图访问必须另行
解决完整存储归属，不能直接放宽此处的标量资格。

双候选包 Bundle 保存同一联合快照派生的两个 Candidate。扩展时消费首候选，从其完整
ReadSet 中解析第二域的身份和修订，再构造独立根；不从外部接受第二份版本凭据。私有
CandidatePairOwner 管理整包的唯一释放责任，受管 ABI 与解释器资源返回路径一同注册。
Work::CommitPair 复用单一 FIFO 请求和回执，双候选包独立存储，配额包含 Request、
包存储及资源记录的大小。

双候选提交先验证两个写能力，在最终时钟回调返回后重新检查终态和全体候选。执行阶段先
计算两个新修订，随后仅移动根拥有权和写入修订，记录两份修订及 Committed，再回收旧根。
任何预检失败在首个替换之前返回；时钟调用在注册表借用外，重入关闭第二个域同样能终止
整包。Request::touches 覆盖全部候选依赖，finish 一次释放整包；已完成回执不被后续关闭
覆盖。新增私有操作沿用 CPS 调用桥 v2 与 AOT 模块描述 v2，不改变公共帧布局。

一般集合通过 AccessSetOwner、SnapshotSetOwner、CandidateSetOwner 保持唯一拥有责任。
Work::SnapshotSet 在单次注册表借用内捕获完整 ReadSet，并把标量根复制到独立 arena；
SnapshotSet 持有每个副本的模块、类型和源句柄身份。命名投影仅访问冻结副本，检查其源模块
身份后使用原 LoadedModule 执行，因此 AOT 重解码模块或域关闭不会改变已捕获的值。
复制中途失败释放已完成副本，既不修改活根，也不交付残缺快照。

候选集合消费整份快照或旧包，所有 Candidate 共享不可变的完整 ReadSet 尾部。写目标须属于
读取集合且互异；不存在删除依赖、分拆包或合并独立快照的公开接口。动态向量容量固定有界，
向量和复制根计入共享状态预算；元数据使用直接持有 Rc<Budget> 的 RAII 计费凭据，不能从
临时 arena 取出 ExternalCharge 后提前销毁 arena。排队及发布临时向量另计入请求字节配额。

Work::CommitSet 一次准入、一份受理序号；Request::touches 覆盖未写入的只读成员。
最终时钟回调在注册表借用之外，返回后重新检查终态和完整读取集合。先预留全部新修订、
旧根列表与回执向量，并验证所有候选，之后仅移动根、写修订和记录 Committed，无分配、
用户回调或挂起。完整回执发布后才释放旧根。取消/关闭/失败通过 finish 清理整个候选集合；
成功回执保存各写域的源身份与新修订，不依赖活域继续存在。新增私有操作及资源接收路径
同时接入解释器与原生桥，公共 CPS 帧和 AOT 模块描述版本不变。

SC4-A 准入池复用 Domains 的执行器归属和状态字节预算，公开入口位于 `joky/admission`。
注册表只保存逻辑 token 到 Weak<Pool> 的映射；唯一 PoolOwner 持有关闭责任，句柄是受检
Copy token。Owner 销毁或 close 删除映射并关闭池，域注册表关闭时同样关闭全部池。
Permit 和尚未结束的等待上下文持有 Rc<Pool>，因此关闭后归还名额无需访问已销毁的注册表。
池、等待队列和上下文的计费凭据直接持有共享 Budget，不借用创建任务的 arena。

创建池时预先检查整数运算、计费并分配全部等待槽；队列长度包含已预留未交付的申请，
始终不超过 max_waiters。申请只保存当前 TaskWaker 与单调等待 ID；Pending 清除 frame.wake，
沿用执行器通知机制，不新建执行器任务。许可释放先将最早 Pending 标为 Granted 并计入
in_use，再唤醒；新申请不能越过预留。等待的 stop 按确切 ID 移除记录，若记录为 Granted，
归还名额后继续 FIFO 提升。相同根的多个动态分支可共享唤醒器，但拥有不同等待 ID。

交付时将预留的释放责任移动到 Permit，再经已有受管资源收养路径转入任务 arena；任一
收养阶段失败都析构 Permit 并归还名额。关闭将队列内全部记录置为 Closed，撤回尚未交付
的预留，唤醒等待者；已交付许可只在自身释放时递减 in_use。stop 在语言拥有者清理之前
撤销挂起上下文，重复关闭或完成后的清理不能重复归还。唤醒只登记就绪，不执行用户回调。
新增私有 Admission 操作追加到既有 v2 调用桥，三后端共享同一池实现，公共 CPS 帧及 AOT
模块描述版本不变；类型系统只允许复制申请 token，禁止伪造或复制池、许可及其私有存储。

## Godot G0–G2 适配边界

`integrations/godot` 是独立 GDExtension crate，固定 Godot 4.7 API；核心编译器和
运行时不依赖 Godot。适配器注册语言、Script 资源、资源加载/保存器和 ScriptInstance，
在普通 Node 上解释执行 Joky。`State`、`create`、生命周期回调及属性函数组是扩展约定，
不是新增语言关键字。
适配器从 `instance_function_signature` 取得受检元数据，不能伪造实例入口或根引用。

脚本资源通过键保留主线程局部注册表中的不可变 Program 快照（解释器 VM、源码、方法元数据），脚本实例持有
该快照和独立 InstanceId。实例只保存 owner 的 Godot 身份；不以强引用拥有 Node。
删除节点/移除脚本关闭 ID；扩展退出先关闭尚存会话，再移除资源加载/保存器并注销语言。
编辑器只编译并建立 Godot 原生无根占位实例，不运行用户构造、属性默认函数或生命周期回调。
加载和执行限主线程；后台扫描可查询无 VM 状态的元数据，资源在后台销毁时仅排队释放键。

资源 reload 为后续实例编译新快照；旧实例绑定旧快照，失败 reload 不改变它们。
G1 属性由字面量 `default_NAME()` 和受检 `get_NAME`/`set_NAME` 函数组成。getter 只许直接
读取 State 标量字段，避免 Godot 的共享属性查询触发用户引擎回调；setter 使用独占实例入口。
后台与编辑器查询只访问复制的静态元数据，默认值不执行用户代码。构造后先通过 setter 应用默认值，
再由引擎应用场景覆盖，最后执行 `_ready`；PackedScene 保存脚本路径与导出属性当前值，
其余运行状态不序列化。属性访问不暴露字段偏移；属性名与实际节点的引擎属性冲突时拒绝创建实例。

`godot/node` 是适配器提供的固定源码模块。Node 为私有 token 的 Copy 记录，Program 的有界
登记表将其解析为引擎身份；token 不复用，不保活节点，并拒绝跨快照、失效或排队删除的身份。
构造、调用与清理用栈式主线程上下文绑定 owner。释放宿主表借用后才进入引擎调用；可回调引擎的
实例入口持有 gdext 的可重入基类守卫，同实例重入交由核心 Busy 拒绝，其他实例可正常调用。
文本输入只借用到宿主返回，名称结果受检复制进任务 arena，不保留引擎字符串指针。

`_process`/`_physics_process` 同步接收 Float64 帧时间，不隐式创建任务。向量是 Joky 普通
记录，经精确标量 C ABI 和逐分量转换进入 Godot `real`，禁止重解释布局；有限性、引擎范围与
Node2D 类型全部验证后才写入位置。失败实例及排队删除节点跳过后续帧回调，避免重复诊断。
标量 Variant 转换必须验证类型与范围，不能静默截断整数。当前不提供保状态热迁移或扩展库动态重载。
G2 的 `task_` 函数是无 State 接收者的标量输入、Unit 结果异步根。同步方法内的启动请求
先排入 Session，再在 State 借用归还后登记，实际执行由语言 frame 驱动同一 Program 的执行器。
每个 Program 每帧最多推进 64 根；每根切片 10,000 条指令，无生命周期指令上限，
同步 State 访问仍保留 100,000 条指令限额。任务身份经核心可恢复 TLS 映射到 Weak Session，
绑定节点及 Bridge；资源 reload 不改写旧映射，推进中移除脚本的映射保留到延迟清理结束。
驱动前检查排队删除，退出树通知永久停止该挂载任务，
State 直到正常销毁才关闭。错误上报可能重入语言元数据，frame 释放 gdext 可变对象借用后再驱动。

帧/物理步/信号的 Callable 只拥有就绪标记与 TaskWaker，不保留 Joky 指针或 State 借用，
不在信号发射栈中执行脚本。等待请求直接通过 CPS 标量参数槽传入，不为每次等待分配任务 arena 内存；
宿主回调复用已有 BorrowingHostV1 的 poll/stop 协议，
Pending 仅保留引擎身份、连接及有界信号描述符。stop 同步断开所有连接、停止并排队删除
内部 Timer 子节点；部分启动失败、race 输家与实例取消共用此清理。游戏 Timer 为 PAUSABLE，
真实 Timer 为 ALWAYS 并忽略时间缩放。等待源退出树时只发出失败就绪，后续推进报告错误。

构建、约束与真实引擎测试入口见[适配器说明](../integrations/godot/README.md)。

## 宿主与字符串 ABI

Rust 嵌入示例：[examples/embedding.rs](../examples/embedding.rs)。宿主注册入口均为 unsafe：

| 方法 | 生命周期与布局要求 |
| --- | --- |
| `register_c_fn` | 同步 C 接口，合计 0–4 个引用/Ptr 输入、整数/Ptr/Unit 结果；真实布局、引用权限及外部指针契约由注册者保证，可传代码 owner |
| `register_borrowing_suspending_fn` | 异步借用 v1，1–4 个 C 兼容引用输入、整数/Unit 结果；强制 poll/stop，stop 同步停止访问并清理操作状态，可传代码 owner |
| `register_fn` | 非文本标量 C ABI 必须匹配完整 FunctionSignature，所有调用期间有效 |
| `register_text_fn` / `register_owned_text_fn` | TextViewV2；String / 同步 &String 输入使用 JokyText 借用描述符，返回在适配器退出前校验并复制；owned 版本保活代码 |
| `register_text_suspending_fn` / `register_owned_text_suspending_fn` | TextViewV2 CPS；拥有输入移入帧清理，描述符保活到终止；owned 版本接受完整 frame_slots 与代码 owner |
| `register_suspending_fn` | 静态 CPS 回调，只分配参数槽；进度放在 state/host_data |
| `register_aot_suspending_fn` | 提供该入口的完整 frame_slots 和保活代码依赖的 owner |

声明校验无法证明裸指针真实类型；宿主不得向生成代码 unwind、保留借用帧指针或调整 slots 大小。
同名自定义注册只影响后续编译；内置绑定名会被拒绝，避免注册成功但永远不生效。
旧宿主签名中的合法命名类型自动登记；AOT 可显式注册 opaque 类型。注册入口、类型名和 CPS 帧大小
会在修改宿主表前完成校验。
默认已有 `vm.Handle` 和 `vm.Function`，未声明为记录/枚举/别名且未登记为 opaque 的类型在 IR 阶段拒绝；
别名指向未知类型时在别名解析阶段拒绝。宿主注册仍使用实际类型，源码别名不属于注册 API。

同步 C 导入是独立 ABI 种类，不能与旧 direct/CPS 注册互换。共享 core::ir 验证 unsafe 调用和
参数边界，原有借用数据流仍检查别名与生命周期；native lowering 与解释器都传入真实稳定对象地址，
不把 u64 标量槽数组当作 C 记录。记录显式标记 #repr(C)，字段只含定宽整数、Float32 / Float64
与兼容嵌套记录；浮点字段与 C 编译器的 size、alignment 及 offset 逐项核对。
extern 值传递的浮点标量按目标平台浮点寄存器调用约定直传，混合标量签名同样如此；
宿主适配层的每个入口都按精确签名分发，禁止把浮点函数地址强转成整数函数调用。
窄整数的跨边界寄存器值统一提升为 I32 符号值：序言窄化、返回与调用点显式扩展/截断，
C 侧窄参数与窄返回函数按平台规则取低位或扩展，与该约定完全兼容；CPS 槽位仍为零扩展位模式。
`ffi::c_header` 输出本机目标的 C11 布局断言；注册名只负责匹配源码类型，不能替代对外部布局的验证。
返回不携带借用，C 不能保留借用地址或转移其所有权，也不能把引用实参的地址作为 Ptr 返回。
不透明 Ptr 是独立的可空 Copy 标量，使用目标指针宽度与对齐，C 参数/结果和头文件映射为 void *。
解释器保留独立 Ptr 值标签，允许空值，不使用 Reference 的非空检查；判空在共享 IR 中降低为与空指针的比较。
普通聚合、arena 存储和 CPS 帧可保存 Ptr 值，但复制或跨挂起不会保活外部对象，也不会触发资源释放。
代码 owner 继续保活注册入口；外部对象及其所属库的实际寿命由绑定/调用方保证。
旧 direct/CPS 外部注册不接受 Ptr；资源拥有包装未开放，异步借用 v1 也不赋予 Ptr 所有权。

语言 String 是非 Copy 的 UInt8 Buffer 拥有叶，私有布局为目标指针宽度的控制块句柄。
字面量 `Op::Text` 从可重定位 UTF-8 字节常量受检复制，clone 分配独立载荷；全部语言载荷计入
任务 arena。查询算法写在 `stdlib/string.jk`；可信源码身份绑定的私有 freeze_utf8 与公开消费式 into_bytes
仅转移缓冲区，公开 bytes 借用只读 Slice。普通用户定义或同名函数不能取得冻结能力；
from_utf8 必须先经 Joky 源码严格验证，才调用私有冻结桥。into_bytes 消费唯一文本拥有者，
后续数组修改不会改变仍存活的 String；重新冻结必须再次验证。UTF-8 验证与字符遍历共用
同一源码解码器，四类整数格式化和 substring/concat 也由 Joky 实现，不增加后端专属算法。
拥有清理复用 Buffer cleanup group；String 内容不可写，整体替换遵循独占借用。
String 可作为数组元素和聚合中的拥有叶，私有存储布局沿用目标指针宽度，公开 memory_layout
及 C 布局并未开放。递归元素清理描述符按拥有槽释放 String/Builder/嵌套容器，枚举仅运行
活动变体的 Drop；扩容搬迁转移清理责任，不执行元素 Drop。元素或其 bytes 视图依赖整个容器。
join/split 也由 Joky 源码实现：join 先受检累加总字节数再构造，split 保留空项并复制每项；
预算失败、运行时错误和取消沿同一清理路径回收部分输出，不增加后端专属文本操作。
默认 prelude 带入 String 方法，可信文本函数按调用需要规划，未使用的方法不会消耗泛型
实例或令纯标量 AOT 对象依赖 runtime。原生编译仅发出可达的内部库函数，用户定义仍完整检查。

单独 String 可跨语言 Pending，参数在首次轮询前移交到子帧清理责任，未轮询的 race 败方也能
清理拥有实参。恢复不重放构造或描述符初始化；子帧先结束，父清理和 arena 后结束。
String 与整个无引用拥有对象的引用可跨普通语言挂起；无引用元素的 Array 已接入 CPS
及 parallel/race 的拥有者转移和清理，无引用拥有记录、枚举、元组和容器也使用该路径。
容器内部元素/Slice 视图及含引用元素的 Array 仍限同步。
拥有型局部与 Drop 临时数据保存在 CPS 帧的固定区域，动态分支在登记前复制其清理数据，
避免父帧循环复用存储覆盖未轮询捕获。拥有型返回值仅在局部析构全部成功后交出，析构失败则清理返回值。
代码 owner 保活旧代码，文本自身载荷独立于模块常量；两种责任分别处理。

StringBuilder 是 `stdlib/string.jk` 中的名义拥有记录，唯一私有字段为 Array<UInt8>。
布局、借用和清理复用数组及单拥有字段包装规则，不增加运行时文本类型或新的宿主 ABI。
Rune 编码和文本追加由 Joky 方法完成；追加 Rune 先为完整编码预留容量，然后发布已初始化字节。
clear 保留容量，reserve 沿 Array 的受检增长与新旧存储峰值计费。finish 消费包装字段，
通过可信 freeze_utf8 的 Buffer Move 转移同一控制块及载荷，不复制文本、不重新编码或收缩容量。
仅可信库可调用冻结原语，普通用户不能取得可写文本载荷。Builder 拥有值与整个对象引用
可跨语言挂起；解释器内部时间片、预算失败和取消沿现有帧清理处理部分初始化存储。

显式文本视图宿主接口使用 `TextViewV2`：`JokyText { const uint8_t *data; uint64_t byte_length; }`。
String / 同步 &String 输入均传描述符指针；前者转移语言所有权并在调用结束时清理，后者只借用。
同步描述符在调用期间保活；CPS 描述符位于宿主帧，输入拥有者保活到完成或取消。
描述符直接引用原载荷，不分配或复制输入文本；原生同步描述符位于栈上，解释器及 CPS 的
描述符元数据随调用/帧释放，与既有帧元数据同生命周期，不占任务 arena 的文本载荷预算。
CPS 每个 String 参数仍占一个逻辑槽，槽中传描述符地址；逐槽转换不使用固定宽度掩码，
Unit 占位及第 64 个之后的参数位置保持不变。宿主不得调整 slots 或描述符存储。
宿主 String 返回值也是借用描述符地址，必须有效至运行时完成校验和复制；不转移外部分配的
释放责任；动态外部结果使用下述独立 TextFfiV1 适配。错误通道在解引用结果之前检查；长度受 64 MiB 上限约束，
空文本允许 data=null，非空必须有有效载荷，UTF-8 必须合法，内部 NUL 不截断。
普通 register_fn / CPS 注册拒绝文本签名。unsafe 注册者负责真实原型、指针对齐、有效范围、
生命周期及不 unwind；ABI 元数据无法证明指针有效。

同步 C 文本适配使用独立 `TextFfiV1` 注册元数据；源码仍写普通 `extern fn`，不放宽
`extern "C"` 的结构布局检查。`VmEngine::register_text_ffi_fn` 接收签名、复制的
`TextFfiHostV1` 与可选代码 owner；AOT 同名方法只保存签名，链接
`__joky_text_ffi_v1_<配置前缀><函数名>` 常量描述符。`text_ffi_header_v1()` 只生成适配器
描述符声明，真实 C 原型仍由包装函数明确调用。JIT/解释器保留已编译版本的描述符和 owner，
AOT 对象仅包含符号重定位，不含编译进程地址。链接时的参数数目、结果种类、版本与 flags
在运行时重新检查，错误不得进入 C 回调或把整数结果当作 String 句柄。

首版接受 0–4 个 `String` / 同步 `&String` 输入，返回 String、整数或 Unit；不接受混合数值
输入、Rune、引用结果、可写文本或挂起声明。`flags=0` 表示同步访问；不能通过 flags 请求
异步保留。整数输出取 `scalar` 的相应低位；真实 C 长度参数先通过 `input_limits` 检查，
例如 C int 长度设置 INT_MAX，size_t 长度设置目标 SIZE_MAX，包装函数才进行显式转换。

| 适配种类 | 调用范围与资源责任 |
| --- | --- |
| SPAN 输入 | `JokyText` 直接借用原 UTF-8 字节，允许内部 NUL；输入拥有者持续保活到输出复制完成 |
| C_STRING 输入 | 先拒绝内部 NUL，再分配追加终止符的临时字节；描述符长度不包含终止符 |
| SPAN 输出 | 按明确长度检查上限、NULL 与 UTF-8；NULL/0 是合法空文本 |
| C_STRING 输出 | `byte_length` 是含终止符的可读上界，受 `output_limit` 限制；逐字节扫描至首个 NUL，无终止符则失败；NULL/0 不能表示 C 空串 |
| BUFFER 输出 | 提供已清零的受控临时缓冲区与容量；只使用返回长度，忽略 output.data；检查容量与 UTF-8 后复制 |
| SCALAR 输出 | 不建立文本输出，只读取整数位或忽略 Unit 结果 |

回调输出预先清零；非空 `release_token` 无条件移交一次释放责任，即使状态非零或原生错误
通道已记录失败也必须释放。对应 release 函数由描述符提供，只接收该凭据、不依赖 data/length，
所以报错后的载荷无需解引用。返回的借用数据可引用输入或临时缓冲区，但不得引用已结束的
回调栈变量；拥有结果在复制成功、校验失败和语言分配失败后均释放一次。release 不得失败、
unwind、重入访问语言值或操作错误通道。顺序是调用、接管释放责任、检查错误、校验并复制、
释放外部结果、释放临时存储、清理消费式 String 参数。所有后端共用同一个运行时实现。

临时 NUL 输入与 BUFFER 输出计入任务 arena 的 64 MiB 总预算，调用结束立即退还；复制出的
String 与临时存储的同时存活峰值也计费。外部分配由外部 API 负责，读取及复制长度受注册上限
约束。超限为 ResourceLimit，内部 NUL 为 InteriorNul，非法输出 UTF-8 为 InvalidUtf8，
非零宿主状态为 HostError；原生错误通道已有首错时保留该错误。ABI 校验不能证明外部指针
有效或阻止任意 C 越界写；真实原型、可读范围、分配器与同步有效期属于 unsafe 注册契约。
公开 C 布局见 [joky_text_ffi.h](../include/joky_text_ffi.h)。

旧长度前缀 ABI、JokyString、五个旧 `joky_string_*` 查询和旧 require 错误入口已删除，无兼容别名。
VM 的文本 C 入口改名为 `joky_vm_load_source_v2`、`joky_vm_reload_source_v2`、
`joky_vm_call_int32_0_v2` / `1_v2` / `2_v2`，接受 `const JokyText *`；
语言 VM 函数注册的 `joky_vm_register_int32_0_v2` / `1_v2` / `2_v2` 也使用同一名称描述符。
create/close/error 接口不变。
这是一次明确的宿主源码和二进制迁移；旧对象与新版 runtime 不混用。C 示例见
[vm_runtime.c](../examples/vm_runtime.c)。

新文本根出口使用 `__joky_user_text_v2_<配置前缀><函数名>`，不会复用旧视图返回符号。
`CompiledFunction::abi`、`function_entry_abi()` 和 AOT `text_exports_v2()` 标明 EntryAbi::OwnedTextV2；
`text_header_v2()` 根据实际导出签名生成原型。同步入口将 String 输入展开为 data/UInt64 length，
输出使用状态码加输出参数；String 输出为 JokyOwnedTextV2。仅标量/独立文本签名公开，聚合文本
签名沿内部约定调用。新头文件与 runtime archive 配套使用，不承诺混用不同版本的生成对象。

根输出受检复制到独立宿主缓冲区，输入反向复制到任务 arena。Rust `call_string_0/1` 返回
Rust String，`call_async_string_0/1` 返回 StringContinuation；完成后 take_result 只提取一次。
原生 CPS 根在帧结束前 capture，失败清理丢弃已复制结果；子调用仍返回任务内部拥有句柄。
C 使用不透明 JokyCpsFrame、`joky_cps_set_text_input_v2` 和 `joky_cps_take_text_result_v2`；
raw numeric result 不暴露文本句柄。结果初始化为零，失败保持零；成功的非空缓冲区由
`joky_string_result_free_v2` 配对释放并清零。空串结果允许 data=NULL、byte_length=0。
释放 frame 或 VM 后已提取的宿主文本仍有效；清理失败、失败任务和取消任务不能发布结果。
诊断通道复制借用 require 消息，不依赖语言 arena 的后续分配；消息构造先失败则为 ResourceLimit。
更多约束见 [VM 头文件](../include/joky_vm.h) 和 [CPS 头文件](../include/joky_cps.h)。

标准 VM 句柄来自不复用的全局递增编号，但只在创建线程可用。
执行前保留 Rc、释放句柄映射借用，允许嵌套创建/调用其他 VM；正在执行的 VM 不可重载。
错误状态、返回码及完整内置接口见 [语言与内置模块](language.md#内置标准库-jokyvm)。
JIT/AOT Joky 函数可注册为 native entry，目标 VM 可以是 JIT 或解释器；解释器函数本身没有原生地址。

异步借用 v1 使用 `FunctionInfo::borrowing_host` 标记受检的引用 extern，不增加 `uses_arena` 分配能力。
共享 IR 重用 C 所指类型的布局检查，调用及 parallel/race 沿用既有借用来源和冲突检查。
JIT/AOT 导入版本化 `BorrowingHostV1` 数据描述符并生成私有 CPS 包装函数，所有调用形态均进入
`joky_cps_poll_borrowing_v1`。帧在首次 poll 之前登记 stop，终态用 Completed/Failed 收尾，
release/Drop 用 Cancelled 收尾；取走清理入口后才调用，保证失败或重复释放不重复 stop。
`CpsFrame::Drop` 覆盖直接 drop 和 C frame_free，HostPending::Drop 在 binding owner 销毁前显式收尾。
停止回调先于对象存储及代码 owner 释放，错误通道使用独立 checked 边界保留原始失败。
描述符错误版本/缺少回调在注册时和运行时都拒绝；同步停止的真实行为仍是 unsafe 宿主契约。

## Continuation 与调度

CLI 接受同步或挂起 main（无参数，Unit/Int32 结果）。JIT/解释器调用 `prepare_async` 后将
continuation 交给 `runtime::driver::block_on`；AOT 的 C 驱动按 `cps_frame_slots` 分配
完整根帧，调用 `joky_cps_block_on`，检查状态及原生错误通道后才读取结果，最后释放帧。

`joky/task` 的 yield/timer 唤醒元数据由等待中的 CPS 帧拥有。驱动只扫描存活帧，选择立即
可运行状态或最早单调时钟截止时间；取消分支随帧删除元数据，没有全局定时器注册或后台线程。
解释器还单独标记指令时间片让出，不能把所有 Pending 当作立即就绪。没有支持的唤醒来源时
阻塞驱动器报错并清理任务；HostExecutor 保持安静 Pending，等待外部线程安全令牌通知。
Mio Reactor 已接入同一就绪队列；阻塞驱动会等待 I/O、最早截止时间或外部令牌，
在附加内核唤醒入口后复查队列，避免登记与入睡之间丢失通知。


原生 CPS 入口为 `unsafe extern "C" fn(*mut CpsFrame) -> i32`：0 完成、1 Pending、其他值失败。
生成入口完成时还设置 `DONE`；普通 native 子回调按返回状态完成即可。
Int32 / UInt32 使用槽低 32 位，Int64 / UInt64 使用完整 64 位，Bool 使用低 8 位。
UInt32 写入 CPS 槽时零扩展；有符号与无符号类型不因 ABI 位宽相同而互换。嵌套调用及 parallel 使用运行时管理的子帧。
AOT CPS 导入必须传入 `cps_frame_slots` 的完整布局；跨对象编译使用 `compile_with_import_layouts`。

`ContinuationStatus` 区分 Pending、Completed、Failed。终态不能再次 resume，
`cps_result` 只在成功完成后可读。原生错误保留 CPS status，解释器可保留结构化错误及调用轨迹；
`call_async` 首次轮询遇到宿主失败时统一返回 HostError。
生成代码的除零失败在两个 VM 模式均返回带源码范围的 `RuntimeError`，恢复时为 `ResumeError::Failed`。
`call_async` 接受 Int32 参数及 Int32/Unit 结果；`call_async_int64` 接受 Int64 参数及 Int64/Unit 结果。
后者的 `cps_result()` 保存完整原始位，调用者用 `as i64` 解读。同步宽整数入口为 `call_int64_0/1/2`。
无符号入口为 `call_uint32_0/1/2`、`call_uint64_0/1/2`、`call_async_uint32` 和 `call_async_uint64`。
异步入口允许同型整数或 Unit 结果，UInt32 的 `cps_result()` 零扩展为 u64，UInt64 保留全部位。
这些入口均精确检查签名，不能混用位宽或符号；CLI main 与内置 C VM 标量入口保持 Int32 契约。

`Scheduler` 是手动驱动的单线程协作调度器：闭包按入队顺序执行，continuation 按单调 TaskId
顺序轮询。ID 仅属于创建它的调度器。`take_completed`、`take_failed`、`cancel` 删除记录；
终态在收取前计入 task_count，只有 Pending 计入 suspended_count。resume_all 遇首个错误返回。
真实 I/O 就绪和再次轮询的时机由嵌入方提供。解释器预算见
[Resource limits](interpreter.md#resource-limits)。

### 非阻塞执行器与实例任务

`runtime::executor` 在现有 Continuation 之上管理根任务；静态/动态子任务的调度、失败和取消
仍由原有 CPS/解释器任务树负责。首次执行可由 `prepare_async` 推迟到驱动器建立上下文后；
混合标量输入按精确类型检查，Unit 保留既有参数占位槽。AOT 的 `from_native` 是显式 unsafe ABI 边界。

执行器采用 FIFO 就绪队列和去重集合。每次 poll 取有限快照，Immediate 任务排到下一轮；
定时器只在截止时间到达后入队，外部等待无事件时不轮询。根首次失败关闭其组并取消兄弟根。
TaskId 进程内单调且不复用；线程安全 TaskWaker 持有原子有效位、通知计数和队列 Weak，不能访问帧。
解释器宿主等待记录上次轮询时的通知计数；若通知到达后恢复的是兄弟分支的时间片，
该等待仍保持就绪，直到对应回调重新轮询。时间片续跑和定时器入队不增加外部通知计数，
避免挂起分支相互制造空转。观察记录只持 Weak，不使未知等待被误判为有外部唤醒来源。
撤销令牌和删除排队项按同一队列锁排序，防止取消与跨线程唤醒竞争留下死任务记录。
登记项在终态移除；活根额度包含 stop 尚未结束的根，借助最后释放的计数租约退还。
VM 的 TaskId → InstanceId 归属记录保留到整批终态消费结束，期间的重入清理不能按执行器
登记项是否存在提前裁剪。任务恢复一旦失败便标记所属实例 Failed，拒绝同批后续回调访问；
State 仍须等待取消与 stop 完成后再清理。
组绑定一个执行器；组关闭不可再启动任务。轮询及 stop 不持任务注册表的 RefCell 借用。

可嵌套恢复的线程局部上下文提供时钟和唤醒令牌，`sleep_ms` 在该上下文读取时钟，手动/CLI
驱动继续使用系统单调时钟。截止时间随等待帧存在，执行器仅缓存各根的最早截止时间。
根轮询额度不能限制单次 native 执行耗时，也不能限制根内部本轮遍历的子任务数量。

通用外部资源以 `Type::Resource` 表示，类型由宿主显式登记，非 Copy 且没有源级构造器。
私有 Buffer 控制块仅承担拥有者登记和 arena/State 迁移，资源本身由唯一 token 与释放回调持有；
不含伪造的容器字段。控制块释放先调用资源回收函数，再退还自身配额。
同步 ResourceFactoryV1 的所有非空输出立即进入 RAII 守卫，回调失败、空成功及 arena
接管失败都不会丢失释放责任。编译模块同时保留描述符和回调代码拥有者。
普通 C/标量 ABI 不接受资源，只有签名完全匹配的登记工厂可返回该拥有叶。
ResourceFactoryCpsV1 为异步工厂提供独立描述符：Pending 的资源留在操作 context，
非空输出先由守卫接管，终止时先 stop 再释放或采用；成功采用和调用者清理登记之间
没有解释器预算切点。ResourceEvent 身份全进程不复用、耗尽报错，release 前先失效。

ResourceIoV1 在编译时绑定精确的资源接收者与读/写签名，普通宿主借用 v1 的布局规则不变。
资源引用只指向稳定控制块，可跨语言 Pending；普通容器视图仍同步使用，资源视图不能
逃逸到存储。borrow checker 保留重叠访问、移动和结构化子任务的权限检查，运行时以独占
lease 补充检查；stop 在释放请求存储和 lease 前撤销外部访问。
ByteRequest 使用最多 1 MiB 的宿主快照，不向平台公开 Buffer 布局；读完成后才生成语言
Array，写消费输入数组并复制快照。ExternalCharge 与 arena 分配共享任务及实例峰值预算，
复制结果时计入两个副本，退款采用稳定计费句柄，避免保存可移动解释器 arena 的地址。
公开嵌入描述符见 `include/joky_resource.h`。TCP 公共模块通过内部受检查适配器
交付资源/Array 及独立错误输出，再由语言包装为 Result；不放宽普通宿主聚合 ABI。
内部 UInt64 输出存储只能作为精确 TCP 调用实参跨该调用存活，noescape 与同步 stop 保证
父存储清理之前结束访问。资源的单字段包装链沿用稳定控制块借用，不授予普通容器视图权限。
连接与接受结果立即进入 RAII 资源守卫，所有失败路径保留唯一释放责任。
TCP 所有者、source 的 Rc 存储、请求与字节快照计入任务/实例峰值；
内核 socket 缓冲和 Mio 平台内部存储不计入语言载荷。Reactor 另持有 socket 准入计数，
默认每执行器最多 4096 个；bind/connect/accept 在系统调用前预留，Pending 请求持有许可，
成功发布时随 socket 原子转入连接/监听器拥有存储；失败/取消退还，最后拥有者关闭后退还。
空闲连接和监听器也计数，不依赖是否存在 I/O 登记。许可保活创建时的 Reactor，
已有 I/O 的 source 仍不得迁移执行器。
write_all 在 Joky 库层保留原数组与发送偏移，按实际写入长度推进最多 16 KiB 的分块，
块间显式 yield；保持发送输入的拥有转移。同步 helper 接收并归还原数组拥有者，
原数组、分块、宿主快照及 CPS 临时拥有存储都计入现有峰值预算。

TcpStream.split 消费完整连接，TcpReader/TcpWriter 的控制块分别持有独占 lease，
共享一个 Rc Connection，其中只有一个 Mio source、socket 许可、地址快照、方向关闭状态与计费守卫。
共享存储只计一次，直到最后一个端释放。成功的方向 shutdown 幂等；关闭方向后保留地址，
读返回 EOF、写返回 NotConnected。端的 close/Drop 只结束本方向，操作 stop 仅撤销该次等待。
两个受检私有 split 原语沿用单资源发布 ABI：第一步发布 reader，原 StreamOwner 转为
持有未发布 writer 的中间状态；第二步发布 writer 并清空原拥有者。两次调用之间的指令预算切断、
取消和任意分配失败始终保留释放责任，不改变公共 CPS 帧或宿主资源 ABI。

BufferedTcp 与 BufferedTcpReader 在库层拥有相同的 ReceiveBuffer，包含接收数组、偏移、
capacity 与 Open/EOF/失败状态。同步 ReadProgress 统一处理原始读取、读满与分隔符的消费边界，
两个具体端分别驱动底层 I/O；行解码与长度头处理共用 helper，不增加运行时 ABI。
BufferedTcp.split 经同步 helper 拆构，再跨挂起保活整个缓存并接收两个方向拥有者；
缓存随读端移动，既不重新分配也不重置状态。读端 shutdown 不丢弃已有缓存或错误。
消息发送先验证完整载荷，再分别写头和载荷；不建立发送队列，取消或错误后的协议收尾由应用协调两端。

`runtime::reactor` 的 IoSource 拥有非阻塞 Mio source；一次操作的 IoRegistration 持有
source 和 Reactor。一个 source 至多有两个互不重叠的方向等待者，分别持有逻辑身份、
ResourceEvent、TaskWaker 与就绪提示；一个内核 token 对应当前 interest 的并集，事件按方向路由。
stop 先移除自身身份与提示，再更新剩余 interest；最后等待者退出才 deregister。
身份不复用，重新登记使用新内核 token。注册/更新/撤销失败会失效路由并禁止 source 再登记；
尚存等待者被唤醒以观察运行时失败。source 的 Poll 在两次操作之间仍保活，不能跨执行器迁移。
每轮 poll 使用零等待收取最多 256 个事件，每个执行器最多 4096 个登记，通知只排队根。
就绪可虚假，读写/accept 登记后先实际尝试 I/O，WouldBlock 后 rearm；
connect 先观察 writable 提示再检查 SO_ERROR/peer_addr，有界处理不能丢弃未排空的就绪进度。
登记的就绪提示保留到 rearm/stop，每轮额外重放最多 256 项并旋转队列；
根因解释器指令预算让出、尚未访问对应子任务时，不会提前消耗唯一边沿。
停止时同时清除提示，失效事件不重放，也不使阻塞驱动伪完成。

`HostExecutor::wait` / `VmEngine::wait_tasks` 只等待，不执行脚本；之后由 poll 推进。
保留 TaskWaker 的外部宿主可以中断阻塞等待，未知等待仍报错。Clock 默认不准许阻塞，
SystemClock 或明确声明 `allows_blocking_wait` 的真实单调时钟可使用等待；虚拟时钟由宿主推进。
Godot 每帧调用相同的 poll_tasks，始终非阻塞，网络截止时间使用真实单调时间。
NET1a/NET1b 已提供资源、交接、字节请求及事件驱动，NET2 提供 TCP 公共模块；NET3 引擎网络联合场景
见[网络运行时开发计划](network-runtime.md)。

VM 持有实例任务执行器；每个根另持实例访问环境，保活不可变模块快照、身份、受检状态和额度。
环境在 poll、任务析构和 State 清理期间恢复所属身份 TLS；`current_instance_id` 只提供身份，
不绕过关闭/失败/Busy 检查。显式任务解释器限额可与短同步 State 访问限额分开配置。
环境没有 VM 裸指针，不把 `&mut State` 放进 continuation。同步访问仍通过原 checked 根入口，
禁止借用跨 Pending。失败调用的临时 arena 如需延迟销毁，保存到 State 的清理区，防止其拥有
分配在外部 host stop 前释放。关闭立即移除身份并关闭任务组，活跃 poll/stop 计数归零后才销毁根。
同步方法和任务执行期间的重入关闭共用此出口清理路径；成功的状态调用不扫描其他实例，
出口只处理去重的待清理队列。VM Drop 先拒绝新实例/实例任务，再显式关闭全部实例任务。

### DNS 线程边界与关闭

`runtime::dns` 共享固定大小的系统解析线程池，`joky/dns` 负责公开 Result 与地址数组包装。
私有受检原语 `__dns_lookup(String, UInt16, &mut UInt64) @suspends -> Array<UInt8>` 只接受精确签名，
复用网络输出槽的固定位置规则；不放宽一般局部借用跨挂起限制。String 保持拥有 Buffer ABI，
不走 TextView。解释器、JIT 与 AOT 都调用同一个 poll/stop 实现；沿用 CpsFrame 的 host_context
和 host_stop，不增加帧 ABI 字段。内部字节包每个地址占 24 字节，按大端存 high/low/endpoint；
错误包携带受限 UTF-8，错误种类写入独占 UInt64 槽，库层复用 `joky/tcp.Address` 的类型身份。

工作线程只持有拥有主机名、端口、Arc 请求身份、Mutex 完成状态、服务额度及 TaskWaker。
不持有 Buffer、CpsFrame、arena、Rc、VM、实例 State 或 Godot 对象。系统调用期间不持锁；
结果发布和通知撤销使用同一完成状态锁。每次 lookup 独立分配身份；取消 race 失败分支后，
旧结果不能命中新请求，已进入根就绪队列的旧通知只产生无害的额外 poll。

队列与完成包有固定容量；未回收额度一直保留到最后一个请求身份释放，包含完成未领取与
取消后在途工作。任务线程通过 ExternalCharge 计费请求、完成存储及输入快照；正常交接时
保持计费直到语言字节包分配成功，覆盖复制峰值。后续地址数组遵循普通拥有值与预算规则。
取消立即释放任务计费，后台存储仍受服务额度约束；工作线程从不释放非 Send 的 arena 额度。
系统解析器内部列表、缓存与线程栈属于宿主开销，不受语言 arena 硬限制。

VM 加载 DNS 模块、Rust block_on 和原生阻塞驱动在进入 poll 前初始化服务。手动原生 poll
须先调用 Rust `runtime::dns::initialize()` 或 C `joky_dns_initialize()`；线程创建失败会关闭
并回收已经启动的空闲线程，初始化失败保持错误状态。每份链接的运行时只有一个服务；多个
VM 共用，独立链接的动态库可以各自拥有一份。不为 VM 销毁 join 工作线程，也不自动关闭
其他 VM 使用的服务。首版固定限额没有宿主调节入口，数值见[语言 API](language.md#内置-dns-模块-jokydns)。

Rust `runtime::dns::shutdown()` / C `joky_dns_shutdown()` 永久关闭服务准入，排队请求获得
SystemFailure，在途查询返回后线程退出；接口只回收已经结束的线程，返回时不等待系统解析。
返回 true / 1 表示工作线程全部退出并已 join。宿主先销毁所有任务拥有者，再保持运行时代码
加载直到该返回值成立，之后才能卸载；初始化后的服务不支持重启，无法承诺有界卸载时间。
C 声明见 [joky_cps.h](../include/joky_cps.h)。

Godot 适配器保持 `reloadable = false`，初始化时用 libloading 额外取得自身动态库的加载引用，
静态保留至进程结束；退出阶段先关闭实例与任务，再关闭 DNS 准入，避免在途线程执行已卸载代码。
扩展代码与静态服务占用因此保留到进程退出；扩展卸载后重新加载不受支持，脚本重载仍可使用。
这是 Godot 适配器的具体保活策略，其他嵌入宿主须遵守上述显式关闭契约。

## 整数转换内建函数

`core::integer::IntegerType` 集中维护四个转换名称及整数位宽/符号元数据。
共享 IR 检查转换的实参数量和整数类型，独立推导源类型后生成 `Convert(dst, src)`，
两个 typed slot 保留源类型及目标类型；不向函数签名注册器伪造 Any 参数、重载集合或宿主 extern。
转换结果类型也进入纯类型提示，保证算术、条件和聚合中的局部定型一致。
调用规划位于 `core::ir::calls`，避免继续增大递归表达式规划器的栈帧。

JIT / AOT 共用 narrowing `ireduce`、signed widening `sextend`、unsigned widening `uextend`；
同位宽直接复用原生值。解释器用 `Convert` 指令按源值标签扩展，再按目标类型截断/解释。
转换自身不设置 may_fail 或增加 CPS 状态，但实参中的调用、除零、移位和 Pending 仍按原规则传播。
没有新增运行时 helper、C ABI 或帧布局；纯同步转换不要求链接运行时。

名称在共享类型解析的声明检查及 IR 规划中保留，CLI / VM 在查询 extern 宿主实现之前拒绝重定义；
宿主及模块绑定注册同样拒绝占用这些名字。它们不是模块导出或可取地址的普通函数，
带 Integer 能力约束的转换签名仍是未来设计。用户语义见 [显式整数转换](language.md#显式整数转换)。

## 位运算与解析边界

位运算和移位复用 typed IR 的 Binary / Unary，不增加运行时值类型或 CPS 状态结构。
移位两侧由共享语义检查保证同型。原生 lowering 使用 `band` / `bor` / `bxor` / `bnot`、
`ishl`，以及依符号选择的 `sshr` / `ushr`。位运算按源码求值顺序保留快照。
parser 的分支上下文将最外层 `|` 保留给 match / parallel；进入括号、调用参数、元组、字段或块时
允许按位或，退出时恢复外层状态。优先级和用户写法见 [位运算与移位](language.md#位运算与移位)。

## 原生错误传播

Int32 除法先检查零，再将两个操作数符号扩展到 I64 做有符号除法，最后截断回 I32。
Int64 除法在零检查之后，将 -1 除数替换为安全的 1，再选择环绕取负结果；其他除数执行 I64 有符号除法。
UInt32 / UInt64 使用相应位宽的无符号比较和 `udiv`，同样先检查除零。
这样两个有符号位宽的 `MIN / -1` 都环绕为 MIN，不执行会触发除零或有符号溢出的机器除法；不使用 signal、
longjmp 或跨生成代码的 Rust unwind。已有标量签名继续使用原有 C 参数及返回值 ABI，聚合内部调用使用隐藏结果指针；CPS 帧保持 opaque，须由匹配 runtime 分配。

移位先以操作数完整位宽做无符号 `count >= width` 检查，同一检查也拒绝负的有符号移位量。
检查发生在机器移位之前，避免处理器对移位量掩码；失败调用 `__joky_runtime_invalid_shift`，
通过现有错误通道携带表达式源码范围，再走同步 / CPS 的失败返回路径。

`runtime::error` 用线程局部通道保存本次调用的首个结构化错误及半开 UTF-8 字节范围。
生成代码在可能失败的调用之后、消费结果之前检查错误，并立即向上传播；失败返回的机器值
不具备语言含义，也不能作为 String 指针解引用。IR 通过调用图固定点传播 `may_fail`，
将所有外部调用保守视为可能失败；无除法、移位和外部依赖的纯函数无需生成调用后检查。

`VmEngine`、continuation 及解释器 native 适配器的 Rust 调用边界保存外层错误、隔离嵌套调用，
退出时恢复外层状态。嵌套 VM 中已由调用者处理的失败不会污染外层执行或下一次调用。
该通道与 `joky/vm` 的公共错误查询独立。CPS 除零或非法移位返回 `JOKY_CPS_RUNTIME_ERROR`，
设置 `JOKY_CPS_FAILED` 并释放子帧；parallel 不再轮询后续分支。失败任务没有成功结果，不能重试。

AOT 编译后用 `AotCompiler::requires_runtime()` 判断是否需要链接 `libjoky.a`；含除法、移位、
外部调用或 CPS 的对象需要 runtime。C 调用方按 [joky_runtime.h](../include/joky_runtime.h)
在顶层调用或每次 CPS poll 前清除错误，返回后先查询状态，再读取结果；宿主再次调用生成函数时
必须传播尚未处理的失败。跨动态库需要共享同一个 runtime，不能分别静态链接独立错误通道。
新增 helper 依赖要求旧分发环境更新配套 archive 和头文件，无需改变现有函数签名或复制帧布局。
CLI 自动链接所需 runtime；独立程序除零或非法移位时报告错误和字节范围并以状态 1 退出，无需保留源码文件。

## 已知边界

- 四种整数的除法语义已一致；原生错误携带出错范围但没有完整语言调用轨迹，解释器仍提供
  `runtime_trace`。Span 不带文件 ID，跨模块或重载后的嵌入方必须使用对应模块的源码。
  不捕获宿主自身的机器陷阱，不能把 catch_unwind 当作机器陷阱处理。
- 解释器执行栈是平坦存储，但解析器、AST 规划和原生执行仍有递归；解释器限额不约束
  解析/编译内存、源码嵌套深度、原生回调或回调新建的 VM。当前不是不可信代码隔离环境。
- `core` 已与机器码生成分层，但单 crate 仍编译 Cranelift；没有 interpreter-only feature，
  也没有证明可在所有禁止可执行内存的平台构建。可序列化字节码也尚未定义。
- resolver 仍认识 `joky/vm` 的内置调用形式；有第二种真实模块需求后再考虑通用重写协议。
- 保持公开 API/C 符号和显式 ABI 包装，避免为减少几行代码引入宏生成或任意函数指针调用。

## 构建与验证

Release 使用 opt-level 3、Thin LTO、一个 codegen unit 和符号裁剪，保留 unwind。
CLI 的 Release 原生链接也清理无用代码/符号。LTO 可能增大含中间代码的 archive，
分发体积应看最终可执行文件；导入 `joky/vm` 会带上 JIT 编译器。
`joky build` 没有独立模式参数，要用 Release CLI 和配套 Release runtime 构建发布程序。

原生产物先在输出目录内链接，成功后 rename 发布；失败清理临时文件并保留旧输出。
安装和 runtime 查找方式见 [README](../README.md#安装与产物)。Cranelift 依赖保持同一版本系列，
Cargo.lock 固定精确版本。C 示例链接所需系统库可用 `cargo rustc --lib -- --print native-static-libs` 查询。

按改动范围选择验证：`./scripts/check.sh` 默认快速检查，`--full` 增加 Release 常规回归，
`--stress` 独立执行 Release 穷举与长输入基准正确性，发布验收运行 full 和 stress；
测试要求见 [CONTRIBUTING](../CONTRIBUTING.md)。
解析器测试按声明、表达式、运算符和泛型归入 `core/parser/tests`；AOT 测试按功能归入
`backends/aot/tests`，`support` 共享同步结果与 CPS 生命周期断言，C 链接及临时目录工具仍由 `tests/support` 提供。
回归覆盖三个后端的类型与控制流、重复 Pending、不重放副作用、失败/取消、重载后所有权、
真实 AOT 链接和安装布局。检查脚本只验证基准结果，不进行计时。性能测量独立运行，
工作负载和统计边界统一维护在[基准方法](../benches/README.md)，历史数字保留在[实验记录](interpreter-performance.md)。

## 函数值与间接调用

Type::Function 通过 FunctionType 保存完整的结构化签名和独立的 suspends 标记；类型规范化、刚性模板检查、泛型推导和替换均遍历签名。
共享签名图按节点缓存，保留 256 层类型深度及既有泛型实例限制；经引用展开函数签名的路径
另限 32 层，递归函数别名以编译错误结束。函数名取值检查定义作用域、
可见性、完整泛型实参和 trait 约束；推导阶段只读取签名，实际取值才登记实例。

语言函数值与 vm.Function 原生注册引用共用 FunctionRef 操作，但由槽类型区分。
Call 的 indirect 槽表示动态目标；共享 IR 创建内部 __joky_indirect_ 签名契约，
把未知调用保守标为可失败、可分配和可保留引用，按函数类型保留挂起效果。契约仅供类型、存储与借用分析，
不生成外部符号或虚构宿主入口。callee 在实参求值前快照，普通调用顺序和挂起实参不重放。

原生后端对所有被取值的同步目标统一传入隐藏 arena 参数，以完整签名生成 Cranelift call_indirect；
纯函数的 uses_arena 不因此改变。原有标量导出通过 arena entry 包装维持宿主 ABI；
vm.register_int32 仍指向公开包装入口。AOT 使用函数符号重定位，不嵌入编译进程地址。
同步聚合返回继续使用调用者的结果缓冲，间接调用后先检查运行时错误，再读取结果。

挂起函数值指向只读描述符，包含可重定位的 CPS 入口及该目标的完整 frame_slots；它仍占一个指针槽。
首次调用按描述符申请子帧并保存参数，恢复时从已快照的描述符读取入口，只轮询原子调用。
动态 scope/race 分支使用相同元数据和既有 child_at 协议。聚合返回偏移从静态参数签名计算，
帧大小取实际目标的完整布局，不能用参数槽数或函数类型代替。完成、失败、取消均复用 CPS 清理路径，
包括异步借用宿主的 stop 回调；无需新增或伪造 CPS 帧布局。

解释器使用模块内 callee 索引作为 Function 值，IndirectCall 支持标量和多槽聚合返回，
并作为复制传播边界。函数值可进入 Copy 聚合、数组和 arena；不携带捕获环境或引用来源。
含函数值的签名不导出为宿主入口，extern / C 参数禁止函数值；已有模块 / continuation 所有权
覆盖其全部可调用目标，重载后旧任务保持旧 callee 表或代码所有者。无需改变 CPS 帧协议。

当前可取同步及挂起语言函数（含完整泛型实例）的值；方法取值、任意表达式的连续括号调用
和函数指针的非保留效果契约均未开放。直接匿名字面量另允许括号包住后立即调用。

同步闭包使用编译器私有的名义 `Record.closure` 元数据，每个字面量/所属函数实例具有独立身份；
环境非 Copy，首个私有字节为身份占位，随后捕获字段依源码第一次使用顺序排列；
即使零捕获也保留移动状态。共享/独占环境和消费式环境分别生成私有入口，
原生入口参数依次为环境指针、普通实参、多槽结果指针（如有）和 arena；消费式入口从该指针
接收拥有责任。无捕获转 fn 使用独立无环境入口，AOT 均通过符号重定位链接。

环境复用稳定局部存储与现有拥有值清理组：解释器先预留环境存储再转移捕获，消费捕获时从
环境清理组分离对应字段，剩余字段保持声明序清理。普通借用捕获带来源与权限，刚性 callable
参数也携带符号环境来源；抽象模板和具体实例都参加借用/noescape 检查。内建 callable 契约仅
保证环境不逃逸，普通输入参数仍保守检查。闭包移动有效性按 CFG 交汇与循环检查，静态
`Op::Closure` 标记在后端生成前擦除。禁止环境返回、聚合/容器存储、宿主 ABI 或 CPS 帧；
同步 helper 的不逃逸效果自动推导，原有模块/continuation 继续保活隐藏入口。

`joky/check.require` 的身份只绑定在编译器内嵌 Check 定义上，源码同名函数和文件名不获得权限。
直接调用在参数检查及顺序求值后产生 `Op::Require`，携带实际调用 Span；函数值调用使用
绑定定义中的同一 IR 操作。原生 JIT/AOT 共用失败分支与现有 cleanup 路径，运行时立即复制
借用 String 消息并保留首个错误；解释器产生同类 RuntimeError 并走既有帧/arena 清理。
这是通用源码检查入口，不包含 Map 的索引、容量或容器算法。

内嵌 `joky/internal/types.require_plain_copy<T>()` 是通用存储类型资格检查，身份由 TypeCheck
定义绑定，用户源码/文件名不能赋予身份，也不能直接导入内部模块。泛型实参具体化时按实际
`is_copy_storage_value`、`contains_references`、`is_buffer_element` 分类验证；记录、枚举、元组
使用现有递归内容分类。刚性参数延后检查，固定非法类型在未使用泛型体中也拒绝。
通过检查的调用从 IR 擦除，不引入运行时分支、标记 trait 或 Map 专用 ABI；拥有者和引用规则不变。
同一模块的 `require_reference_free<T>()` 允许无引用拥有者，仍检查递归引用与 buffer element 资格。

借用效果在共享 IR 中按参数推导。FunctionInfo 分别保存显式 `@noescape` /
`@noescape(parameter, ...)` 契约和推导结果；有函数体的同步函数、刚性模板和具体实例参加分析，
无函数体的 trait 要求、宿主和间接入口不因签名形状而获得保证。同步文本视图沿用其专门 ABI。
borrowing 复用来源数据流，分别记录返回和保存参数借用的效果；容器中已有引用的来源也计入摘要。
返回视图保留来源关系，但不会自动推导成保存输入。未知调用的保存效果仍保守传播。
候选从全部可借用参数开始，遇到逃逸后单调撤销并重查直接调用者，直到递归调用图收敛；
分析有编译预算，失败的函数体不能发布部分证明。收敛后重新执行普通借用和显式契约检查。
CFG 输入快照的引用槽表采用写时复制；不修改引用的指令共享快照，写入时才复制槽表。
合并直接记录来源/loan 集合增长、祖先权限交集收缩及标志变化，避免复制完整旧状态再比较；
来源关系、任务期保留、区域 loan、循环固定点与编译预算仍按原规则处理。
未使用模板依赖的惰性 helper 也提供分析体，检查后移除，不因此生成额外的运行时代码。
调用处只排除已证明不逃逸的参数；相同 slot 若也传给未受约束参数则保留保守来源。
实例入口准入使用最终证明，不要求源码属性。隐式共享借用在规划阶段记录调用位置与参数义务，
待推导结束后统一验证；因此声明顺序不影响转换，省略 `&` 也不能绕过逃逸检查。
刚性按值泛型参数尚无确定槽位布局时，抽象调用保守处理实参来源，不能使用具体槽位映射
或从缺少引用槽位推出不会保存引用；全参数显式契约仍须验证，具体实例重新计算效果。
trait 实现继承显式契约，具体实现和未实例化模板都必须通过验证；间接调用不继承该保证。
它不改变 uses_arena/needs_arena，也不允许宿主自行声明未检查的效果。
单参数 blanket impl 经过普通约束证明和静态分派；多个候选匹配时报错，不按具体程度选择实现。

可信源码容器仍可使用受检内部存储与类型资格模块，但其导出遵守显式 `pub`，
与普通源码模块使用相同的声明/方法可见性规则。Array、Element、Slice 显式列出既有公开接口；
容器可以隐藏桶类型与算法 helper。最小回归是私有 helper 可被同模块公开函数调用、
却不能从消费模块导入或点调用；不增加容器专属运行时 ABI。


`joky/map.Map<K, V>` 是五个私有 Array 拥有字段与删除计数构成的普通名义记录。
桶使用既有 Empty/Deleted/Full(UInt64) tagged enum 布局，数量与字节上限始终查询目标布局。
Joky 源码实现有界线性探测、缓存哈希重建、四个载荷同步 swap_remove 与被搬末项的桶修正。
new 与 insert 调用通用 ReferenceFree 存储资格检查；核心查找/插入使用 BorrowEq + BorrowHash，
旧 Copy key 入口及 Eq/Hash 通过普通源码 blanket impl 适配，
生命周期函数无协议约束。重建只交换索引拥有字段，不调用用户协议、不析构 value；
各个中断点的清理由既有 Array 初始化前缀和拥有临时量登记承担，不增加 Map ABI。
真实生产算法的双向索引检查由 cfg(test) 标准库加载附加的同模块用例执行；
默认标准库没有测试导出或私有字段访问逃生接口。


Map 的四种元素借用是查询 entry 后调用 Array 借用的普通源码函数；返回引用沿用整个 Map
的存储来源。新增 value_ref/value_mut 使用参数级 noescape 排除查询 key 的借用来源；
Array/Slice 的直接引用同时支持无引用 Copy 元素，其指针指向内联元素存储。
复制出的普通共享引用仍沿用已有 contents 与 retained 分析，独立于 Map 控制块；
任务期来源保留不会因为 remove、clear、移动或 release 而缩短。无需 Map 专用借用规则。

原生同步调用的失败分支在清理调用者之前，通过通用 `__joky_runtime_call_failed` 记录
当前调用 Span。`Error::native_call_sites()` 按由内向外顺序保存这些真实源码调用点；
错误主 Span 和首个消息不变，不伪造解释器 PC 或原生栈。已附加的源码快照随错误保留，
独立 AOT 的运行时打印来源 ID 和字节范围。该机制使源码容器内部 require 失败也有用户调用位置，
同时适用于普通函数和函数值调用；解释器继续使用已有完整 activation 轨迹。

Map 切片视图直接转发到私有载荷 Array 的完整范围，借用来源仍是整个 Map，不导出可变 key。
pop 从紧凑载荷尾部逐项移出并标记对应桶为 Deleted，无需修正其他 entry 或调用 Hash/Eq；
into_entries 预留输出容量并循环 pop，余下 Map 字段自动清理，不依赖可复用部分移出。
from_entries/extend 先按输入长度受检 reserve，再原地反转输入并从尾部消费，以线性移动次数
保持输入处理顺序；每轮作用域清理 insert 返回的旧值，析构失败阻止处理下一项。
全部中断点复用已有 Array 初始化前缀、拥有型元组和临时量清理，不新增编译器操作或运行时 ABI。

## Show 与字符串插值

Show 是 `stdlib/show.jk` 中的普通静态 trait，使用受检查的共享接收者与独占 builder
`@noescape` 契约，内置与用户实现均单态化，不增加动态分派或运行时模板解析。
Show 的默认 `to_text` 包装共享 builder 创建、show 和 finish；自由函数与 io.print 复用它，io.println 保留直接追加换行的单 builder 路径。
Lexer 将 f 字符串分为解码文本和保留原 UTF-8 span 的表达式 token；Parser 展开成
普通 builder 块和不可由源码拼写的临时名/模块别名，并仅按需引入 show/string。
共享 IR 区分已有拥有位置、引用和需要求值的临时值，临时局部按既有机制物化借用位置，
Show 完成后逐段清理，最后消费 finish。借用、返回、分配失败和 Drop 仍走共享检查/清理路径。
JIT、解释器与 AOT 不分别实现插值操作码，字节码格式不变。

`stdlib/io.jk` 在整次格式化成功后调用 `joky_io_write_stdout_v2`；内部绑定签名
为 `(&String) -> Int32`，宿主接收 TextViewV2 描述符，同步写 UTF-8 字节、不保留指针。
三后端和独立 AOT 使用同一 Rust runtime 边界，避免各后端重复浮点格式化。
公开 C 声明位于 `include/joky_io.h`，安装脚本一起部署；输出失败记录运行时错误且可能
已写入前缀。通用输出只需显式导入 io，不扩大默认 prelude 的宿主依赖。

## 递归拥有容器清理（JSON1a）

元素描述符只列出一个元素的内联拥有句柄、Drop 与枚举标签守卫；子缓冲区各自携带其元素描述符。
递归边不展开成嵌套描述符，也不建立描述符强引用环。描述符、代码快照和元素布局沿用现有登记及保活路径。

`Buffer::release` 使用控制块中的父节点、元素内拥有 lane 与 hook 游标迭代遍历。反向索引、
字段声明序、先 enclosing Drop 再当前子拥有者、inactive enum lane 的 null 规则与首个错误保留均不变。
父数据保持存活直到全部子节点释放，Drop 修改过的子句柄在 hook 返回后重新读取。
遍历状态随控制块分配计入 arena 预算；释放不另分配工作栈，深树清理不依赖 JSON 深度限制或原生递归。
truncate/覆盖/根清理释放子节点时共用同一路径；失败后继续释放其余拥有者。
用户 Drop 主动触发的析构重入仍受既有 32 层限制，普通树遍历不会累计该深度。

完整拥有者移动在检查源和目标的存活 loan 后重建独立控制身份，保存 Copy 元素的已有内容来源。
这与消费解构的分离规则一致，避免循环中较早一轮拥有者与同一调用点的新分配发生虚假借用冲突。
移动前的真实别名仍必须通过原有冲突检查，不能借重建身份解除存活的内部借用。


## JSON 数字转换原语（JSON1b）

`joky/json` 是遵守显式 pub 与私有字段的源码模块。Value 复用递归 Array/Map 清理；
Number 通过私有 String 字段和公开受检构造维持语法/1024 字节不变量，扫描、整数累积与错误策略在 Joky 中。
唯一新增可信函数为私有 parse_float64(&String) -> Float64，由嵌入源码身份绑定 FloatKind::FromText；
用户模块不能通过名字冒充、导入或调用该原语。

JIT/AOT 调用 `__joky_float_from_text_v1(owner) -> UInt64`，解释器调用同一个 Rust 解析核心。
返回值是 IEEE 原始位模式；无任务 arena 参数、不分配、不转移拥有权、不保留 String 借用。
输入超过 1024 字节或解析失败返回 NaN；十进制转换正确舍入，溢出可产生 Infinity，
下溢保留符号。源码包装只传已验证的有限长度 JSON 数字，并将非有限结果映射为 OutOfRange。
无效 Buffer/UTF-8 句柄经普通 ABI 错误通道传播，原生调用消费返回位前先检查该错误。
不扩展公开聚合宿主 ABI，也不向标准数值类型添加通用 from_text。

## JSON 解码状态与拥有权（JSON2a）

解码是 `joky/json` 源码库的同步状态机，不增加运行时原语或后端专属算法。
私有 Decoder 保存输入 offset、节点数、限额、当前完成值及 Array<DecodeFrame>；
frame 独立拥有未完成 Array 或 Map 和待插入键。主循环调用单步 helper，按模式推进
值、数组分隔符、对象键、冒号及对象分隔符，不按输入深度递归。helper 划分避免复杂循环
扩大引用分析状态，编译器原有预算保持不变。

子树完成后从 frame 移出并插入父容器；数字复用范围语法检查后复制原始拼写，字符串由
StringBuilder 独立构建。返回值不保留原始输入借用；字节入口消费输入并先做严格 UTF-8 验证。
失败、解释器时间片取消、挂起后取消或旧代码重载均沿用普通拥有值清理责任，未完成 frame、
待插入键和完整子树各清理一次。栈、Map 元数据与临时字符串继续计入任务 arena 预算。

DecodeErrorKind 与 NumberErrorKind 均在 `joky/json` 声明，各自的 NumberLimit 通过类型限定名区分。
JSON 依赖使用限定名导入，不重导出依赖类型，也不再需要独立错误模块。

## JSON 编码索引路径（JSON2b）

编码是 `joky/json` 源码库的同步状态机，不新增宿主 codec ABI。
Encoder 只拥有输出 StringBuilder 和 Array<UInt64> 路径，另保存节点数、限额与访问模式。
路径中的索引对应 Array 元素或 Map 的 keys/values 同位置元素；输入树始终保持共享借用，
Map 不修改或排序，视图的索引配对在整个调用中稳定。

每次访问/退出节点都从共享根沿路径重新借用；path_value 对路径参数标注 noescape，
返回引用只来自根。引用不进入拥有容器、不跨步保存，工作栈空间受 max_depth 限制，
没有按输入深度递归调用，也不复制拥有子树。重复遍历祖先最多 128 层，
时间为 O(节点数 × 深度 + 文本字节)，额外索引空间 O(深度)，输出按实际分配计入 arena。

访问当前 Value 时计一次节点，容器在输出开括号前检查深度；文本和 Number 在输出前检查源长度，
所有追加检查实际 UTF-8 输出增长。不可恢复预算失败和取消沿用普通拥有者清理，
可恢复限额错误只清理编码工作栈与部分输出，输入树仍可查询、修改和再次编码。
EncodeError 同样直接在 `joky/json` 声明，与其他错误枚举共享限额成员名称，
构造器按枚举身份解析；私有数字原语身份绑定保持不变。
