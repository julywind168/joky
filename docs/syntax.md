## 1. 设计取舍

- 静态类型、表达式导向：函数和块用末尾表达式返回值，不做隐式类型转换。
- `let` 不可重新赋值，`var` 可重新赋值；函数签名显式，局部类型可推导。
- 用 `{}` 划分作用域、`,` 分隔参数；`;` 是连接表达式的序列运算符，不强制使用。
  块可以顺序容纳多个表达式；完整表达式后的换行分隔下一项，行首 `.` 明确继续字段或方法链。
- 挂起沿用 `@suspends`，调用形式与普通函数一致；结构化并发使用 `join` 和 `race`。
- v0.1 先完成函数、分支、循环和宿主交互；完整目标还包括名义数据类型、泛型与能力约束、
  函数值以及所有权与借用。资源规则先确定，再开放会捕获或跨挂起保存资源的功能。

## 2. 程序与函数

当前顶层允许 `import`、`type`、`struct`、`enum`、`impl`、`trait`、`const`、`extern fn` 和 `fn`。没有顶层执行语句或全局变量。
导入必须放在文件开头（`const` 计入声明）；函数可以先调用后定义，允许递归，不允许同名重载、重复参数或嵌套定义。

下面是**当前 JIT、解释器和 AOT 都可运行**的完整程序，也是目标语法的共同子集：

```joky
import joky/io.{println}

fn sum(n: Int32) -> Int32 {
    var i = 0
    var total = 0
    while i < n {
        total = total + i
        i = i + 1
    }
    total
}

fn main() {
    println(sum(10))
}
```

输出 `45`。`fn main()` 返回 `Unit`；省略 `-> Type` 总是表示 `Unit`，不推导函数返回类型。
普通函数参数必须写类型，impl 的首个 `self` / `&self` / `&mut self` 例外；实参按位置传递；没有默认参数、命名参数或可变参数。
函数体正常结束时，其末尾表达式必须匹配返回类型。

```text
fn name(parameter: Type, ...) [@suspends] [-> Type] { ... }
extern fn name(parameter: Type, ...) [@suspends] [-> Type]
```

这里的方括号表示可选部分，不是源码字符。`@suspends` 固定写在参数列表之后、返回类型之前。
`extern fn` 没有函数体，宿主注册必须匹配完整签名和挂起约定；指针与代码所有权规则不属于语法。
顶层声明后可选写分号；这是声明间的分隔便利，不要求声明本身成为表达式。

CLI 入口为无参数的 `main`，可标注 `@suspends`，返回 `Unit` 或 `Int32`。
通用打印由 `joky/io` 的 `print` / `println` 提供，默认 prelude 导入；它们是普通源码函数。

## 3. 词法与名称

源码为 UTF-8，区分大小写。支持 `//` 行注释和可嵌套的 `/* ... */` 块注释，
已实现的注释与换行规则见 [语言说明](language.md#注释)。
标识符以 `_` 或 Unicode 字母开头，后续可为 `_`、Unicode 字母或数字；不做 Unicode 规范化。
项目示例与宿主名称使用英文 `snake_case`，类型使用 `PascalCase`。

v0.1 核心目标保留字为：

```text
fn extern unsafe import pub type struct enum impl trait dyn for const match let var if else while break continue return parallel scope race branch
true false mut Int32 Int64 UInt32 UInt64 Bool Unit String Ptr
```

`parallel` 仅为旧语法的迁移诊断保留，不再接受并发块。`join` 为上下文词，
在表达式位置后接 `{` 时解析为并发组合；普通 `join(...)`、`fn join`、`string.join(...)` 不受影响。

`self` / `Self` 在 impl 和 trait 内具有接收者 / 目标类型含义。`trait for` 已实现，`dyn` 已保留，
同步借用型 dyn 已支持资格检查、关联等式规范化、擦除、显式重借用和三后端动态执行，见[实施记录](borrowed-dyn-trait.md#9-实施记录2026-10-08)。后续扩展还包括
第 10 节列出的数值与 Rune 类型名。这里的 `for` 仅用于 trait 实现，不引入 for 循环。
这些名称在对应阶段启用时才变成关键字，不提前改变当前源码的解析结果。

`suspends` 只在 `@suspends` 位置有特殊含义。声明属性使用 `#`，当前开放 struct 前的 `#repr(C)`、`#derive(ToJson, FromJson)`、`#state`，以及 `#state` 固有方法前的 `#every(milliseconds)`，
不开放通用属性或用户属性宏；后续语法方向见 [Arena 设计 §2.5](arena-borrowing-ffi.md#25-后续属性系统的语法方向)。
函数名、参数名和局部名称是单个标识符；`vm.call_int32` 是限定调用名，
`vm.Vm` 是限定类型名。`.` 支持字段访问、固有方法调用和关联常量读取。
局部值遮蔽模块或类型前缀时按值的方法查找，找不到即报错。
宿主 opaque 类型名继续使用当前注册器接受的 ASCII 标识符段，段间用 `.` 连接。
运行时函数名前缀 `__joky_cps_`、`joky_cps_`、`joky_vm_`、`__joky_runtime_`、
`joky_runtime_` 保留，用户不能声明。

### 核心字面量

| 类型 | 形式 | 规则 |
| --- | --- | --- |
| `Int32` / `Int64` / `UInt32` / `UInt64` | `42`、`1_000`、`0xff`、`0b1010` | 十/十六/二进制；单个下划线仅在数字之间，无后缀 |
| `Float32` / `Float64` | `1.0`、`1.5e-3`、`2.5E+3` | 小数点两侧都有十进制数字；分隔符同整数规则，无后缀 |
| `Bool` | `true`、`false` | 不与整数隐式转换 |
| `String` | `"hello"` | 不可变拥有型 UTF-8；`"{expr}"` 默认 Show 插值，`{{` / `}}` 输出字面花括号，无 `+`；字符字面量产生 Rune |
| `Unit` | `{}` | 空块产生 Unit；第一版不增加 `()` 别名 |

负号是一元运算符。四种整数字面量的上下文定型已实现，无约束局部绑定默认 Int32；
大数字不自动升级。范围和最小值拼写见[当前整数语义](language.md#整数类型与字面量)。
浮点字面量同样按上下文定型，无约束默认 Float64；见[浮点类型与运算](language.md#浮点类型与运算)。
直接负号允许 `-2147483648` / `-9223372036854775808`，但括号内正数必须先满足选定类型的范围。
`-` 与数字之间允许空白或注释；UInt32 / UInt64 不接受一元负号，包括 `-0`。显式整数转换及返回 Option 的整数方法已实现；其他数值类型仍是第 10 节的后续目标。

进制前缀只接受小写 `0x` / `0b`，十六进制数字可大小写混用；不支持八进制。
进制不会改变类型或将高位解释为符号位，直接负号在各进制下均允许对应有符号最小值。
数值 token 包括紧邻的字母和下划线，非法数字、后缀或分隔符整体报错，不能拆成后续表达式。
完整边界和示例见[进制与分隔符](language.md#进制与分隔符)。

字符串转义包括 `\n`、`\r`、`\t`、`\0`、`\"`、`\\` 和 Unicode 标量转义 `\u{H...}`，当前实现已支持。
普通单行字符串不允许裸 LF / CR，也不支持反斜杠续行；未知转义和未闭合字符串报错。花括号默认触发插值，`{{` / `}}` 输出字面花括号。
转义只解码一次，`"\\n"` 表示反斜杠和字母 n；`\0` 是字符串内的 NUL 字节，不截断文本。
错误范围使用原始源码的 UTF-8 字节偏移，不使用解码后的字符串下标。
`r` 关闭转义和插值，支持 `#` 定界；三引号支持多行，并按结束定界符的缩进去掉各行前缀，
两者可组合。具体换行、空白及错误规则见[字符串字面量](language.md#字符串字面量)。

显示协议与插值已实现：`joky/show.Show` 以共享接收者写入 StringBuilder，
`joky/io.print` / `println` 接受共享引用。插值是非原始字符串字面量的默认行为，写作 `"text={expr}"`，
`{{` / `}}` 表示普通花括号；表达式顺序求值一次，不移动现有拥有值。
已知同步函数中经推导或显式契约证明不逃逸的共享引用实参支持自动借用，包括 `println(value)`。
格式规格、自动派生留待后续，实际语义见
[Show 与插值](language.md#showprint--println-与字符串插值)。

## 4. 绑定、赋值与作用域

```joky
fn increment(start: Int32) -> Int32 {
    let step: Int32 = 1
    var value = start
    value = value + step
    value
}
```

- 所有绑定必须初始化；显式类型注解必须与初始值一致。
- 参数默认不可重新赋值，可用 `var name: Type` 声明可变参数；`let` 绑定不可重新赋值，`var` 赋值不能改变类型。
- 核心阶段赋值目标只能是现有局部变量，结果是 `Unit`；类型扩展后，字段赋值和可变借用
  还须满足所有权规则。支持算术与位运算复合赋值，目标只求值一次，旧值在右侧求值前快照。
- 允许同名遮蔽；新声明的初始值先在旧环境求值，随后新绑定生效。
- `{ ... }` 引入词法作用域；新声明不能逃逸，外层 `var` 的赋值可以保留。
- 括号和分号序列不创建作用域；`let` 的不可变性不意味着 opaque 句柄所指资源不可变。

## 5. 表达式连接、块与分号

`;` 是最低优先级的**表达式连接运算符**：`a; b` 先求值 `a`，丢弃其结果，
再求值 `b`，整个序列取 `b` 的值和类型。它恰好也能充当传统语言的语句分隔符，
但声明、赋值、调用和控制流都不强制以分号结束。

1. 块按源码顺序执行其中的表达式，丢弃非末尾表达式的值，以末尾表达式为结果；空块为 Unit。
2. 独立表达式之间必须有分号或换行。
   同一行写 `let x = 1; let y = 2; x + y`；分行时可以省略分号。
3. 完整表达式后的换行分隔下一项，但不丢弃值；行首 `-`、`*`、`&` 作为新表达式的一元运算符。
   不完整的表达式可续行，例如 `1 +` 换行接 `2`；圆括号和实参列表内部换行为空白，列表仍须用逗号分隔。
   嵌套花括号恢复换行分隔。下一行以 `.` 开头时继续字段或方法链，可跨注释与空行；分号会结束该链。
   圆括号外，被调用表达式与 `(`、记录构造名称与 `{` 在同一行；参数和字段内容可跨行。
4. 尾随分号丢弃最后一个正常值，序列正常结果为 Unit；不吸收 return、break 或 continue。
   连续分号允许作为空连接，不产生副作用；单独的分号不产生有用值。
5. 声明、赋值、while 和 branch 正常结束时返回 Unit；scope 返回主体末值，join 返回按源码顺序的结果元组（全 Unit 分支仍返回 Unit），race 返回获胜分支的值。尾随分号丢弃正常结果。

```joky
fn answer() -> Int32 { 42 }
fn discard() { 42; }
fn grouped() -> Int32 { (1; 2) }
fn empty_result() { (1; 2;) }
```

序列不限于括号内，`{ a; b }` 直接连接两个表达式。括号用来控制结合方式，
不创建新作用域。初始化与赋值右侧默认解析到分号之前：`let x = a; b` 先绑定 `a`，
再执行 `b`；要把序列整体作为初始值，写 `let x = (a; b)`，赋值同理。

实参中的序列按逗号或右括号结束：`f(a; b, c)` 有两个实参，第一项是序列 `a; b`，
第二项是 `c`；也可写成 `f((a; b), c)` 强调分组。分号不增加实参数量。
while / if 条件中的序列使用括号，例如 `while (advance(); ready()) { ... }`。
控制流也可连接：`return value; next()` 中 `next()` 不会执行，按不可达代码规则报错。

## 6. 运算符与求值顺序

从高到低：

| 优先级 | 形式 | 结合性与约束 |
| --- | --- | --- |
| 最高 | `name(...)`、`(...)`、`{...}` | 调用、分组、块 |
| 一元 | `-x`、`!x`、`~x` | 右结合；分别要求有符号整数、Bool、任一整数 |
| 乘除与余数 | `*`、`/`、`%` | 左结合；两侧同型，`%` 仅接受整数 |
| 加减 | `+`、`-` | 左结合；同型 Int32 / Int64 / UInt32 / UInt64 |
| 移位 | `<<`、`>>` | 左结合；两侧同型整数，移位量为 0 到位宽减一 |
| 按位与 | `&` | 左结合；两侧同型整数 |
| 按位异或 | `^` | 左结合；两侧同型整数 |
| 按位或 | `\|` | 左结合；两侧同型整数，分支边界处需定界 |
| 比较 | `==`、`!=`、`<`、`<=`、`>`、`>=` | 不结合；禁止链式比较 |
| 逻辑与 | `&&` | 左结合、短路；Bool |
| 逻辑或 | `\|\|` | 左结合、短路；Bool |
| 赋值 | `=`、算术与位运算复合赋值 | 右结合，结果为 Unit |
| 最低 | `a; b` | 从左到右连接表达式，取末项结果 |

当前算术和有序比较接受 Int32 / Int64 / UInt32 / UInt64，但两侧必须类型相同；`==` / `!=` 还接受两侧同为 `Bool`，
不支持 `String`、`Unit`、opaque 类型比较。条件必须为 `Bool`，没有 truthy/falsy 规则。
`a < b < c` 必须改写为 `a < b && b < c`；后者会按源码重复求值 `b`。
赋值返回 Unit，因此 `a = b = 1` 对两个 Int32 变量是类型错误。

`if let Pattern = value` 与 `while let Pattern = value` 复用枚举 `match` 模式与移动/借用规则。
`if let` 只匹配一次，成功绑定只在 then 块有效；支持 else 与 else if let，分支结果规则与 if 一致。
`while let` 每轮重新求值，失败退出；绑定限本轮，循环返回 Unit，支持 break / continue / return。
右侧和成功块可挂起，恢复时不重放副作用；尚无 `&&` 模式链、守卫或顶层非枚举解构。

普通二元运算、调用实参按从左到右求值；已经读取的 Int32 等值不受后续赋值影响。
引用是对原值的访问能力，不会自动复制其指向的数据；冲突访问由借用检查拒绝。
`&&` 左侧为 false 时不求值右侧，`||` 左侧为 true 时不求值右侧。
短路规则同样适用于右侧副作用和挂起调用；跳过的路径仍须通过名称、类型和挂起约定检查。
左操作数必定执行，其序列中的声明遵守当前作用域；右操作数可能不执行，其中的新声明
仅在该操作数内有效。对已有外层 var 的赋值仍然生效，圆括号本身不引入新作用域。

四种整数加、减、乘采用各自位宽环绕；仅有符号整数支持一元负号，也按位宽环绕。
除法向零截断，有符号 `MIN / -1` 规定为 `MIN`；无符号比较和除法保留非负数含义。
`%` 与乘除同级，非零余数与被除数同号；`MIN % -1` 为 0，仅整数支持。
除法和余数的除零是运行时失败，不能变成正常的 `0`。四种整数的这些规则已在 JIT、AOT 和解释器实现；
原生生成代码显式检查除数，不依赖机器陷阱捕获。错误协议见[架构说明](architecture.md#原生错误传播)。

`~` 按位宽反转，左移截去高位，有符号右移补符号位，无符号右移补零。
移位两侧都要求同型，包括移位量；负数或大于等于位宽的移位量在执行时失败，即使它是常量。
先完整检查移位量，再执行机器移位，不采用处理器的掩码/取模行为；错误传播与除零一致。
`flags & mask == 0` 按 `(flags & mask) == 0` 解析，`1 << 2 + 1` 按 `1 << (2 + 1)` 解析。
`&` / `|` / `^` 均求值两侧，不能替代 Bool 短路运算。

match 分支以逗号或真实换行分隔，分支结果可直接写按位或 `a | b`。
join/race 分支最外层的 `|` 保留为分隔符；按位或写为 `(a | b)` 或 `{ a | b }`。
括号、调用参数、元组、记录字段和块内部允许按位或；闭合定界符后恢复外层分支规则。
嵌套 match 自己管理逗号与换行分支分隔符，不进行按名称或后续 `=>` 猜测；表达式沿用换行与圆括号的通用规则。

当前 `1 + 2 * 3` 为 `7`；依赖旧版同优先级规则得到 `9` 的代码应迁移为 `(1 + 2) * 3`。
一元运算、算术、位运算、移位、比较和短路 `&&` / `||` 均已实现。

## 7. 条件、循环与提前结束

`if` / `else`、`else if`、`while`、`for`、`return`、`break` 和 `continue` 均已实现。
for 使用同步 Iterator.next 与关联 Item；`Range<T>` 支持八种整数及实现 Step 的 Copy 类型。
`a..b` 为半开区间，`a..=b` 为闭区间；也可显式导入 range/range_inclusive 调用。
Array、FixedArray、Slice 支持 `&xs[a..b]` / `&mut xs[a..=b]` 的有界范围切片，沿用现有借用检查。
Array.into_iter 按原顺序消费元素，Array 与 Slice 的 iter/iter_mut 通过借用游标给出 &T / &mut T。
Map 的 keys/values/values_mut 切片可通过相同接口进行单列遍历；
Map.iter/iter_mut 每轮提供 Entry 借用视图，键只读、值按游标权限访问。
for (key, value) in &table 支持键值解构；for index, (key, value) in &mut table
再增加编号。编号根据循环体推导统一整数类型，无约束时默认 Int32，冲突报错。
借用游标使用 advance/current 两步接口，不改变普通 Iterator 的 @noescape 契约。
普通输入经 IntoIterator 转换一次；Array 支持按值消费以及 &values / &mut values 借用入口。
Slice 与 Map 引用也自动生成借用游标，自定义普通容器可实现 IntoIterator。
当前规则见 [for 循环与迭代器](language.md#for-循环与迭代器) 和 [范围表达式](language.md#范围表达式)，
整数范围模式见 [当前参考](language.md#整数范围模式)。普通迭代器已支持 take/zip/map/filter
[惰性组合器](language.md#惰性组合器)，借用游标组合等后续目标见 [专项计划](for-iterators.md)。
以下示例当前可运行：

```joky
fn absolute(value: Int32) -> Int32 {
    if value < 0 { -value } else { value }
}

fn sum_until(n: Int32, limit: Int32) -> Int32 {
    if n <= 0 { return 0 }
    var i = 0
    var total = 0
    while i < n {
        i = i + 1
        if i == 2 { continue }
        if i > limit { break }
        total = total + i
    }
    total
}
```

`absolute(MIN)` 仍为 `MIN`，按 32 位环绕规则计算，不承诺数学意义上的非负结果。

- `if condition { ... } else { ... }` 是表达式，两条正常结束路径的结果类型必须相同。
  条件只求值一次，只执行选中的分支；允许 `else if`。
- if 条件中序列的新声明仅在条件内有效，不进入任一分支或后续语句；
  对已有外层 `var` 的赋值仍然生效，与 while 条件采用相同规则。
- 无 `else` 时整个 `if` 为 Unit；then 分支正常结束时也必须为 Unit。
- `while` 每轮先检查条件，正常结束结果为 Unit，循环体正常结束的末值丢弃。条件内序列的新声明
  不泄漏到循环体或循环外，循环体每轮有独立的局部绑定。
  条件求值也处于该循环的跳转范围内；所有条件路径都提前跳转时，循环体必须为空。
  例如 `while (break) {}` 正常结束，`while (return 42) {}` 返回函数，`while (continue) {}` 持续循环。
- `break` 退出当前函数中最近一层 `while`/`for`；`continue` 回到该循环的条件检查或取下一项，均不要求分号。
  循环外使用报错，不支持标签或 `break value`。
- `return value` 结束当前函数；没有值的 `return` 返回 Unit，必须匹配函数返回类型。
  返回值按非序列表达式解析，返回整个序列的值需写 `return (a; b)`。
  块内 `return` 后的换行结束裸 return；跨行返回值写成 `return (` 后换行展开表达式。
  不允许从函数体内部返回到调用者的调用者。
- 提前结束的路径不参与分支结果类型合并；其他可达结束路径仍须匹配类型。
  不引入用户可写的 `Never` 类型；明确跳转后的表达式、运算右侧或后续实参报不可达错误。
  可达性按结构判断；字面量 `while true`（可加圆括号）没有退出当前循环的 `break` 时不正常结束，
  如 `fn answer() -> Int32 { while true { return 42 } }` 无需补返回值。
  不扩展到一般常量推导，也不排除 `if false { break }` 这样的分支；内层循环的跳转只作用于内层。
  跳转参与运算时须用括号或块，例如 `1 + (return 2)`；尾随分号不改变跳转。

## 8. 挂起与结构化并发

管道分支形式先由 `scope` 改名为 `parallel`，现已统一为 `join`，行为不变。
旧 `parallel { ... }` 和管道式 `scope { | ... }` 均给出迁移诊断，不提供别名。
`isolate { body }` 已实现为显式失败边界，语义与限制见 [语言参考](language.md#失败隔离-isolate)。
它是后接块时的上下文词，监督策略在其返回的 Result 上组合。

顺序主体的 `scope` 与动态子任务 `branch` 已实现并通过三后端验收：解析、所属关系、
捕获移动与借用检查、动态登记、调度轮次、汇合与取消清理均在
JIT、解释器与独立 AOT 上一致。语义、迁移与验收记录见
[结构化并发作用域开发计划](structured-concurrency-scopes.md)。以下示例使用 `join`
展示既有管道分支形式。

```joky
extern fn wait_tick() @suspends

fn worker(count: Int32) @suspends {
    var i = 0
    while i < count {
        wait_tick()
        i = i + 1
    }
}

fn run_pair() @suspends {
    join {
        | worker(2)
        | worker(3)
    }
}
```

此形式当前已经支持；上例的自定义 `wait_tick` 需要嵌入方注册并驱动。
纯 Joky 程序可导入 `joky/task`，使用 `yield_now()` / `sleep_ms(UInt64)`，
再从 `fn main() @suspends` 调用 worker；CLI 的 JIT、解释器及独立 AOT 均能驱动。

- 普通函数只能调用同步函数；`@suspends` 函数可调用两者，挂起约束沿调用链传播。
  不另加 `async` / `await`，标注也不保证调用必定挂起。
- 恢复必须继续挂起位置，不重放已完成的实参求值、赋值或宿主副作用。
- `join` 和 `race` 只能在挂起函数中使用，至少有一个分支；每个分支必须是挂起函数调用。
  join 接受不同的无引用结果类型；race 要求各分支返回相同的无引用类型，整个表达式返回获胜值。
  按分支书写顺序、实参从左到右准备全部参数，之后开始分支轮询。
  引用及含共享引用聚合可传入分支；共享读允许重叠，独占借用不能与其他分支的读写重叠。
  较早参数的借用在后续参数求值期间已生效；普通分支借用直到整个操作完成或取消才结束。
  分支可分配，所有嵌套分支共享根任务 arena 和预算；join 不回收对象。各分支按源参数的保留效果
  检查任务期存储前置条件；仅有分配能力不会保留全部引用输入。
- 所有分支完成后 `join` 才返回按源码顺序的结果元组，混合结果保留 Unit 位置，
  单个非 Unit 分支返回 `(T,)`，全 Unit 分支仍返回 Unit。分支失败使整个 join 失败，
  并取消其余分支、清理已接收的拥有结果。
  父任务取消也取消其子任务。核心阶段没有 `defer` 或用户析构语法；所有权扩展后，
  取消必须释放已初始化且仍由任务拥有的值，清理动作同步完成、不可挂起，见第 10 节。
- `race { | first() | second() }` 按源码顺序轮询，首个观察到的完成或失败决定结果：
  完成返回获胜分支的值，失败终止整个任务；同轮就绪按轮询顺序处理。父函数继续前同步清理
  其余分支及嵌套子帧，后续分支可能从未被轮询，已发生副作用不回滚。
  普通分支借用在此边界结束，实际保留的任务期存储借用及 arena 对象仍保持到根任务结束。
  无引用拥有结果的清理责任先交给父任务，败方清理失败则释放结果并传播错误。
  不返回获胜编号，不自动合并异构类型；Result.Err 也属于正常完成，不新增外部异步取消 ABI。
- `scope` 返回主体末值，汇合前保存、汇合后交付；支持与 join / race 相同范围的无引用结果，
  空主体及尾随分号仍返回 Unit。`branch` 仍为 Unit；跨 scope 的 return / break / continue 仍先汇合再跳转。
- 当前 `join` / `race` 表示单线程协作并发，不承诺并行、抢占或 CPU 循环公平性；执行限额由嵌入 API 配置。
- `return` 只完成当前分支函数；不能逃出父函数或父 join。
  `break` / `continue` 不得跨函数边界，两者都不接受任意语句块作为分支。

可选多线程模式按[任务执行器专项计划](task-parallel-executor.md)推进：直接覆盖同一任务树的
join / race 分支和 branch，保留宿主可选的单线程执行及 Godot 主线程路径。
线程资格、取消清理屏障和模式间顺序差异属于待实现契约，不改变上述当前行为。

后续服务端并发按[状态域与任务并发设计草案](server-concurrency.md)推进：长期状态与任务生命周期分离，

### 8.1 后续并发构造与组合器（仅设计）

本节记录后续建议，不构成当前实现承诺；此次仅完成 `parallel` → `join` 的名称迁移。
不修改 `branch` 的正常汇合语义，不实现 `background`、`select` 或以下组合器，也不提前保留新关键词。
并发构造规定完成、失败与取消的规则；是否使用 worker 线程由宿主执行配置决定，
单线程模式与 Godot 主线程路径继续保留。名称 `join` 不暗示多核同时执行。

| 名称 | 分工 | 状态 |
| --- | --- | --- |
| `scope` | 顺序执行主体，拥有动态子任务，负责汇合与清理 | 已实现 |
| `isolate` | 局部失败边界，清理后返回 Result；取消继续传播 | 已实现首版，见语言参考 |
| `branch` | 必须等待的动态子任务；正常退出 scope 前必须完成 | 已实现，保持现有语义 |
| `join` | 静态分支全部完成，按源码顺序返回结果 | 已实现，本次仅改名 |
| `race` | 首个观察到的完成或运行时失败决定结果，取消并清理其余分支 | 已实现 |
| `background` | 作用域内辅助任务，随必要工作结束而取消 | 后续设计 |
| `select` | 选择一个就绪的通信或事件操作 | 更后期设计 |

不把现有 `branch` 改成 Verse 风格的随上下文结束而取消：已有代码依赖正常退出时等待它。
使用独立的 `background` 表达辅助工作，可在同一 scope 中同时表达“必须完成”和“陪同运行”：

```text
// 设计伪代码，background 尚未实现。
scope {
    background { report_progress() }
    branch { load_assets() }
    prepare_scene()
}
// prepare_scene 与 load_assets 均结束后，取消 report_progress，并等待清理完成。
```

`background` 提前正常完成不结束 scope；它的运行时失败默认仍使所属 scope 失败。
主体结束但必要 branch 尚未完成时，辅助任务继续存活；主体和全部必要 branch 完成后，
才取消剩余辅助任务并等待清理屏障，再交付 scope 结果。失败或外部取消停止整个子树并清理。
它不表示低优先级、独占线程或脱离父任务；依赖其已启动/已就绪时必须显式握手。

`select` 应围绕可选择操作建立独立的登记、选择与提交契约，不能直接作为 `race` 的别名。
例如 Channel 接收的败方不得消费消息；任意 I/O 或有副作用的函数并不会因放进 select 自动变得取消安全。
需要先具备相应通信原语与取消安全保证，再确定具体语法。

组合策略优先放在库中，不为每种结果策略增加关键词：

| 建议 API / 模式 | 契约与依赖 |
| --- | --- |
| `first_ok` | 并发尝试候选，首个业务 Ok 获胜；候选 Err 不提前结束；全部 Err 时聚合失败 |
| `first_completed` | 返回首个完成结果，其余任务继续由显式外层 scope 拥有；依赖可管理的任务句柄，不做隐式游离任务 |
| 收集全部业务结果 | 让 join 的分支返回 Result，全部完成后检查各项；运行时失败仍按现有规则终止 |
| 超时 | 使用 race 与计时器，或提供库包装；保留取消与清理屏障 |
| 限流 / 有界并发 | 准入许可、Channel 与库组合，分别控制活动任务数及队列容量 |
| 监督与故障隔离 | 显式服务/所有者 API 定义重启和错误策略，不静默吞掉任意运行时错误 |
| Actor、流水线、流 | 围绕有界通信与明确生命周期提供库抽象 |
| 长期独立任务 | 必须有实例、服务或宿主所有者负责停止和回收，不提供无主 detach |

`first_ok` 接收尚未调用的挂起函数值，让组合器负责启动候选；不能先顺序调用再传入结果。
以下仅为 API 草图，函数名、错误类型和聚合形式尚未实现或定稿：

```text
// load_primary / load_backup 均是 @suspends 函数，返回 Result<String, LoadError>。
fn load_config() @suspends -> Result<String, FirstOkError<LoadError>> {
    task.first_ok(load_primary, load_backup)
}
```

例如主源在第 1 轮返回 Err、备用源在第 3 轮返回 Ok，first_ok 继续等待并选取备用源；
若使用 race，第 1 轮的 Err 已是正常完成的获胜值。两者都返回 Err 时，建议返回
`AllFailed`，错误按候选输入顺序收集；它不等于第一个错误，也不自动重试。
一个 Ok 获胜后须取消其余候选并完成清理再交付结果，已经发生的副作用不会回滚。
运行时失败仍终止整个组合，不能伪装成业务 Err；清理失败也不能被成功结果掩盖。
多个候选同时就绪时采用所在执行模式的完成仲裁，不额外承诺多线程中的源码优先级。

实现这些库策略仍需内部受控的任务组合能力；普通源码的 join/race 不足以直接拼出 first_ok。
结果任务句柄、挂起闭包及统一取消接口需另行设计，当前已有的具名挂起函数值可作为初期输入形式。
空候选的错误形式、异构错误归一化和可变数量候选留到 API 阶段确定。
继续沿用 `@suspends`；暂不引入 `spawn`、`fork`、`go`、`rush` 或 `async` / `await`。

## 10. 完整类型系统目标

本节主要是后续设计；以各小节明确标注的已实现子集为准。类型系统由基础值、组合类型、
泛型约束、可调用契约和资源规则共同组成；ADT 只覆盖其中的积类型与和类型。
除非明确允许，类型必须精确匹配，不存在通用 Any、隐式数值转换、结构体鸭子类型或类继承。

### 10.1 基础类型与字面量推导

**已实现**：Int32 / Int64 / UInt32 / UInt64、局部上下文整数字面量定型、同型运算、环绕和除零失败，
以及位运算、受检移位和显式 wrapping 转换，覆盖三后端同步 / CPS。
UInt8、Rune 也已实现，实际支持的运算与边界见 language.md。
全局约束推导尚未实现。八种整数（含 Int8 / Int16 / UInt16）与受检转换矩阵均已实现；静态 trait 约束已实现。
浮点和剩余窄整数的契约细化、后端/ABI 开发顺序及验收见
[数值专项阶段](persistent-instances-numerics.md#42-数值线)；USize/ISize 不作为 Godot 首版前置条件。

| 类别 | 类型 | 规则 |
| --- | --- | --- |
| 布尔 | `Bool` | true / false，不隐式转成数字 |
| 有符号整数 | `Int8`、`Int16`、`Int32`、`Int64` | 固定位宽，二进制补码 |
| 无符号整数 | `UInt8`、`UInt16`、`UInt32`、`UInt64` | 固定位宽，非负整数 |
| 平台尺寸 | `USize`、`ISize` | 当前目标平台的指针位宽，用于长度和索引，不直接作为持久化格式 |
| 浮点 | `Float32`、`Float64` | IEEE 754 二进制浮点，保留 NaN、无穷和有符号零 |
| 字符 | `Rune` | 一个 Unicode 标量值，不等于一个字节或一个用户感知字符 |
| 文本 | `String` | 拥有不可变 UTF-8 文本，字面量同为 String；非 Copy，显式 clone 与共享借用已实现；宿主使用版本化文本出口 |
| 无信息结果 | `Unit` | 唯一值用空块 `{}` 表示，表示正常完成 |
| 不返回 | 内部 `Never` | 没有正常完成路径；暂不开放用户书写 |

- 整数字面量由参数、返回值或注解等上下文定型，无约束时默认为 Int32；浮点默认 Float64。
  泛型仍有歧义时要求显式类型参数或注解，不按函数名猜测类型。
- 整数支持十进制、十六进制和二进制及数字间分隔符；浮点写作 `1.0` 或 `1.5e-3`，必须有小数点且两侧都有数字。
  `1` 可以在明确的 Float64 上下文中成为浮点字面量，但已经定型的 Int32 值不会因此隐式转型。
- 各整数类型按自己的范围检查字面量，负号和有符号最小值采用第 3 节相同规则。
  正的最小值绝对值只在紧邻的一元负号下被允许；无符号类型不接受负数字面量或一元负号。
- 同一算术运算的两个已定型操作数必须具有相同数值类型。整数加减乘以及有符号负号按位宽环绕，
  除法向零截断，有符号 MIN / -1 为 MIN，整数除零失败。浮点按自身规则计算，不套用整数除零规则。
- 新增数值类型的比较也要求两侧同型。浮点 NaN 不等于自身，有 NaN 参与的有序比较为 false；
  因此原始浮点不实现要求等价关系的 Eq，不能直接用作 Map 键，需使用定义了相等与哈希规则的包装类型。
- Rune 字面量写作 `'a'` 或 `'\n'`，解码后必须恰好一个合法标量值；代理项非法。
  Rune 的 32 位存储宽度不意味着任意 UInt32 都能构成 Rune。
- String 不提供按整数下标返回“字符”的语法；字节访问与 Rune 遍历使用不同的库接口。
  `String` 的不可变性约束文本内容，`var` 绑定仍可替换为另一个 String。
- 拥有型文本目标采用非 Copy String、显式 clone 与 `&String` 只读借用；StringBuilder 可变构造后
  消费式 finish 转移缓冲区。首版字面量构造拥有值、子串复制，不公开 Str、Substring 或 ffi.CString，
  C 字符串由边界适配。String 的拥有存储、clone、借用与字面量以及同步 StringBuilder、UTF-8 转换和复制式子串已实现；新的直接 C 文本适配尚未实现。迁移、热更新与旧宿主 ABI 的验收见[专项计划](string-storage-ownership.md)。

转换通过具名函数完成，不提供一个含多种隐式行为的 `as`。四个 wrapping 整数转换函数的目标签名是：

```joky
fn int32<T: Integer>(value: T) -> Int32
fn int64<T: Integer>(value: T) -> Int64
fn uint32<T: Integer>(value: T) -> UInt32
fn uint64<T: Integer>(value: T) -> UInt64
```

这里 `Integer` 表示静态整数约束，首版接受 Int32 / Int64 / UInt32 / UInt64；
不包含 Bool、浮点、文本或仅在底层使用整数存储的 opaque 类型。
**当前转换仍是编译器内建调用；无约束的泛型函数已实现，但以上 Integer 约束声明仍不可直接编写**，也未引入普通函数重载。
类型参数从实参自身推导，结果类型不反向约束实参；无约束字面量仍默认 Int32。
因此 `int64(2147483648)` 越界，而先绑定 `let n: Int64 = 2147483648` 后调用 `int32(n)` 得 `-2147483648`。

wrapping 转换窄化保留低位，宽化按源类型符号扩展或零扩展，同位宽保持位模式；
函数名决定如何解释结果。转换自身不失败，但实参的失败、挂起和提前跳转仍正常传播。
这些小写名字保留在函数命名空间，不能由用户函数、extern 或宿主绑定替换；
当前具体调用与迁移规则见 [显式整数转换](language.md#显式整数转换)。

受检转换已采用实例方法，不再规划额外的 `try_int32` 内建函数：

```joky
// The prelude supplies this ordinary Joky implementation.
impl Int32 {
    fn to_u64(self) -> Option<UInt64> {
        if self < 0 { Option.None } else { Option.Some(uint64(self)) }
    }
}
```

`to_i8/to_i16/to_i32/to_i64/to_u8/to_u16/to_u32/to_u64` 覆盖全部 64 种组合，一律返回 Option，越界为 None；强制转换继续写同名小写内建。
`MIN` / `MAX` 是各整数类型的关联常量，范围检查和转换包装由 Joky 库源码实现；无需先实现 Integer trait。
库导入、名义类型身份及明确的当前限制见[固有方法与关联常量](language.md#固有方法与关联常量)。
浮点到整数需另行显式选择截断或舍入并检查范围，不自动加入上述四个整数函数。
普通库调用失败通过 Result 表达；分配耗尽等运行时失败不能悄悄伪装成成功的值。

### 10.2 记录、元组、别名与名义身份

**已实现的记录子集**：`struct` 名义值类型、Copy 或拥有型类型参数、空记录、嵌套、字段读取/赋值、完整构造；
Copy 实例支持同步及挂起函数的参数/返回值。Copy 字段支持 Int32 / Int64 / UInt32 / UInt64 / Bool / Unit / Ptr、共享引用及这些类型组成的记录、有限枚举和元组；
含共享引用的值可用于同步/挂起调用链及受检的 join 分支；
类型注解写 `Pair<Int64>`，构造支持字段 / 上下文推导或 `Pair::<Int64> { ... }`。
同步拥有字段支持 String、StringBuilder 和容器，按值移动并递归清理；opaque 资源字段、记录解构和整体相等比较尚未开放。具体记录及完整泛型记录的固有方法已实现。
准确的解析消歧、实现限额及宿主边界见[当前记录语义](language.md#记录)。
**已实现的元组子集**：结构化 Copy 或拥有型元组、单元素尾随逗号、嵌套 let / var 解构、`_` 丢弃及整体注解；
支持字段、枚举载荷和同步传参返回，Copy 元组也支持 CPS。支持 `.0` / `.1` 十进制成员访问、嵌套投影、成员赋值与借用；尚无动态索引或解构赋值。
求值顺序、相邻括号的消歧及迁移规则见[当前元组语义](language.md#元组与解构绑定)。
下面示例的 UInt64、拥有型 String 与 Float64 均已实现。

```joky
struct User {
    id: UInt64
    name: String
    active: Bool
}

fn make_user() -> User {
    User { id: 42, name: "Ada", active: true }
}

fn coordinates() -> (Float64, Float64) {
    (12.5, 30.0)
}

type UserNumber = UInt64

struct UserId { value: UInt64 }
struct OrderId { value: UInt64 }
```

- struct 和 enum 是名义类型：声明不同即类型不同，字段相同也不能互换。
  `UserId` 与 `OrderId` 因而不同；type 别名则完全等同于被引用类型，不创建新身份。
  **已实现**模块级 `type Count = Int32` 和 `type PairOf<T> = (T, T)`，目标也可为记录、枚举、元组、已有基础类型、注册的 opaque 类型或其他别名。
  支持前向引用、任意顺序及别名链；重复别名、与已有类型冲突、未知目标或别名环均拒绝，即使未使用。
  类型与值命名空间独立；别名在定义模块解析，公开别名可导入及重命名，重载不污染宿主类型注册器。
  别名不能作构造函数或成员命名空间；不支持局部声明或带点的声明名。普通泛型调用、记录、别名、枚举和元组可使用 Copy 或拥有型实参，包括 String 和 StringBuilder，
  包括未用于目标的参数；每次规范化最多 256 个不同别名应用（含刚性参数应用），共享目标不重复展开。
  参数最多 64 个，目标沿用布局上限；不能形成别名环，经过未使用参数的依赖环也保守拒绝。
- 记录构造必须恰好提供所有字段，不重复、不依赖隐式默认值；字段按源码书写顺序求值。
  `User { name, age }` 中的 `name` 等价于 `name: name`，支持与显式初始化混用；
  名称查找、复制或移动及字段访问权限沿用显式写法，详见[当前记录语义](language.md#记录)。
  相邻字段声明和相邻初始化项之间必须有逗号或真实换行（不插入丢弃值的分号）；
  不能以此省略函数实参的逗号。字段默认私有，`pub` 字段在类型可见时可跨模块访问。
  相邻枚举变体之间同样必须有逗号或真实换行，载荷类型的尾随逗号仍允许。
- 元组按元素类型、数量和位置匹配；`(T)` 是分组，`(T,)` 才是单元素元组类型，
  `(value,)` 同理。`()` 暂不作为另一种 Unit 表示。
- 可用 `let (x, y) = coordinates()` 解构元组；普通 let / var 模式必须不可失败。
  enum 分支解构放入 match，不能通过可能失败的 let 隐式丢掉其他情况。
- 字段写作 `user.name`；拥有值的可变字段位置需要 var 或独占可变借用。
  读取非 Copy 字段须明确是借用还是移动；不开放会留下半初始化记录的部分移动，
  单一拥有字段包装可通过字段移出消费整个记录；记录解构已实现（见 language.md），
  可复用的部分移动仍待实现。

### 10.3 容器与递归布局

目标是以 Joky 编写这些参数化库类型，编译器与运行时提供泛型、借用、布局和通用存储原语，
不为每个容器增加关键字。Array、List、Set、Map、Option / Result 的已实现子集及拥有型元素规则见
language.md 和各自阶段文档；数组方法由普通 impl 提供。FixedArray 已支持 F2 独立值、聚合嵌入、嵌套和 Array 元素，以及 F3 元素引用和切片、F4 C 数组字段与同步引用，
其余组合及尚未验收的资源能力仍是规划。完成 arena/FFI 阶段不足以自动获得其余容器，需另行推进
[容器与所有权扩展](arena-borrowing-ffi.md#61-容器与所有权扩展)。FixedArray 的首版范围、
内联存储、常量参数、C 数组映射及 F0–F5 验收见[专门开发计划](fixed-array-storage-ownership.md)。
F0 已完成设计冻结，F1–F4 已实现常量参数、类型布局、数组值及聚合组合、元素引用/切片和 C 数组字段/同步引用；F5 已完成首版模型集成与边界验收。

| 类型 | 所有权或布局 | 必要约束 |
| --- | --- | --- |
| `Array<T>` | 拥有动态长度的连续元素 | 不隐式复制 T；可变操作需要独占访问 |
| `FixedArray<T, N>` | 内联存放 N 个元素，N 属于类型；已支持构造、复制、受检访问、聚合/嵌套、Array 元素及同步直接/间接调用 | F0 冻结 N 为 UInt64 常量参数，首版单维最多 65,536；另受逻辑工作量、布局与任务预算限制 |
| `Slice<T>` | 非拥有的连续元素视图，动态大小 | 通常经 `&Slice<T>` / `&mut Slice<T>` 使用，不能裸值传递 |
| `Map<K, V>` | 拥有键和值 | K 无引用，满足 BorrowEq、BorrowHash；旧 Copy 协议自动适配 |
| `List<T>` | 拥有元素，以内部索引连接同步可变双向链表；L1–L4 已验收 | 首版元素准入沿用 Array，位置不代表稳定节点身份 |
| `Set<T>` | 拥有无序去重元素；S1–S3 已验收 | 元素准入沿用 Map key，查询与插入要求 BorrowEq、BorrowHash |
| `Option<T>` | None 或 Some(T) | 没有跨类型通用 null |
| `Result<T, E>` | Ok(T) 或 Err(E) | 业务错误是数据，不自动取消 join 的其他分支 |

泛型类型参数默认要求有确定的值大小；裸 dyn 已采用固定大小的拥有句柄，Slice 等视图仍须放在明确的引用后面。JSON1a 已支持经 `Array<T>`、`Map<K, V>` 等拥有容器间接存储的有限递归值树，
包括别名、互递归和有限泛型实例图；Box 尚未实现。
`struct Node { next: Node }` 的无限内联布局非法。
容器类型默认不变：即使两种元素有相关能力，也不能把 `Array<A>` 当作 `Array<B>`。
引用生命周期的缩短由借用规则处理，不作为任意容器协变的理由。

Array 与 Slice 提供返回 Option 的受检访问，不把越界转换成一个伪造元素；
数组与切片的下标运算符已实现，越界为运行时错误；求值顺序和借用约束见[下标访问](language.md#数组与切片下标)。
数组按 `Array<Int32>` → Copy 元素泛型数组 → 非 Copy 元素与嵌套容器逐步验收。
即使元素是 Copy，独占管理缓冲区的数组也不可隐式复制；其管理权、已初始化范围和退出清理
必须受检。元素或切片借用期间禁止冲突的扩容、删除等操作，借用结束后可继续修改容器。
这种临时借用与共享对象图的永久封存分别建模，不能直接把含引用对象的封存规则套到所有容器上。

拥有型数组元素已支持 `borrow_ref(&Array<T>, UInt64) -> &T` 及同名方法，只读访问资源的 Copy 字段、
共享借用方法及内部拥有字段；派生引用借用整个原数组，最后使用后恢复修改权限。无引用元素视图可跨挂起，
禁止视图逃逸到聚合、arena 对象或宿主 ABI；越界产生运行时错误。Copy 元素沿用 Element/Slice 接口，无引用 Copy 元素也支持直接引用，
拥有型元素及切片支持 `borrow_ref/borrow_mut_ref` 和共享/独占借用式 match，完整规则见[拥有型数组元素](language.md#拥有型数组元素)。

当前数组扩容后立即回收旧载荷及临时控制块，显式 release 消费拥有者并退还预算；
尚未显式释放的存储由根任务兜底，自动析构留待 Drop。只读链表和封存循环图不等于可变链表，后者需另验收节点所有权、
链接修改、删除后的借用失效及回收。String 已可用于同步数组元素、Map value 及通过借用式协议的 Map key。

### 10.4 枚举、模式匹配与动态数据

**已实现的子集**：带 Copy 或拥有型类型参数的名义枚举、零或单个载荷、有限嵌套、`match` 表达式、
穷尽/重复/不可达检查、载荷不可变绑定及 `_`；Copy 实例及无引用拥有型实例支持同步与 CPS；借用按稳定存储、生命周期和访问权限检查。
构造须写 `Enum.Variant` / `Enum.Variant(value)`；只有模式可从被匹配类型推导限定名。
载荷支持 Int32 / Int64 / UInt32 / UInt64 / Bool / Unit / Ptr / 共享引用及 Copy 或拥有型记录、枚举、元组与 Array；
拥有型实例禁止混入引用，单个载荷可用记录或元组组合多个值。
match 支持递归载荷模式，包括元组、嵌套枚举和 `_`；共享借用匹配将拥有载荷绑定为 `&T`、Copy 载荷绑定为快照，保留原值。
独占匹配把每个载荷绑定为 `&mut T`，递归模式支持不重叠成员的同时借用；支持整数、Bool、Rune 和序列模式，暂不含 guard。
解析边界、存储成本、限额及完整规则见[当前枚举语义](language.md#枚举与模式匹配)。
以下 Option / Result 声明已可编译，实例支持 Copy 或拥有型载荷，包括 String 和 StringBuilder；动态数据模型仍依赖后续能力：

```joky
enum Option<T> {
    None
    Some(T)
}

enum Result<T, E> {
    Ok(T)
    Err(E)
}
```

构造支持 `Option.Some(42)`、`Option.None::<Int32>` 与 `Result.Ok::<Int32, Bool>(42)`，
缺少类型信息时要求注解；详细推导及限额见[当前泛型枚举](language.md#泛型枚举)。
下例的非 Copy String 载荷及消费匹配已可编译：

```joky
fn present(result: Result<Int32, String>) -> String {
    match result {
        Ok(value) => value.to_string()
        Err(message) => message
    }
}
```

整数 `to_string` 由文本库提供。match 是表达式，要求穷尽所有情况，
正常完成的分支具有相同结果类型；不提供隐式贯穿。返回、失败等终止分支不参与结果类型合并。
已实现整数/Bool/Rune 字面量、整数范围、序列、绑定、`_`、元组和枚举构造模式；`_` 覆盖尚未列举的情况。
分支书写为 `pattern => expression`，多步分支可用块或括号序列，不要求尾随分号。相邻分支必须用逗号或真实换行分隔，块分支也遵循同一规则；允许尾逗号。
目标设计中同名构造项由被匹配类型或期望类型确定，无法唯一确定时需写 `Result.Ok` 等限定名。

按值匹配会消费非 Copy 的被匹配值；匹配 `&value` 时，载荷绑定获得共享借用，
匹配 `&mut value` 时获得独占借用。借用匹配不能悄悄把非 Copy 载荷移出原值。
匹配分支有自己的绑定作用域；条件中或分支中的局部声明不会泄漏。

动态输入使用显式数据模型，而非让每个类型都可接受任意值：

```joky
enum Value {
    Null
    Bool(Bool)
    Number(Float64)
    Text(String)
    List(Array<Value>)
    Object(Map<String, Value>)
}
```

这里 `Null` 只属于 Value，取值需要匹配或受检转换。此简化模型不保证精确保留所有 Int64 / UInt64，
需要无损数字往返的解析库应提供另外的数字变体。Object 依赖 String 的 Eq、Hash 库实现。

### 10.5 泛型、trait 与分派

**已实现**最小泛型函数：类型参数、从实参局部推导、显式 `::<...>` 调用、定义时刚性检查，
以及三后端共用的有界编译期实例化。普通调用的类型实参支持 Copy 与拥有者，包括 String 和 StringBuilder；
独立泛型函数值使用相同的实参范围，opaque 类型实参不支持。无约束参数按移动检查；复制需要显式 `T: Copy`。静态 trait 约束及参数化记录、枚举与透明别名已实现。

```joky
fn identity<T>(value: T) -> T { value }
fn first<T, U>(left: T, right: U) -> T { left }
fn wide() -> Int64 { identity::<Int64>(42) }
```

已有实参类型优先，未确定的整数字面量默认 Int32；外层返回值注解不反推类型参数。
缺少局部信息时需显式指定全部类型实参；没有部分 `_` 推导。
即使模板未使用，也检查其函数体；不能因某次实例恰好是整数或记录而放行无约束的操作。
类型参数只在所属函数内有效，支持元组与枚举类型应用；具体函数实例不成为模块公开入口，宿主使用普通包装函数。
实例缓存、编译限额和完整限制见[当前泛型语义](language.md#泛型函数)。

具体类型及 Copy 参数化记录 / 枚举的固有 `impl` 已实现，
泛型目标形如 `impl<T> Pair<T>`，方法继承 impl 参数，也可独立声明 `fn method<U>`，两层参数共同复用函数实例化。
关联函数支持 `Pair.make::<Int64>(...)` 和 `Pair::<Int64>.make(...)`；实例接收者确定类型实参。
完整规则和限制见[泛型固有 impl](language.md#泛型固有-impl)。静态 trait 与能力约束已实现：

```joky
pub trait Eq {
    fn eq(&self, other: &Self) -> Bool
}
struct UserId { value: Int32 }
impl Eq for UserId {
    fn eq(&self, other: &Self) -> Bool { self.value == other.value }
}
fn same<T: Eq>(left: &T, right: &T) -> Bool { left.eq(right) }
```

`T: Eq + Hash` 表示同时具备两种能力；`impl<T: Eq> Eq for Pair<T>` 表示条件实现。
泛型函数只能使用声明的能力，即使模板未使用也检查；不通过具体类型反推能力。
多个 trait 提供同名方法时用 `Eq.eq(left, right)` 消歧；具体类型的可见固有方法优先，
模板已选中的 trait 不会在单态化时被新增方法替换。全部调用静态分派，不引入 vtable。
必需方法与关联类型必须完整，默认方法可覆盖，签名一致；trait 或被实现的名义类型须属于实现模块；相同 trait / 名义类型不允许重叠实现。
trait 由 `pub` 控制导出，使用 `import module.{type Eq}` 导入，方法继承 trait 可见性。
借用规则保持不变，抽象调用默认采用保守存储效果；函数体自动推导参数不逃逸保证，函数类型和方法可声明受检查的 `@noescape` 接口契约；该属性可与 `@suspends` 组合。
单参数 blanket impl 可提供通用协议适配，重叠匹配报错，不开放特化。
详情、编译限额与示例见[静态 trait 与泛型约束](language.md#静态-trait-与泛型约束)。

默认方法、`type Item`、`Self.Item` / `T.Item` / `<T as Trait>::Item`、关联能力与具名等式约束已实现。
当前规则见[默认方法与关联类型](language.md#默认方法与关联类型)，验收记录见[第 4 项计划](trait-default-methods-associated-types.md)。
trait 本身的泛型、方法级泛型、关联默认值、GAT、trait 关联常量、继承、特化、动态挂起 dyn 和运算符重载尚未实现。
Drop 已按专门所有权规则实现，不属于本次待补的普通 trait 能力。
Eq / Hash 的代数规律由实现方和测试保证，不由编译器证明。

**F1 已实现** `<T, const N: UInt64>` 常量参数与 FixedArray 类型/布局元数据；原 USize 方案不再采用。
F2 已实现独立数组值、嵌套与无引用 Copy 聚合组合，F3 已实现元素引用及共享切片，F4 已实现 C 字段与数组引用；当前用法见[常量参数与 FixedArray 类型](language.md#常量参数与-fixedarray-类型)。
函数、记录、类型别名及固有 impl 的参数列表可混合类型与 const 参数，合计最多 64 个；
枚举自身、trait 声明及 trait impl 的 const 参数暂不开放。首版常量实参只接受非负 UInt64
整数字面量或已声明常量参数，模块/关联常量虽已存在也不能直接作为长度实参；不接受计算、
运行时变量、默认 const 值或长度方程推导。N 在值表达式中为只读 UInt64，实例化后替换为立即值；
同作用域形参/局部绑定不能再次遮蔽该 const 参数。
类型中的长度按数值规范化，刚性参数按声明身份判断；N 不同的 FixedArray 是不同类型。
无显式实参时只从普通实参类型推导；显式列表须给齐非 callable 参数，可省略末尾 callable
参数以支持 `from_fn::<T,N>(init)` 的同步 FnMut 回调。泛型函数取值仍需给齐所有实参。
完整的名称绑定、实例键、接口与限额见 [F0 冻结记录](fixed-array-storage-ownership.md#7-f0-核对与冻结记录)。

### 10.6 函数值、闭包能力与挂起效果

**已实现**同步及挂起无捕获函数值、Copy 存储、泛型函数显式取值、名称 / 字段间接调用及三后端执行。
调用后缀适用于任意表达式，支持 `(f)(x)`、`factory()(x)`、下标及解包结果调用；
同一行独立表达式须用分号分隔，跨行仍遵守既有换行规则。
间接调用保守检查失败、分配和引用保留效果，函数值不跨宿主 ABI；完整规则见[函数值](language.md#函数值)。
挂起函数值已接入 Pending / 恢复 / 取消及 join/race 分支；同步闭包及 Fn / FnMut / FnOnce 已实现。

函数类型包含参数、返回类型和挂起约定：

```text
fn(Int32, Int32) -> Int32
fn(String) @suspends -> Result<String, ReadError>
```

```joky
fn apply<T, U>(value: T, transform: fn(T) -> U) -> U {
    transform(value)
}

fn apply_once<T, U, F: FnOnce(T) -> U>(value: T, transform: F) -> U {
    transform(value)
}
```

`fn(...)` 是不捕获环境的语言函数指针类型，可存储、传参和间接调用；其代码所有者必须保活。
它不自动等于任意 C 函数裸指针。泛型函数在确定实例参数后才有这样的具体函数值。
函数参数与返回类型精确匹配，暂不加入函数参数逆变等隐式子类型转换。

每个闭包有独立的环境类型，捕获关系参与借用和销毁检查，由编译器推导；
可调用能力决定如何访问或消费该环境：

| 能力 | 调用需要的访问 | 可保证的行为 |
| --- | --- | --- |
| `Fn(A) -> R` | 共享访问 | 可重复调用，不要求独占捕获环境 |
| `FnMut(A) -> R` | 独占访问 | 可重复调用，允许修改捕获环境 |
| `FnOnce(A) -> R` | 消费环境 | 只保证一次调用，可移出捕获值 |

Fn 同时满足 FnMut 和 FnOnce，FnMut 同时满足 FnOnce。
闭包字面量采用 `|parameters| { body }`，普通闭包自动借用捕获，`move |参数|` 显式转移捕获；
具体推导、能力约束、非捕获到 fn 指针的转换及分阶段验收见
[匿名函数与闭包计划](anonymous-functions-closures.md)。C0 已冻结解析与内建约束身份、
上下文推导、嵌套捕获权限、私有环境 ABI 和清理责任，见该计划第 9 节。
已实现同步局部环境及无引用 move 闭包的记录存储与返回；当前规则见[同步匿名函数与闭包](language.md#同步匿名函数与闭包)。
捕获环境不能转换成 fn 指针；无引用 move 闭包支持泛型记录存储及挂起帧，
并可按受检资格作为同树 worker 的拥有输入。闭包本身仍是同步 callable，借用环境仍不得逃逸；
具体边界见[语言参考](language.md#同步匿名函数与闭包)。

挂起闭包仍是后续目标；若开放 `FnOnce(A) @suspends -> R` 等约束，必须保留效果信息，
传进泛型或转换成动态接口都不能把挂起能力擦除。
同步和挂起入口不按函数指针直接互换，必要时生成符合目标约定的包装函数。
Result 表达可处理的错误结果，`@suspends` 表达执行可能暂停，二者相互独立。
目前只确定这一种效果，不预设通用效果行、I/O 效果推导或效果处理器语法。

拥有型 `dyn Trait` 按 [W3 计划](startup-worker-configuration.md) 实现。裸 `dyn Trait` 表示拥有对象，现有 `&dyn Trait`／`&mut dyn Trait`
表示借用视图；由期望接口类型触发拥有转换，与自定义 Drop 转移共用清理协议。
首版保持动态方法同步，不因此开放挂起动态方法或跨 worker 借用。

### 10.7 所有权、借用与释放

第一版优先采用 [Arena 与隐式生命周期方案](arena-borrowing-ffi.md)，以下为目标规则。
Box / Rc 等其他拥有类型属于后续候选能力，不是 arena 的实现前提。
数据引用已可来自 arena 分配或无引用 Copy 局部值的 `&local` / `&mut local`。
阶段 4a/4b 已实现整个局部值及其内联记录字段借用；Copy 局部引用现已支持跨语言挂起与结构化子任务。显式 Arena 已支持同步 `&arena` 能力借用。
根任务自动拥有一个隐式 arena；`alloc` 返回 `&mut T`，`&*p` 或受检的
赋值/参数共享化得到 `&T`。高级子 arena 接口由 `joky/arena` 提供 `Arena.new()` 和 `arena.alloc(value)`；
同步 helper 接收 `&Arena` 并返回依赖该能力的引用。首版不允许用户函数按值返回 Arena，
也不开放能力聚合、普通泛型携带、闭包捕获、持久化、reset 或跨挂起；当前规则见[同步显式 arena](language.md#同步显式-arena)。

| 形式 | 含义 | 约束 |
| --- | --- | --- |
| `T` | 拥有值 | 非 Copy 值默认移动，移动后原位置不可再读 |
| `&T` | 共享只读借用 | 可以有多个，不能与冲突的独占访问同时有效 |
| `&mut T` | 独占可变借用 | 不可复制，借用期间排除对同一位置的其他冲突访问 |
| 隐式任务 arena | 当前任务的一批稳定存储 | 不作为用户值暴露；任务完成、失败、取消或 continuation 丢弃时整体释放 |
| `Arena` | 显式拥有一批稳定存储 | 非 Copy，高级接口；离开作用域整体释放，引用不得超过拥有者寿命 |
| `Ptr` | 不透明的 C 对象指针（阶段 5b 已实现） | Copy、可空，Ptr.null() 创建空值，Ptr.is_null(value) 判空；无所有权或自动释放；禁止解引用、地址运算、整数及 Joky 引用转换 |
| `Box<T>` | 独占拥有堆上对象 | 随拥有者释放，可承载递归或动态大小对象 |
| `Rc<T>` | 单线程共享所有权 | 显式 clone 增加所有者；引用计数不解决强引用环 |

数值、Bool、Rune、Unit 和无捕获函数指针属于 Copy 值；复合类型只有所有字段都满足
Copy 且没有析构逻辑时才可声明 Copy；当前记录、枚举和元组子集自动满足这一规则，后续开放非 Copy
字段时再提供显式能力声明。资源句柄不能自动获得该能力。
String、Array、Box、Rc 默认不是 Copy；需要复制文本、元素或共享所有权时使用显式 clone，
具体成本由类型说明，不承诺所有 clone 都是深拷贝或常量成本。

let / var 控制绑定可变性，借用类型控制访问权限，两者分开检查。
当前对局部拥有值取 `&mut` 要求 var；`let view: &mut T` 已持有独占能力，允许修改其所指值，
不允许重新绑定 view。参数绑定默认不可重新赋值，也不妨碍 `&mut T` 参数修改所指对象；参数上的 `var` 只改变绑定可变性，不改变引用权限。
`&mut T -> &T` 是单向共享化：短暂调用重借用在调用结束后恢复，赋值、返回或存入对象的共享视图
会冻结原独占访问，不能从 `&T` 重新得到 `&mut T`。
借用不能比所有者活得更久；禁止返回局部拥有值的引用。字段访问自动解引用，
`*p` 复制所指 Copy 值，`*p = next` 替换 Copy 或拥有值并清理旧值；
`&*p` / `&mut *p` 重借用已有引用，`(*p).field` 和显式字段借用沿用隐私与来源检查；
通用 `mem.replace(&mut T, T) -> T` 支持 Copy 与拥有型值，返回旧值并保持原存储完整初始化，`Option.take()` 由此实现；`joky/mem.swap` 交换两个不重叠的独占位置，`joky/mem.drop` 消费并清理一个值；受检引用支持 `*reference`，裸指针仍不能解引用。
自动解引用不能隐式复制或移动整个借用对象，绑定赋值仍表示重新绑定。
局部引用不得存进任务 arena；传给具有 arena 分配能力的函数时，对应参数必须有自动推导或显式契约提供的不保存借用保证，返回引用继续跟踪来源。String 和无引用拥有者支持同步及跨挂起借用，opaque、
引用本身或含引用聚合仍不能作为局部借用目标。参数引用可以从 helper 返回，按值参数的局部引用不能从该函数返回。
局部字段按根对象和字段路径检查：不同字段可分别独占；同一字段及父子路径属于重叠位置。
例如借用 p.left.x 时可以修改 p.left.y，但不能冲突地覆盖 p.left 或 p；字段引用受根绑定的词法寿命约束。
根必须是受支持的无引用 Copy 或拥有型局部值，取借用路径可投影记录字段与元组元素；枚举载荷借用使用 match。
具体例子、作用域和存储限额见[局部值借用](language.md#局部值借用)。

```joky
fn make_point() -> &Point {
    (&*(alloc(Point { x: 1, y: 2 })))
}

fn move_x(point: &mut Point, distance: Int32) {
    point.x = point.x + distance
}

fn choose(flag: Bool, left: &Point, right: &Point) -> &Point {
    if flag { left } else { right }
}
```

示例 Point 为包含两个 Int32 字段的记录。方法接收者可以受检地重借用，不能让已有 `&mut T`
因每次方法调用被无意永久移走。不要求用户写生命周期参数：返回引用依赖所有含引用参数的
并集，函数体按该契约检查，调用方只看签名；不生成或缓存函数体借用摘要。
使用隐式任务 arena 的函数具有同样的存储前置条件；显式签名有 `&Arena` 时，其他引用输入的对象
必须覆盖目标 arena，相关借用保守地保持到目标 arena 释放。没有分配能力的 choose 只按返回值使用期延长借用。
新分配与输入重借用的区分、多个 arena 参数和无来源返回等规则见专项 §3.2。
已有引用作为实参时自动重借用，返回值若携带该重借用，其占用范围相应延长。

专项阶段 1 禁止引用作为类型实参或进入聚合；阶段 2 才开放共享引用字段及 Option / Result
等 Copy 聚合，并按实例检查来源和存储前置条件。`&mut T` 不可复制，不能作为当前 Copy
泛型的实参；T 含引用时由 `alloc` 先产生构造期 `&mut T`，共享发布后必须 `seal`，不能用字段赋值
或 *p = next 绕过。循环共享图通过 `graph { ... }` 中的 graph.alloc 构造句柄、
graph.link 字段连接并在块末尾自动封存；没有独立 graph.seal。阶段 2b 已实现构图子集，
阶段 3a 允许 graph 位于挂起函数中，块内仍不可挂起，封存后对象可跨后续挂起保留。
具体限制见[受检循环图构造](language.md#受检循环图构造)。`&mut T` 字段和可变循环图仍拒绝。
无引用对象的普通 alloc 结果仍可独占修改。

离开作用域时，仍拥有且已初始化的非 Copy 值按逆声明顺序释放，已移动的值不重复释放；
赋值替换拥有值时释放旧值。提前返回、循环跳转、任务失败和取消都必须遵守相同清理规则。
析构不得挂起、传播可恢复业务错误或越过 native 边界 unwind；需要这些行为的资源提供显式
close 操作，析构仅做同步兜底。7c.4 已实现单一拥有字段记录的同步析构：显式导入
joky/drop.Drop 后使用 impl Drop for Resource { fn drop(&mut self) { ... } }；完整边界见
[Drop 与自动清理](language.md#drop-与自动清理)。运行时失败仍继续其他清理并保留首个错误。
第一阶段不提供多线程共享指针，也不把 Rc 类型当作可跨线程对象。

### 10.8 动态能力、挂起资源和宿主边界

`&dyn Reader` 表示具体类型被擦除但读取能力确定，裸 `dyn Reader` 承担唯一对象所有权。
只有可生成固定调用入口的能力可动态化：方法有明确接收者，不能带未实例化类型参数，
也不能在接口中要求返回未知大小的裸 Self；效果仍保留在方法签名中。
第 10.5 节的静态 `Eq.eq(self, other: Self)` 要求另一个相同具体 Self，不能直接用于 dyn Eq。
dyn 不代表任意值，读取动态数据仍用 Value 等明确模型。

首版实施见[借用型 dyn Trait 计划](borrowed-dyn-trait.md)：仅同步非逃逸的 `&dyn Trait` /
`&mut dyn Trait`，关联类型必须绑定，方法签名满足动态化条件。W3 在此基础上增加拥有对象及聚合/容器存储；
动态挂起、普通源码的视图返回及宿主 ABI 仍未开放。
`&*view` / `&mut *view` 建立受检引用的重借用，不能提高共享权限；dyn 目标仅可借用，普通 Copy 目标可通过 `*view` 读取。
全部关联项须显式绑定；裸 dyn 是非 Copy 拥有值，支持别名和期望类型驱动的转换。
语言挂起和并发禁止活跃 dyn 视图；挂起点之间的同步局部范围与限制见 [language.md](language.md)。

挂起任务保存的每个拥有值、借用、闭包环境和代码入口都有生命周期：

- 被暂停执行保留的借用必须在所有后续恢复期间有效；可移动拥有值或显式使用 Rc 保活，
  不能靠 `@suspends` 消除借用错误。
- scope 内子任务可借用父范围的数据，前提是所有退出路径都结束或取消子任务后再释放数据；
  不允许子任务携带此借用逃出 scope/race。分支实参按现有规则准备，借用冲突同样需要检查。
  对异步 FFI，取消请求不等于停止访问：已实现的宿主借用 v1 要求 stop 返回前同步停止访问，才可释放借用对象和 arena；异步取消/draining 后续设计。
- 局部、字段及无引用容器视图已覆盖恢复、失败和取消；显式 Arena、dyn 视图等未开放能力仍在挂起边界拒绝；
  不允许通过裸指针暂时绕过规则。
- 当前 Rust Continuation API 没有表达任意借用宿主值的生命周期，新借用能力不能直接套进
  现有入口；必须先设计任务生命周期约束或要求任务持有完整拥有者。

String 语言内部使用拥有存储，宿主参数使用显式 JokyText 指针/长度描述符；
根结果使用版本化拥有文本出口。旧长度前缀 ABI 已删除，宿主绑定需要迁移和重新编译。
`vm.Vm` 已由源码记录包装私有 Resource `vm.Owner`，操作借用、close 消费拥有者，退出自动释放。
线程绑定、热重载与旧代码保活语义保留；Rust/C 数值句柄仍采用显式关闭协议。
新的 Rune、元组、泛型、借用或 dyn 类型不会自动成为合法的 extern 参数；
须先定义对应 ABI 与宿主适配器，无法验证的裸入口仍需 unsafe 契约。

## 11. 核心语法（EBNF）

`[ ... ]` 表示可选，`{ ... }` 表示重复，`|` 表示选择；引号内为源码终结符。
`Identifier`、`Integer`、`StringLiteral` 按第 3 节识别，排除保留字；`StringLiteral` 内的 `{expr}` 是插值孔。

`private: Int32` 仍是名为 private 的普通字段。

impl 目标必须是支持的具体类型或按顺序应用全部 impl 参数的记录 / 枚举，不能特化或以别名声明。
const 的表达式子集、方法 self 位置及 join/race 分支必须为挂起调用等规则由语义检查收窄。
Postfix 上的类型实参用于泛型枚举构造、关联函数或方法自己的类型参数。
实例接收者或已绑定类型命名空间后的列表只包含方法参数；未绑定命名空间后的列表依次包含 impl 和方法参数。
显式列表可省略末尾 callable 参数，其余部分必须完整；全部省略时从实参推导；详见[方法类型参数](language.md#方法类型参数)。
TypedName 可作类型命名空间的接收者、空载荷泛型构造或完整指定类型实参的泛型函数值；不产生类型值。

表达式按优先级尽可能继续解析；遇到不能继续当前表达式、但能开始下一表达式的 token 时，
块才开始下一项。`;` 优先并入当前 Expression，连接其后可解析的 NonSequence，
在逗号、右括号、右花括号或 join / race / match 分支边界前允许尾随。连续分号优先并入同一序列。
末尾单独的空分号也使块结果为 Unit。完整表达式后的换行开始下一项，行首 `.` 明确续写上一项；
圆括号和实参列表内忽略换行，嵌套花括号恢复分隔。未完整的表达式继续读取下一行。
Binding、Assignment、Jump 的内部不直接吞入分号序列；通过 Group 显式将序列作为一个值。
Jump 没有正常完成时的值，分号不吸收返回、跳转、失败或挂起效果；语义检查负责其合法位置。
记录初始化项内部也用 NonSequence，需要序列值时使用 Group 或 Block。
元组元素使用 Expression；括号内逗号决定是否形成元组，单元素必须有逗号。
let / var 的 `_` 只丢弃，不引入名称；元组模式内名称必须唯一。
Name 后的 `{}` 或以 `Identifier :` 开始的块优先解析为 RecordValue；其他块保持独立。
条件及 match 被匹配表达式中未分组的 RecordValue 受限，精确规则见[当前记录语义](language.md#记录)。
`Name` 后紧接 `(` 或 `::<...>(` 时按 Call 解析，`::<...>` 可独立取泛型函数值，类型实参须完整。
空载荷泛型构造可独立写 `Option.None::<Int32>`，无括号且不是函数值。
类型注解中的 Name 先匹配当前声明的类型参数，且形参不能重复或使用 `_`；impl 参数也不能命名为 `Self`。
方法参数不能遮蔽 impl 参数、impl 目标名称或 `Self`，两层参数合计最多 64 个。
连续运算符按最长匹配分词；`||` 不是两个分支符。类型列表解析时按需拆分 `>>` 的闭合符，
或 `>=` 中的闭合符与赋值符；表达式中的比较和移位保持原规则。
EBNF 的 BitOr 在 join / race 分支最外层禁用；进入括号、参数、字段、元组或块时恢复，退出时还原。
数值 token 需要整体满足 Integer，不能把 `0b102` 拆成 `0b10` 和 `2`。
枚举构造复用限定名 / Call 文法，由类型检查辨认；模式中的 `_` 不能被限定或带载荷。
模式载荷递归解构元组、记录、枚举和序列；变体载荷有无必须与声明匹配。序列中的 rest 最多一个，let/var 中的序列项仅允许绑定模式。空枚举及不穷尽的空 match 在语义阶段拒绝。

## 12. 实施顺序与验收

迁移现有源码时，保留现有可选分号与表达式序列写法；需补齐列表逗号，将导入移到文件开头，
为依赖旧四则结合方式的表达式加括号，并检查新增保留字占用的旧名称。
字符串中的裸换行改为 `\n`，需要保留反斜杠的未知转义改为显式 `\\`。
`type`、`struct`、`enum`、`match`、`impl`、`const` 已启用为保留字，以它们命名的旧函数、参数或局部变量需要重命名。
mut 已在 Arena 专项阶段 1、unsafe 已在阶段 5a 启用为保留字；同名旧标识符需要迁移。
受检引用使用 `*` 读写与重借用；整值操作由 `joky/mem` 提供，不新增 ref 关键字。
借用表达式中，`a` 换行接 `&b` 是两个表达式；跨行位与应写 `a &` 后换行，或使用圆括号；
多层引用无论写成 `&&T`、`& &T` 或通过别名组合，首版均拒绝。
`Int64`、`UInt32`、`UInt64`、`Ptr` 已启用为类型关键字，原先使用这些名称的用户标识符需改名。
`int32`、`int64`、`uint32`、`uint64` 现为内建转换函数名，同名用户函数、extern 和宿主绑定需改名；
同名局部变量和类型名称仍合法。转换参数默认定型规则与目标返回类型相互独立。
`__joky_generic_` 前缀保留给编译器实例，使用该前缀的用户函数或 extern 需要改名。
数值后紧邻标识符须添加空白或 `;`，如 `1foo` 不再拆成两个表达式。
旧的 `let _ = ...` 再读取 `_` 的代码须给绑定改名；它现在是丢弃模式。
名称后独立的空块或形似字段简写的块需要明确分隔，如 `value; { name }`，或将 `{` 放到下一行，避免被识别为记录构造。
第一版先采用单一目标语法，不设计兼容模式或按文件切换语法版本的指令。

1. **规范解析边界**：运算符优先级、一元运算和 Bool 相等比较已实现；保留分号连接及可省略规则。
   参数与实参必须用逗号分隔、允许尾随逗号；字符串转义和文件开头导入规则已实现。
   依赖旧优先级的测试已加括号；现有示例和三个循环基准符合新解析规则。
   旧省略逗号、后置导入、未知转义和裸换行写法需要迁移，不能宣称保持旧程序语义。
2. **补齐控制流**：if、短路、return、break、continue 已通过共享 IR 实现，
   JIT、AOT 和解释器覆盖一致的求值顺序、类型检查与不可达诊断。
3. **覆盖挂起路径**：条件、分支、短路右侧、返回值和循环跳转均已覆盖多次 Pending、不重放、
   失败、取消及重载；join 完成与跳转顺序、参数提前返回及解释器时间片也有回归测试。
4. **完成跨后端一致性**：四种整数除零失败、位宽环绕、无符号比较/除法及有符号 `MIN / -1`、同步/CPS/join 失败传播及源码范围
   已覆盖三个后端；仍保留[诊断及资源限制差异](architecture.md#已知边界)，不宣称所有运行时能力相同。

关键验收用例：`1 + 2 * 3` 为 7；`false && side_effect()` 不调用右侧；无 else 的 Int32 分支
报错；`let x = 1; x = 2;` 报错；循环外 break 报错；同步函数调用挂起函数报错；
`fn f() -> Int32 { let x = 1 let y = 2 x + y }` 无分号也返回 3；
`f(a; b, c)` 只有两个实参；函数末尾 `42` 与 `42;` 的结果类型不同；
`f(a b)` 报缺少逗号，`f(a, b,)` 合法；字符串转义跨后端保持字节一致，包含 NUL；
悬挂任务恢复后每个副作用只执行一次。

   生命周期覆盖任务恢复、失败、取消和重载后，再开放携带借用的挂起任务。
   拥有型 String 按[字符串专项计划](string-storage-ownership.md)推进；Box / Rc、挂起闭包与借用闭包逃逸和动态挂起 dyn 后续单独扩展。
8. **纯 Joky 容器与所有权**：按 [容器扩展步骤](arena-borrowing-ffi.md#61-容器与所有权扩展)，
   先用 Joky 实现 `Array<Int32>` 的受检访问、push/pop 与扩容，再推广 Copy 元素泛型容器，
   资源型数组元素与嵌套容器已实现；[Map 分阶段计划](map-storage-ownership.md)首版已验收。
   [List / Set 开发计划](list-set-storage-ownership.md)中的 List L1–L4 与 Set S1–S3 已完成，保留 graph。
   同步容器无需等待异步 FFI；跨挂起使用另行
   验证保活与取消。源码库算法、存储原语和三后端行为共同构成验收。
9. **网络运行时**：按[网络开发计划](network-runtime.md)推进。NET0 已完成三后端真实 TCP
   探针与边界确认；NET1a 已实现通用外部资源、拥有型聚合 CPS、原子交接、
   资源独占借用和有界字节请求；NET1b 已接入有界 Mio 就绪、外部唤醒和阻塞/逐帧驱动。
   NET2 已实现 `joky/tcp` 公共接口与业务 Result，Godot 与 CLI 共用语言任务语义。
   NET3 已补 write_all、背压/额度和引擎网络联合验收；DNS、UDP、TLS 与读写拆分另行分期。

类型验收还需覆盖：UserId / OrderId 不混用，别名等价，字面量溢出拒绝、窄化显式，
match 不穷尽报错，移动后使用拒绝，独占借用不重叠，不能返回局部引用，闭包调用次数受约束，
挂起效果不能经泛型或 dyn 擦除，所有退出路径的资源只释放一次。

关联类型已实现，见[第 4 项验收记录](trait-default-methods-associated-types.md)；借用型 dyn 的 V0–V5 已验收，见第 5 项计划。
关联类型项与后续成员须以换行或分号分隔；只有 trait impl 可定义关联类型，且不能加 `pub`。
数组字面值及展开构造、下标访问、共享/独占/消费式序列模式和固长解构已实现，规则见[数组字面值](language.md#数组字面值)及[序列模式](language.md#序列与字面量模式)。
后续尚待单独设计的表面语法：挂起闭包与借用闭包逃逸、其他容器字面量、重复数组构造及区间索引。
本草案暂不加入：异常捕获、通用效果处理器、类继承、高阶类型、`for` 循环、
包管理、反射。多线程调度另按[任务执行器专项计划](task-parallel-executor.md)设计，尚未实现。
类型布局与 ABI 变更必须有独立的迁移方案。

有状态服务计划的 S2a 已统一 `when`／句柄方法的候选执行：标准顶层业务 Result.Err 丢弃候选，
成功发布才推进修订；普通 false 与 Ok(false) 正常提交。显式原地短操作保留旧规则。
S2b 已提供受检的 `outbox.emit`，与候选状态一起原子发布；S2c 将 chat 的收费与成员变更
移入具名业务操作，目录依赖解析进入有界重算。进度及验证见[实施计划](stateful-service-ergonomics.md)。

2026-10-23 的服务易用性阶段补充：共享 Script 入口预检及依赖快照、`Vm.try_call`、
`joky/session` 连接组件已实现；chat 使用有界迭代淘汰、创建等待超时和可配置空房回收。
具体接口见 [language.md](language.md)，阶段验收见
[stateful-service-ergonomics.md](stateful-service-ergonomics.md)。
