# 模块编译：依赖类型快照基准

> 历史记录：本文保留原阶段的设计、环境与验收结论，不代表当前能力。归档于 2026-09-24；当前说明见[文档入口](../../README.md)，未完成工作见[计划索引](../../plans/README.md)。

2026-09-21，基于 `cd38723` 对比本次依赖快照优化。环境为 macOS ARM64、
Rust 1.97.1，使用 Cargo 默认 test profile。结果为本机合成负载观测。

## 测量范围

`compiler::module_bench::module_compilation_scaling` 创建 8 / 32 / 128 个业务模块，
另加入口模块和共享泛型定义模块。每个业务模块有一个独立的名义 struct 和
8 个函数，调用共享泛型 `identity`，因此分别生成 8 / 32 / 128 个泛型实例。
入口导入所有业务模块，覆盖大量模块依赖和调用方自定义类型的实例化。

只计时 `compile_units`：包含模块语义检查、HIR/MIR、验证、泛型实例化和
缓存读写；不包含模块图加载、JIT 初始化、MIR 链接、机器码生成或程序执行。
冷编译使用空的 Joky 缓存目录；随后热编译必须完全命中源码模块和泛型实例。
这里的“冷”不表示清空操作系统文件缓存。

每种规模取三个独立缓存目录的冷/热配对样本，报告中位数。分配量来自已有的
进程级计数分配器，表示阶段内累计分配字节数，**不是峰值内存或 RSS**。
基准必须单独运行，避免其他测试的分配混入计数。

```bash
cargo test --locked --lib compiler::module_bench::module_compilation_scaling -- \
  --ignored --exact --nocapture --test-threads=1
```

## 第一阶段的实现与验证

- 普通模块先读取缓存，未命中才建立依赖上下文。
- 泛型实例先计算缓存键并读取缓存，未命中才复制模板 AST、建立依赖上下文。
  遍历实例请求时只复制请求和符号，不再复制调用方整个 `TypeTable`。
- 一次编译会话按需为已完成的模块建立只读 `TypeTable` 快照，同一个快照由
  普通检查器、泛型检查器和类型查询共享；依赖映射本身也共享。
- 已完成的模块集合只追加，每张依赖表至多为会话快照深复制一次。完整热命中
  不创建此类快照。快照在模块编译阶段结束时释放，不驻留于 `Compiler`。
- 嵌套类型函数查询通过依赖映射的写时复制安装私有调用方快照，避免查询间
  类型索引污染。泛型仍能访问定义模块、调用方和传递依赖。
- `TypeTable`、模块产物的序列化形状和缓存版本未改变。

新增回归 `cached_dependencies_support_changed_callers_and_nested_type_queries`
在同一个 Compiler 上先完成冷/热编译，再将调用方类型的字段从 Int32 改为
String。依赖模块继续命中缓存，调用方和两级泛型实例重新编译；再次执行应
全部命中。程序同时验证不同类型参数的嵌套跨模块类型函数结果。

本次验证：

- `cargo test --locked --lib`：沙箱内 1038 passed、8 failed、10 ignored；
  8 项失败均为本地 TCP bind 的 `Operation not permitted`。沙箱外重跑
  `cargo test --locked --lib compiler::tests::runtime`，17 passed、3 ignored，
  包括全部 8 项受限用例。共验证 1046 项非 ignored 库测试。
- `cargo test --locked --test cli cache`：13 passed，覆盖缓存启停、损坏恢复、
  JIT/AOT 缓存复用、跨模块泛型与 trait/container 行为。
- 隔离模块基准通过；`cargo fmt --all --check` 和 `git diff --check` 通过。
- `cargo clippy --locked --all-targets` 完成，仅报告已有代码的告警。

## 第二阶段：拆分前端、模块接口与后端布局

在第一阶段提交 `6962350` 上增加缓存体积计数，使用同一基准、环境和三次
配对采样，对比三层数据拆分后的结果。计时与分配计数结束后才统计 `.jmir`
文件大小；缓存体积不包含 `.jabi`。下表全部数值为中位数，MB 使用十进制。

| 源码模块 / 泛型实例 | 热编译 ms：拆分前 → 后 | 热编译累计分配 MB：前 → 后 | MIR 缓存 MB：前 → 后 |
| --- | --- | --- | --- |
| 10 / 8 | 8.89 → 8.91 | 0.857 → 0.719 | 0.171 → 0.146 |
| 34 / 32 | 34.70 → 30.95 | 3.303 → 2.769 | 0.672 → 0.573 |
| 130 / 128 | 134.08 → 115.03 | 13.087 → 10.971 | 2.675 → 2.280 |

最大规模缓存体积进一步减少约 14.8%、热编译分配减少约 16.2%。冷编译耗时
中位数为 9,515.77 → 9,573.15 ms，未观察到提速；累计分配为
548.92 → 541.00 MB。此次重构主要建立消费边界并减少缓存负担，不能宣称
解决了冷编译的非线性增长。

实现上，`CheckedTypes` 持有源码节点事实，不实现 Serialize/Deserialize 或
Clone；`ModuleInterface` 持有独立模块元数据；`TypeTable` 只持有后端类型
和布局。导入快照共享后两者。struct 默认值在接口中转为可重定位常量；不能
导出的计算默认值保留延迟错误，维持本模块合法、导入时报错的原有语义。
模块 import 清单从已解析的 MIR stub 收集。单文件 JIT 使用 MIR 类型表
安装 provider，不再为此克隆整份前端结果。

缓存格式升级为 `JKMIR019`。新增回归覆盖本地计算默认值与延迟导入诊断，
并在完整 payload/checksum 下替换旧格式标识，验证旧缓存按 miss 重建。
既有跨模块泛型、嵌套类型函数默认值、调用方类型变化、C 布局序列化等用例
继续验证新边界。第二阶段的验证结果在下方记录。

- `cargo test --locked --lib`：1047 passed、10 ignored；在允许本地 TCP bind
  的环境运行。10 项 ignored 包括隔离资源测试和基准，不表示已全部运行。
- `cargo test --locked --test cli cache`：13 passed，含默认 debug AOT。
- 扩展后的旧缓存格式回归单独重跑通过，隔离模块基准通过。
- `cargo fmt --all --check`、`git diff --check` 通过；
  `cargo clippy --locked --all-targets` 完成，只保留已有代码的告警。

## 前端检查回归

无执行和无动态库加载、类型/effect/ownership/挂起诊断、模块来源、泛型缓存与
`run` 互用、依赖失效，以及复用 `Frontend` 时的统计和诊断清理。新增用例还验证
`--json` 的成功/失败结构、多模块诊断收集、内存源码快照、未保存模块、结构化诊断路径/span，
以及长期 `Frontend` 会复用未变化的模块图条目并在源码修改或显式清理后失效。
`cargo test --locked --lib` 覆盖抽取后既有模块、泛型、JIT 和 AOT 的行为。
