# Chat 域资格校验实验（2026-10-31，未采用）

**本轮没有合入运行时代码，保留 `9ca683f` 的实现。** 两个候选都通过正确性检查，
但性能对照未显示稳定收益，四 worker 配置出现明显负向样本，因此没有按分配次数减少就认定优化成功。
这些短样本不能单独证明退步的根因；在风险未排除前保留基线。

## 候选与结果

`value_eligible`、`constructor_eligible` 和编译期 `domain_value` 此前只判断
`domain_schema(...).is_some()`，生成的字符串会立即丢弃。候选增加 `domain_supported`，
与 schema 编码共用同一套有界遍历和接受规则，校验路径跳过格式化。
初版保留空 String 返回；最终候选改用零大小的校验标记，递归不携带 String 或其清理路径，
真正编码时直接向结果字符串追加。两个候选的测量分别保留，以下只统计最终候选的 30 个样本。

每格为三个独立进程样本中位数；吞吐为广播/秒，CPU 为每个样本先算服务端 ms/广播再取中位数。

| 房间 / worker | 基线吞吐 | 候选吞吐 | 变化 | 基线 CPU | 候选 CPU |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 / 1 | 869.3 | 894.6 | +2.9% | 1.7375 | 1.7025 |
| 1 / 4 | 1417.1 | 1309.6 | −7.6% | 2.3263 | 2.4375 |
| 4 / 1 | 2172.6 | 2133.3 | −1.8% | 0.7863 | 0.7863 |
| 4 / 4 | 3039.7 | 2724.5 | −10.4% | 1.1342 | 1.2058 |

单连接吞吐 1938.0→1909.8（−1.5%），P50 0.4746→0.4789 ms，P99 0.6408→0.6529 ms，
CPU/请求 0.419→0.423 ms。四 worker 配置均有一轮正向、两轮负向，范围重叠；
不将个别正向样本或单房间／单 worker 的改善外推为普遍收益。全部样本通过内容、顺序、扣款和退出校验。

## 独立分配复测

单连接预热后分别运行 0／500 条消息窗口，扣除零消息窗口后按广播条数归一化。
基线计数复用上一轮同一实现的探针，候选使用相同探针并将纯校验入口归入同一 schema 类别；
两版探针的 chat 源码哈希一致，各窗口都通过协议校验。计数与性能采样使用不同产物。

| 每条消息 | 基线 | 候选 | 减少 |
| --- | ---: | ---: | ---: |
| alloc／alloc_zeroed 次数 | 2645.40 | 2530.38 | 4.3% |
| realloc 次数 | 246.01 | 141.03 | 42.7% |
| schema 格式化分配（不含类型遍历） | 115 | 0 | 100% |

类型遍历约 270 次、布局约 211 次、预算准入约 170 次分配仍在。
这确认候选消除了预期的字符串分配，但没有证明它是端到端性能瓶颈；负向样本的原因尚未定位。
后续应先做 CPU／等待时间归因，再决定是否重启这项改动。

## 方法与验证

基线为 `9ca683f` 的实现，复用上一轮保存的正常工具／应用；候选基于该提交加实验改动。
基线与候选 chat 源码逐文件哈希一致，重新交替采样，未拼接历史性能结果。
沿用[请求契约缓存测量](chat-request-contracts-2026-10-31.md)的方法：Apple M1 Pro、16 GiB、
macOS 26.6.2 ARM64、Rust 1.99.0、Cranelift 0.137.1，生成代码 `speed`，工具及运行时为 Rust Release。
16 客户端、64 字节正文、1／4 房间 × 1／4 worker；每客户端预热 25 条、每批 250 条、至少 3 秒。
单连接每批 5000 条。三轮旧→新、新→旧、旧→新，第二轮配置顺序倒置。
计时与构建、测试、分配探针分开；单机短闭环负载不代表最大容量，也未重测 Tokio。

8 项 Script 契约测试、域拥有值／泛型请求三后端执行及资格拒绝测试、拥有图与 Drop 拒绝测试、
chat 串行／并行真实 TCP 测试通过。边界回归覆盖实际解析后的 64／65 lane 类型、成员上限、
嵌套深度、零 lane／phantom 成员，以及既有 schema 编码；校验与编码路径接受范围保持一致。
格式与 `cargo clippy --all-targets -- -D warnings` 通过，未运行全量检查或压力穷举。
原始数据、源码补丁、工具快照、探针及日志留在 `target/benchmarks/chat-schema-check/`，不提交 Git。

候选源码、测试和探针已从工作树撤回，正常工具产物恢复为基线；本次提交仅保留实验结论。
