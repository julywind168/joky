# 内部直接调用共享浮点保护（2026-10-31）

本轮在 `48e08ed` 上修改 JIT／AOT 共用的原生后端，为需要 arena 或可挂起的
生成函数提供私有主体。模块内已知的直接调用转向主体，在已有标准浮点环境中执行，
省去逐层 enter／restore；没有根据 chat 源码是否出现 Float 来关闭整套保护。

导出符号、函数地址、动态分派表、Drop 回调及 CPS 恢复描述继续指向受保护入口。
未知宿主／间接调用返回后仍 reset；含浮点值的主体继续用独立调用适配函数阻止
Cranelift 把浮点运算移动到环境重置之前。编译、解释器和 Rust 运行时 Guard 不变。
纯标量函数保留原策略，不为本优化引入运行时链接依赖。内部调用允许累积状态标志，
语言不暴露这些标志；完整边界调用仍恢复宿主的控制位和状态标志。

## 验证

新增执行生成代码的计数回归覆盖 `none`、`speed`、`speed_and_size`，整数／浮点主体，
以及直接调用、函数指针、宿主重入。三层直接调用只执行一组 enter／restore；
通过函数指针或宿主重入则执行两组，未知调用后的 reset 均保留。
测试从异常舍入／FTZ 和非零状态标志进入，检查最近偶数舍入结果与完整环境恢复；
宿主重入还检查内层返回后宿主的异常环境仍被保留。

通过 `cargo test --lib float_` 的 22 项测试，包含 JIT、解释器、真实 C 链接 AOT，
覆盖浮点运算、优化级别、闭包、宿主重入、Pending／恢复、失败及清理边界。
纯标量 AOT 无运行时链接测试单独通过。重新构建当前 Debug 静态库后，
`cargo test --test chat -- --ignored` 显式执行的串行／并行真实 TCP 矩阵均通过。
`cargo fmt --check`、`cargo clippy --all-targets -- -D warnings` 和 `git diff --check` 通过。
按本轮约定未运行 `check.sh`、全量测试或额外压力穷举。

## 性能结果

24 个样本均完成协议与退出检查。表中吞吐单位为广播/秒，CPU 为 ms/广播。

| 房间 / worker | 基线吞吐 | 优化后吞吐 | 变化 | 基线 CPU | 优化后 CPU |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 / 1 | 898.7 | 924.1 | +2.8% | 1.715 | 1.669 |
| 1 / 4 | 1,441.4 | 1,424.5 | -1.2% | 2.244 | 2.246 |
| 4 / 1 | 2,195.8 | 2,348.3 | +6.9% | 0.775 | 0.737 |
| 4 / 4 | 3,338.8 | 3,395.0 | +1.7% | 1.006 | 0.985 |

四房间／单 worker 三组配对吞吐均改善，CPU 成本中位数下降 4.9%，P99 从 11.52 降到 10.35 ms。
四房间／四 worker 三组配对也均改善，但吞吐中位数只提高 1.7%，CPU 成本下降 2.1%；
样本吞吐范围仍有重叠，不宜据此宣称明显的多核性能提升。
单房间／四 worker 的配对变化方向不一致，中位数下降 1.2%，CPU 基本持平，没有明确收益。
本轮是减少内部调用重复保护的局部改善；未知调用后的 reset 和调度唤醒成本仍然存在。
这里使用同轮基线，不将上一轮不同时间的吞吐拼成增幅。

## 测量方法

Apple M1 Pro、macOS ARM64，正常 Rust Release，生成代码 `speed`。
基线复用上一轮全范围切片优化后的工具与应用快照；编译器／静态库哈希与应用构建记录一致。
候选重新构建，相同 chat 源码逐文件哈希一致。16 客户端、64 字节正文，
每客户端预热 25 条，每批 100 条；四房间至少 20 秒，单房间至少 5 秒。
每配置三个独立进程样本，交替旧→新、新→旧、旧→新，第二轮反转配置顺序。
吞吐和 CPU 成本均取样本中位数；CPU 成本先按每广播归一化。
测量保留协议内容、顺序、扣费和退出检查，构建与正确性测试不与计时重叠。
闭环负载不代表最大容量；本轮没有重测 Tokio，也没有修改唤醒机制。

原始样本、构建快照、验证日志保留在 `target/benchmarks/chat-fp-boundaries/`，不提交 Git。
