# 预算准入与类型遍历的小分配（2026-10-31）

本轮以 `f1c60e5` 为基线，先更新 CPU／分配归因，再调整两个高频小分配路径。
固定控制签名只占单连接每条消息 4 次分配，本轮没有优先修改它，也没有引入全局缓存或对象池。

四房间／四 worker 的 Time Profiler 有效窗口约 20.63 秒，收集 61,401 个 Running 样本。
分配器叶节点约占运行 CPU 的 14.3%；预算准入 `Accounts::charge` 的包含调用时间约占 10.3%，
类型遍历与布局各约占 2.4%／2.3%。包含调用时间与分配器叶节点存在重叠，不能相加。
采样使用保留调试符号和帧指针的 Release 产物，不用于吞吐对照。

## 改动

- 预算准入将前两个锁守卫放在栈上，更多预算仍用动态数组保存剩余守卫。
  所有预算仍按相同身份排序加锁、全部预检后收费，失败回滚和并发归还规则不变。
- 类型遍历单独保存起始节点，确实需要暂存子节点时才分配工作栈。
  节点访问顺序、共享类型图去重及各边策略不变；简单叶子查询不再为起始节点创建 Vec。

## 分配计数

下表为每条广播的事件数，alloc 包含 alloc_zeroed；不是驻留内存或泄漏量。

| 配置 | 总分配：旧 → 新 | realloc：旧 → 新 | 预算准入分配：旧 → 新 |
| --- | ---: | ---: | ---: |
| 1 客户端 / 1 房间 / 1 worker | 2,642.0 → 2,440.7 | 244.0 → 177.0 | 167.0 → 0.0 |
| 16 客户端 / 4 房间 / 4 worker | 3,463.1 → 3,211.5 | 277.1 → 210.1 | 215.0 → 0.0 |

总分配次数分别下降约 7.6%／7.3%，realloc 下降约 27.5%／24.2%。
两种配置中，类型遍历的分配均为 270→235 次／广播，realloc 为 67→0 次／广播。
预算准入的锁守卫分配在该负载中完全消除；多预算集合仍保留动态兜底。
两版探针应用源码哈希一致，计数不包含启动与 JIT 编译。
探针已撤回，生产源码与验证时的补丁逐字节一致；正常性能产物重新构建。

## 正常产物的性能对照

24 个样本均通过协议与退出检查。表中为三个样本的中位数，吞吐单位为广播/秒；
CPU 变化按每广播的服务器 CPU 时间计算，负值表示成本下降。

| 房间 / worker | 基线吞吐 | 优化后吞吐 | 吞吐变化 | CPU 成本变化 |
| --- | ---: | ---: | ---: | ---: |
| 1 / 1 | 990.8 | 973.5 | -1.8% | +0.6% |
| 1 / 4 | 1,400.8 | 1,545.0 | +10.3% | -4.7% |
| 4 / 1 | 2,339.4 | 2,427.7 | +3.8% | -2.8% |
| 4 / 4 | 3,265.2 | 3,166.0 | -3.0% | +1.2% |

单房间／四 worker 的三组配对吞吐均提高，但 CPU 成本变化方向并不完全一致。
四房间／单 worker 的三组配对 CPU 成本均下降，幅度较小。
单房间／单 worker 与四房间／四 worker 的吞吐和 CPU 都出现过正负两种变化，
本轮中位数为负向结果，没有剔除这些样本。
四房间／四 worker 吞吐范围为基线 3,254–3,393、候选 3,065–3,672 广播/秒，
P99 中位数为 7.52→9.22 ms，因此不能宣称尾延迟改善。

保留这两处局部、无新增缓存生命周期的小分配优化。分配减少已经由计数确认，
端到端收益只在部分配置中体现；尚未证明普遍提速，也不能将负向样本简单归为已排除的噪声。

Debug 下 40 项类型测试、14 项并行存储／预算测试、4 项并行聚合测试通过，

## 测量方法

Apple M1 Pro、macOS ARM64，正常性能产物为 Rust Release，生成代码 `speed`。
基线使用上一轮定向唤醒优化后的工具与应用快照，候选重新构建；chat 源码逐文件哈希一致。
16 客户端、64 字节正文，每客户端预热 25 条、每批 100 条；四房间至少 20 秒，单房间至少 5 秒。
每配置三个独立进程样本，交替旧→新、新→旧、旧→新，第二轮反转配置顺序。
吞吐和 CPU 成本取样本中位数，CPU 成本先按每广播归一化。
测量保留协议内容、顺序、扣费及退出检查，不与构建、正确性测试或探针重叠。
闭环负载不代表最大容量，本轮没有重测 Tokio。

分配探针与性能测量分开。每版分别测 1 客户端／1 房间／1 worker 和 16 客户端／4 房间／4 worker，
预热后运行每客户端 0／500 条消息窗口，扣除零消息窗口的固定开销再按广播条数归一化。
统计 Rust 全局分配器的 alloc／alloc_zeroed，realloc 单列；阶段和细项两组归因不能相加。
探针记录事件次数，不代表相同比例的 CPU 收益；每配置是一组计数差值，不作为统计吞吐结果。

原始采样、探针、构建快照和验证日志保留在 `target/benchmarks/chat-request-prep/`，不提交 Git。
