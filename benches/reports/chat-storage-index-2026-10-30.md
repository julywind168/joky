# Chat 共享分配索引优化（2026-10-30）

本机三轮交替对照中，共享分配索引与锁外释放使固定 chat 负载的广播吞吐提高到旧版的
**1.88～3.65 倍**，每条广播的服务端 CPU 时间下降约 **45%～52%**。
单客户端请求到回显的 P50 从 **1.143 ms 降至 0.794 ms**。
这些是应用路径的端到端结果，不能解释成 TCP 单程延迟或服务器最大容量。

## 改动与安全边界

- 精确地址查询从“锁根分片表、逐分片线性扫描”改为 16 个独立索引桶内的二分查找。
  登记保存所属分片与稳定槽位；删除使用空闲槽链，避免使其他地址的登记失效。
  插入／删除仍移动桶内索引条目，不宣称所有操作均为常数时间。
- `contains` 只锁目标桶；finalizer 登记、拥有权迁移与释放按“桶 → 分片”加锁。
  释放先取出唯一分配记录，解锁后执行元数据 finalizer、dealloc 与退款。
  Region 清理先撤销全部索引，再清理分配。
- 保留普通借用的任务来源、对齐和完整范围检查；没有开放新权限，没有新增 `unsafe impl`，
  没有改变语言析构的 worker 归属，也没有改动浮点环境或控制桥语义。
- 索引和稳定槽位增加了计费元数据。空闲槽与索引容量可由根保留复用，根销毁后归还；
  载荷释放不意味着索引缓存立即退款。分配失败、未领取结果和取消仍须恰好清理一次。

实现见 [storage.rs](../../src/runtime/parallel/storage.rs)，当前不变量见
[共享存储](../../docs/architecture.md#可转移准备与共享存储)。

## 方法与构建身份

环境与[首轮基线](chat-workers-2026-10-30.md)相同：Apple M1 Pro（6P + 2E）、16 GiB、
macOS 26.6.2 arm64、Rust 1.99.0、Apple clang 21.0.0。
工具和静态运行时为 Release；Joky 代码生成仍采用默认设置。
同一 AOT host + JIT 业务脚本，Parallel 模式启动 1／2／4 worker；另有控制和 I/O 等线程。

旧版复用 `target/benchmarks/chat-workers/build-20261030` 的已保存产物，代码基线为 `a9bfcde`。
`a9bfcde..3847d6f` 只新增基准和文档，没有运行时变更。
新版基于 `3847d6f` 加本次 `storage.rs` 改动；构建时工作树为 dirty。
[旧版](chat-storage-index-2026-10-30/before-build.json)、
[新版](chat-storage-index-2026-10-30/after-build.json)元数据保存工具、静态运行时、应用和资源的 SHA-256；
[产物哈希](chat-storage-index-2026-10-30/artifact-hashes.json)另含构建时运行时补丁与源码哈希。
不能用测量时的 HEAD 代替旧版产物身份。

所有构建及正确性检查完成后才开始计时，期间不并行编译、测试或采样。
三轮顺序为旧→新、新→旧、旧→新；worker 顺序依次为 `1,2,4`、`2,4,1`、`4,1,2`，
房间顺序依次为 `1,4`、`4,1`、`1,4`。每个配置每版共 3 个独立进程样本。

- 并发矩阵：16 客户端，1 房间各 16 人／4 房间各 4 人；每连接预热 25 条、计时 500 条，
  共 8000 条广播，正文 64 字节。每个连接等待房间全部接收者收到后才发送下一条。
- 单客户端：1 房间、1 worker，每样本预热 25 条、计时 5000 条，独立交替测量 3 轮。
- 运行器沿用 [chat-workers.py](../chat-workers.py)：只在独立副本修改监听端口和初始余额，
  核对完整消息、接收者、顺序、最终余额及正常退出。没有修改仓库 chat 的业务逻辑。
- 编译、启动、join、预热与 shutdown 不计时。负载为固定并发闭环，未测开放到达率、慢消费者或过载。
  不固定 CPU 亲和性；三个样本只用于本轮对照，不给置信区间或跨机器保证。

本轮旧版比历史的 239 广播/秒快，因此所有倍率都使用本轮交替测量的旧版作分母。
新版 1→4 worker 的中位吞吐增加约 36%（单房间）／35%（四房间），开始受益于并行，仍远非线性扩展。
四房间的每条消息 fan-out 更少，不能将两种布局直接相除解释为消除房间锁竞争的收益。

| 1 | 1 | 5.086 | 2.792 | 1.36 | 1.41 |
| 1 | 2 | 5.921 | 3.254 | 1.54 | 1.71 |
| 1 | 4 | 8.286 | 4.416 | 2.04 | 3.04 |
| 4 | 1 | 2.445 | 1.196 | 1.35 | 1.60 |

新版每条广播的 CPU 成本降低，同时在多 worker 下使用更多核。新版 4 worker 的单位 CPU 成本
仍高于 1 worker，后续优化还需关注共享路径和调度成本。
各配置采样 RSS 最大值的中位数：旧版 76.4～76.9 MiB，新版 75.2～76.4 MiB。
这不代表索引没有内存成本：RSS 包括编译／运行时、allocator 缓存且仅每 250 ms 采样，不能代替预算记账或泄漏证明。

## 单客户端请求到回显

| 指标 | 旧版 | 新版 |
| --- | --- | --- |
| 完成请求/秒 | 843.8 | 1194.7 |
| P50 ms | 1.143 | 0.794 |
| P95 ms | 1.531 | 0.879 |
| P99 ms | 1.592 | 0.962 |
| 服务端 CPU ms/请求 | 1.116 | 0.722 |

P50 下降约 30%，吞吐提高约 42%。仍包含协议解析、脚本调用、域访问、扣费、队列、回环网络和 Python 客户端调度，
不是纯 TCP echo，也不能除以二当单程发送耗时。

## 分配表等待复核

正式计时后另用保留符号的新版产物采样：复用相同 Release 工具与运行时，链接时仅去掉
`-S,-x`，保留其他参数，与首轮基线使用相同 wrapper。4 worker、16 客户端、1／4 房间，
每连接改为 2000 条，保证新版在 5 秒采样期间仍有测量流量；采样间隔 1 ms。
这两个受采样干扰的运行均不进入上面的吞吐表。符号版有独立的
[构建身份](chat-storage-index-2026-10-30/profile-build.json)。

旧版采样复用首轮报告的同运行时产物；新版完整调用树见
[单房间](chat-storage-index-2026-10-30/profile-room-1.txt.gz)、
[四房间](chat-storage-index-2026-10-30/profile-room-4.txt.gz)，
[逐线程统计](chat-storage-index-2026-10-30/profile-mutex.csv)包含两版原始计数。

| 房间 | 旧分配路径互斥等待样本 | 新分配路径互斥等待样本 | 旧 worker/control 互斥等待占栈样本 | 新占比 |
| --- | --- | --- | --- | --- |
| 1 | 4859 | 128 | 30.91% | 5.29% |
| 4 | 5341 | 463 | 32.35% | 12.97% |

分配路径按 `__psynch_mutexwait` 的上层 Arena::contains／release、Storage::finalize_with
及相应索引操作归组；统计系统调用本体，不包含同名 dyld stub。
占比的分子是四个 task worker 和 control 线程的全部互斥等待栈样本，分母是这些线程的全部栈样本。
它们不是 CPU 时间、锁持有时间或每条消息的等待量；两版采样的消息总数和实际栈样本数也不同。
采样支持“原分配表等待已明显减少”的判断，具体收益仍以上面的未采样交替测量为依据。

新版 `__joky_float_env_reset` 分别有 3416／3134 个栈顶样本，成为下一步值得核查的工作热点。
不能据此直接省略真实宿主边界的浮点环境恢复；后续应单独核查内部调用边界并重新对照测量。
控制桥、预算和调度仍有共享成本，本次没有继续修改这些路径。

## 验证与复现

本次实际通过：

- 新增索引生命周期／分配失败退款／无关锁隔离／锁外可重入 finalizer 测试，以及原分片复用测试。
- 三后端聚合值传递；50 个只读借用测试；拥有 Drop 与闭包的迁移、返回、失败和取消行为。
- Debug `exhaustive_parallel_drop_value_budgets`、`exhaustive_scoped_borrow_budgets`。
- **一次**完整 `./scripts/check.sh`：fmt、Clippy、默认 Debug 测试及三后端短输入 while／Map 正确性。
  库测试 1833 通过，CLI 340 通过，其他集成测试全部通过。没有运行全部 ignored 穷举或 Release 全量测试。
- 36 个并发矩阵样本和 6 个单客户端样本均完成协议、余额及退出校验，没有剔除失败或慢样本。

完整样本与参数保存在 `target/benchmarks/chat-storage-index/`，包括逐消息延迟、日志、构建源码、资源和运行器快照；
紧凑数据见 [42 个样本](chat-storage-index-2026-10-30/samples.csv)及
[每轮环境与 argv](chat-storage-index-2026-10-30/environments.json)。

```sh
cargo build --release --bin joky --lib
python3 benches/chat-workers.py prepare \
  --joky target/release/joky --runtime target/release/libjoky.a --profile release \
  --output target/benchmarks/chat-storage-index/build
python3 benches/chat-workers.py run \
  --build target/benchmarks/chat-storage-index/build \
  --output target/benchmarks/chat-storage-index/matrix-1-after \
  --clients 16 --rooms 1,4 --workers 1,2,4 --messages 500 --warmup 25 --samples 1
```

其他轮次按上面的轮换顺序改变 build、输出目录、rooms 和 workers；单客户端改为
`--clients 1 --rooms 1 --workers 1 --messages 5000`。输出目录须不存在。
旧版须使用保留的旧产物或从旧代码重新构建，不能把新版文件重命名当作旧版。
