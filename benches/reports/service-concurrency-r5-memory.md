# R5 候选存储预算对照（2026-10-26）

环境：Darwin arm64，rustc 1.99.0 (b940084d7 2026-09-28)，默认 Debug test profile。
实现基线为 `76f6bcd`，测量代码为本次 R5 提交中的
[`transactions_tests.rs`](../../src/vm/state_domains/pairs/transactions_tests.rs)。

复现：

```sh
cargo test state_domains_when_readonly_roots -- --nocapture
```

只读根包含 16,384 项 `Array<Int32>` 与字符串 `shared`，写根为单字段 Counter。
访问顺序为「只读根、写根、同一只读根」，重复读取不重复快照。
编译及初始根构造完成后，以同一共享预算的增量比较两种候选捕获策略：

| 后端 | 全访问集合快照 | 仅写域快照 | 纯读候选 |
| --- | ---: | ---: | ---: |
| JIT | 66,906 B | 284 B | 0 B |
| Interpreter | 66,906 B | 284 B | 0 B |

全访问集合列通过同一捕获器将三个位置全部标为需要快照，复现 R4 的候选捕获策略；
它不是执行写操作，也不是跨版本二进制的吞吐对比。两种策略使用相同的根与快照实现，
计数包含保留的根、拥有载荷及候选列表预算，排除既有活根、编译、调用和后续临时分配。
该数字不是完整事务峰值，也不是进程 RSS。

行为回归另外验证：只增加 16 KiB 预算时，大只读根的事务仍能完成，而全根快照无法准入；
混合读写的预算扫描在第一次完整业务拒绝且清理成功后停止，检查只读数据可继续读取、
写域未发布、预算及存活分配归还。还覆盖纯读、重复只读绑定、成功写入和运行错误回滚。

本轮未进行耗时测量，不能据此推导聊天室吞吐或延迟的提速比例。
多根调用仍遍历和临时转移拥有图元数据；R5 消除的是只读候选的深复制。
